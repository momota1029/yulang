# Run a goal-driven Yulang sprint

Read `rules/goal-driven-sprints.md` and its governing decision. This skill is for
the Luna primary during authorized research/simple-sub-intrusion work. Children
follow one assigned packet and do not recursively start a team. Maintenance,
plan-only and status-only requests never imply production work or live spawning.

## Establish one outcome

Read `tasks/agent-loop/current.json` and README, then the active sprint contract.
At migration, leave legacy workers/leases UNKNOWN until the live primary
reconciles them; an archived board is not proof of cessation. Preserve current
uncommitted/foreign work and pending questions. Read only needed original
source/theorem locators and owner-path history, not entire historical ledgers.

At sprint start consult next_action_selector once. Fill the sprint template:
original theorem and quantifiers, accepted source/native meaning, implementation
path, success evidence, open premises/owners, exact authority/baseline/dependency
hashes, non-goals, both lane plans, bounded resources, exact output leases,
independent review seam and stop conditions. The supplied candidate is not a
launch packet until these fields are resolved and Luna grants it.

## Dispatch a continuation envelope, not a tiny task

Use registered implementer (Luna/high) and constructive prover/astra_prover as
appropriate. Sol can independently search counterexamples or source coverage;
fresh reviewers are separate from authors. Grant several related stages and
exact paths up front, including one handoff file for the assignment. Keep the
existing two-leaf proof-coordinator exception and global resource accounting.
Every supported spawn uses fork_turns: "none"; do not invent unsupported fields.

Try only supported runtime operations. Record actual worker ID/session/receipt,
requested/observed model and effort, and effective permissions. Missing model
metadata remains UNKNOWN. No supported spawn means explicit degraded serial
work, not a fictional team or independent self-review. Never run a nested CLI
merely to work around a tool-backed session's missing role support.

## Continue toward the parent

Allow each worker to complete related steps within the same contract, leases,
dependencies and budget without a new dispatch/commit/review after every result.
Apply lemmas back to the parent proof. Advance approved implementation through
source, constraint generation/propagation and actual execution. Unproved A/B
premises block only dependent production; provisional evidence stays provisional.
A stalled lane does not stop independent safe work in the other lane.

Use one frozen assignment handoff with outcome, parent application, exact
remaining premise, source/native owner evidence, artifact/dependency hashes,
mutual TODOs, next in-scope step, checks and writer-stop status. Luna acknowledges
intake directly. Consult the dispatcher only at the policy's material boundaries.
Do not use auxiliary test/performance activity as a permanent substitute for
sprint outcomes. If no safe implementation remains, record NO_SAFE_CODE_SLICE
with at least two actual inspected owners rather than manufacturing work.

## Review and integrate substantial results

Freeze the coherent artifact and direct dependencies, assign an eligible fresh
independent reviewer, adjudicate findings and batch repairs. Keep abstract proof,
source/native, implementation and production gates distinct. Do not certify a
producer/coauthor, a moving diff, or a theorem inferred from green tests.

Checkpoint at meaningful verified milestones, or use the existing explicitly
unreviewed research-only preservation path. Only Luna stages explicit intended
paths and inspects the full outbound range before a non-forced push. Update
compact current state and a durable outcome receipt; archive resolved history
without discarding active leases or pending reviews. Do not append duplicate
micro-progress narratives to all legacy task ledgers.

## Stop and resume truthfully

On STOP or session end request actual cancellation, clear stale RUNNING states,
quarantine unconfirmed writers and retain their resource reservations. Mark
STOPPED only from cessation evidence. Reconcile descendants as well as parents.
On resume verify authority/dependency hashes and fresh runtime receipts before
RUNNING; do not reset spent sprint budgets or take an unknown worker's files.

Run `python tools/agent_sprint.py check` for static consistency and
`python tools/agent_sprint.py simulate` for a labeled offline example. Neither
launches agents, authenticates receipts, enforces sandbox leases, or proves math.

## One-time migration review gate

The checked-in migration snapshot records INDEPENDENT-REVIEW as NOT_RUN.
Before live adoption of this policy/tooling revision, Luna must obtain a fresh
isolated review of the frozen diff, adjudicate findings and record its receipt.
Keep the snapshot in RECONCILE until both that review and legacy-worker/lease
reconciliation finish. Static tests and the editing primary's reread do not lift
this gate. This is one adoption boundary, not a new per-step review ritual.
