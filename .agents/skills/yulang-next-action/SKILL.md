# Resolve a sprint boundary

Primary-only. Read `rules/goal-driven-sprints.md` and the compact current state.
Outside an authorized sprint, preserve bounded occasional next-action selection;
a read-only planning request does not authorize compiler work.

First classify the event. An internal lemma, test, ordinary result, minor repair,
review receipt or commit does not alone need dispatch. Continue inside the
existing authority/lease/resource envelope instead. STOP is immediate and never
waits for this consultation.

For a real boundary send `next_action_selector` the fixed original goal, contract
hash, current baseline/dependency hashes, both lane summaries, precise missing
premises, current runtime/lease observations and only relevant frozen handoffs.
Search prior work by exact parent/source owner; do not dump historical boards.
Reuse a healthy dispatcher through supported messaging; a waiting identity is
not RUNNING. Record requested and observed model separately.

Request a compact delta: preserve/revise the sprint with reasons; both lanes'
next multi-step outcome or concrete blockers; dependencies, exact proposed
leases, Astra/resource reservations, review/integration seam and next material
consultation trigger. Prefer continued parent-theorem work and an end-to-end
implementation path, not more microtasks or a panel of selectors.

Luna validates authority and grants actual leases. The dispatcher is read-only
unless a primary explicitly leases one recorder path; it never starts agents,
certifies results or touches Git. Routine handoff intake can be acknowledged by
Luna directly. An unsafe proposal returns its exact blocker; unaffected work
continues without waiting. The primary owns `tasks/agent-loop/current.json`.
