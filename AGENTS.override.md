Read the root [AGENTS.md](AGENTS.md) explicitly: Codex loads this override instead
of that file at the same directory level. All of its unrelated instructions,
safety rules, artifact conventions and language/semantic authorities still apply.

For authorized ongoing work on `research/simple-sub-intrusion` (and a worktree
explicitly continuing that goal), read
[the 2026-10-16 workflow decision](notes/design/2026-10-16-resident-research-loop.md),
the [operational addendum](notes/design/2026-10-16-resident-loop-operations-addendum.md)
and apply [.agents/skills/yulang-research-loop/SKILL.md](.agents/skills/yulang-research-loop/SKILL.md).
This narrow user-approved decision supersedes conflicting older routing cadence,
selector read-only status, shared-board ownership and three-role model pins.
It does not supersede compiler correctness, proof closure, independent review,
question-board approval, Git safety, or the user's current explicit scope.

These primary-loop duties apply to Luna, not to delegated children. A child
follows its exact role/packet and never starts its own trio or becomes primary.

Keep Luna as primary. Maintain `next_action_selector` as the resident dispatcher,
`implementer` as the implementation lane, and `prover` as the proof lane. All
dispatcher and prover normally use Sol/high; the implementer is **pinned to
Luna/high at minimum**, with one-off Astra implementation escalation after
explicit lease handoff. Bounded Sol-to-Astra reasoning for other lanes remains
available under the original decision. Luna consults the dispatcher at every next-action boundary,
not merely when stuck. Workers submit mutual TODOs through their own leased
inbox files; only the dispatcher writes the leased scheduling board. Luna alone
validates authority/leases, launches workers, adjudicates and integrates.

Before new substantive work, locate relevant historical implementation and
reasoning and reuse valid evidence rather than repeat withdrawn attempts.
Luna audits untracked files frequently: commit coherent authorized artifacts,
delete only exactly identified disposable files after their writer stops,
and preserve unknown/other-worker files and pending questions. When a question
answer is explicitly approved and independently questioner-validated, curate
and commit **the entire** selected question directory—including previous trial
and failed-attempt files and the validation receipt—in one atomic bundle. Never
commit unfinished/unapproved questions to clean the tree.

Keep ready implementation moving while independent proofs run. Never occupy a
lane with invented work, bypass a genuine proof prerequisite, or claim that
editing these files launched workers or a daemon. Reconcile actual worker IDs
and unfinished leases before adopting the loop in an existing session. Plan-only,
status-only, question-answering and workflow-maintenance requests do not by
themselves authorize compiler work or require launching the resident trio.
