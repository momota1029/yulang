## Exact boundary: interpolated-string source-key owner

No all-carrier uniqueness claim is made. Interpolation differs from the fresh-child cases above: `interpolated_string` creates one fresh body slot per CST interpolation (1799–1827), then `lower_string_plan` takes references to those slots through externally produced `string::pieces` indices (1830, 1847–1861). Generated concat nodes use the previous result once and fresh reference/partial/result nodes (1864–1876). Candidate Visit follows only `lowered: Some(inner)` (1278–1279), not both the `parts` metadata and lowered tree; `lowered: None` rejects at 1258.

At each interpolation piece, lowering consumes the next CST interpolation node and checks `self.key(part_node) == selected_part.source` (1855–1857); the final check rejects unconsumed nodes (1878). To conclude that a successful lowering cannot select the same part/body twice, one needs injectivity of the source keys of those distinct consumed CST nodes. If that injectivity holds, a repeated part index would fail the second equality, regardless of how `pieces` was produced. This means the decisive missing premise is the actual key-construction owner, `crate::source_identity::try_source_keys`/`source_keys`, called in module.rs (e.g. 2189). Its implementation is outside the R124 manifest. I stopped before reading that owner. The `string::pieces` helper is also outside the manifest, but the downstream equality checks would suffice for at-most-once selection once key injectivity is authenticated; no assumption that it emits unique indices has been silently added.

This is an exact remaining source premise, not a reachable source counterexample and not an assertion that those keys collide. Nested annotated local Lambdas inside an interpolation body remain in this dependency cone. Ordinary carriers without interpolation already have the preceding unconditional construction derivation. Do not turn this bounded result into a language-domain restriction.
