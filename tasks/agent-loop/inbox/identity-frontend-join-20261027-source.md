## Rejection boundaries and falsifiers

- **Artifact/root/index:** `DefinitionRootId`, `ExpressionRootId`, `SourceMemberRootId`, `HirOccurrenceId`, and `HirParameterId` are artifact/root branded. HIR accessors validate pointer ownership; `LocalSourceIndex` and `LocalSourceNamedGroupId` also compare their full `SourceRootId` owner before ordinal indexing. Do not accept equal ordinals or equal file/module payloads as ownership. A LocalSource index borrowed from another root is rejected by `expression()`; a root minted by another HIR is rejected by `owns_source_root`/`source_carrier_for`.
- **Retained parse source:** `HirSourceIdentity.parse_root` is the exact parse root; `ShadowArtifact` checks that its own parsed snapshot owns that root/key. SourceNodeKey lookup rejects foreign parse keys, missing keys, and ambiguous reused zero-width CST handles. A successfully parsed matching byte string alone is not a key join.
- **Inline formal:** the parameter ID is root-owned; source-origin lookup requires HIR owner and a registered identity row. Inline provenance intentionally resolves the Lambda node plus the unique Identifier token whose range equals the retained binder range; it is not an `IdentifierPattern` and `parameter_source_position` reports `MissingSource` for this case. This origin gives no type, runtime role, or lexical-environment fact by itself.
- **Lexical scope:** spelling is only the lookup key in the active lexical stack. The resolution value is the nearest stored ID. Nested same-spelling identity lambdas must resolve their body to the inner parameter; outer references remain the outer ID after inner restoration. Sibling restoration is explicit; equal spelling/range or a global spelling table is insufficient.
- **Occurrence/order/label:** occurrences belong to the HIR artifact and are associated with keys by staged constructor insertion plus source-child-order publication. LocalSource indices are owner/ordinal pairs; Labels are per-root offset plus a checked LocalSource ordinal; SourceSites carry root, occurrence and range. Do not infer correspondence from coincident numeric ordinals or labels, reordering a traversal, or child-construction order. Reordering the source while retaining the same rendered text changes source keys/order and must rebuild the mapping from that parse.
- **Foreign artifact/parse evidence:** the focused test `typed_origins_join_exact_tokens_and_preserve_pattern_accessor` creates a second HIR from the same ParsedFile and a ShadowArtifact from a separate parse. It expects the foreign HIR parameter query to return `ForeignHirArtifact` and the foreign parse query to return `ForeignParse`. The whole gate must preserve both checks; do not join artifacts by source text or copy parameter IDs.
