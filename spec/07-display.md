# 章7 型の表示

状態の凡例は [README](README.md)。この章は、型を**利用者に見せるとき**の規則を扱う。hover、playground、CLI、診断の型表示が対象。
注釈（書く型）と表示（見せる型）は**同じ意味**で扱う（T1、確定）。ただし、表示は注釈より開いた形になることが多い（T3）。
内部の帳簿（solver が持つ重みや証拠）を、そのまま見せるわけではない。何を見せ、何を隠し、何を `…` に置き換えるかをここで決める。

## 7.1 表示は「公開シグネチャと同じ綴り」に収束する　〔仮採用〕

型変数は `'a` と書く（`α` などの Greek 文字は使わない。確定, 2026-11-04）。

- hover や playground の型は、**公開シグネチャの contract と同じ綴り**になる。
- 内部の型の様子をすべて見せる面（debug 用の dump）と、利用者に見せる面（公開表示）は別。消費面ごとに文字列を後から加工することはしない。
- 公開の型に残らない内部の飾り（`#N` のような stack の添字、`stack(T, ...)`、`filter`、`floor`）は**見せない**。

出典: `main:notes/design/2026-07-03-hover-public-type-projection.md` 決定 P1・P2

## 7.2 式の型と effect 行　〔仮採用〕

```text
e : A ! rho            // 式 e は値 A を返し、途中で行 rho の effect を起こしうる
[console] str          // console を起こしうる str を返す computation
() -> [console] str    // unit を受けて、console を起こしうる str を返す関数
```

- 関数型の戻り側にはいつも effect 行がある（章5.1）。**行が空なら表示は省略される**（`() -> int` と `() -> [] int` は同じ。確定, 2026-11-04）。
- 行の区切りは `,`（T1）。例: `'a [undet, 'b] -> ['b] list 'a`。
- 残った型変数（`'a`、`'b`）はエラーではない。多相な binding に残る、量化された変数である。
  行に残る変数 `'b` は公開型の本物の一部で、表示のノイズとして消してはならない。

## 7.2b 弱多相の型変数の表示　〔仮採用〕

値制限で一般化されなかった型変数（後の使い方で決まる単相の変数）は、`'_a` のように `_` を付けて見せる（確定, 2026-11-05）。量化された多相の変数 `'a` とは区別する。

```text
list (int | '_a)          // [1] の型。'_a は後の使い方で決まる
list 'a                   // 多相: 使うたびに別の型にできる
```

- 弱多相の変数は、同じファイルの終わりまでに決まらなければ、その場で決まる型に落ちるか、role 制約が付いていればエラーになる（章6.3）。
- 保護の解除の記法 `'e?`（7.3、暫定）とは別の記号にしてある。`?` は保護の解除のために空けておく。
- 注釈の型の穴 `_`（章4.2）とは別のもの。`'_a` は推論された型にだけ現れ、注釈には書かない。

## 7.3 保護と解除の表示　〔意味は確定、記法は暫定〕

T2 の「引いてよい」という属性を、行の変数に付けて見せる記法が現行の実装にある（`@`）。**これは仕様として固定しない**（確定, 2026-11-04）。

- 「型変数に属性を付ける」という説明の枠組みは使わない。意味は下の**符号付き重み**で定義する（確定, 2026-11-05）。Lean で証明した（`lean/Yulang/Directed.lean`）。
- 記法は変える。`'e?` という記法が入り、あらかた綺麗になる見込み。意味は上のとおり。章5.5 の表をこの語り方で書き直すのは J6 で行う。
- したがって、T2・T3 が述べる**振る舞い**（引ける・引けない、具体的な型が見えない）は確定だが、
  それを「型変数に属性を付ける」と説明する枠組みと、その表示は暫定である。

### 意味: 境界ごとの符号付き重み（確定, 2026-11-05）

effect の各出現は、境界ごとに整数の重みを持つ。境界 `b` を越える保護は、許可マスク `P` に含まれない effect の `b` の重みを **+1** する。対応する解除は同じ境界・同じマスクで **−1** する。handler が捕まえられるのは、対象の effect で、**すべての境界の重みが 0** のときだけである（負の重みも捕まえることを妨げる）。同じ境界・同じマスクの保護と解除は、どちらの順でも相殺する（`release ∘ protect = protect ∘ release = id`）。これは関数を含む任意の有限shapeの値について成り立つ（`DirectedHigherOrder.transport_opposite`）。

| 表示 | 意味 |
| --- | --- |
| `'e` | マスクが空の保護。許可なし、重み +1 |
| `'e[io]` | マスク `{io}` の保護。`io` は据え置き、それ以外が +1 |
| `'e?` | その位置での解除。同じ境界・同じマスクの −1 |

- 重みの数字そのものは**公開表示に出さない**（7.1）。表示は、保護・マスク・解除の見せ方である。
- 複数の境界の保護が同じ行変数に重なるとき、解除は `'e??` のように `?` を重ねて書く（暫定, 2026-11-05。問題が出たら変える）。
- 相殺は無条件の非 capture を意味しない。もともと −1 の入力に +1 すれば 0 で見えるようになる。非 capture の定理は、変換する出現がその境界で重み 0 から来たという前提を明示する。

以下は2026-11-04のユーザー説明を残したもので、意味は上の2026-11-05の符号付き重みに従う。表示記法は引き続き暫定とする。

- effect 行の変数 `'e` は**保護される**。保護された行の effect は、その位置の handler が勝手に引けない。
- `'e[io]` のように書くと、保護される型を指定できる。`io` は引いてよく、それ以外は保護される。
- `'e?` は「このスロットでは `'e` の保護が解除される」という意味。
- `[_]`（全 effect を列挙した glob。章5.5）と `'e?` は別物（確定, 2026-11-04）。`[_]` は「全部を列挙した」注釈で、`'e?` は「保護の解除」。`'e?` は注釈に書くものではなく、**推論された型に自動で現れる**（確定, 2026-11-04）。

```yulang
my compose(f: _ -> [io] _, g) = g f x
// 推論される型（ユーザー提示の例）:
// ('a -> ['b[io]] 'c) -> ('c ['b] -> ['b?, 'd] 'e)
```

  `f` の戻り行 `'b[io]` は、`io` だけ引いてよく残りは保護される。`g` の戻り側の `'b?` は、その位置で `'b` の保護が解除される。

現行の表記（参考のために残す。固定ではない）:

| 記法 | 意味 |
| --- | --- |
| `'c@∅` | この出現からは何も引けない |
| `'c@∀` | すべての effect を引ける |
| `'c@[io]` | `io` を引ける |
| `'c@(except [io])` | `io` 以外を引ける |
| `'c@(2)` | 数字の括弧は pop 数 |

```text
(('a | 'b) ['c@∅] -> ['c@∅ & 'd@∅] 'b & 'e) -> 'a -> ['d] 'e@
```

出典: `main:notes/design/2026-07-03-hover-public-type-projection.md` 決定 P2R

## 7.3b 再帰する行の表示　〔仮採用〕

行が自分自身を含む型（再帰のたびに保護が積み増される場合など。章10.3.2）は、再帰を `as` で閉じて見せる（確定, 2026-11-05）。

```text
[k, 'e] as 'e             // 'e は { k } と、'e 自身を保護したものを含む
```

- 重みの数字は出さない（7.3）。`as` は自己参照があることだけを示し、保護の積み増し方は 7.3 の `'e` / `'e?` / `'e[io]` で見せる。
- 推論された型にだけ現れ、注釈には書かない（章4.8）。`…`（7.4）は使わない。再帰する行は正当な型であり、上流の不具合ではない。
- 型の等価・包含は、`as` を展開した意味で判定される（章10.13）。
- 複数の変数が互いに再帰するときの書き方は、実例が出てから決める。

## 7.4 見せられないものは `…` にする　〔仮採用〕

- 型の意味を持つ内部の実体（合成名、`#` を含む名前、両側が自明でない sandwich 境界）は、隠さずに `…`（U+2026）に置き換える。
  `…` が公開面に現れることは「内部の実体が表示に届いてしまった」印で、表示の問題ではなく上流の不具合として扱う。
- 巨大な型は、ある上限を超えた部分を `…` に切り詰める。上限の数値（現行は深さ 10・出力 600 文字、LSP は 1200 文字）は**実装の値**で、仕様ではない（確定, 2026-11-04）。
- 偽のきれいな型を作文して見せることはしない。

## 7.4b 表示の標準形　〔仮採用〕

意味が等しい型は、同じ文字列で表示される（確定, 2026-11-06）。推論の順序や、式の書き方の違いで、同じ型が別の文字列に見えることはない。

- **型変数の名前**は、表示される型を左から読んだときの**出現順**に `'a`, `'b`, … と振る。
- **union・intersection のメンバー**は、型変数を先に、その後に具体的な型を**名前の辞書順**で並べる（`'a | 'b | int | str`）。
- 行の中の effect も同じ規則で並べる（変数を先に、具体的な effect を辞書順）。
- 簡約は、意味を保つもの（正にだけ、または負にだけ現れる変数の除去、共起する変数の併合）に限る（7.4）。標準形は、簡約した結果の並べ方だけを決める。

```text
'a -> 'b -> 'a | 'b       // if c: x else: y と if c: y else: x のどちらも
```

- 弱多相の変数 `'_a`（7.2b）は、`'a` と同じ出現順の数に数え、`_` を付けて見せる。

## 7.5 union・intersection・省略可能な field　〔仮採用〕

```text
'a | int
'a & {width?: ⊤}
{width?: 'a} -> 'a | int
```

- 推論結果には union（`|`）と intersection（`&`）が出る。これらを**注釈として書く構文はない**（章4.8）。
- 省略可能な record の field は `?` 付きで出る。
- 注釈を足すと、表示型を意図した公開形に絞れることが多い。
