\section{実行型と静的な入力}
\label{sec:types}

\subsection{実行型の射影}

実行型は、元稿の値型から effect/profile の\emph{精度情報}を射影した型である。
family、nominal、constructor、payload/response の型引数は消さない。
\[
\begin{split}
 A::={}&\alpha\mid 1\mid\mathsf{bool}\mid\mathsf{int}\mid\mathsf{float}
 \mid\mathsf{string}\mid\mathsf{bytes}\mid\mathsf{path}\mid\mathsf{char}\\
 &\mid\top\mid\bot\mid A\vee A\mid A\wedge A
 \mid(A_1,\ldots,A_n)\mid\{l_i^{p_i}:A_i\}
 \mid\langle t_i(\bar A_i)\rangle\\
 &\mid D\langle\bar A\rangle\mid\mu\alpha.A\mid U A
 \mid C(A,B)\mid\forall\alpha.A.
\end{split}
\]
\(C(A,B)\) は carrier \(UA\) を受け取り \(B\) を返す callable の型である。
Value/Computation entry の違いは callable の code に残す。
\(U(E,A)\) の射影は \(UA\)、四ポート Function の射影は \(C(A,B)\) である。
この射影から、元の latent effect が保存されたとは結論しない。

\(\D\) は有限の宣言表で、nominal constructor ごとに payload template、
operation ごとに \(\forall\bar\alpha.P_o(\bar\alpha)\to Q_o(\bar\alpha)\)、
primitive ごとに signature を持つ。
生成 template の code 表も宣言表の一部であり、全 entry の body を所定の formal 環境で型付けする。
別の宣言 identity は同じ綴りでも別のキーである。
閉じた実行では、request は一つの instance \((o,\bar A)\) を運び、
その payload と response の両方に同じ \(\bar A\) を使う。
well-formed 宣言表では、primitive signature は第\ref{sec:prim}節の表と一致し、
ListView/Range 等の native 結果 constructor は宣言表の対応する identity を使う。
たとえば IntAdd の signature を bool の演算へ変更した宣言表は対象に含めない。

型の表示の \(A\vee B\)、\(A\wedge B\) は、型付き view に保持した
producer alternative と複数 interface の証拠として実装する。
union injection/elimination と intersection projection は明示形である。
intersection introduction は\emph{同じ underlying value}に二つの導出を持つ場合だけ許す。
異なる計算を二回実行して二つの結果を intersection にする規則はない。
\(\top\) は消去可能な view、\(\bot\) は introduction rule を持たない。
再帰型は明示的な \(\mathsf{roll}/\mathsf{unroll}\) により扱う。
これらは実行計画中の証拠であり、新しいソース記法ではない。

\subsection{値と計算}

以下は有限の構文、または明示的な有限再帰定義表を伴う構文である。
\[
\begin{split}
v::={}&x\mid c\mid(v_1,\ldots,v_n)\mid\mathsf{seq}(v_1,\ldots,v_n)\mid\{l_i=v_i\}
 \mid t(\bar v)\mid c_D(\bar v)\\
 &\mid\lambda^{m,\pi}x.M\mid\Delay M
 \mid\mathsf{wrap}(v,a,r)\mid\Lambda\alpha.v\mid v[A]\\
 &\mid\mathsf{in}_i(v)\mid\mathsf{both}(v;d_1,d_2)
 \mid\mathsf{roll}(v)\mid\mathsf{top}(v)\mid\View_\chi(v)
 \mid\mathsf{cont}(\bar u,x.M).
\end{split}
\]
\(m\in\{\mathsf V,\mathsf C\}\)。\(\pi\) は元の source receipt template、
\(a,r\) は引数・結果 adapter の code である。
\(\chi\) は runtime view の metadata。
\(\mathsf{cont}\) は runtime が作る raw continuation で、\(\bar u\) を束縛する。
実行時にはさらに immutable な値 graph への参照 \(r\) を値に含める。
これは reference protocol の可変 cell ではない。
\[
\begin{split}
M::={}&\Ret v\mid\mathsf{let}\ x\leftarrow M\ \mathsf{in}\ M
 \mid\Force v\mid\Call(v,v)\mid\Resume(v,v)\\
 &\mid\mathsf{split}(v,\bar x.M)\mid\mathsf{field}_{l}(v)
 \mid\mathsf{switch}(v,\bar a)\mid\mathsf{unroll}(v)\\
 &\mid\mathsf{choose}_i(v)\mid\mathsf{unioncase}(v,x.M,y.M)
 \mid\mathsf{absurd}(v)\mid\mathsf{prim}_p(\bar v)\\
 &\mid\mathsf{perform}_{o,\bar A}(v)
 \mid\Handle_h M\mid\mathsf{mapop}_{w}M
 \mid\mathsf{rec}\ \bar x=\bar v\ \mathsf{in}\ M\\
 &\mid\mathsf{template}_{\ell,\bar A}(\bar v)\mid\Fail r.
\end{split}
\]
\(\mathsf{field}_l\) は required field 用であり、optional field は
\(\mathsf{lookup}_l\) により \(1\vee A_l\) を返す糖衣形も用いる。
\(\mathsf{switch}\) は constructor identity/tag と arity を検査してから payload を束縛する。
non-exhaustive な末尾は \(\Fail\mathsf{MatchFailure}\) へ移る。
\(\mathsf{rec}\) の右辺は値であり、循環は実際の data constructor、lambda、delay を通る。
単なる alias/roll/型証拠だけの循環は値を構成しない。
一般の計算再帰は
\[
 \mathsf{fix}\ x.M\;:=\;
 \mathsf{rec}\ x=\Delay M\ \mathsf{in}\ \Force x
 \quad(x:UA)
\]
で表せる。この展開は計算を停止させるという仮定を含まない。

\(\mathsf{template}\) は、nominal mapper 等の有限の生成 code 表への参照である。
表の各項は型引数、値引数、結果型と、その環境で型付けした body を持つ。
相互再帰は同じ表への参照で表し、自由な捕捉値は明示引数にする。
これは source lambda の導入ではなく、展開時にも新しい receiver を作らない。
adapter のために source invocation を増やさずに、非正則な nominal 引数の
\(D(\alpha)\) から \(D(D(\alpha))\) 等への template 再利用を表せる。

\subsection{型付け規則}

\(\D;\Gamma\ty v:A\)、\(\D;\Gamma\ty M:A\) は有限の導出である。
型変数についての全称導入は値だけに許し、
\(\alpha\notin\fv(\D,\Gamma)\) を要求する。
\(\Gamma\) は全ての捕捉値・共有資源の型を含む。
scheme の新しい instance が既存の共有値を別の型に変更する規則はない。

主要な規則を全て列挙する。各行の自由変数はその行で全称量化する。
構造値は宣言した順序・arity と component 型を満たすことを要する。
\begin{longtable}{p{.26\textwidth}p{.66\textwidth}}
\toprule
結論の形 & 前提 \\
\midrule\endhead
\(x:A\) & \(\Gamma(x)=A\)。literal は対応する一つの base 型。\\
\((\bar v):(\bar A)\) & 各 \(v_i:A_i\)。\\
\(\mathsf{seq}(\bar v):\mathsf{List}\langle A\rangle\) & \(\mathsf{List}\) は宣言表の固定 native identity、各 \(v_i:A\)、列の長さは有限。\\
\(r:\{l_i^{p_i}:A_i\}\) & required labels \(\subseteq\dom r\subseteq\) 全 declared labels。存在する payload は各 \(A_i\)。\\

\(\lambda^{\mathsf V,\pi}x.M:C(A,B)\) & \(\Gamma,x:A\ty M:B\)。\\

\(\mathsf{rec}\ \bar x=\bar v\ \mathsf{in}\ M:B\) & \(\Gamma,\bar x:\bar A\ty v_i:A_i\)、同じ環境下で \(M:B\)。値 graph の guard 条件。\\
\(\mathsf{perform}_{o,\bar A}(v):Q_o(\bar A)\) & \(\D(o)=\forall\bar\alpha.P_o\to Q_o\)、\(v:P_o(\bar A)\)。\\
\(\mathsf{prim}_p(\bar v):B\) & \(p\) の全型引数を一度だけ置換した signature が \(\bar A\to B\)、\(\bar v:\bar A\)。\\
\(\mathsf{template}_{\ell,\bar T}(\bar v):B\) & code 表の同じ一つの型 instance の formal 型が \(\bar A\)、結果が \(B\)、\(\bar v:\bar A\)。表の body は formal 環境で別に型付けする。\\

handler、operation mapper、raw continuation の規則は次節で与える。
ここに、実行安全性を仮定する subsumption rule、
型の合うことを理由に実行変換を省く rule、
未解決の compiler port を値として使う rule は存在しない。

\section{実行機械：値、request、継続を同じ構文で扱う}
\label{sec:machine}

\subsection{閉じた raw 計画と administrative forms}

束縛には capture-avoiding substitution を用いる。
実装では有限 environment graph でよいが、この定義の変数 lookup は閉じた置換として読む。
再帰値は有限の参照 graph であり、辺を辿って data/lambda/delay の node を一つ観測する。
guard 条件により、この一回の値観測は終わる。

機械状態は \(\langle\D,H,M,\omega\rangle\)。
\(H\) は immutable な有限値 graph であり、code の自由変数は graph 参照で閉じる。
graph typing \(\Xi\) は各参照の型を記す有限写像である。
\(\D;\Xi\ty H\) は、各 \(H(r)\) が \(\Xi\) の下で \(\Xi(r)\) を持ち、
前節の guard 条件を満たすこととする。
\(\Xi(r)=A\) から \(\D;\Xi;\Gamma\ty r:A\) を得る。
型付けの \(\Xi\) を省略した箇所では、同じ \(\Xi\) を全前提で使用する。
\(\omega\) は動的 owner/handler 名、activity、view の改名環境を持つ。
計算の結果は \(\Ret v\)、\(\Req(q,p,K)\)、\(\Fail r\)。
request の \(q\) は operation instance、origin、request identity、view metadata を持つ。
\(K=\mathsf{cont}(\bar u,x.N)\) は型付き response を受け取る一つの有限計画である。
外向き request は故障ではない。

機械内部では次の形を追加する。
\[
 \Scope_u M,\quad \mathsf{expose}_{\chi}M,\quad
 \mathsf{enter}_u(f,t),\quad
 \mathsf{try}_h(q,p,K;\bar a),\quad
 \mathsf{wait}_h(q,p,K;a,\bar a;M).
\]
\(\mathsf{try}\) は operation arm の試行、\(\mathsf{wait}\) は試行の計算中である。
handler を対象計算の周囲から外してから試行するので、
guard/default/body の effect は同じ handler で自動的に処理されない。

\(\Bad(r)\) も raw 機械の結果として用意する。
これは未束縛 local、間違った constructor/arity の無検査除去、
存在しない required field、非 callable の call、間違った response などである。
\(\Bad\) を \(\Fail\) に改名しない。型付け規則は \(\Bad\) を導出しない。

linked root 列は一つの順序付き block として実行する。
最初に fresh な root owner \(u_0\) を確保し、\(\Scope_{u_0}M\) から開始する。
root は formal を持たず、profile は空である。top-level の let/handler の owner はこの \(u_0\)。
root 内の source Call は別の fresh owner を持つ。
root の正常終了では \(u_0\) を終了し、root を越える request では通常の Scope 規則で保存する。
従って最上位の catch にも所有者があり、未定義の ambient owner を必要としない。

\subsection{通常の遷移}

評価は一つの最左 active computation で行う。
構造値中の delay/lambda body は評価しない。
以下の規則の左辺で要求された constructor がない raw 項は \(\Bad\) へ進む。
optional lookup と switch の明示的不一致はその例外で、規則に従って分岐する。
\begin{align*}
 \mathsf{let}\ x\leftarrow\Ret v\ \mathsf{in}\ N&\longrightarrow N[v/x],\\
 \Force(\Delay M)&\longrightarrow M,\\
 \mathsf{split}((\bar v),\bar x.M)&\longrightarrow M[\bar v/\bar x],\\
 \mathsf{field}_l(r)&\longrightarrow\Ret r(l),\\
 \mathsf{lookup}_l(r)&\longrightarrow
 \begin{cases}\Ret\mathsf{in}_2(r(l))&l\in\dom r,\\
 \Ret\mathsf{in}_1(())&l\notin\dom r,\end{cases}\\
 \mathsf{unioncase}(\mathsf{in}_i(v),x.M_1,y.M_2)&\longrightarrow M_i[v/x_i],\\
 \mathsf{choose}_i(\mathsf{both}(v;d_1,d_2))&\longrightarrow\Ret(v;d_i),\\
 \mathsf{unroll}(\mathsf{roll}(v))&\longrightarrow\Ret v,\\
 (\Lambda\alpha.v)[A]&\longrightarrow v[A/\alpha],\\
 \mathsf{prim}_p(\bar v)&\longrightarrow\delta_p(\bar v),\\
 \mathsf{perform}_{o,\bar A}(p)&\longrightarrow
 \Req(q_{o,\bar A},p,\mathsf{cont}(\varnothing,x.\Ret x)).
\end{align*}
型適用と view projection の値正規化も一つの administrative step と数える。
\(\mathsf{switch}\) は最初に一致する constructor/tag の arm を選び、
その payload を同時置換する。一致がなければ \(\Fail\mathsf{MatchFailure}\)。
\(\mathsf{rec}\ \bar x=\bar v\ \mathsf{in}\ M\) は fresh な \(\bar r\) を確保し、
\(H'=H[\bar r\mapsto\bar v[\bar r/\bar x]]\)、\(M'=M[\bar r/\bar x]\) に移る。
既存 node を書き換えない。型 graph は \(\Xi'=\Xi[\bar r:\bar A]\) と拡張する。
\(\mathsf{template}_{\ell,\bar T}(\bar v)\) は、表の body に型と値の引数を同時置換して一段で進む。
有限の body を一回展開するだけであり、再帰呼出しを先回りして展開しない。
新しい scope、receipt、View をこの administrative step だけで作ることはない。

最外の形が let、scope、expose、handle、mapop、wait で、
その唯一の active child が一段進むなら同じ child を一段進める。
子が \(\Fail r\) または \(\Bad r\) になれば同じ結果を伝播する。
正常 return、request の場合は以下の特別規則を使う。
これで通常評価の context 規則を尽くす。

\subsection{順序付き bind と request の伝播}

\(K=\mathsf{cont}(\bar u,z.M)\) とする。
\(\bar u\) を右辺の自由名から fresh に選び直してから、次を行う。
\[
 \mathsf{let}\ x\leftarrow\Req(q,p,K)\ \mathsf{in}\ N
 \longrightarrow
 \Req(q,p,\mathsf{cont}(\bar u,z.
       \mathsf{let}\ x\leftarrow M\ \mathsf{in}\ N)).
\]
通常の effect を rollback しない。順序は continuation の code に保存する。
\(K\) の型は次の構文規則で与える。
\[
 \frac{\D;\Gamma,z:Q\ty M:A}
 {\D;\Gamma\ty\mathsf{cont}(\bar u,z.M):\mathsf{Kont}(Q,A)}.
\]
束縛される \(\bar u\) は owner/handler 名だけであり、operation family、
State scope、共有 resource の identity と型引数はこの束縛に含めない。
\[
 \frac{p:P_o(\bar A)\quad K:\mathsf{Kont}(Q_o(\bar A),B)}
 {\Req(q_{o,\bar A},p,K):B}.
\]
request の型は応答型そのものではなく、\emph{その後の計算の正常結果型}である。
この区別が bind と handler の保存に必要である。

\subsection{call の入口と adapter}

\(\Call(f,t)\) は fresh な一つの受信 owner \(u\) を確保し、
\(\Scope_u(\mathsf{enter}_u(f,t))\) へ移る。
\(\mathsf{enter}\) は wrap を外から順に剥がし、引数は
\[
 t'=\Delay(\mathsf{let}\ z\leftarrow\Force t\ \mathsf{in}\ a(z))
\]
とし、結果 adapter を後ろに保存する。
\[
 \mathsf{enter}_u(\mathsf{wrap}(f,a,r),t)
 \longrightarrow
 \mathsf{let}\ z\leftarrow\mathsf{enter}_u(f,t')\ \mathsf{in}\ r(z).
\]
wrap の剥離で新しい \(u\) を作らない。argument code もまだ実行しない。
source lambda に到達したとき、\(u,\pi\) による receipt を carrier の
指定された observation path に付け、\(t_u\) を得る。その後にだけ
\[
\begin{split}
 \mathsf{enter}_u(\lambda^{\mathsf V,\pi}x.M,t)
 &\longrightarrow\mathsf{let}\ x\leftarrow\Force t_u\ \mathsf{in}\ M,\\
 \mathsf{enter}_u(\lambda^{\mathsf C,\pi}x.M,t)
 &\longrightarrow M[t_u/x]
\end{split}
\]
とする。宣言結果 consumer は lambda の body の最後の明示 adapter である。
\(\Scope_u(\Ret v)\to\Ret v\) は \(u\) の activity を終了させる。
返却値の view/latent code は消去しない。

\textbf{受領の順序の注意。}
wrap の引数変換は delay の中なので、receipt は最初の force より先に作られる。
同じ入力を受け取るという事実は、同じ owner による metadata 構成で表す。
後の結果 adapter が user cast を呼ぶ場合、その call は別の本物の source call である。
wrap の administrative frame 自体を source receiver にしないこととは両立する。

\subsection{shallow handler と arm の試行}

handler \(h:A\Rightarrow B\) は、正常値用の順序付き match 計画と、
operation ごとの順序付き arm 計画を持つ。
各 operation arm は、同じ instance の
\[
 p:P_o(\bar\alpha),\qquad k:\mathsf{Kont}(Q_o(\bar\alpha),A)
\]
を受け取る。polymorphic arm の \(\bar\alpha\) は rigid である。
一つの instance に専門化した arm は、その instance にだけ一致する。
\(P_o\) と \(Q_o\) を別々の instance に置き換える規則はない。

pattern/guard の試行は \(1\vee B\) を返す計算とする。
左は No、右は arm body の正常値である。
body をまだ実行しない段階では \(1\vee\mathsf{Env}(\Gamma_p)\) を使用し、
guard は bool、true のときだけ body を実行する。
この翻訳は第\ref{sec:patterns}節で定義する。
全試行が所定の環境下で型付くときにだけ \(h:A\Rightarrow B\) とする。
\[
 \frac{M:A\qquad h:A\Rightarrow B}{\Handle_h M:B}.
\]

\(\Handle_h(\Ret v)\) は value-arm の試行列へ移る。
\(\Handle_h(\Req(q,p,K))\) は、operation identity と instance が一致し、
eligibility が真である arm の列を source 順に試す。
選択した \(h\) を取り除いた外側で \(\mathsf{try}\) を実行する。
\begin{align*}
 \mathsf{try}_h(q,p,K;a,\bar a)
 &\longrightarrow\mathsf{wait}_h(q,p,K;a,\bar a;\mathsf{attempt}_a(p,K)),\\
 \mathsf{wait}_h(q,p,K;a,\bar a;\Ret\mathsf{in}_2(v))
 &\longrightarrow\Ret v,\\
 \mathsf{wait}_h(q,p,K;a,\bar a;\Ret\mathsf{in}_1(()))
 &\longrightarrow\mathsf{try}_h(q,p,K;\bar a),\\
 \mathsf{try}_h(q,p,K;\varnothing)
 &\longrightarrow\Req(q,p,H_hK).
\end{align*}
\(H_hK\) は \(K=\mathsf{cont}(\bar u,x.M)\) に対して
\(\mathsf{cont}(\bar u\bar h,x.\Handle_h M)\) である。
\(\bar h\) は復元する handler activation の束縛名であり、source 定義 identity ではない。
試行中に request \(q'\) が出れば、wait の残りをその continuation に bind して外へ渡す。
元の \(q,p,K\) は wait の閉じたデータとして保存する。
具体的に \(L=\mathsf{cont}(\bar b,x.N)\) に対して
\[
\begin{split}
 &\mathsf{wait}_h(q,p,K;a,\bar a;\Req(q',p',L))\\
 &\quad\longrightarrow\Req(q',p',\mathsf{cont}(\bar b\,h,x.
       \mathsf{wait}_h(q,p,K;a,\bar a;N))).
\end{split}
\]
pending な handler activation \(h\) はこの wait frame が所有する束縛であり、
多重再開では各枝で fresh になる。\(\mathsf{owner}(h)\) は別の名で、
その owner の Scope まで capture した場合にだけ束縛集合へ入る。
元の \(K\) の内側の binder は alpha 変換で捕捉を避け、ここで二重に束縛しない。
value arms が全て No を返す場合だけ \(\Fail\mathsf{MatchFailure}\) になる。

\textbf{二つの継続を区別する。}
選ばれた arm が受け取るのは \(K\) そのもの、型は \(\mathsf{Kont}(Q,A)\)。
外へ転送する request が持つのは \(H_hK\)、型は \(\mathsf{Kont}(Q,B)\)。
前者へ \(h\) を入れると deep handler になり、後者から \(h\) を除くと
無関係な request の復帰後に元の catch が失われる。

\subsection{複数回 resume と metadata}

\(\Resume(K,v)\) は \(K=\mathsf{cont}(\bar u,x.M)\) の各束縛名を
今回だけの fresh な \(\bar u'\) へ一様に改名し、\(M[v/x]\) を実行する。
saved continuation を変更しないので何回でも呼べる。
\[
 \frac{K:\mathsf{Kont}(Q,A)\quad v:Q}{\Resume(K,v):A}.
\]
public な resumption function は Value entry で response carrier を force した後、
この規則を実行する callable として表す。
request が \(\Scope_u\) を越えるときは、\(u\) を continuation の束縛集合に加え、
その body に \(\Scope_u\) を復元する code を入れる。
scope の suspension を normal return として処理しない。

改名は\emph{view の解釈}にも作用する。
改名環境 \(\theta\) の下で、変数、projection、protocol の応答から得た値は
\(\theta^*v\) として観測する。
共有資源の stored value を書き換える操作ではない。
\[
 \mathsf{readView}_{\theta}(\ell)=\theta^*(\mathsf{storedView}(\ell)).
\]
この式の \(\ell\) は一般の reference の物理表現を仮定しない。
protocol が返した view にも同じ作用を適用するという規約である。
\(\theta\) は owner/handler 名を改名し、family、State scope、free owner、
共有 reference の underlying value、型引数を固定する。
既に別枝へ実体化された自由名を、元の bound 名の次の改名で変更しない。

\(\mathsf{expose}_\chi\) は request へ metadata を付け、
continuation に残りの exposure を保存し、return には result-path metadata を付ける。
構造導入は path prefix の付加、projection はその prefix の除去、
adapter はその計画が明記する path correspondence の合成である。
これらの操作は underlying constructor、payload 型、response 型を変更しない。
raw 値に \(\View_\chi\) が付いている場合、除去 instruction は underlying node を観測し、
返す component に指定された path の metadata を付ける。
force/call の場合は body を expose で囲む。
graph 参照・type application・view の最外の除去は administrative step であり、
実際の constructor の内部を先回りして評価しない。

\textbf{実行型定理に必要な metadata の境界。}
元稿単体の \(\mathsf{Inc},\mathsf{Protected},\mathsf{Grant}\) は、
authentic path の完全な帰納定義をまだ与えていない。
本稿の実行機械は、eligibility を有限 packet に対する任意の\emph{全域 Boolean 関数}
\(\mathsf{eligible}(q,h,\omega)\) として parameter 化する。
ただし operation identity/instance/arity の一致を省くことはできない。
後述の実行型定理は、この関数の\emph{全ての選択}に対して成り立つ。
従ってこの parameter は型保存を仮定する oracle ではない。
一方、これだけで元稿の衛生性や pure effect 注釈の健全性を証明したとは言えない。
この差を第\ref{sec:remaining}節で正確に戻す。

参照先の \texttt{notes/design/2026-10-02-typed-boundary-realization-draft.md}
792--868行には \(\mathsf{Flow}/\mathsf{Receive}/\mathsf{Observe}\) と
候補ごとの activity filter による具体的な候補定義がある。
従って「既存の衛生性には何の定義もない」という理由で作り直すのは誤りである。
同文書991--1026行は有限 evidence graph の query と、
source ごとの profile・correspondence・reentry owner の構成を区別している。
後半の第\ref{sec:decoration}--\ref{sec:full-proof}節で、この候補を全計画と abstract cell へ接続する。

\paragraph{単純な outward bubbling では足りない。}
同参照先388--460行の観測規則では、event の発生時に、handler より外側にあるものも含めて
全ての\emph{現在実行中}の View delimiter を記録する。
従って expose を越えて外へ出た request だけに observation を付ける実装は一致しない。
具体的には、\(h\) の内側の View から、別 owner に由来する live protection が届き、
外側の complete CallView から、\(\mathsf{owner}(h)\) 自身の \(o\) の grant が届く配置を取る。
発生時の全 context 観測なら \(P(q,h)=1,G(q,h)=1\) なので \(h\) は処理可能である。
outward bubbling だけなら、\(h\) の検索時には内側の protection だけが見え、
\(P(q,h)=1,G(q,h)=0\) となって転送する。
他の条件（activity、role、operation coverage）は双方で真とする。
これは decorated graph における二つの観測手順の判別例であり、
特定の compiler source を実行した反例ではない。
実行型の保存ではこの差は発見できない。値と応答の型はどちらの順序でも保存されるからである。
元の衛生性のためには、request 生成時の context 全体への観測と、
arm 実行時には suspended delimiter を観測しない規則の双方が必要になる。

\subsection{decorated plan に対する eligibility の具体化}
\label{sec:concrete-eligibility}

前項の parameter を、既存 transport 仕様の有限 graph query に具体化する。
ここで対象とするのは source inference 前の文字列ではなく、
view の実行位置、source profile、各変換の対応が\emph{項の定数として記された} decorated plan である。
これらの定数を推論器に問い合わせる遷移はない。

\paragraph{状態のデータ。}
\(\omega\) に次の有限な表を持つ。全ての identity は sort を区別する。
\begin{enumerate}
\item view occurrence \(v\) と、その underlying value、有限の signature descriptor。
      alias/binding にも新しい occurrence を与え、同じ raw value の別の経路を混同しない。
\item \(\mathsf{Boundary}(b,u,v,\pi)\)：source occurrence と受信 owner \(u\)、
      view root、profile の有限 template。
      正則な型 graph では automaton として、parametric nominal では下記の guarded template として、
      型の child labels と call/force/effect/result の別を読む。
      negative concrete row は Admit 集合、omission は空の Admit、
      explicit computation wildcard は AllowAll を持つ。
      explicit callback wildcard は新しい boundary を作らない。
      異なる Admit を持つ profile は別の \(b\) に分ける。
      一つの \(b\) では accepted path 全ての Admit template が同じである。
\item \(\mathsf{Flow}(v,w,T)\)：実行した一つの typed transport と有限 template \(T\)。
      \(w\) は新しい occurrence とする。tuple/record/nominal introduction は prefix 付加、
      projection は指定 prefix の除去、alias は identity、adapter は項に記した対応。
      constructor identity だけから新しい辺を作らない。
\item \(\mathsf{Receive}(u,s,v)\)：owner \(u\) の実際の slot \(s\) に入った view。
      formal、captured binding、let、pattern binder、reference の返却値を含む。
      callee の public view を、その callee 自身が受領したとみなす行は追加しない。
\item \(\mathsf{Observe}(q,v,p,j)\)：event \(q\) の生成時に実行中だった
      View occurrence \(j\)、その view と現在の effect port \(p\)。
      View の実行 frame は \(\mathsf{View}(v,p,M)\) と明示する。
\item 現在の実行 context、現在検索している handler、
      continuation 内で suspension 中の context、終了した activation の区別。
\end{enumerate}
同じ名前への単なる改名では、保存した template/view を同じ置換で解釈する。
別枝も参照している全 global 行を破壊的に書き換える操作ではない。
resume 後の新 view は必要な行をその置換の下で参照し、既に実体化された他枝の free 名を固定する。
event は発生時の Observe 列を immutable packet として保持する。
pending query を二枝で再開するときは、それぞれの解釈置換をこの同じ列へ適用する。
同じ元 event ID を持つことを理由に、別枝の観測列を global union してはならない。
これは新しい emission ではなく、元の event の枝ごとの解釈である。
旧 view から新 view への辺だけを追加するため、実行履歴の Flow graph は有限 prefix ごとに DAG である。
再帰値の underlying graph は循環してよい。必要な component を実際に取り出すたびに
新しい view occurrence を作るので、その循環を provenance の循環と同一視しない。
これは履歴を捨てない参照意味論であり、一定メモリの実装という主張ではない。

\paragraph{各遷移が追加する行。}
literal/primitive の新しい値は新しい root を持つ。
構造値は実際に保存する各 component から、新しい構造 view への Flow を追加する。
optional absence は component 辺を作らない。
projection、pattern bind、返却、store protocol の応答は、その実際の入力 view から
新しい出力 view へ、上記の固定 template による Flow を追加する。
let/formal/captured binding を作るときに、その新 view に対する Receive を追加する。
receipt は source \(\pi\) の該当する各有限 template について Boundary を一度だけ作る。
正の effect upper filter は型制約であり、grant の Boundary を作らない。

call は receipt の後、\emph{入口から結果 consumer と adapter まで}を
source plan に指定した complete View で囲む。
force は force-effect port の View で囲む。
closure/delay の構築は View frame に入らず、後で実行したときにだけ入る。
\(F[\mathsf{perform}(p)]\) を縮約するとき、\(F\) にある全実行中 View frame から
Observe を追加する。間に handle があっても、この走査はその handle を越える。
request を外へ bubble させるだけの遷移では、新しい event を作らない。

\paragraph{経路 query。}
\(\mathsf{Path}(q,u,b)\) を次の有限 route の存在として定義する。
\[
\begin{split}
\exists v_b,v_r,v,p_b,p_r,p,s,j.\quad&
 \mathsf{Profile}(b,v_b,p_b)\land\mathsf{Receive}(u,s,v_r)\\
 &\land (v_b,p_b)\mathrel{\mathsf{Flow}^*}(v_r,p_r)
 \land (v_r,p_r)\mathrel{\mathsf{Flow}^*}(v,p)\\
 &\land\mathsf{Observe}(q,v,p,j).
\end{split}
\]
\(\mathsf{Profile}\) は Boundary の template が \(p_b\) を accept すること、
\(\mathsf{Flow}^*\) は記録した template を route 順に合成する関係である。
接続では view occurrence と中間 port の\emph{両方}が一致しなければならない。
異なる alias の endpoint、別 event の Observe、family 名だけの一致を使用しない。
primitive Flow template は、固定 prefix の置換 \(a\cdot s\mapsto b\cdot s\) と
固定した terminal port 対の有限和である。identity、構造の prefix/除去、
Call/Force/mapper の一段の対応はこの形を持つ。任意の descendant を即時 effect に潰す辺はない。
再帰 mapper はその実際の一段ごとに辺を追加し、型引数の無限展開を一つの辺にしない。
query は DAG の有限 route を列挙し、\emph{実際の有限な} observed port \(p\) から辺を逆に辿る。
各辺の逆像候補は有限なので、Boundary に至る有限個の \(p_b\) を得る。
各候補を profile template で検査する。
正則 graph では通常の finite automaton と同じ判定である。
parametric nominal の profile template は、宣言 node と型引数 environment を持ち、
一つの child label ごとに一つの型の辺を辿る有限プログラムとする。
表現を開く場合にも constructor/payload label を一つ消費する。
従って非正則な \(D(D(\alpha))\) 等でも、有限 path を検査する間の置換は有限回で停止する。
型 alias の無限な無進展 cycle は well-formed 型表に許さない。
これで finite query が得られ、非正則型を有限状態 automaton と同一視する仮定は不要になる。
source plan に記されていない「等しそうな path」を推測する case は存在しない。

候補 \(h\) に対する activity は、\emph{現在検索している残りの context}から読む。
既に越えた inner scope は saved continuation 側へ移っており、現在の root にはない。
その receipt は捨てないが、検索時の activity と saved reachability は区別する。
guard/default は候補 handler の外で実行する。No なら、保存した元 request と
残りの arm 列へ戻り、その候補の query context で検索を続ける。
guard の実行で追加した graph 行や共有資源の変更を取り消さない。
guard の request が外側の handler に捕捉された場合は、この pending query 自体が
continuation の code/data に入り、同じ capture-avoiding rename を受ける。

\(\tau\) は上の Path の一つの具体 witness（route、中間 port、instance 対、Observe occurrence）を表す。
grant の照合ではその\emph{同じ} \(\tau\) を用いる。

\[
\begin{split}
 I(q,h,b;\tau)&=\mathsf{Path}_{\tau}(q,\mathsf{owner}(h),b)
 \land\mathsf{Active}(h)\\
 &\quad\land\mathsf{Active}(\mathsf{owner}(h))
 \land\mathsf{Active}(\mathsf{receiver}(b)),\\
 P(q,h)&=\exists b,\tau.\ I(q,h,b;\tau),\\
 G(q,h)&=\exists b,\tau.\ I(q,h,b;\tau)\land
       \mathsf{receiver}(b)=\mathsf{owner}(h)
       \land\mathsf{Admit}_{b}(q;\tau),\\
 \mathsf{eligible}(q,h)&=\mathsf{Active}(h)\land\mathsf{Active}(\mathsf{owner}(h))\\
       &\quad\land\mathsf{RoleAllows}(q,h)\land\mathsf{Covers}(q,h)
       \land(\neg P(q,h)\lor G(q,h)).
\end{split}
\]
Admit は Boundary の有限 concrete set または AllowAll と、その typed view における operation instance の比較。
OpMap の辺は port 対応とともに、同じ \(w\) の source/target instance 対を保持する。
従って Boundary 側で読む instance と、外向き request の現在の instance を区別できる。
Admit は同じ Path witness に沿って Boundary 側の instance を読み、Covers は現在の instance を読む。
型引数の双方向 adapter があることを、二つの instance の equality に置き換えない。
Covers は arm の operation identity と instance。
RoleAllows は decorated plan に記した source role/phase 表の lookup とする。
\(\mathsf{Active}(\mathsf{owner}(h))\) は eligibility の外側の conjunct にも必要である。
Inc の中だけに置くと、owner が失効したとき \(P=G=0\) になり、
\(\neg P\) によってその handler を誤って許可する。
この条件は既存 typed-boundary draft の Visible の定義に従う。
その有限表は local/incoming と entry/body/result の各組について真偽を全て持つ。
表の欠けた計画は well-formed decorated plan ではない。
まだ body に入っていない Value entry に body 内の handler を置く frame は存在しない。
Pure receiver でも、自分の body にある local operation の catch はこの規則で扱える。
未知の type equality を真とする実行規則はない。
operation 型引数を変換するときは、必ず次項の mapop の code を先に使う。

\begin{lemma}[decorated graph query の有限性と非捏造]
上記の decorated plan の任意の有限実行 prefix に対して eligibility は全域に定まり、
真の Grant は、同じ event と view path、現在の handler の owner、
source の明示的な Admit を持つ Boundary の witness を必ず持つ。
\end{lemma}
\begin{proof}
一段は有限個の graph 行と finite template を追加するので、prefix 長への帰納で表は有限。
Flow は新しい occurrence へ向かうため有限 DAG。
query は有限 route と各辺の有限逆像、有限 path の guarded profile 検査だけを行い、必ず真偽を返す。
Grant の式を展開すると、宣言した四つの witness がそのまま得られる。
transport は元 Boundary を移すだけで Admit を変更せず、Receive は Boundary を作らない。
own receipt の導入以外に Admit を導入する規則はない。
scope の終了は activity を落とし、rename は全 witness を同じ写像で移すので、
外来 owner を現在の owner に偶然同一視することもない。
\end{proof}

この具体化により、\emph{完全に decorated された計画}には、
型推論器も event ごとの意味論 oracle も呼ばない一つの実行を与えられる。
ただし、元の source/certificate から全ての View port と template を供給する構成、
および元稿の有限 abstract descriptor との simulation は、この補題には含まれない。
具体 query の有限性から、全実行履歴の有限静的商があるとは結論しない。

\subsection{operation mapper}

\(w\) は同じ family/member の source instance \(\bar A\) と target instance \(\bar B\)、
payload code \(a:P_o(\bar A)\to P_o(\bar B)\)、
response code \(r:Q_o(\bar B)\to Q_o(\bar A)\) の一つの組である。
同じ \(w\) を両方向で使う。
\(\mathsf{mapop}_w(\Ret v)\to\Ret v\)。該当 request には
\[
\begin{split}
 \mathsf{mapop}_w\Req(q_{o,\bar A},p,K)\longrightarrow{}&
 \mathsf{let}\ p'\leftarrow a(p)\ \mathsf{in}\\
 &
 \Req(q_{o,\bar B},p',\mathsf{cont}(\bar u,z.
    \mathsf{let}\ z'\leftarrow r(z)\ \mathsf{in}\
    \mathsf{mapop}_w M[z'/x])).
\end{split}
\]
ここで \(K=\mathsf{cont}(\bar u,x.M)\) とし、response code の自由名を捕捉しないように
\(\bar u\) を先に改名する。新しい continuation の resume で一度だけ freshening を行う。
同じ bound 名を内側の Resume で二重に freshen する定義にはしない。
他の request は payload を保存し、continuation の周囲へ mapop を戻す。
payload adapter の計算はこの mapop の外で実行する。
response adapter もその計算自身を再び変換して無限に包むことはしない。
これは stream の transformer であり、handler の source grant を作らない。
型規則は上記二つの code の構文的型付けと、変換前後の operation signature の一致だけを要する。
型の違う応答を元の continuation に直接渡す規則はない。

\section{複合構文を明示的な計画にする}
\label{sec:patterns}

\subsection{record と boundary code}

literal record の計画は \(\mathsf{Field}(l,e)\)、\(\mathsf{Spread}(e)\) の有限列である。
全 RHS を左から右へ let で評価し、可視写像へ右優先で追加する。
optional field が不在なら上書きしない。上書きされる RHS の effect も実行する。
この処理は有限写像の構築と、optional lookup の分岐だけで展開できる。
入力は backing object 全体ではなく現在の view である。

record 境界 \(R\to S\) は target label 順の明示 code である。
required target には、source の required field、または\emph{その分岐での present 証拠}を必要とする。
optional target は lookup の No を absence、Yes を子 adapter に渡す。
target 外の field を出力に置かない。
子 adapter は通常の \(z:A\ty M:B\) の導出を持つ code であり、
「resolver が成功した」という未定義の前提ではない。

\begin{lemma}[record code の型付け]
各 present branch の子 code が所定の payload 型を持ち、required field の存在証拠があるとき、
展開した code は \(z:\mathsf{Rec}(R)\ty M:\mathsf{Rec}(S)\) を持つ。
\end{lemma}
\begin{proof}
target label 列に帰納する。required は field 規則の前提を満たすか、
lookup の右分岐の束縛 \(x:A_l\) を使用する。
子 code と let の規則で \(S_l\) の値が得られる。
optional の左分岐は field を追加せず、右は同じ導出を持つ。
record introduction の domain 条件により、全 required field と存在する payload の型が揃う。
target 以外の label を導入する規則を使わない。
\end{proof}

二つの境界 code は let で合成できる。
しかし、合成導出は一回の \(R<:T\) 判定の証拠ではない。
\(\{foo:int\}\to\{\}\to\{foo?:int\}\) は foo を復活させない。
nominal mapper も宣言 payload の有限 template から同じ code を作る。
function field は wrap、thunk field は delay/force、正負の引数対は別の code を使う。
再帰 mapper は上記の有限 template 表であり、実際の user cast 呼出しだけが通常の source Call になる。
mapper の停止を型保存の仮定にしない。

\subsection{全11 pattern の翻訳}

\(\mathsf{Match}_{p}(v)\) は \(1\vee\mathsf{Env}(\Gamma_p)\) を返す計算とする。
\(\mathsf{Env}(\Gamma_p)\) は公開 binder を固定順に並べた tuple。
branch-local な一時 binder と公開 binder は異なる identity を持つ。
以下の記述は実行の再帰定義であり、任意の match oracle を使用しない。

\begin{longtable}{p{.17\textwidth}p{.75\textwidth}}
\toprule
pattern & 計画 \\
\midrule\endhead
Wild & \(\Ret\mathsf{Yes}(())\)。\\
Var & \(\Ret\mathsf{Yes}((v))\)。\\
Lit & 同じ literal 種別と値の比較。真なら Yes、偽なら No。\\
Tuple & shape と arity を先に照合し、各子を左から右へ bind。最初の No で No。\\
List & 有限 sequence の長さ条件を先に照合し、prefix/suffix の子を順に照合。rest は中央の sequence。\\
Record & 可視 field を記述順に lookup。present ならその値、absent なら既存の先行 binder 環境で default を実行。default がなければ No。spread binder には入力全体。\\
PolyVariant & tag/arity の照合後、payload の子を順に照合。\\
Con & nominal/constructor identity と arity の照合後、同じ instance の payload を順に照合。\\
Ref & 解決済みの一つの definition instance の値と、指定された equality code で比較。bool の結果から Yes/No。binder は作らない。\\

型付き match 計画は、各 constructor が実際に持つ payload 型を子の入力型にする。
default の入力環境と結果型は別に型付けする。
OR の merge 型は各枝からの union injection を持ち、片枝だけの binder を公開しない。
Lit の equality は base equality、Ref の equality はその型に対応する明示 code であり、
\(\mathsf{Unknown}\) を equality function として実行しない。
equality code 自身が source 関数なら、その code にも通常の型付け導出が必要である。

\begin{lemma}[match 計画の型付け]
上の構文規則で検査された \(p:A\Rightarrow\Gamma_p\) について、
\(v:A\) なら \(\mathsf{Match}_p(v):1\vee\mathsf{Env}(\Gamma_p)\)。
\end{lemma}
\begin{proof}
pattern の有限構文に帰納する。
Wild/Var は unit/tuple introduction。Lit/Ref は bool case の両枝。
Tuple/List/Record/Variant/Con は検査した payload の elimination と子の帰納仮説を let で合成する。
No では未実行の子へ進まず、Yes では既存の tuple と新たな型付き binder を連結する。
default の型付けはその式の\emph{構文的導出}を使い、実行の安全性をここでは仮定しない。
As は元の入力型の component を追加する。
Or は片枝の Yes tuple から公開する component を projection し、
対応する union injection で merge 型を得る。
この導出には他方だけの binder の lookup は出現しない。
\end{proof}

guard は Yes tuple を開いた環境で bool を返す通常の計算とする。
false の場合、lexical tuple を捨てて次の arm を開始する。
既に実行した request や reference update は bind の履歴に残り、元に戻さない。
この規則は request/\(\Fail\) を No に変換しない。

\subsection{一般の reference と State}

\(\mathsf{ref}\langle E,A\rangle\) の実行型は nominal な get/update protocol である。
共有 cell の型と同一視しない。
代入は reference、右辺をこの順に一回評価し、
resolved \(\mathsf{StdRefUpdate}(r,\lambda\_.v)\) を呼ぶ。
\(\mathsf{ref\_update}\langle A\rangle\) の request に対して、
同じ \(A\) の \(v\) を返して raw continuation を resume し、handler を明示的に再設置する。
他の request は転送する。これは通常の rec/call/handler 計画である。
型付けは \(A\to A\) の mapper と同じ \(A\) の operation signature から導出できる。

State の実行は、同じ shallow handler を再設置する通常の recursive callable として定義する。
状態値 \(s:A\) と対象計算を引数に持ち、
get の response は \(s:A\)、set の payload \(s':A\) を次の状態値にする。
無関係な request は、その時点の \(s\) を捕捉する continuation で転送する。
その continuation を二回呼ぶと双方が同じ \(s\) から始まり、
外側の State は元の外側の計画で共有される。
このため snapshot は \emph{捕捉された handler 内の状態値}についてだけ生じる。

State frame を heap に持つ VM を使わなくてもこの意味は定まる。
frame 実装を使用する場合の対応関係は
\(\mathsf{State}(s,M)\sim\text{状態 }s\text{ の active frame と }M\)
である。get/set は同じ response/更新、forward は同じ \(s\) の capture、
resume は新しい frame occurrence と同じ State scope、return は frame 除去に対応する。
これは規定した frame 操作との対応であり、現在の VM の全 fast path の証明ではない。

\subsection{全13式、statement、root}

\midrule\endhead

Let の値 SCC は \(\mathsf{rec}\) の有限 graph、computed root は順序付き let である。
computed root の結果は一度束縛し、その後の Var はその値を読む。
Module は identity 解決後の値表と root 列、Expr root はその計算、
ComputedDef root は一度評価して後続環境を拡張する計算になる。
\(\Gamma\) にない未初期化 computed root の fetch を型付けする規則はない。
遅延した body が将来初期化される root を参照する場合には、
linker は正しい環境を閉じた計画として供給する必要がある。
その source/linker 対応を本稿の substitution lemma に隠さない。

role/member/cast は明示 code または dictionary component であり、実行時に再選択しない。
qualified 計画の dictionary 変数は \(\Gamma\) の通常の型付き値である。
impl head の正しさや候補選択の完全性は、ここで使う部品の型付けと別の命題である。
type/struct/enum、act copy、control、loop、rule、Yumark 等の生成 code も、
この有限文法の計画を与えられた後には同じ定理の対象となる。
全ての生成 code を compiler が正しく作るという Q1 を、これだけで閉じない。

\section{primitive を型保存の未証明な仮定にしない}
\label{sec:prim}

\(\delta_p\) は正しい arity と入力 constructor を先に検査する raw 関数とする。
間違えば \(\Bad\)、正しければ以下の有限値上の操作を行う。
範囲は半開区間 \(0\leq i\leq j\leq n\)、index は \(0\leq i<n\)。
失敗は \(\mathsf{BoundsError}\)、整数の 0 除算は \(\mathsf{DivideByZero}\)、
YadaYada は \(\mathsf{Unimplemented}\) とする。
list の \(A\) は全引数で同じ一つの型である。
native List の値 constructor は有限 vector \(\mathsf{seq}(\bar v)\) に固定し、
一般の nominal constructor 規則で別の内部 ListTree node を捏造しない。
要素が再帰値 graph を参照しても、長さ/slice は有限 vector の骨格だけを見る。
ListViewRaw の tail もその vector の有限な残余である。

この表における character 分割、formatting、range の解釈は元稿が指定する
固定 helper を用いる。実行型定理は、次の\emph{型付き有限列関数の全選択}に対して一様である。
grapheme/line 分割は有限文字列を有限個の部分文字列へ分け、range 正規化は
有限 endpoints または BoundsError を返し、formatting は有限文字列を返し、
character predicate は bool を返す。
これらは言語の数値・文字列上の観測意味を固定する parameter であり、
任意の Yulang code の安全性を仮定する parameter ではない。
その選択まで含めた完全な byte-for-byte の意味論には、
特に数学的整数の範囲外 hex formatting 等の未指定箇所の固定が必要である。

\begin{lemma}[primitive の実行型保存]
\(\bar v:\bar A\) と primitive の signature \(\bar A\to B\) があるとき、
\(\delta_p(\bar v)\) は \(\Ret v'\) with \(v':B\)、または表の \(\Fail r\) である。
\end{lemma}
\begin{proof}
入力型の inversion により arity と全入力 constructor の検査は成功する。
bool/比較/predicate は bool constructor、長さは非負の数学的整数である。
整数の演算は整数に閉じ、0 除算は明示 failure へ分岐する。
binary64 の演算は64 bit の float constructor に閉じる。
列の index は検査済み位置にある既存の \(A\) の値を返す。
slice は既存要素の部分列、splice/merge は同じ \(A\) の有限列の連結である。
ListViewRaw の head と tail にも同じ性質がある。
string/char/bytes/path は表に指定した finite sequence constructor から作り、
UTF-8 prefix は定義上有効な string と整数の tuple を作る。
range constructor の二つの payload は int である。
YadaYada は正常値を返さない。この分類は表の62個を尽くす。
\end{proof}

\section{実行型健全性の証明}
\label{sec:proof}

\subsection{補題の依存を固定する}

証明の順序は、置換、値の形、frame、continuation の切出し、一段保存、進行、
有限 prefix の帰納、という順である。
意味論的 \(\V(A)\) の定義に安全性を入れてから、
「値が \(\V(A)\) に属するので安全」と結論する循環を使わない。
以下の全ての型付けは第\ref{sec:types}節の構文的な型付けである。

\begin{lemma}[項・型・名前の置換]
次が成り立つ。
\begin{enumerate}
\item \(\D;\Gamma,x:A\ty M:B\)、\(\D;\Gamma\ty v:A\) なら
      \(\D;\Gamma\ty M[v/x]:B\)。値についても同じ。
\item 一つの型代入 \(\sigma\) を宣言 instance、環境、計画、全 payload/response、
      結果へ同時に施すと、型付けが保存される。
\item owner/handler 名への capture-avoiding injective renaming は型付けを保存する。
      family/State/resource の free identity と型引数を固定する。
\end{enumerate}
\end{lemma}
\begin{proof}
型付け導出に帰納する。
変数が \(x\) のとき与えられた値の導出、それ以外は元の環境の lookup を使う。
binder を持つ各規則では binder を置換値から fresh にしてから帰納仮説を適用する。
record の label/presence、tuple/variant/nominal の arity と宣言 identity は変わらない。
function の二つの entry では \(x:A\) と \(x:UA\) の各前提をそのまま保つ。
handler は payload/response の両方へ同じ \(\sigma\) を使うため、
operation signature の instance が一致したままである。
polymorphic arm の rigid binder と \(\forall\) 導入の binder は先に fresh にする。
\(\alpha\notin\fv(\D,\Gamma)\) は共有環境を含むので、既存 resource の型が
使用ごとに変わることはない。
rec の全右辺には同じ再帰環境を同時に置換する。graph の guard は保持される。
continuation の名は binder として扱い、その free support を捕捉しない。
metadata の改名は underlying value と実行型に作用しないため、view の規則を再適用できる。
以上は全 introduction/elimination と administrative form を尽くす。
\end{proof}

\begin{lemma}[immutable graph の拡張]
\(\D;\Xi\ty H\) と \(\Xi\) の下の導出は、既存 node の値・型を変えない
well-typed な拡張 \(H'\supseteq H,\Xi'\supseteq\Xi\) の下でも成り立つ。
rec の上記 allocation はそのような拡張を作る。
\end{lemma}
\begin{proof}
既存の参照規則は同じ型を読むので、導出に関する帰納法で weakening を得る。
新しい各 node について、rec の前提
\(\Xi;\Gamma,\bar x:\bar A\ty v_i:A_i\) に、
\(\Xi'(r_i)=A_i\) による参照値を同時置換する。
各 node は \(A_i\) を持ち、古い graph に新 node への辺を加えないので、
新しく生じうる cycle はこの rec の検査済み guard を通る。
body も同じ置換補題で型付く。
\end{proof}

\begin{lemma}[値の形]
well-typed graph の下で閉じた \(v:A\) の最外の型 constructor を除去する instruction は、
対応する値 constructor またはその明示 view 証拠を必ず得る。
\(\bot\) の閉じた値はない。
\end{lemma}
\begin{proof}
型付けの最後の introduction を反転する。
同じ型の別の形を許す規則は、明示 view、type application、rec 参照だけである。
view は underlying constructor を保存し、type application は置換補題で同じ導出に戻る。
rec 参照は有限 graph の guard により有限回の alias 移動で実際の constructor に達する。
\(UA\) は delay またはその inert thunk wrapper、\(C(A,B)\) は lambda/wrap、
\(\mathsf{Kont}(Q,A)\) は明示 continuation。
record introduction 自体が required field の存在を要求する。
\(\bot\) の introduction はなく、guard のない alias/型証拠 cycle も許さない。
従って \(\bot\) の有限導出・guarded value graph は構成できない。
\end{proof}

\begin{lemma}[frame の型付けと穴への代入]
active hole を一つ持つ評価 context \(F\) に
\(F:(A\Rightarrow B)\) を、その hole を \(A\) 型の計算として扱う構文導出で与える。
\(M:A\) なら \(F[M]:B\)。
また \(F[M]:B\) の導出を active hole まで反転すると、この中間型 \(A\) と両導出が得られる。
\end{lemma}
\begin{proof}
context の長さに帰納する。
空 context は恒等。
let の frame は hole の結果型を binder 型にし、残りの body の導出を使う。
scope/expose は同じ実行型。
handle は \(A\Rightarrow B\) の規則。
mapop は正常結果型を変えず、operation の instance と継続の型だけを輸送する。
wait は attempt の \(1\vee B\) を受け取る frame で、両枝の遷移先が \(B\)。
他に active evaluation context はない。
\end{proof}

\begin{lemma}[call の局所保存]
\(f:C(A,B)\)、\(t:UA\) なら、receipt、argument adapter、entry、body、
declared result consumer、result adapter の各遷移は結果型 \(B\) を保存する。
\end{lemma}
\begin{proof}
wrap の有限外側列に帰納する。
\(a(z):A\) under \(z:A'\) から
\(\Delay(\Force t\bind a):UA\) が let/force/delay の規則で得られる。
内側の enter が \(B\)、\(r(z):B'\) なので外側は \(B'\)。
これは値型の反変・共変を code の型付けで用いるだけで、effect ポートの比較を仮定しない。
最内の source lambda が Value なら \(\Force t_u:A\)、
body は \(x:A\ty M:B\) なので let が \(B\)。
Computation なら \(t_u:UA\) を置換して \(B\)。
receipt は view の規則で \(UA\) を保存する。
result consumer は body の最後の通常 code なので同じ let 規則を使う。
scope の entry/exit は値型を変えない。
\end{proof}

\begin{lemma}[request の切出しと raw continuation]
型 \(A\) の対象計算から \(q=(o,\bar T)\) が露出するとき、
payload は \(P_o(\bar T)\)、対象計算の末尾までの raw continuation は
\(\mathsf{Kont}(Q_o(\bar T),A)\) である。
\end{lemma}
\begin{proof}
request の生成と有限個の outward propagation の長さに帰納する。
perform の最初の continuation は \(x.\Ret x\) なので
\(\mathsf{Kont}(Q,Q)\)。
let を越えると frame 補題により body を後ろに合成でき、結果型をその let の結果型にする。
scope/expose は同じ結果型を保持し、型付き continuation の code と束縛名を追加する。
未選択の handle を越えると、その \(A\Rightarrow B\) の frame を後ろへ入れるので
\(\mathsf{Kont}(Q,B)\)。
選択した handle の直前で切り出した場合、その frame を入れないので
\(\mathsf{Kont}(Q,A)\) のままである。
wait を越える場合も保存した元 request と試行の残りは型付き閉じたデータで、frame 補題を適用する。
mapop は payload code によって \(P_o(\bar T')\) を得て、
\(z:Q_o(\bar T')\) を response code で \(Q_o(\bar T)\) にしてから元の continuation に渡す。
その let の導出が新しい continuation の型を与える。
全ての outward context を尽くした。
\end{proof}

\begin{lemma}[handler と resume の局所保存]
\(M:A\)、\(h:A\Rightarrow B\) なら、handle/try/wait の全遷移は \(B\) を保存する。
任意回の \(\Resume(K,v)\) は \(K:\mathsf{Kont}(Q,A),v:Q\) の下で \(A\) を保存する。
\end{lemma}
\begin{proof}
正常値は value attempt の所定の入力型を持つ。
request は切出し補題の同じ instance の \(p,K\) を持つので、
arm の rigid 型変数へその一つの instance を代入できる。
eligibility の真偽は試行する arm を選ぶだけで、arm の型を変えない。
各試行は \(1\vee B\)、Yes は \(B\)、No は同じ型の残りの試行列へ移る。
空列は \(H_hK:\mathsf{Kont}(Q,B)\) を持つ request。
試行中の外向き request は wait frame を持つので、切出し補題が適用できる。
value-arm の空列は明示された MatchFailure で、任意の結果型を持つ。
raw resume は束縛名を fresh rename した後、\(Q\) 型の値を code へ置換する。
二つの置換補題から \(A\) を得る。
saved code は変更しないため、同じ証明を任意回適用できる。
継続が一回だけ使われるという仮説は一度も用いていない。
\end{proof}

\begin{theorem}[一段保存]
閉じた well-formed 宣言表 \(\D\)、\(\D;\Xi\ty H\)、\(\D;\Xi\ty M:A\) とし、
\(\langle\D,H,M,\omega\rangle\to\langle\D,H',M',\omega'\rangle\)
とする。このときある \(\Xi'\supseteq\Xi\) が存在して、
\(\D;\Xi'\ty H'\) と \(\D;\Xi'\ty M':A\) が成り立つ。
metadata は underlying constructor を保存する上記の有限写像、
eligibility は全域 Boolean 関数の全ての選択について量化する。
\end{theorem}
\begin{proof}
遷移の最後の規則で場合分けする。
let、force、split、switch、unioncase は項置換補題。
field/lookup は record introduction の inversion と presence。
choose/unroll は対応する明示証拠の elimination。
type application は同時型置換補題。
primitive は第\ref{sec:prim}節の補題。
perform は \(x.\Ret x\) と同じ operation signature で request 規則を導出する。
rec の graph 構築は graph 拡張補題を使う。他の規則は同じ \(H,\Xi\) を使う。
template の一段展開は code 表の導出への型・値の同時置換である。
call/enter/wrap は call の局所保存、scope/expose は名前置換と view 規則。
bind による request の伝播は切出し補題の let case。
handle/try/wait/resume は直前の補題。
mapop は payload code、response code、同じ \(w\) に対する型置換と let の規則。
Fail の伝播は同じ許された failure の規則。
子の遷移には遷移導出の帰納仮説と frame 補題を用いる。
これらが全遷移であり、\(\Bad\) の導出を必要とする case は値の形補題によって生じない。
\end{proof}

\begin{theorem}[進行]
\(\D;\Xi\ty H\)、\(\D;\Xi\ty M:A\) が閉じた計画の型付けなら、次のいずれかである。
\begin{enumerate}
\item \(M=\Ret v\)、\(v:A\)。
\item \(M=\Req(q_{o,\bar T},p,K)\)、
      \(p:P_o(\bar T)\)、\(K:\mathsf{Kont}(Q_o(\bar T),A)\)。
\item \(M=\Fail r\)、\(r\) は列挙した言語 failure。
\item 一段の遷移が存在する。
\end{enumerate}
\end{theorem}
\begin{proof}
唯一の active child を辿る。
有限 context を抜けて通常 redex に達すれば、値の形補題が必要な constructor を与える。
primitive の数値処理は有限値上の全域処理または定義した failure。
rec の構築は有限、force 後の再帰計算は停止しなくても次の一段を持つ。
template の展開も有限の一つの body への置換であり、次の一段を持つ。
child が Ret/Req/Fail なら、その外側 frame に対応する明示規則がある。
handler の eligibility は全域 bool、arm 列は有限で、試行中の計算は普通の active child。
従って guard の発散も「次の一段がない」状態にはならない。
最外の frame がなくなれば1--3のいずれかである。
\(\mathsf{absurd}\) の場合は閉じた \(\bot\) 値がないので起こらない。
全 raw instruction を尽くしており、型付き状態が \(\Bad\) へ進む場合はない。
\end{proof}

\begin{theorem}[推論器から独立した実行型健全性]
\label{thm:safety}
初期の閉じた graph と計画に \(\D;\Xi\ty H\)、\(\D;\Xi\ty M:A\) があるとする。
graph を持たない source plan は \(H=\Xi=\varnothing\) から開始できる。
外界は、露出した各 \((o,\bar T)\) に対して \(Q_o(\bar T)\) の型付き response を返すか、
その request で実行を停止する。callback を返す場合、その code も同じ構文的型付けを持つ。
response に新しい immutable graph node が必要なら、既存の \(H,\Xi\) を固定した
well-typed な fresh extension とともに渡す。
任意の有限回の内部遷移・型付き外部 response・多重 resume の後、
拡張した well-typed graph の下で計画は型 \(A\) を持ち、進行定理の四つのいずれかである。
従って未束縛 local、不正な field/constructor の取得、
間違った payload/response、非 callable の実行には到達しない。
無限に内部遷移が続く場合も許す。
\end{theorem}
\begin{proof}
有限 prefix の長さに帰納する。
長さ0は前提。内部遷移は一段保存を適用し、graph typing の拡張を保持する。
外部 response は、進行の第2の場合に得る \(K:\mathsf{Kont}(Q,A)\) と
応答の \(v:Q\) から resume の局所保存を適用する。
外界が fresh node を供給する場合も graph 拡張補題で既存の continuation の型を保つ。
同じ request/continuation を複数回再開しても各回この導出を使用できる。
現在の world の metadata を観測し直す操作と名前の freshening は view/名前置換補題に含まれる。
各 prefix の末尾に進行定理を適用する。
\(\Bad\) は型付け規則を持たないので、保存と両立しない。
無限実行に有限の最初の Bad があるなら、その有限 prefix に上の帰納法を適用して矛盾する。
よって有限 prefix 全てと無限実行の双方について主張が成り立つ。
\end{proof}

\subsection{この証明が実際に不要にした前提}

この導出には、型推論器の実行、解の構成可能性、主型性、全 role の探索、
ordinary graph の有限モデル、\texttt{BuildLocal}、全 Q1--Q8 のどれも出現しない。
代わりに必要なのは、\emph{具体的に提示された code の構文的導出}である。
adapter の保存を仮定していない。adapter は通常 code で、その型付けから同じ保存定理を得る。
host が型の違う応答を返さないという開いた protocol 条件は残るが、
内部 primitive と内部の source callable の安全性を host 条件へ移してはいない。

\section{元の型を戻す：型付き構文から decoration を作る}
\label{sec:decoration}

以下では型を元稿の \(A!\Phi\) に戻す。
\(A\) は \(U(E,A)\)、\(F(A,E^-,E^+,B;\pi,m)\)、全 latent port を含み、
\(\Phi\) は同じ assignment を共有する有限 descriptor graph である。
前半の型を \(|A|\) と書く。\(|A|\) の導出だけでは本節以降の型付けにならない。
適合証拠は、引数・結果を変換する\emph{具体的な code とその導出}を持つ。
双方向の code を恒等写像または互いの逆写像と仮定しない。

\subsection{有限の入力と、生成する定数}

入力は、解決済み宣言 identity、型 instance、source annotation の occurrence、
lambda の導入箇所、選択済み member/adapter code を持つ型付き構文である。
型変数や dictionary が残る場合は、それらを \(\Delta;\Gamma\) の binder として扱う。
未解決の名前を runtime lookup へ送る規則はない。
この入力を生成する推論器の存在は仮定しない。

decorator \(d\) は次の有限の構文再帰である。
型の child labels は tuple index、record label、nominal argument、variant payload、
\(\mathsf{arg},\mathsf{result},\mathsf{force},\mathsf{effect}\) とする。
正則型では型 graph の node と polarity \(\{+,-\}\) の積を状態にし、
arg 辺だけ polarity を反転する。annotation occurrence を保持したままこの積 graph を辿り、
次の表に一致する node を受理状態とする。再訪は同じ状態への辺であり、再展開しない。
これが正則部分の source profile の有限 automaton である。
非正則な nominal は有限な宣言 template と型引数 environment の組で保持し、
前述の有限 path 検査で解釈する。型引数 environment の全展開を状態の有限性の根拠にはしない。
abstract signature は宣言 template node と有限色を使い、保持できない environment/path の相関は全候補にする。
抽象的な型 binder の shape がまだ見えない箇所は、元の occurrence に属する
delayed-shape template として保持する。未知の callback 位置を「存在しない」と確定しない。
その instance の型 descriptor を同時に渡して template を満たし、
有限 cell 側で未表現の path/profile 座標は全候補にする。
nominal の表現を無限に monomorphize しない。型引数位置は引数位置のまま扱い、
表現との対応は、その宣言の有限 mapper template を実際に実行した辺から得る。

明示 Function annotation または expected callback ありなら Handler とする。

型付き構文の各 node に一つの静的 label を付ける。
動的 owner、view occurrence、handler activation の identity は label と異なる。
\(d\) は型に存在する effect port を次の位置でだけ実行に接続する。

\paragraph{phase と role。}
phase は、entry/argument、body、declared-result、outer-adapter、attempt の code label の分類である。

\(\mathsf{RoleAllows}\) は、候補 activation がこの lexical catch の occurrence であり、
検索 context においてその囲まれた計算から来た query であることを検査する。
source role は profile 構成へ使用し、row の空/非空から作り直さない。
body にしかない catch は entry force の context に存在しない。
Pure body の local catch を一律に禁止する追加条件は置かない。
これは元稿2506--2512行の phase 条件の具体化である。
raw reentry では保存した label と handler activation の束縛を使用し、
元の call stack にいたという理由だけで catch を追加しない。

\begin{lemma}[decoration の全域性と保守性]
有限な型付き構文と有限の template graph に対して \(d\) は停止する。
全13式・全11 pattern に結果を持ち、実行型を保存する。
消去すると前半の明示 code になり、constructor、計算の順序、遅延位置、
call の receiver 数、selected shallow handler の非復元を変更しない。
\end{lemma}
\begin{proof}
非再帰の子への処理は有限構文の真の部分木、再帰辺への処理は visit 済み label への参照である。
profile 構成は有限 node と二つの polarity の積、または有限の宣言 template の走査で停止する。
表の各行は新しい値・実行を作る場合と、metadata だけを付ける場合を区別している。
後者の消去は恒等。前者は前半の let/force/call/adapter 展開そのものである。
各表の入力 constructor を列挙すると13式と11 pattern が尽きる。
match の binder 型、record の存在性、OpMap の同じ payload/response instance は
前半の構文規則をそのまま使う。従って構文帰納と既出の局所型付け補題が適用できる。
これは推論された未検査 certificate の消去定理ではなく、明示された\emph{型付け導出}の翻訳定理である。
\end{proof}

\section{具体的な観測と有限 cell の表示関係}
\label{sec:representation}

\subsection{観測 world と complete cell}

具体 world \(w\) は第\ref{sec:concrete-eligibility}節の有限履歴、
現在の executing/search context、saved contexts、view の解釈置換を含む。
interface \(I\) は、比較する有限個の operand/result port と名前 register を指定する。
名前の sort は owner、handler、family、State scope、resource、event を区別する。
名前でない path は、type node・profile state・primitive transport label・polarity の有限色を持つ。
同色性は path equality の証拠ではない。

\(\alpha_I(w,\bar v,q)\) を次の有限 diagram と定義する。
\(q\) がない値 interface も許す。
\begin{enumerate}
\item register の defined bit、同じ sort 内の実際の equality partition。
\item named owner について、全 profile、候補別 incidence、grant、現在の activity の membership vector。
\item named でない各 owner の完全な membership vector \(\beta\) ごとの非空 bit \(e_\beta\)。
      universe はその有限履歴の support であり、未確保の無限個の名を入れない。
\item path 色、保持された対応 witness、source phase/origin、operation 宣言、
      同じ family-argument instance を指す query label とその真偽。
\end{enumerate}
各述語の意味を任意に選ぶことはできない。\(P\) は Boundary と transport の解釈、
値 interface の \(R_{c,j}(r)\) は owner \(r\) の Boundary から
候補 \(j\) の Receive を通ってその view の指定 port へ至る Flow route、
event interface ではそのうち同じ event の Observe 列に至る第\ref{sec:concrete-eligibility}節の Path、
\(G\) はそのうち同じ owner と Admit を満たすもの、\(A\) は現在の activity である。
event の Observe は\emph{発生時の全 executing View}から作り、後の dispatch はそれを読み取る。
permission があるだけでは event 座標を持つ cell は生成されない。

有限の cell 全体を \(S_I\) と書く。
\(w,\bar v,q\models_I s\) は単に \(\alpha_I(w,\bar v,q)=s\) を意味する。
これは実行が安全であるという述語ではない。
一つの concrete packet は一つの cell を持ち、抽象値 \(U\subseteq S_I\) は
\(\alpha_I(w,\bar v,q)\in U\) によりその packet を表示する。
複数 port の比較では、それぞれ独立した cell を作らず、union interface の一つの diagram を使う。

\begin{lemma}[query の正確性]
候補の register と全 query 述語を持つ \(s=\alpha_I(w,\bar v,q)\) について、
cell 上の \(\mathsf{Elig}(s)\) と具体機械の \(\mathsf{eligible}(q,h,w)\) は一致する。
\end{lemma}
\begin{proof}
named owner については membership を読む。
hidden owner が \(A\land R\) を満たすかは、その二座標が1の全 vector の \(e_\beta\) の disjunction。
従って \(\exists r(A(r)\land R_{c,h}(r))\) は正確に判定できる。
grant の owner は named candidate と同じ点であり、同じ diagram の \(G\) を読む。
activity は handler とその owner の両方を検査する。
role/phase、coverage、family instance の残りの conjunct も定義により同じ値である。
異なる hidden 集合が各々非空という情報から交差を推測する段階は存在しない。
\end{proof}

\subsection{全候補 relation の具体的な作り方}

元稿の primitive transfer を、有限 diagram 間の relation として次の手順で固定する。
input/output の union interface を作り、各 primitive が\emph{指定する座標式}を課す。
指定されない座標は全整合候補を残す。
これは successor の実行 trace を探索する定義でも、型安全性を問い返す oracle でもない。
以下の手順は有限集合上の Boolean 演算と列挙だけである。

ambient observation は、その時点の全 executing View の potential incidence の和を表す入力 packet とする。
各 View frame は外側の packet を保存し、内部ではそれと新しい View の和を使う。
正常 leave では保存した外側へ戻る。同じ witness を二つの View が持ちうるため、集合差で除去しない。
capture では保存した内側 View の列だけを保持し、resume では\emph{現在の resumer の ambient packet}へ加える。
元の外側 packet を復元して現在の外側を上書きしない。
有限 interface で保持できない candidate 列・対応は全候補となる。
従って unbounded な実行 stack を一つの source site に同一視せず、有限 diagram で安全に表示できる。

\begin{enumerate}
\item \textbf{同じ名・集合の輸送。}
恒等/既知 prefix edge は同じ名前 partition を保ち、指定した port の述語をコピーする。
\(B'_i(r)=f_i(B_1(r),\ldots,B_n(r))\) のような指定式は、各 named vector に \(f\) を適用する。
hidden vector は
\[
 e'_{\gamma}=\bigvee_{\beta:f(\beta)=\gamma}e_\beta
\]
とする。複数 input は最初から共同 diagram の全述語を入力にする。
追加の未知述語は各 vector の0/1の全 refinement を許す。
一つの非空 region が複数 region に分かれうる場合、非空の出力 region の任意の非空部分集合を許す。
これは cardinality を数えないことに対する上近似である。
\item \textbf{確保・forget・再観測。}
fresh は入力 support 全体と異なる点を追加し、旧 profile/receipt の membership は0、activity は1。
source receipt の新しい \(P/R/G\) だけを表の式で設定する。
register を忘れるとき、その最後の named point の vector を該当 \(e\) に加える。
再観測は非空 region の vector を持つ一点を named にし、残余 region の空/非空の両候補を出す。
まだ named な点との equality が指定される場合はその点を使用する。
candidate 列を忘れた後の再観測は、その失った列の全候補を作る。
\item \textbf{activity・束縛置換。}
entry/normal exit/検索のための suspension は、指定された現在の activation だけを更新する。
capture した frame-bound 集合は resume 時に fresh に一様改名し、free 名を固定する。
named な bound/free 判定と equality は保存する。
ここで一様というのは\emph{再開する packet とその解釈下の read の内部}で一様という意味である。
現在の resumer の ambient packet や、他枝で既に実体化した packet は作用範囲に含めない。
union interface の各 column/register に、saved 側か ambient 側かの有限 action tag を付ける。
同じ旧名 \(u\) が両側にあれば、saved の bound occurrence は fresh \(u'\)、ambient は \(u\) となる。
従って入力で等しかった二つの register を、作用範囲を無視して出力でも等しいと拘束しない。
同じ action の bound occurrence は全て同じ \(u'\) にし、別の bound 名および全旧 support とは不等にする。

hidden 点についても同じ構成を行う。bound な vector \(\beta\) は、
非作用側の列を持つ旧点 \(f_0(\beta)\) と、作用側の列を持つ fresh 点 \(f_1(\beta)\) を生む。
free な点は両側を保った一点になる。出力の region bit はそれぞれの像についての disjunction である。
旧点を同時に消す規則にはしない。共有 storage や元の continuation が旧点を保持しうるからである。
activity は旧 world と再開した frame の実際の active 集合から別に更新する。
hidden な bound 分類が表現されていない場合は、分類の全 refinement にこの構成を適用する。
最後に不要な register/column を forget する。
この有限操作は、hidden bound 名の置き去りと、ambient 側の破壊的な改名の双方を避ける。
receipt column の候補添字も同じ action に従って再索引する。
saved view と ambient candidate のように作用の異なる端点間の route は、
既知の具体対応が保持される場合以外は全候補とする。
旧 candidate と新 candidate の列を、同じ source label を持つことだけでコピーしない。
後の read は同じ置換を metadata 解釈に合成してから現在の activity を観測する。
\item \textbf{path と observation。}
同じ view の identity、実行した一つの prefix/除去、項にある primitive correspondence には
その witness が保証する座標式を課す。色の一致だけに基づく式は課さない。
frame の enter/leave は executing View の追加/除去であり、emission はその時の全 View の observation の union。
具体的な Path は値 packet の potential incidence から event incidence へのこの union と一致する。
抽象側は保持された incidence の列を Boolean union し、保持されない列は全候補にする。
static transfer の生成時に具体的な実行履歴を入力として要求するものではない。
有限 interface に残らない endpoint や合成 path の関係は全候補。
既知の direct receipt と、未知の古い route とを取り違えない。
\item \textbf{operation/branch。}
operation は指定した宣言・instance・origin の event seed を一つ作る。
branch は全構文 alternative を残す。scalar condition を評価して未検査 arm を削る規則はない。
scalar primitive は既出の \(\delta\) に従う constructor と component transport のみを返す。
\end{enumerate}

ここで「指定した座標式」は自由に追加できる注釈ではない。
使用できるものは identity、prefix/除去、source receipt、同時改名、現在の activity、
実際の lexical frame の phase/coverage、上の Boolean 集合演算だけである。
長い typed route がこの有限 interface に保持されない場合、その座標は未指定となる。
従って transfer 表を作るために一般の path inclusion 判定を要求しない。

\begin{lemma}[有限 transfer の表示保存]
上記の各具体的な metadata 操作 \(t\) とその有限 relation \(\widehat t\) について、
\(w,\bar v,q\models_I s\) かつ \(t(w,\bar v,q)=(w',\bar v',q')\) なら
\[
 \alpha_J(w',\bar v',q')\in\widehat t(s).
\]
新規 seed の場合は入力の event がなくてもよい。
\end{lemma}
\begin{proof}
Boolean 集合操作では、各具体点の出力 vector は入力 vector に \(f\) を適用したものになる。
named 点は直接計算され、hidden 出力 region が非空であることは上式の disjunction と一致する。
未知列による分割は、実際の非空出力 region 集合が列挙した部分集合の一つである。
forget は同じ点の表示位置を変えるだけ。
再観測の残余は実際に空か非空のどちらかなので、二候補の一方が表示する。
fresh は旧 support と不等であり、receipt 以外の old membership はない。
receipt は同じ source automaton と受領 slot を使うため、指定式と具体 Boundary/Receive が一致する。

activity の更新は機械の context 操作そのもの。
rename の実際の bound/free 分割は列挙する分割の一つである。
各旧点に対し、実際にそのまま残る occurrence と saved 側で fresh になる occurrence は
上記 \(f_0,f_1\) の二つの像と一致する。
named register の equality は action tag と fresh 条件から、hidden region の非空性は像の disjunction から得る。
後の read にも同じ作用を行うので、保存時にしか改名しない実装の穴は残らない。
path の指定式は実際の一段の辺の定義、残りは未指定の全候補に実際の座標を含む。
emission は handler を挟むかにかかわらず全 executing View を先に観測する。
観測の和に必要な保持されない相関も全候補に含まれ、都合のよい grant を一つ選ばない。
operation、branch、scalar の場合は指定された constructor/alternative を含む。
これで定義した全 metadata 操作を尽くす。
\end{proof}

\paragraph{この補題の限界ではないもの。}
\(S_I\) が有限であることは具体履歴が有限の大きさに抑えられることを意味しない。
実行の各有限 prefix は有限 graph だが、その大きさに一定上限はない。
表示保存は正確な商を要求せず、忘れた相関を全候補へ戻すことを用いる。
source の既知 operation を Unknown のために消すことはなく、
profile の存在から operation を生成することもない。

\section{有限の宣言的効果型付け}
\label{sec:refined-typing}

\subsection{値の情報と request の情報を分ける}

descriptor graph には二種の事実を置く。
\[
 \mathsf V(p,s),\qquad \mathsf E(p,s).
\]
\(\mathsf V\) は値・入力環境・pending query の packet が持つ diagram、
\(\mathsf E\) は実際の operation contribution の diagram である。
\(\mathsf V\) は効果ではなく、型付き値に元からある profile/latent graph の補助判断である。
例えば \(\Delay M\) の構築では \(\mathsf V\) があり、immediate \(\mathsf E\) は空である。
\(M\) の graph はその値の force port に結ぶ。
この区別をせず operation seed だけを伝播させると、
pure な callback が運ぶ受領情報を後の call まで保存できない。

各 code node の interface は、入力 packet、正常結果 packet、外向き event packet、
結果の全 latent port を持つ。saved context と closure 環境も有限 template により参照する。
各 port の abstract 値は \(\mathcal P(S_I)\)。
共同入力 \(\eta\) は row variable、値の入力 diagram、ambient observation、
ordinary witness の verdict を\emph{一つの assignment}として与える。
source type/profile が満たすべき等式は、この入力の整合性条件に残す。
Unknown の座標は全候補であり、\(\eta\) が選ぶ自由変数にしない。

\paragraph{正常結果 relation の意味。}
正常結果 port は、入力型に合う応答によって中断が再開された場合の結果も許す。
perform の応答 port は \(Q_o\) の型付き値の入力 diagram 全体である。
この port は「その request が必ず応答される」と主張しない。
型付けでは到達可能性を理由に後続 code を未検査にしない。
実行の正常値がこの port に含まれることは後の保存証明で導く。

\subsection{descriptor の意味}

元稿の descriptor を、有限の相互再帰を許した次の文法で読む。
\[
 E::=0\mid a\mid X\mid E\cup E\mid T(E_1,\ldots,E_k)\mid\mu\bar z.\bar E.
\]
\(0\) は空集合、\(a\) は指定した operation の seed 集合、\(X\) は共同入力 \(\eta(X)\)、
union は集合和である。\(T\) は上記の有限 relation の像であり、
\[
 \llbracket T(\bar E)\rrbracket_\eta
 =\{s'\mid \exists\bar s\in\prod_i\llbracket E_i\rrbracket_\eta.
       (\bar s,s')\in\mathcal R_T\}
\]
で定義する。tuple の joint 整合性も \(\mathcal R_T\) の条件である。
再帰変数は全て正に現れ、\(\mu\) は有限 power-set lattice の最小固定点。
同じ \(X\) は全 port で同じ集合を表す。
abstract Unknown は \(X\) の一種ではなく、既知座標と整合する全 cell の定数である。

positive closed row \([C]\) は、同じ instance witness の下で operation が \(C\) に属する
全 cell の upper set と解釈する。empty row は空集合。
negative row の permission は値 packet の profile/grant 座標であり、operation seed ではない。
value relation も同じ有限 relation image で表せるが、その事実を \(\mathsf E\) として出力しない。
\(\Phi\) は immediate と全 latent/reentry port のこの graph を保持する。

以下の表が effect 型付けの構文規則である。
edge は第\ref{sec:representation}節の有限 relation image、
連結は同じ binder の値/latent port への接続を意味する。
複数入力 edge では joint diagram の整合する tuple を全て使う。
型の列は前半の導出も同時に要求する。

\paragraph{型付けを有限 inclusion で定義する。}
この表から生成した有限 Horn graph を \(G\) とする。
\(U\) は各値/effect port に cell 集合を与える table である。
\[
 \Delta;\Gamma\vdash_d M:A!\Phi
\]
は、前半の型付き構文の導出、上記 \(d\)、各局所 relation の全 tuple に対する
Horn closure \(F_G(U)\subseteq U\)、および指定した全出力で \(U_E\subseteq\llbracket\Phi\rrbracket_\eta\)
を持つことと定義する。
自由な共同入力がある導出では、この inclusion を全整合 \(\eta\) に要求する。
formal input の seed は、宣言した型/profile の有限な等式を満たす\emph{全}入力 diagram である。
literal/constructor/operation の seed は対応する導入規則の全出力である。
これらを空集合へ任意に狭める選択は \(F_G\) にない。
宣言した function/thunk の code 契約は値の導入で検査し、diagram だけから code の正しさを推測しない。
型付き値は同じ定義の \(\mathsf V\) とその全 latent port を用いる。
annotation の upper obligation と Function 適合も同じ \(\eta\) の inclusion である。
入力 \(\eta\) を port ごとに選び直す規則はない。

特に Function の適合は、実際の source entry/profile を保った adapter 付き complete call と
target contract について、同じ generic whole-argument vector \(\bar x\) で
\[
 \forall\eta,\bar x\ \forall p\in\mathsf{OutputPorts}.\quad
 \mathsf{Call}_{S,a,r}(\eta,\bar x)_p
 \subseteq \mathsf{Contract}_{T}(\eta,\bar x)_p
\]
を要求する。\(p\) は結果の全 latent port を含む。
これは有限 relation/table の inclusion であり、任意の実行 trace を量化する判断ではない。
この検査を別々の \(E^-\) と \(E^+\) の比較に置き換える rule はない。

この定義は実行の安全性を前提にしない。
有限表の各行が生成する辺の閉包と inclusion だけを検査する。
最小固定点を求めることもできるが、保存定理は任意の post-fixed point について成り立つ。
従って solver の停止・完全性・主型性は不要である。
\(\mathsf V\) の rule に任意の \(\View_\chi\) を導入するものはない。
view は decoration、指定 transport、source receipt、同時置換からのみ作る。
前半の unrestricted view rule は実行型射影専用である。

\subsection{totality と shallow filter}

\(\mathsf{Total}(p,A)\) の有限導出は以下に限る。
Wild/Var、total な子の As、同じ shape/arity の全成分が total な tuple、
全要求 field が required または default を持ちその子が total な record、
閉じた nominal/variant の全 constructor を total payload pattern で覆う unguarded arm 列。
list は、全要素 pattern が total な arm について、rest なしなら長さ集合 \(\{n\}\)、
Wild/Var/As の total rest ありなら \(\{m\mid m\ge n\}\) を付ける。
\(n\) は prefix と suffix の要素数の和である。
これらの有限和が \(\mathbb N\) を覆う場合だけ全域とする。
これは最小の tail 下限 \(r\) を取り、\(0,\ldots,r-1\) の singleton が全部あるかを調べれば判定できる。
tail がなければ全域にはしない。これ以外の list pattern も実行・型付けするが、この totality rule からは証拠を得ない。
Lit/Ref、guard、open variant の現在見える tag 列だけからは total を導出しない。
default は正常に返るなら指定型を持つという通常の型付けを要する。

\begin{lemma}[totality の意味]
\(\mathsf{Total}(p,A)\) と \(v:A\) があれば、\(\mathsf{Match}_p(v)\) が
正常に No を返ることはない。unguarded な全域 arm 列は、全試行が正常に No となって尽きることはない。
発散、request、列挙した failure はこの命題に反しない。
\end{lemma}
\begin{proof}
totality 導出に帰納する。Wild/Var は Yes。
shape が固定した積では各子の帰納仮説により No の伝播枝に入らない。
record は presence または default の正常結果で子の入力を得る。
閉じた constructor の場合は値の形補題が必ず列中の tag とその payload を与える。
先行する partial arm が No でも、この全域の候補は残る。
guard がある場合を除外しているため、この最後の Yes を false guard が取り消す規則はない。
\end{proof}

候補の検索 world における cell 上で
\[
 \mathsf{Res}_h(U)=\{s\in U\mid
 \neg(\mathsf{Total}(h,\mathsf{inst}(s))\land\mathsf{Elig}_h(s))\}
\]
とする。operation arm の入力は同じ \(p:P_o\)、\(k:\mathsf{Kont}(Q_o,A;E_M^r)\)。
\(\mathsf{inst}(s)\) は宣言と同じ型引数 witness を持つ instance であり、単なる family 色ではない。
totality は、その instance に一致して試行される arm 列について検査する。
別 instance 専用の total arm を現在の coverage に流用しない。
handler 全体の event 義務は
\[
 \mathsf{Res}_h(E_M)\ \cup\ E_{\rm value\ attempts}\
 \cup\ \bigcup_o E_{\rm operation\ attempts}\ \subseteq E_{\rm out}.
\]
attempt の正常結果は Yes の \(B\)、No は次の試行へ接続する。
試行中の event は候補 handler の外側へ出す。
この filter は最終結果の集合の否定を取らず、\emph{一つの complete cell}に対する固定述語である。
従って入力 row に関して単調である。

\subsection{raw continuation の graph を有限に構成する}
\label{sec:cuts}

\(E_M^r\) を「安全な再開の効果」という未定義の意味で置かない。
source code graph の各 computation label を穴にした、型の合う\emph{評価 context の文法}を作る。
terminal frame は前半の六種、すなわち bind、scope、View、handle、mapop、wait である。
code label、穴の型 node、全体の型 node、mode を非終端記号の添字とする。
wait の添字には有限 arm index と pending operation 宣言を追加する。
型は有限 template graph の node であり、scheme では同じ型代入を添字全体に適用する。

生成規則は、構文の active child から親へ進む辺ごとにその frame を追加する、というもの。
bind では残りの body label、handle では未選択 handler の label、
wait では保存した元 event と残りの arm 列の interface を保持する。
再帰呼出しは同じ非終端記号への辺。
選択された handler の scrutinee の出口で止め、その handler frame は追加しない。
外へ転送する場合にはその handler frame を追加する。
imported callable の内部 suffix は、その値型の reentry port を一つの terminal summary として使う。
その port を持つ値の導入にも同じ規則を課すため、未検査 code の summary ではない。

frame は、穴の値/event/latent port の有限 lattice \(L\) から親の lattice への
単調関数を表す。異なる interface は有限共通 interface へ埋め込み、不要座標を forget する。
bind は穴の結果を body input へ結び、event は bind の request 伝播へ結ぶ。
scope は現在 activity と保存束縛の transfer、View は observation と結果 path の別々の transfer。
handle は上記 filter と attempts の接続。
mapop は payload/response code と同じ \(w\) の接続。
wait は attempt の event と、No の場合の残りの検索、Yes の正常結果を接続する。
pending event は \(\mathsf V\) に保存し、No の先で元 event として再び検索に渡す。
新しい operation として seed し直さず、元の emission 観測を保つ。
検索を再開するとき activity/eligibility は\emph{その時点}で再観測する。

各 grammar rule の summary は関数の合成と pointwise union。
有限 lattice 上の単調関数は有限個なので、この連立 inclusion には最小固定点がある。
これを \(\mathsf{Cut}_{i,j}\) とする。
code の port table と cut summary が相互参照する場合は、両者の有限な積 lattice で同時に閉包を取る。
関数の合成は関数順序の両引数について単調で、filter の条件は固定 cell 上で決まるため、
この同時作用素も単調である。未検査の \(E^r\) を先に仮定してから body を検査する循環ではない。
各 response 型 \(Q\) の穴に、event が空で \(Q\) の入力値 diagram を持つ \(\Ret z\) を入れ、
normal、restored-bound、inactive-free の各 mode の関数を適用した出力の union が \(E_M^r\) である。
不明な boundness/activity/path は前節の全候補 relation を使う。
saved environment は保存した型/profile を持ち、現在の read と ambient View は再観測する。
再開前の実行を replay する定義ではない。

この構成も元稿の有限 graph 表現の範囲に入る。
有限 power-set lattice 上の単調関数 \(f\) は、出力 bit ごとに
\(b\in f(X)\) となる入力集合 \(X\) の最小要素を列挙し、
\(\bigwedge_{a\in X}a\Rightarrow b\) という有限 Horn 規則で表せる。
再帰する summary は graph の \(\mu\) 辺になる。
一般の無限 trace の inclusion を問い合わせる箇所はない。
関数 table の大きさは大きくなりうるが、ここで必要なのは明示的な有限構成と保存である。

\begin{lemma}[切出した context の表示]
型付き計画の実行で request が有限個の frame を越えて得る raw continuation \(K\) は、
その capture 出口の上記 grammar に導出を持つ。
任意の admissible response packet と現在の world で、その suffix の全局所義務は
\(\mathsf{Cut}_{i,j}\)、従って \(E_M^r\) に含まれる。
\end{lemma}
\begin{proof}
request 生成時の continuation は恒等で、穴の \(\Ret z\) の規則である。
次に越える frame は六種のいずれかで、機械の request 伝播規則と grammar の生成規則は同じ。
従って伝播した frame 数への帰納で実際の有限 frame 列の導出を得る。
その列の summary は各 frame 関数の合成であり、grammar の post-fixed point に含まれる。
この事実は関数順序の定義から、\emph{全ての}穴の入力に成立する。
bound/free の実際の分類は三 mode と Unknown の全候補に含まれ、
同時改名・現在の read は有限 transfer の表示保存に従う。
未選択の handler は frame として残り、選択した handler と外側の View は grammar の出口の外にある。
従ってそれらを誤って \(K\) に追加する導出は不要である。
wait の場合も元 query の packet は閉じた値であり、保存した観測と現在の activity で再検索する。
再帰により frame 列が長くても、この帰納は各有限 capture について成立する。
\end{proof}

\paragraph{単なる row のコピーでは不十分である。}
\(E_M^r:=E_M\) としたり、作成時の activity を継続へ固定したりする定義は採らない。
guard の request で中断し、free owner が終了した後に再開した場合、
失敗した guard の先の元 query は、変わった eligibility で再検索される。
その event は元の normal mode では除去され、reentry mode では残ることがある。
上記の cut graph はこの場合も元 event を捨てずに表示する。
継続を後で呼ぶ式は \(E_M^r\) の Call/Resume 義務を持つ。
これを元の immediate row だけで検査することは、元稿の retained reentry 契約にも反する。

\section{効果・profile を含む保存と進行}
\label{sec:full-proof}

\subsection{置換、共有、frame の補題}

\begin{lemma}[精密な項置換と graph 拡張]
\(\Delta;\Gamma,x:A\vdash_d M:B!E\)、\(\Delta;\Gamma\vdash_d v:A\) なら、
同じ共同 assignment の下で \(M[v/x]:B!E\) が導出できる。
全 free metadata と型を固定した well-typed immutable graph の拡張でも導出は保存される。
\end{lemma}
\begin{proof}
実行型部分は既出の置換補題。
精密な規則は変数の値/latent port を、その変数の契約を満たす値の port で置き換える。
各規則は relation image、union、共同 tuple の存在量化、fixed cell filter のいずれかであり、
いずれも入力集合に関して単調である。
従って formal に許した集合の部分集合を接続しても既存 inclusion を破らない。
同じ \(x\) の複数使用は同じ packet と row assignment を参照し、
コピーごとに外来 owner や profile を freshen しない。
handler case の filter は complete cell ごとの固定述語なので、ここでも単調性が使える。
lambda/delay の body と結果の全 latent port に同じ帰納仮説を適用する。
rec では有限 graph の全 binder を同時に置換する。
古い node の型・code・metadata が変わらないので、その局所 inclusion も変わらず、
新しい node の導出だけを付加することができる。
\end{proof}

\begin{lemma}[名前と型 instance の一貫性]
bound owner/handler 名への injective renaming は、decoration、具体 query、
表示関係、全 graph inclusion と可換する。
qualified scheme の一つの instance は、その instance の全 ordinary 条件を満たす
同一の型・row・dictionary 代入の下で導出を持つ。
\end{lemma}
\begin{proof}
名前について、各具体規則が使用するものは sort、equality、membership、
scope の束縛関係、同じ template の path である。
injective renaming はこれらと非空性を保存する。
従って cell の座標名を変えるだけで finite relation の各 tuple が対応する。
union、合成、post-fixed-point inclusion もこの対応を保つ。

型 instance については単なる名前の改名を用いない。
型付き導出の template へ同じ代入を施し、必要な型 node と port を展開して
その有限 instance の \(d,G\) を構成する。
変数・Ret・identity transport は代入型の全 component/latent packet をそのまま運ぶ。
tuple/record/nominal と pattern は宣言 payload template の同時置換、
function は同じ generic 入力と出力への同時置換、operation は同じ \(P_o,Q_o\) への置換である。
抽象型変数のままでは許されなかった projection を新しく導出する必要はない。
新しい shape を見る必要がある dictionary/code は、qualified 条件に含まれるその instance の導出を使う。
新しい座標について古い signature が表現しなかった関係は全候補へ lift する。
すなわち忘却 \(\rho:S'\to S\) に対して \(U\) は \(\rho^{-1}(U)\) に移り、
既存 inclusion は逆像により保たれる。新しい latent port は代入型の契約と構造規則から得る。
ここで必要な局所条件は、同じ primitive の拡張 relation \(\widehat t'\) に対して
\(\rho(\widehat t'(\rho^{-1}(U)))\subseteq\widehat t(U)\) である。
これは座標式ごとに確かめられる。既知の identity/prefix/fresh/receipt 式は同じ代入を両端に行い、
新しい shape の関係は旧側の未指定座標の全候補に落ちる。
operation 宣言と既存 query の条件は同じ qualified instance を用いる。
新たな family 色は旧 \(\star_O\) へ、追加された path 座標は旧 unknown へ忘却する。
忘却は各既存 query の \(P/R/G\) を対応する追加列の和で表し、その query の真偽を保持する。
cut summary についてもこの包含を合成・union に帰納して保つ。
これで型付き規則への帰納を行える。
古い signature の truth table が任意の構造代入とそのまま可換する、という主張は使わない。
\end{proof}

scheme の一般化では free 環境・捕捉値・共有 resource・profile の dependency closure と
交わらない binder だけを量化する。
reference read は新しい scheme instance を作らず、同じ monomorphic protocol の値を得る。
同じ graph の名前変更が本補題の前半、構造的な型の instance が後半である。
両者を混同しないことが、同じ storage を異なる型や異なる外来 owner として読むことを防ぐ。

\begin{lemma}[精密な frame 合成]
各六種の frame \(f\) の穴へ、その入力の型・値・event・latent inclusion を満たす導出を入れると、
\(f\) の有限関数が与える出力契約を満たす導出を得る。
frame の有限列については関数の合成が対応する。
\end{lemma}
\begin{proof}
bind は精密な項置換により結果を body へ渡す。
穴の request は元 event と body suffix を持つ continuation へ移り、event の伝播 edge に対応する。
scope は入退場または suspension の activity 関係と同じ bound 名の保存、
View は実行中の観測と結果 path の別の関係である。
handle は次の handler 補題、mapop は payload/response の各普通の導出を bind で合成する。
wait は閉じた pending packet と attempt の結果を持ち、Yes は値、No は残りの query への edge を使う。
いずれも前半の frame typing と第\ref{sec:refined-typing}節の生成規則そのものに対応する。
列については長さへの帰納法で合成する。
handler 補題はこの補題の handle case を用いず、query の正確性と totality から直接示すので循環しない。
\end{proof}

\subsection{handler、停止と再開の補題}

\begin{lemma}[handler の event 保存]
現在の query cell \(s\in E_M\) を持つ \(q\) に対し、
\(\Handle_h\) の直接の選択・転送は上記 filter と attempts の edge に表示される。
正常に失敗した attempt の後の検索も表示される。
attempt が request を出して中断した場合、その残りは cut-context graph に表示される。
\end{lemma}
\begin{proof}
query の正確性により、具体的な eligibility は \(\mathsf{Elig}_h(s)\) と同じ。
偽なら元 event を転送し、\(s\in\mathsf{Res}_h(E_M)\)。
真の場合は一致する arm を source 順に試す。
全域でなければ filter は元 event を残し、全 No の転送も覆う。
全域なら totality 補題により全試行が正常に No で尽きる場合はない。
Yes はその body の結果、途中の request/failure/発散はその attempt の普通の port に属する。
従って全域かつ eligible な元 event を除くことは正しい。

中断を伴わず No が返る場合、元 event の Observe は既に固定されている。
以後の Flow 辺は fresh occurrence に向かうので、元の observed endpoint に戻る
新しい Boundary--Receive--Observe route を作れない。
正常な attempt の call/scope は自分の activation だけを入退場し、
呼出し元の query context の既存 activation を終了させない。
従って元 query の Path と、復帰した search context での既存 owner の activity は変わらない。
同じ filter の下で残りの arm を試せる。共有値の更新は残るが、元 event の観測を変更しない。

中断がある場合は wait frame が元 \(q,p,K\) と arm index を保存する。
再開時の同時置換と read の現在観測は finite transfer に表示される。
現在の activity が元と異なる場合、normal row を流用せず、cut graph の wait 関数で
元 query を再検査する。従って inactive free owner による eligibility の変化も表示される。
ここで使用するのは cut grammar の局所構成であり、まだ全体の実行安全性を仮定していない。
\end{proof}

\begin{lemma}[精密な raw resumption]
切出しで作った \(K:\mathsf{Kont}(Q,A;E_M^r)\) と \(v:Q\) があれば、
\(\Resume(K,v)\) は値型 \(A\) と reentry port の契約を持つ。
同じ \(K\) の任意回の使用にこの導出を再利用できる。
\end{lemma}
\begin{proof}
切出した context の表示補題から、実際の frame 列の関数は cut summary 以下である。
response の契約をその穴へ項置換する。
bound 名は今回の fresh 名へ一様に変え、free family/resource/owner を固定する。
この作用は saved packet 内で行い、resumer の ambient packet には行わない。
名前の補題と action tag を持つ有限 transfer の表示保存により、この枝の全 packet は同じ summary に表示される。
今後の共有 read もその置換を合成するため、保存した local だけの複写に依存しない。
selected handler は frame 列に存在せず、unselected handler は存在する。
別枝を開始しても保存した code と packet は変化しない。
二枝の実際の名前は異なっても、それぞれ同じ source の summary の一つの instance であり、
effect upper bound は同じ冪等 union に含まれる。linear な使用条件は必要ない。
\end{proof}

\subsection{一段の simulation を状態について述べる}

実行状態の精密な型付けは、以下の\emph{現在の有限な証拠}からなる。
\begin{enumerate}
\item 値 graph と active code の実行型導出。
\item 各 code label にある精密な局所導出と、その自由値の同じ型付き instance。
      再帰参照は同じ有限 graph の参照である。
\item active/saved frame の、上記 grammar における導出。
\item 現在使用する interface の実際の diagram が、その入力 \(\mathsf V\) 集合に属すること。
      発生済みまたは pending の event は、その現在の event/query port の集合に属すること。
\end{enumerate}
heap 内の全値に古い activity の snapshot を要求しない。
保存するのは immutable な型・profile と解釈置換であり、次にその値を使用するとき
reobserve relation を通して現在の interface の事実を得る。
この状態判断には「今後安全に実行できる」という条件はない。

\begin{theorem}[精密な一段保存と表示 simulation]
上記の状態判断を持つ \(C\) が内部で一段進んで \(C'\) になるとき、
\(C'\) は同じ型付き derivation graph の残余、またはその明示された latent/reentry port の instance として
状態判断を持つ。値型は \(A\) を保ち、各現在 port の concrete diagram は宣言した abstract 集合に含まれる。
immutable graph の fresh extension と束縛名の一様な改名を許す。
\end{theorem}
\begin{proof}
縮約規則の最後の形で場合分けする。
\begin{enumerate}
\item \textbf{Ret/bind、構造除去、分岐。}
値の形と精密な項置換を使う。実際に選んだ branch は全 alternative の union にある。
値の projection/transport は有限 relation に表示され、graph closure により次の入力事実がある。
No から次の arm に移る場合も同じで、未成功の binder を参照しない。
\item \textbf{literal、構造導入、scalar primitive、rec。}
固定 constructor と各 component の relation を使う。
primitive の正常 constructor は既出の全62 case の補題、失敗は列挙した \(\Fail\)。
rec の新 node は同時置換と graph 拡張で型付きとなる。
これらの値導入は \(\mathsf V\) を作るが、存在しない event seed を作らない。
template 参照の場合は、code 表の精密な導出に型・値の引数を同時置換する。
再帰的な table 参照の graph は back edge であり、有限 prefix の帰納を妨げない。
\item \textbf{Call/enter/wrap、Force。}
call graph は機械と同じ一つの owner、inert carrier、receipt、entry の順序を持つ。
その後の body/result consumer/adapter も同じ bind edge である。
引数や結果 adapter が operation を起こす場合はその code の通常の port を通り、
この case だけで効果を0と仮定しない。
force/call は current-world reobserve と実際の View enter を使用する。
closure の導入時に示した全共同入力の inclusion を、この実際の入力に適用できる。
\item \textbf{perform と observation。}
型の合う payload と同じ family instance の seed がある。
実際の active context 全体から作る Observe は finite transfer の出力候補に含まれる。
graph closure がその cell を event port に含める。
初期 continuation は恒等であり、切出し grammar の base case である。
\item \textbf{request の伝播、scope、View。}
越える frame に対応する grammar rule と finite transfer を使う。
scope の suspension は normal exit と区別され、saved bound set を保存する。
event の Observe を bubbling の時点で作り直さない。
View の正常値は result path、request は保存 context の View という別の rule を使う。
\item \textbf{handle/try/wait。}
直前の handler 補題が元 event の除去/転送、attempt の新 event、No/Yes の遷移を全て覆う。
wait が新しい request で中断する場合は、閉じた pending packet を持つ frame の切出し規則を使う。
\item \textbf{resume。}
精密な raw resumption 補題を適用し、その明示された reentry port を active code に接続する。
saved code を直接 normal-entry の row で再検査する必要はない。
\item \textbf{mapop。}
payload code の導出を bind し、元 event の instance を同じ \(w\) で運ぶ。
response の port には逆方向の code と元 \(K\) の suffix を bind する。
payload/response の code が出す別 event は mapper 自身の外側の通常 port に属する。
両方向の code と free owner を独立に instantiate しない。
\item \textbf{型適用と failure。}
同じ qualified instance の置換補題を使う。
failure は既出の frame 伝播である。\(\Bad\) に到達する case は実行型保存と値の形が排除する。
\end{enumerate}
active child の一段には縮約導出の帰納仮説を使い、精密な frame 合成で親へ戻す。
すべての concrete metadata successor は有限 transfer の表示保存を満たし、
その全 tuple は \(F_G(U)\subseteq U\) の検査対象である。
従って出力 cell の包含を新しい前提として仮定する必要はない。
以上で全通常形と administrative form を尽くす。
\end{proof}

\subsection{推論器を前提にしない全型健全性}

\begin{theorem}[全構文の値・効果・衛生性の健全性]
\label{thm:full-safety}
有限の宣言表、型付き graph、明示的な導出
\(\Delta;\Gamma\vdash_d M:A!\Phi\) を固定する。
閉じたプログラムでは \(\Gamma=\varnothing\)。開いたプログラムでは、
\(\Gamma\) に同じ精密な型の値を代入し、一つの共同 assignment が全 qualified 条件を満たすものとする。
root の開始前の raw metadata は空、または同じ導入/transport 規則による型付き interface から供給する。
root entry は上記の一つの fresh owner と空 profile を作る。
機械の eligibility は第\ref{sec:concrete-eligibility}節の具体 query に固定する。
任意の有限な内部実行 prefix について、次が成り立つ。
\begin{enumerate}
\item 現在の code/value/request/continuation は所定の精密な残余契約を持ち、\(\Bad\) に到達しない。
\item 正常結果は \(A\) を持ち、含まれる closure/thunk/reference の全 latent 契約も保存する。
\item 各 immediate port から外へ出る request の complete cell は、その port の \(\Phi\) に属する。
      returned latent value や raw continuation を後で実行した場合は、
      その値に保持された call/force/reentry port の同じ主張を得る。
\item 具体的な処理/転送は、元の source receipt、authentic typed path、現在の activity、
      同じ operation instance による query に従う。
      型適合、alias、scope の停止、resume は外来 grant を現在 owner の grant に作り替えない。
\end{enumerate}
従って、初期の immediate upper が空なら、その計算の外へ request は出ない。
発散と明示した言語 failure は許される。
\end{theorem}
\begin{proof}
初期状態は構文導出とその input diagram によって状態判断を持つ。
prefix 長に帰納する。内部の一段は精密な一段保存を適用し、
fresh graph extension、同じ assignment、残余 port の導出を保持する。
最外で正常値が出たら Ret の値/latent 規則から2を得る。
最外で request が出たら、その cell は現在の event port の \(U_E\) に属し、
型付けの最後の inclusion \(U_E\subseteq\llbracket\Phi\rrbracket\) から3を得る。
caller が型付き response を渡して再開する場合も、raw resumption の導出を
その caller の Call/Resume port へ接続し、同じ帰納を続ける。
型付き host response についても、この response が latent code を持つ場合は
その精密な導出を要求する。内部 code の安全性を host の約束へ移すものではない。

進行は前半の値の形と具体 query の停止性から従う。
最外は Ret、型付き Req、列挙した Fail、または次の一段を持つ。
4は具体 query の定義、decoration の Boundary 導入箇所、同時改名の補題から従う。
grant を導入できるのは source receipt だけであり、他の規則は既存 evidence の輸送である。
空集合に request の cell は属せないので pure の帰結を得る。
無限実行に初めての違反があればその有限 prefix に上の帰納が適用され矛盾する。
\end{proof}

\paragraph{保存している対象。}
ここでの \(A!\Phi\) は元稿の whole packet であり、表示された family の集合だけではない。
同じ \(\nu\)、source profile、全 latent port、reentry graph を保つ。
step 後に読むのはその graph の現在の残余 port である。
escaped continuation の呼出しに元の creation-time immediate row を流用する、という誤った保存命題は含めない。
この区別は定理を弱めるための例外ではなく、元稿が明示した \(k:Q\to(A!E^r)\) の型規則そのものである。

\subsection{規則から得られる四つの判別計算}

以下は実装を実行した結果ではなく、上記規則の直接の導出である。
全候補への近似が必要ない、名前と direct correspondence が interface に残る場合を用いる。

\paragraph{permission は operation を作らない。}
pure な provider の event port は0である。
negative \([io]\) receipt は \(\mathsf V\) の grant を作るが、\(\mathsf E\) の seed を作らない。
従ってその provider を force/call した port も、他の code に seed がなければ0のままである。
Computation entry の \(\lambda x.\Ret 0\) は引数の latent port に接続せず、
\(\lambda x.\Force x\) はそこへ接続する。
Value entry の body が \(b\) を持つ場合は
\(\mathsf{Call}_S(X)=X\cup b\) なので、target の \(b\cup X\) と同じ共同入力で inclusion が成立する。
ここから \(X\subseteq0\) は生成されない。

\paragraph{omission と local grant。}
active な候補 owner \(u\) に届く一つの actual \(io\) cell で、
\(\mathsf{Prot}=1\)、omission の \(\mathsf{Grant}=0\) なら eligibility は偽、event は残る。
同じ direct port の \([io]\) receipt により \(\mathsf{Grant}=1\) なら、
total arm がある場合にその cell だけを除去できる。
別 owner の helper には \(G(io,u)\) を \(G(io,u')\) として読む規則がなく、同じ除去はできない。
owner が inactive の場合は eligibility の外側の conjunct が偽となる。

\paragraph{返却値の latent effect。}
\(\Ret(\Delay(\mathsf{perform}_{choose}()))\) の immediate port は0、
結果の force port は \(choose\) seed を含む。
この値を返すだけの catch は、その latent port を fixed filter に通さない。
後で force する式が、その時点の View/activity と handler の下で同じ seed を処理する。

\paragraph{共有された旧名と二回の再開。}
stored view が capture 前の bound 名 \(u\) を保持するとする。
第一枝の置換を \(\theta_1(u)=u_1\)、第二枝を \(\theta_2(u)=u_2\) とすると、
\(u,u_1,u_2\) は全て異なる。
\[
\begin{array}{c|c|c}
 & \text{第一枝の観測}&\text{第二枝の観測}\\\hline
\text{元の stored view }u&u_1&u_2\\
\text{第一枝で実体化して保存した }u_1&u_1&u_1\\
\text{resumer の ambient view }u&u&u
\end{array}
\]
一行目は future read にも作用する置換、二行目は既に free な名の固定、三行目は action 範囲の区別である。
保存時だけのコピー、global な破壊的 rename、入力 equality の無条件な保存は、この表のいずれかを破る。
本稿の action tag と hidden-region の二つの像は、この三行を同時に表示する。

\section{型コンストラクタにおける rank-2 の利用}
\label{sec:rank2}

\subsection{格納する多相性と、コンストラクタ自身の多相性}

単に constructor の型を外側で一般化するだけでは、格納 field は多相にならない。
例えば、次は異なる宣言である。以下は型付き核の数学的表記であり、
未採用の declaration spelling を現行 source syntax として示すものではない。
\[
\begin{array}{ll}
 D_1\langle\alpha\rangle\text{ の payload}:&F(\alpha,0,0,\alpha;\pi_0,\mathsf{Value}),\\
 D_2\text{ の payload}:&\forall\alpha.
       F(\alpha,0,0,\alpha;\pi_0,\mathsf{Value}).
\end{array}
\]
\(D_1\) の一つの値の payload を取り出すと、その値で固定された一つの型の関数を得る。
\(D_2\) では同じ payload を \(\mathsf{int}\)、\(\mathsf{bool}\) で別々に型適用できる。
その constructor を callable として表すと、引数の位置に全称型を持つ。
これが本節で明示的に含める rank-2 の基本例である。
effect の0はこの例の choice であり、一般の多相 payload の body は effectful でもよい。

さらに、型引数へ多相型を直接置く
\(\mathsf{Box}\langle\forall\alpha.F(\alpha,0,0,\alpha;\pi_0,\mathsf{Value})\rangle\)
も、明示された型付き核では扱う。
通常の型変数を全称型で instance 化するこの形は、格納 field の rank-2 と区別して
\emph{明示的な impredicative instance}と呼ぶ。
rank-2 という呼称だけから任意の impredicative 推論を要求したことにはしない。
本節は両方の実行健全性を与えるが、無注釈の higher-rank 推論、主型性、
どこに型適用を挿入できるかの完全な探索は主張しない。

\subsection{宣言・型抽象・構築・取得の規則}

宣言表の一つの nominal constructor を
\[
 \D(c)=\forall\bar a.\ S_c(\bar a)\longrightarrow D\langle\bar a\rangle
\]
と書く。\(S_c\) は既存の値型文法であり、record/tuple の子、function の引数、
nominal の型引数にも \(\forall b.B\) を含めてよい。
これは型の syntax を追加する操作ではなく、第\ref{sec:types}節の文法の許された使い方を固定する。
constructor ごとの payload は一つの template とし、別々の field に無関係な代入を使わない。
型演算子への beta reduction や暗黙の型等式は導入しない。

\(\Psi\) は保持している scope/view の型付き環境、\(\Xi\) は共有 graph の型環境とする。
型抽象・型適用の規則を精密な判断について次のように明示する。
\[
 \frac{\Delta,a;\Gamma;\Psi;\Xi\vdash_d v:B
       \quad a\notin\fv(\Gamma,\Psi,\Xi,\D)}
      {\Delta;\Gamma;\Psi;\Xi\vdash_d\Lambda a.v:\forall a.B}
 \qquad
 \frac{\Delta;\Gamma;\Psi;\Xi\vdash_d v:\forall a.B\quad\Delta\vdash T\ \mathsf{type}}
      {\Delta;\Gamma;\Psi;\Xi\vdash_d v[T]:B[T/a]}.
\]
\(v\) は値である。\(\Lambda a.M\) に一般の計算 \(M\) を入れる規則はない。
\(B\) の call/force 契約は全て抽象内部の導出で検査する。
型適用は値、row、family instance、profile、captured environment、
関連型、解除の scope 対応を含む\emph{全 packet}への一つの型代入である。
型適用自体が新しい receiver、保護 scope、reference、event を作ることはない。
実行時に存在する free な identity はそのまま共有する。

nominal の導入・除去は次である。
\[
 \frac{v:S_c(\bar T)}{c_{\bar T}(v):D\langle\bar T\rangle}
 \qquad
 \frac{v:D\langle\bar T\rangle\quad
        (\Gamma,x_c:S_c(\bar T)\vdash_d M_c:B!E_c)_c}
      {\mathsf{switch}(v,\{c(x_c)\mapsto M_c\}_c):B!\bigcup_c E_c}.
\]
effect/transport の辺は構造導入・除去の既存の辺であり、
constructor tag の判定は全称型の内部を検査しない。
source の引数が計算なら、通常の Value entry で carrier を一回 force してから格納する。
その計算の効果を constructor が純粋な値であることを理由に消さない。
record field の取得と pattern binder も同じ規則で、field 型に書かれた
\(\forall\) を保持する。取り出し時に単相の fresh metavariable に置き換えない。

\paragraph{注釈を検査する宣言的規則。}
期待型が \(\forall\bar a.B\) である明示された値 introduction は、
\(\bar a\) を fresh rigid として body を検査し、上記の型抽象へ elaboration する。
既に \(\forall\bar a.B\) を持つ変数・field はそのまま格納できる。
単相値を、存在する一つの instance に適合したことだけで全称型へ昇格させない。
全称型から特定の型で使う導出には、使用する \(\bar T\) とその全 qualified 義務を明記する。
ordinary source の型適用挿入はこの導出を見つける仕事であり、実行定理の前提ではない。

\begin{lemma}[全称 payload の構築・取得・置換]
\label{lem:rank2-payload}
上記の有限な導出は、全称型が任意の宣言済み payload/型引数位置にある場合にも、
実行型、全 latent 契約、同じ代入に結び付いた scope/view を保存する。
\end{lemma}
\begin{proof}
型抽象導入では \(a\) は rigid で、free な環境・共有 graph の型に現れない。
従って任意の well-formed \(T\) に対し、body の有限導出へ capture-avoiding に
\([T/a]\) を施せる。forall case では内側 binder を先に fresh にし、
\(T\) の自由変数が捕捉されないようにする。
constructor と field case は同じ payload template への代入となる。
function/operation case は input、output、family の全出現に同じ代入を施す。
共有 graph は \(a\) を含まないので変更されない。
精密な effect 部分は第\ref{sec:full-proof}節の型 instance の補題を用い、
増えた座標をその型の契約で構成し、失われた相関を全候補へ lift する。
\(T\) が全称型でもこの構文帰納は同じであり、型変数を実行時に検査する case はない。

型適用の redex は
\((\Lambda a.v)[T]\longrightarrow v[T/a]\) で、今の置換が型を与える。
nominal elimination の redex は
\(\mathsf{switch}(c_{\bar T}(v),\bar M)\longrightarrow M_c[v/x_c]\) である。
導入の inversion により \(v:S_c(\bar T)\)、項置換により結果の型を得る。
\(S_c\) の全称 binder はこの項置換で instance 化されない。
metadata は prefix/除去の対応で運び、元の identity を固定する。
この二つ以外の新しい実行 redex はない。
\end{proof}

\paragraph{共有 reference と一般化。}
\(\mathsf{Ref}(\forall a.B)\) は、一つの固定された多相値型を格納する monomorphic reference として
扱える。それは \(\forall a.\mathsf{Ref}(B)\) を同じ一つのセルから作れることを意味しない。
型 \(\mathsf{Ref}(a)\) の既存セルを捕捉して \(a\) を一般化しようとすると、
\(a\in\fv(\Gamma,\Xi)\) となり型抽象導入が失敗する。
効果を伴うセル生成を値であるかのように \(\Lambda\) の外へ出す規則もない。
\(\Lambda a.\Delay M_a\) は許されるが、セル生成は各 force の実際の計算に残る。
constructor の内側であることは値制限や dependency closure の例外にならない。

\paragraph{同じ payload を二つの型で使う例。}
\(i=\Lambda a.\lambda^{\mathsf V,\pi_0}x.\Ret x\) とし、
\(p=c(i):D_2\) を作る。\(p\) を一回 switch して得た \(g\) に対し
\[
 \mathsf{let}\ n\leftarrow\Call(g[\mathsf{int}],\Delay(\Ret 1))\ \mathsf{in}\
 \Call(g[\mathsf{bool}],\Delay(\Ret\mathsf{true}))
\]
は \(\mathsf{bool}!0\) を持つ。\(g\) は同じ値であり、二つの型適用は別の型代入である。
捕捉している外来 scope は別の scope に作り替わらない。
\(D_1\langle\mathsf{int}\rangle\) から得た単相の関数には、この二つ目の適用の導出がない。
この判別が、外側の let-generalization だけでは代用できない理由である。

\section{カンマで書く混合 effect row}
\label{sec:mixed-row}

\subsection{区切りと意味の分担}

既存の BracketRow 文法は、item 間に comma、semicolon、qualifying newline を許す。
これは反変位置でも同じであり、\texttt{[undet, 'e]} を
\texttt{[undet; 'e]} に書き換えてからでなければ読めないという制限は置かない。
参照：\nolinkurl{syntax-reference/ja/src/types/bracket-row-grammar.md} 第2節。
bare bracket row と standalone \texttt{'[...]} は別の構文である。
\texttt{'e?} は次節の release marker として意味を持ち、ordinary identifier の末尾文字として
読めるという tokenizer の事実だけでその意味を与えたことにはしない。

well-formed な row の elaboration は、まず source span を保持して区切りを除いた
\emph{順序付き item 列}を作り、各 item を同じ名前環境で解決する。
concrete family、共有 abstract component、release marker をその解決結果で区別する。
最後の item であることやセミコロンの右側であることを tail 判定に使わない。
この規則は separator の違いだけを消す。item の並べ替え、binder の freshening、
row の吸収等式、family 引数の分散はここからは導かない。

\subsection{反変の具体成分と共有成分}

\(C\) を concrete item の集合、\(X_1,\ldots,X_n\) を共有 abstract component とする。
polarity は source 型全体から合成し、function argument 辺で反転する。
\(\forall\) binder と構造 field 自体では反転しない。
nominal の表現との対応は既存の宣言済み mapper/variance evidence に従う。
不変な位置を勝手に共変として走査することはない。

\begin{longtable}{p{.25\textwidth}p{.67\textwidth}}
\toprule row の位置 & elaboration が保存する義務 \\
\midrule\endhead
negative \([C,\bar X]\) & 実際の流入 packet と各 \(X_i\) の共有制約を保持する。
当該 source receiver/typed port に \(C\) の local permission を構成する。
\(C\) だけから流入 event を生成せず、入力全体を \(C\) に閉じない。\\
positive \([C,\bar X]\) & concrete allowance と同じ \(X_i\) の出力契約に対して
実際の contribution を検査する。concrete allowance 自体は operation の発生ではない。\\
\(X_i\) & 同じ binder、同じ assignment、同じ dependency を参照する。
concrete permission の収集から外すことは、その制約を消すことではない。\\
\(X_i?\) & 同じ abstract contribution を保持し、第\ref{sec:release}節の scope 対応と
実際の crossing に基づく保護変換を加える。row の省略可能性ではない。\\
\bottomrule
\end{longtable}

従って反変の \texttt{[undet, 'e]} は、resolved family \texttt{undet} に対する
局所的な処理許可と、共有された \texttt{'e} の契約を同時に持つ。
\texttt{undet} を綴りだけで特別扱いするのではなく、他の family と同じ解決規則を使う。
処理許可は、その効果が実際に流れることや handler が必ず消費することを意味しない。
具体成分と \(X_i\) の matching family instance の適合条件も、同じ型代入・境界証拠の下に残す。
\(\bar X\) から自動的に \(C\) を集合差で引く rule はない。
実際の shallow catch では全域性・eligibility・arm body・raw reentry の既存の規則を使う。
承認済みの deep-handler 例での residual と、shallow handler の後続 request を混同しない。

参照：\nolinkurl{notes/design/2026-10-10-annotation-effect-hygiene-integration.md}
第1節および後続の明確化、ならびに
\nolinkurl{questions/2026-10-05-function-effect-row-denotation/approved-answer.md}。
元の field/payload に入る mixed row も、その型付け導出の source occurrence を保ったまま走査する。
rank-2 の型適用で別々の port に独立の \(X_i\) を生成しない。

\begin{lemma}[separator 正規化の保存]
同じ解決環境、同じ item 列、同じ annotation occurrence の対応を持つ二つの well-formed row が、
区切りとして使った comma/semicolon/newline だけ異なるなら、その elaboration は
source span の対応を除いて同じ型・permission・scope 対応・計画を作る。
\end{lemma}
\begin{proof}
区切り除去の結果は同じ item 列である。名前解決と polarity は区切りを引数に取らない。
item 列への帰納で concrete、abstract、marker の各結果が一致する。
後の計画生成はそれらの結果だけを読むので、同じ評価順序と metadata 作用を得る。
source span から作る静的 label は対応する一様な改名で移す。
malformed layout、回復用 CST、異なる item 順をこの補題の前提には含めない。
\end{proof}

\section{\texttt{'e?}：実際の crossing による scoped release}
\label{sec:release}

\subsection{保存する決定と、新たに具体化する機械}

\texttt{'e?} は、独立に \texttt{'e} 由来と認められた寄与について、
指定された出力 view で \texttt{'e} の scope の保護を外す記法である。
効果の発生、row membership、元の attribution、別 scope の保護を消さない。
handler を選択せず、新しい grant も作らない。
次の二つを同時に満たす。
\begin{enumerate}
\item \nolinkurl{questions/2026-10-05-handler-protection-release-crossing/approved-answer.md}
の q1/d1：介在する計算・handler の後に実際の outward crossing が起きた時に発火する。
同じ target view の typed transport と元の receiver の生存が保たれる間、解除状態を引き継ぐ。
単なる dispatch 前 Observe、未実行の latent code、他の receiver への移動は初回解除ではない。
\item \nolinkurl{notes/design/2026-10-15-compose-scoped-effect-release.md}：
\texttt{compose id g} でも、出力の \texttt{'f} 内に現れる同じ \texttt{'e} の scope を解除する。
独立した別の scope は残す。表示上の \texttt{'e?} 項だけを解除して
同じ出力 packet 内の alias を保護したまま残す構成では満たされない。
\end{enumerate}
これらは既存の決定である。以下の scope handle、target handle、delimiter、有限 transfer は、
その決定を実行可能な規範計画へ具体化する本稿の構成であり、compiler 表現の採用決定ではない。

\subsection{scope・attribution・target の有限な生成}

owner、handler、event と別の sort として、保護 scope \(s\) と target view handle \(t\) を加える。
\(s\) の origin は \((b,r,e,j)\) である。
\(b\) は実際に導入した Boundary、\(r\) はその receiver、\(e\) は型付き注釈の abstract binder、
\(j\) はその binder を受ける ingress の source occurrence である。
同じ字面の \texttt{'e} でも、別の binder/instance/ingress は同じ \(s\) にならない。
一つの scope は既存 Boundary の保護を細分して識別するものであり、
scope handle を付けること自体は新しい Boundary や処理許可を作らない。
\(e\) と無関係な Boundary にも独立の識別子を付け、解除対象と混同しない。

\(\Psi(e,j)=s\) は型付き annotation の binder 環境に保持する対応である。
その環境を構成できる規則は次の三つに限る。
\begin{enumerate}
\item source profile が実際に Boundary を導入する ingress に、同じ source annotation が
参照する \(e\) の component port を結ぶ。そこで fresh \(s\) と上記 origin を記録する。
\item alias、構造の prefix/除去、明示 adapter、whole-scheme instance は、実際の typed edge に
沿って同じ対応を運ぶ。instance 化では binder 対応を一度だけ置換する。
\item qualified な値入力は、その値型に明記した同じ対応を前提として受け取る。
閉じた計画では、その値の introduction に対して1または2の導出が必要である。
\end{enumerate}
値型の一致、family の一致、row membership だけで対応を作る規則はない。
annotation の同じ binder が複数の ingress に現れる場合、対応は一つの row ID へ潰さず、
source occurrence を添字とする有限表として残す。

attribution の証拠は第\ref{sec:concrete-eligibility}節の実際の typed route に、
その ingress port を通ったという印を付けた有限導出である。
その生成は、上の ingress edge、既存の primitive Flow edge の合成、実際の Observe に限る。
\(\mathsf{From}_s(q)\) は、その \(s\) の ingress から現在の寄与に至るこの導出があることを表す。
query は有限 DAG を逆向きに辿る既存の Path 検査に ingress 印の検査を加えたもので、停止する。
別名の row に格納されたことは印を消さず、\(s\) と無関係な局所 operation は印を作らない。
複数の独立した scope の印を持つ寄与も許す。
印は full contribution/route の証拠であり、event ID を等しくするだけでは複製しない。

target \(t\) は一つの印付き出力 slot の\emph{whole packet}に付ける handle である。
対応表は、そこで解除を指定した各 \(s\) について
\(\mathsf{Target}(t,s,r(s),j_{\rm out})\) を保持する。
各 \(s\) は \(\Psi\) の既存 entry から取得し、元の receiver はその origin と一致しなければならない。
複数の ingress を持つ場合も receiver を一つに同一視しない。
印 \texttt{e?} は \(\Psi\) の当該 binder/occurrence の対応を参照してこの表へ elaboration する。
表は型付き annotation の一部であり、表層構文へ新しい scope 名を要求するものではない。
対応が欠けた印に、適当な row の全保護を解除する fallback はない。
一般の source から正しい対応表を発見する推論器の完全性は、この規則とは別の義務である。

whole packet の target は、値・event・結果の全 latent port・pending continuation に沿う
typed transport で保持する。これはコード実行前に latent event を発生させる操作ではない。
潜在 port には有限 template を保存し、実際の read/force/call で同じ handle を解釈する。
任意の descendant を immediate effect に変える辺は加えない。
別の source receiver や独立の target slot の introduction では fresh \(s',t'\) を作り、
以前の解除状態を初期値にしない。

\subsection{解除状態と、whole packet の読み方}

world に有限集合 \(L\subseteq\mathsf{ScopeName}\times\mathsf{TargetName}\) を追加する。
\((s,t)\in L\) は、同じ target でその scope の最初の適格な crossing が既に起きたことを表す。
初期集合は空で、fresh target の対も全て未解除である。
型付き外部入力が既存の状態を運ぶ場合、その実際の導入・crossing の導出を一緒に要求する。
\(L\) は Observe の追加だけでは変更しない。

現在の whole packet を target \(t\) の view で読むとき、各元の保護 witness \(w\) について
\[
 \mathsf{LiveProt}_t(w)=\mathsf{Prot}(w)\land
 \neg\bigl((s(w),t)\in L\land\mathsf{Active}(r(s(w)))
                 \land\mathsf{TransportedTarget}(w,t)\bigr)
 \tag{RP}
\]
とする。\(\mathsf{TransportedTarget}\) は、上記 target introduction から identity、
prefix/除去、明示対応、型適用、capture-avoiding rename を合成した有限導出である。
別の view を同じ raw value と判定しただけでは導出できない。
target のない通常の packet では \(\mathsf{LiveProt}=\mathsf{Prot}\)。

(RP) は\emph{その target の出力 projection 全体}に一度適用する。
\(P\) を「まだ保護された witness がある」という存在量化にする前に、
同じ \(s\) の全 witness を (RP) で読む。
\texttt{['e?, 'f]} の \texttt{'f} 内に保持された \texttt{'e} の alias も、その同じ出力 projection の一部である。
旧 Observe 行は provenance として残すが、旧 packet の未解除 projection を別 alternative として
解除後の出力へ再 union しない。旧 input view は旧 view のままであり、破壊的に変更しない。
target の typed transport を持たない独立の view では (RP) の解除条件は偽である。

第\ref{sec:concrete-eligibility}節の \(P(q,h)\) では、各 witness にこの
\(\mathsf{LiveProt}\) を conjunct として加える。
\(G(q,h)\)、Admit、Covers、RoleAllows、元の Path/Observe と activity の検査はそのままとする。
解除は existing grant を消したり新しく作ったりしない。
別の scope \(s'\ne s\) の \(\mathsf{LiveProt}\) は変わらない。
その後の eligibility は、残った全 witness と既存 grant の元の規則で決まる。

\subsection{crossing を起こす七番目の frame}

管理計算に \(\mathsf{release}_{\bar s,t}M\) を追加する。
\(t\) の対応表、各 \(s\) の \(\Psi\) での束縛、body の型付き導出を静的に要求する。
この delimiter は型付き annotation が指定する\emph{実際の出力 slot}に置く。
complete Call 自身の slot なら、その実際の body/result consumer/adapter の後である。
さらに外側の source output の印を、receiver が生存している内側へ勝手に移動してはならない。
元の receiver がその slot で既に非 active なら、下記の条件は偽となり、古い解除権限を作らない。
外側の型適合が新しい receiver を作り直すことはない。
\(t\) の whole-view template は実行開始時から存在してよいが、\(L\) は未解除のままである。

world の他成分を \(W\) と略記し、次の規則を定義する。
\[
\begin{split}
 (W,L;\mathsf{release}_{\bar s,t}\Ret v)
   &\longrightarrow(W,L;\Ret\mathsf{view}_t(v)),\\
 (W,L;\mathsf{release}_{\bar s,t}\Fail a)
   &\longrightarrow(W,L;\Fail a).
\end{split}
\]
\(\mathsf{view}_t(v)\) は既存の結果 transport に target 対応を保存した値である。
return 自体は effect contribution の crossing ではないので、\(L\) を増やさない。
return された latent view は後に実際に実行された時にこの状態を読む。

body が request になった場合だけ、次の有限集合を計算する。
\[
 J(q,t)=\{s\in\bar s\mid
       \mathsf{From}_s(q)\land\mathsf{Active}(r(s))
       \land\mathsf{Target}(t,s,r(s),j_{\rm out})\}.
\]
\(\mathsf{From}\) は上で定義した ingress/transport 導出から先に計算する。
解除後の eligibility や「外へ出るはず」という handler image を使わない。
\[
\begin{split}
 &(W,L;\mathsf{release}_{\bar s,t}\Req(q,p,K))\\
 &\quad\longrightarrow
 (W,L\cup\{(s,t)\mid s\in J(q,t)\};
       \Req(\mathsf{view}_t(q),p,\mathsf{ReleaseCont}_{\bar s,t}(K))).
\end{split}
\tag{RC}
\]
\(\mathsf{ReleaseCont}_{\bar s,t}(\mathsf{cont}(\bar u,x.M))\) は
\(\mathsf{cont}(\bar u,x.\mathsf{release}_{\bar s,t}M)\) である。
frame 自体は receiver を導入せず、その free handle を新しく束縛しない。
\(q\) は元の event/instance/Observe/attribution を保持する。
payload と response の型、raw continuation の穴の型は変わらない。

active child の通常遷移はこの frame の内側で行う。
従って内側の handler が request を消費した場合、(RC) の左辺は現れず、初回解除も起きない。
request を観測しただけではこの規則を先取りできない。
外側の handler は (RC) の\emph{後}に更新後の packet を見る。
複数の delimiter を越えるときは source context の順で一段ずつ適用する。

\paragraph{なぜ frame を再開に戻すのか。}
元の raw continuation が後続の request を出せば、それも同じ出力 slot を通る。
そのため release frame は復元する。選択された shallow handler は復元しない。
選択されなかった handler や wait frame は既存の capture 規則に従う。
これにより、保護解除を理由に shallow continuation を deep に変えることはない。

\subsection{寿命、複数回の resume、遅れて使う値}

\((s,t)\in L\) は、同じ生存中の receiver の同じ view に対して冪等な状態である。
二度目以降の query は (RP) を使用し、新たな crossing の有無を要求しない。
一方、receiver の normal exit 後には \(\mathsf{Active}(r(s))\) が偽となるので、
古い entry を別の receiver の権限として使用できない。
原 receiver が非 active なら、その古い Boundary の protection/grant も既存規則により非 active である。
これは古い解除状態を新しい scope にコピーすることとは異なる。

resume の一様改名を、owner/handler に加えて、capture した frame に束縛された
\(s,t\)、その origin、target 表、saved packet、対応する \(L\) entry に延長する。
\(L\) の扱いは次のように定める。
\begin{itemize}
\item captured frame に束縛された handle は各 resume で fresh にし、
保存した状態のうち bound な端点を持つ対を同じ改名で復元する。
片方が free ならその端点は固定する。旧 entry と他枝の entry は変更しない。
\item free な生存中の receiver/target は freshen せず、現在の world の同じ \(L\) を読む。
現在の resumer の world を creation-time snapshot で上書きしない。
\item 新しい通常の source call は新しい receiver の fresh handle と空の解除状態から始める。
saved frame の alpha-renaming と、新しい source call の導入は別の規則である。
\end{itemize}
capture 時に bound な状態を保存するのは既存の Scope suspension の一部である。
共有 resource を read する場合も、stored value を書き換えず、
その response view に同じ改名と target 解釈を施す。
これが自由な live view の現在の解除状態と、各再開枝の束縛状態の両方を保存する。

\begin{lemma}[解除の局所保存、非捏造、改名]
\label{lem:release-local}
well-scoped な release 計画の有限 prefix で、query と (RC) は全域であり、
実行型と payload/response/continuation の型を保存する。
解除は attribution、membership、全 ordinary grant と独立 scope の保護を保存し、
一様な bound 名改名と可換する。
\end{lemma}
\begin{proof}
\(J\) は有限な \(\bar s\) 上の、有限 DAG の Path/ingress 検査と表 lookup の集合である。
\(L\) は一段で有限個の対を増やすだけなので、prefix 長への帰納で有限。
(RP) と変更後の query も有限 bool であり、解除の有無を再帰的に問い合わせない。
Ret は値型を変えない view transport、Fail は同じ failure、Req は同じ \(p:P_o\) と
\(K:\mathsf{Kont}(Q_o,A)\) を持つ。穴 \(x:Q_o\) の body を同型の release frame で囲むので
\(\mathsf{ReleaseCont}(K):\mathsf{Kont}(Q_o,A)\) が得られる。
active-child case は穴の型付けへの帰納である。

更新するのは \(L\) と出力 view の解釈だけである。
From、Observe、operation instance、payload、既存 grant は式の右辺にも同じものが残る。
(RP) の同じ \(s,t\) にだけ作用するため、独立の \(s'\) と、typed transport を持たない target は固定される。
receiver の activity は別の Scope 規則で決まり、解除が activity を作る規則はない。
改名は sort、equality、origin/target の対応、集合の対を一様に移す。
従って \(\theta(J(q,t))=J(\theta q,\theta t)\)、
\(\theta(L\cup J_t)=\theta L\cup\theta J_t\) が成り立ち、(RP) の真偽も一致する。
free 部分を固定し bound 部分だけ fresh にすることで、各 resume 枝に同じ議論を適用できる。
\end{proof}

\subsection{有限 cell、型付け、cut summary への追加}

実行型保存だけでは effect annotation の保存にならないので、有限表示も拡張する。
各 interface に現れる有限個の \(s,t,r\) register とその equality/origin 対応、
named な \((s,t)\) の \(L\) bit、\(\mathsf{From}\)、target transport の真偽を加える。
既存の owner diagram に加えて、\emph{保護 witness の joint region diagram}を持つ。
一つの witness の vector には、各候補への incidence、receiver の現在の activity、
対象 scope/target との一致、元の保護、解除条件の真偽を同時に置く。
named witness はその vector、hidden witness は各完全 vector の非空 bit として表す。
scope ごとの周辺集合から交差を推測しない。
各 query の \(P\) は active incidence と (RP) がともに真の region bit の disjunction であり、
\(G\) は既存の query 座標を保持する。従って query はこの拡張 cell でも正確である。

有限 relation は以下の\emph{構文的な座標式}から作る。
\begin{enumerate}
\item fresh scope/target は旧 support と不等で、対応する release bit は0。
ordinary identity/prefix/除去は同じ origin/target と状態の参照を運ぶ。
\item (RC) では、named な各対について
\[
 L'(s,t)=L(s,t)\lor
   (s\in\bar s\land t=t_{\rm frame}\land\mathsf{From}_s(q)
                     \land\mathsf{Active}(r(s)))
\]
とし、他の named な対はそのままにする。whole output の保護 bit は (RP) で再計算する。
Attribution/membership/Grant の列はコピーする。
\item Ret/Fail/Observe だけの step は \(L'=L\)。
query の前には現在の activity と同じ live target の release bit を再観測する。
\item bound/free action tag を持つ改名は、前節までの saved/ambient の分離を
origin、target、release 対へも同じように適用する。
\item interface が保持しない対応・alias・hidden target・後の状態との関係は、
整合する全候補へ戻す。保持できない関係を「未解除」や「解除済み」と断定しない。
\end{enumerate}
hidden witness の region bit は、指定した Boolean vector 変換の像の disjunction を取る。
未知列は全 refinement を列挙する。有限個の bit、partition、region があるため
relation は有限であり、具体的な無限実行や source の将来の効果を探索しない。
後で再観測する状態が失われた場合には両候補を残すので、精度低下はありうる。

\begin{lemma}[解除 transfer の表示保存]
\label{lem:release-sim}
各新しい具体操作について、具体入力を表示する cell の有限 transfer の出力集合は、
実際の具体出力を表示する cell を含む。
\end{lemma}
\begin{proof}
fresh/identity/rename は前の表示保存証明を新しい sort と列に延長する。
(RC) の named な対は、具体的な集合への追加と上の Boolean 式が同じである。
各保護 witness の更新は (RP) の pointwise な式なので、named vector は正確に変わり、
hidden vector の非空な像はその disjunction に含まれる。
旧 Observe を別 alternative として残す transfer は使わないので、
同じ output packet の \texttt{'f} 側にも同じ pointwise 更新が及ぶ。
未知の source/target 対応や free 状態を再観測した際の実際の値は、列挙した全候補の一つである。
未知 bit を一つに選んで適格性を確定することはない。
membership/Grant/attribution の列を固定しているので、それらの保存も表示される。
\end{proof}

\paragraph{effect 型付けの新しい行。}
\(\mathsf{release}_{\bar s,t}M\) の body の whole graph を通常どおり検査し、
外向き event port に (RC) の relation image、正常結果 port に target transport、
全 latent port に同じ state/target 参照を接続する。
\(L\) の状態も \(\mathsf V\) の入出力列へ含め、bind の後段へ渡す。
古い \(E_M\) を更新後の output と無条件に union する規則はない。
ただし abstract interface が区別できない候補は全て残す。
これらの mandatory edge を加えた \(F_G(U)\subseteq U\) と、同じ出力 inclusion を要求する。
\texttt{'e?} はこの relation image の表示であり、単なる family 集合の差や
別の自由 row variable として解釈しない。

特に \texttt{['e?, 'f]} の annotation は、同じ assignment と共有関係を持つ
\emph{出力 packet 全体}に対する一つの作用として読む。
\[
 \mathsf{OutGraph}=\widehat{\mathsf{Cross}}_{s_e,t}(\mathsf{WholeGraph}),
 \qquad
 \mathsf{OutGraph}\not\equiv
       \widehat{\mathsf{Cross}}_{s_e,t}(X_e)\cup X_f
 \quad\text{（一般には）}.
\]
右辺の \(X_f\) に同じ \(s_e\) の寄与が含まれる場合が二つを区別する。
\(\mathsf{WholeGraph}\) は body と全 output の共有 packet から構成し、
表示に \(X_e\) が現れることだけを理由に、未実行の引数の event を seed しない。
複数の marker は各々の認証された scope を同じ whole graph に対して作用させる。
異なる scope の解除は可換であり、同じ対の二度の解除は集合への追加の冪等性により同じ結果を持つ。

cut-context grammar に release を七番目の terminal frame として追加する。
その summary は上記の有限 relation image と result/latent transport であり、単調である。
\(\mathsf{ReleaseCont}\) はこの terminal を suffix に一つ追加する。
従って既存の有限 lattice 上の関数閉包と相互固定点の構成をそのまま延長できる。
その中で選択された handler frame を追加する規則はない。
monotonicity は \(L\) の bit 自体を格子順で0から1へ近似することからは主張しない。
\(L\) を含む\emph{complete cell の集合}に対する relation image だから単調なのである。

\subsection{compose と寿命についての判別導出}

期待される表示をもう一度固定する。
\begin{Verbatim}[fontsize=\small]
compose : ('a ['e] -> ['f] 'b)
       -> ('c -> ['e] 'a)
       -> 'c -> ['e?, 'f] 'b
\end{Verbatim}
型付き計画では、\(g\,x\) の inert carrier を \(f\) に渡す ingress に \(s_e\)、
型付き導出が指定する印付き出力に \(t\) を結び、
その実際の出力を release delimiter で囲む。
\(f\) の Value entry が carrier を force する場合も、Computation entry の body が実際に force する場合も、
その実際の入力辺を通った contribution だけが \(\mathsf{From}_{s_e}\) を持つ。
未使用の Computation 引数から effect seed を作ることはない。

\(f=id\) なら、その返却/転送の identity edge が同じ \(s_e\) と whole packet を保つ。
\(g\,x\) から一つの寄与が実際に delimiter を越え、元の receiver が live なら、
(RC) は \((s_e,t)\) を加え、
\texttt{'f} 内に共有されているその寄与にも (RP) が適用される。
別の scope \(s_z\) の bit は変えない。
逆に内側の handler が最初の寄与を消費して外へ出さなければ、\(L\) は空のままである。
pure な正常 return も解除を作らない。
これらは指定された型付き計画の局所導出であり、表示した compose scheme の主型性や
現在の推論器からの生成を証明したものではない。
特に source の compose からこの ingress/出力位置/receiver lifetime の導出を作る対応は、
局所的な identity edge の保存とは別に必要である。

\begin{longtable}{p{.43\textwidth}p{.49\textwidth}}
\toprule 実行上の状況 & 規則から得る結果 \\
\midrule\endhead
初回 event の Observe の直後、まだ内側の catch にいる & \(L\) は変わらず、元の保護で dispatch。\\
内側の catch が消費し、再発生も outward crossing もない & その寄与による解除はない。\\
同じ \(e\) 由来の event が印付き slot を実際に越える & 同じ \((s_e,t)\) だけ解除。効果と他 scope は保持。\\
同じ live receiver、同じ target の後続 latent 実行 & 現在の \(L\) を読み、再度の初回 crossing を要求しない。\\
新しい通常の呼出し・別 target & fresh な対応は未解除。family/型/lineage 一致だけでは継承しない。\\
同じ raw continuation を二度 resume & free な live 状態は共有し、bound な状態は各枝で一様改名して復元。選択 handler は復元しない。\\
owner の normal exit 後 & 古い release entry を新しい owner の権限に使わない。\\
\bottomrule
\end{longtable}

\subsection{追加した全規則を元の定理へ戻す}

\begin{theorem}[constructor 多相性・混合 row・scoped release を含む型健全性]
\label{thm:extended-safety}
第\ref{sec:rank2}--\ref{sec:release}節を追加した体系で、
有限の well-formed 宣言表と閉じた計画に \(M:A!\Phi\) の構文的導出があるとする。
その導出は全 qualified 義務、origin/target の束縛、同じ whole-packet assignment、
拡張した全 mandatory edge の inclusion を含む。
初期 world と外部応答は第9節と同じ型付き protocol を満たし、\(L\) は空または上記の導入履歴を持つ。
任意の有限実行 prefix において、正常結果・request・continuation の型、
immediate/latent/reentry の全契約が保存され、\(\Bad\) に到達しない。
具体的な handler 検索は (RP) を加えた同じ receipt/path/activity 規則に従う。
解除は適格な実際の crossing にのみ由来し、効果自体・他 scope・既存 grant を保存する。
空の outward 契約から外向き request は生じない。発散と列挙した failure は許す。
\end{theorem}
\begin{proof}
値/項/型の置換に全称 case を加えるのは補題\ref{lem:rank2-payload}である。
型代入で origin/target の型 template も一緒に置換し、free な動的 handle は固定する。
型抽象の side condition は \(\Psi,\Xi\) を含むので、型依存の外来 state を誤って一般化しない。
source separator は同じ導出に正規化され、実行 case を追加しない。

release frame の局所保存と進行は補題\ref{lem:release-local}。
値/状態の精密な置換は、追加した有限 relation image も入力集合に単調であることから延長される。
実行型の変更がない旧 redex の場合も、新しい \(\Psi,L\) 列をその規則の identity/rename/read に従って運ぶ。
From の導出は元の typed route の項置換と同じ辺列を持ち、偽の ingress を項置換で導入しない。
frame 合成に release を追加し、cut summary の表示保存をその terminal case で延長する。
handler の proof は完全 cell 上の query の正確性と totality だけを用いるので、
(RP) 後の query にも同じ論証が適用される。
guard が作る新しい request と pending 元 event の状態は従来どおり別 port に保存する。
再開時には現在の \(L\) と activity を再観測するため、古い query verdict を固定してしまう穴はない。

新しい具体 step と graph edge の simulation は補題\ref{lem:release-sim}であり、
それ以外は第9節の simulation の拡張である。
従って状態判断の一段保存が全 case で得られる。
閉じた全称値の除去では値の形が型抽象またはその正規の graph/view 参照を与え、
release の child が Ret/Req/Fail なら上記の明示規則があるので進行する。
有限 prefix 長への帰納により、第9節と同じ四つの安全性の結論を得る。
解除の由来は \(L\) の唯一の追加規則 (RC) への帰納、他情報の保存は局所補題である。
これで新しい構文を持つ計画を旧定理へ無条件に入力することなく、追加後の定理を導出した。
\end{proof}

\paragraph{残る source/compiler の対応。}
本節は「安全な release が存在する」という未定義の前提を置かず、有限な実行規則と型付けを与えた。
ただし、任意の未注釈 source から rank-2 の型適用や scope/target 表を発見すること、
混合 row の全 constraint を現 compiler が保持すること、compose の選ばれた表示の主型性、
この機械と VM/native の対応は別の証明である。
複数の annotation occurrence を持つ一般 source についての scope 対応の完全性も未証明である。
\texttt{'e?} を suffix identifier として読む既存 parser から release の意味が自動的に得られるとはしない。
本稿の宣言的な対応表を compiler が生成する必要がある。
紙上導出は単独著者によるもので、独立査読・機械検証は未実施である。

\section{証明の依存と実装への適用範囲}
\label{sec:remaining}

本稿の規範的な型付き言語について、定理\ref{thm:full-safety}の依存は次で閉じている。
\[
\begin{gathered}
\text{全構文の明示 code と decoration}
\ \longrightarrow\ \text{実行型の保存・進行},\\
\text{有限 diagram と transfer の具体的構成}
\ \longrightarrow\ \text{表示保存・query の正確性},\\
\text{frame 文法と有限の cut summary}
\ \longrightarrow\ \text{raw continuation の契約},\\
\text{構文的な graph inclusion と置換}
\ \longrightarrow\ \text{一段 simulation}
\ \longrightarrow\ \text{有限 prefix の全型健全性}.
\end{gathered}
\]
「elaboration が正しい」「primitive transfer が adequate」「継続の再開が安全」といった
未定義の意味論命題を、最後の定理の仮説に置いていない。
仮説は、提示された code の上記の構文的導出、宣言表、開いた場合の型付き入力である。
scalar primitive の文字分割等は元稿と同じ固定 helper データを parameter とし、
その有限列上の constructor 保存は前半で示した。
これは arithmetic/Unicode の具体的な表示選択と、効果の安全性を区別する通常の宣言表パラメータである。

\textbf{型推論・compiler について残る仕事。}
元稿の略記のうち、decoration、未知座標の relation、\(E^r\) の作り方は本稿の具体構成に固定した。
特に \(E^r\) に任意の小さい row を選ぶ判断は、この体系の導出にならない。
これらの補完を持たない古い証明書の名前だけから、本稿の導出の存在は結論しない。
未注釈 source からこの導出を見つけること、全 retained constraint を保存すること、
compiler の全 lowering がこの型付き翻訳を生成すること、VM/native がこの機械を実現することは別の定理である。
特に、小さい effect row を出す実装には、この有限規則の inclusion を満たす根拠が要る。
過去の \texttt{CheckedExecutable} という名前や成功した実行例だけではその根拠にならない。
原文の全 source inference、principality、Oracle equivalence、A/B、Q1--Q8 の実装側の gate を
本稿の定理によって一括して閉じない。
