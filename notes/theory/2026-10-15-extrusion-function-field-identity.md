## Objective and frozen statement

Trace the actual Function reconstruction, its direct row-copy Parents and the
final root-output PairGroup. Governing direction is [top-level inference
principles §1.1](../design/2026-10-11-yulang-inference-top-level-principles.md)
and [annotation integration §§1,3–5](../design/2026-10-10-annotation-effect-hygiene-integration.md).
This uses native extrusion construction; it adds no inverse semantic relation,
new compiler invariant, source restriction or profile authority.

Fix one invocation `candidate_extrude(initial, polarity, level)` at the pinned
production bytes that returns `Ok(output)`. Fix its branch-owned term arena and
the one invocation-local `rows` and `structure` maps. For every completed
`Work::Function(K, children, originals)` generated by that invocation, retain
the original four **ordered** fields, without selecting independent witnesses:

```text
K = Key(F, p, t)
originals = [a, ae, re, r]
q = [opposite(p), opposite(p), p, p]
kind = [Value, Effect, Effect, Value]
children[i] = Key(endpoint_kind(originals[i], q[i]), q[i], t)
M(k) = rows[k] if present, otherwise structure[k]
E[i] = M(children[i]) at this Function reconstruction
T[i] = originals[i],                       if E[i] == children[i].endpoint
     = candidate_endpoint_term(E[i], q[i]), otherwise
```

The required local conclusion is the following exact construction formula:

1. Every `E[i]` exists; no canonical-equivalence search substitutes another key.
2. If all four equal their input endpoints, `M(K) = F` and its four fields are
   exactly `originals`. Otherwise `M(K)` is the Function of polarity `p` whose
   field array is exactly `[T[0], T[1], T[2], T[3]]`.
3. For a direct child row that is actually copied, if `children[i]` maps to the
   fresh raw row `c`, the Parent emitted by its first Visit has exactly that
   raw `copy = RowKey(kind[i], c)`, raw `parent = RowKey(kind[i], j)`, polarity
   `q[i]`, target `t` and this invocation's occurrence. The output field
   `T[i]` is exactly a branch-owned LiveVariable with that kind, polarity and
   **raw ordinal `c`**. The claim concerns its node payload, not equality of
   an endpoint enum with a Term handle.
4. The final root lookup returns `M(root)`. If at least one Parent was appended
   and `effect_algebra.processing = Some(comparison)` at finish, finish installs
   an indexed PairGroup for `(comparison, M(root))` whose half-open Parent span
   is exactly `[parent_start, parents.len())`. It does not label individual
   fields, and it does not index non-root reconstructed Functions separately.

For the polarity interpretation in (2), require that every visited Function
tag agrees with its Key polarity and that all original children are valid
branch-owned terms at their declared kind/polarity. An arbitrary successful
call with a mismatched root polarity does not itself establish this hypothesis:
the unchanged branch returns `F` without revalidating its tag. The formula for
the actual branch still describes its behavior. No claim that every source
caller establishes this hypothesis is supplied here.

For (3), assume the initial representative forests and row/term tables are
well formed, fresh allocation supplies a new row ordinal, and representatives,
input term nodes and existing row levels do not change during this synchronous
invocation. These are explicit local operational hypotheses. The inspected
extrusion route appends bounds/terms/Parents and retains evidence; it does not
call row union, intrusion settlement or rollback. Forest redirection belongs
to `candidate_intrusion.rs:480–589`, rather than the Function builder. This
note does not establish all callers' initialization or all reentrant routes.
The `&mut InferenceSession` operation admits no interleaved caller mutation.

All assertions are at successful return, before any later union, rollback,
arena invalidation or State replacement. They do not identify a numeric runtime
term, RelationId or source occurrence. This freezes the local statement before
the derivation; the original H1/H2/U domains, scopes, binders and obligations

## Actual constructors and constructive derivation

### Scheduling, keys and memo lifetime

`candidate_extrusion.rs:27–38` allocates a fresh occurrence, saves the initial
Parent length, and creates empty local maps and work vectors. `root` is
`Key(canonical_extrusion(initial), polarity, level)` at `:75`. Only row
representatives are canonicalized (`candidate_intrusion.rs:217–221`;
`lib.rs:11490–11502`); Function endpoint identity is its complete Term handle.
`Key` equality includes the endpoint enum, polarity and target (`:4–5`).

`Work::Visit` checks these exact keys in both maps (`:79–82`). A row is memoized
before its selected bounds are visited. Function visits extract the four actual
fields using `positive_function_children` or `negative_function_children`
(`:211–225`; `lib.rs:14063–14102`), then construct the four keys displayed above
(`:226–251`). Endpoint conversion canonicalizes row ordinals at key formation
(`lib.rs:11428–11487`); the original field Term handles remain in `originals`.

The builder is pushed before child visits, with children pushed in reverse
order (`:252–255`). The LIFO stack therefore finishes each child before the
parent builder. Bound work is selected only when the main stack is empty
(`:77`), so a row bound naming the Function currently under construction cannot
prematurely revisit that unfinished structural node. Existing term nodes are
immutable; Function constructors accept existing handles, producing a finite
structural DAG. Cycles through row bounds use the earlier row memo instead.
Repeated already-completed keys take the exact memo-hit branch. None of these
maps survives the invocation (`:367`); this is no global memo-lifetime theorem.

For the stated success-qualified conclusion, the stronger termination theorem
is unnecessary: a missing lookup at any executed Function builder returns an
error at `:335`, hence cannot occur in an invocation returning `Ok`.

### Exact four fields and raw copied-row identity

`Work::Function` initializes `terms = originals` and, for each ordered index,
reads `rows.get(children[i]).or_else(structure.get(children[i]))` (`:327–335`).
It replaces exactly that array element only when the mapped endpoint differs
by exact enum equality from `children[i].0` (`:336–339`). This proves the
displayed piecewise formula simultaneously for all four slots.

The no-change branch returns the original endpoint (`:341–342`); its fields
remain exactly the extracted array. The changed branch calls
`positive_function_term` or `negative_function_term` with the four array
elements in their original order (`:344–351`). The wrappers in
`lib.rs:10287–10312` preserve those arguments. The actual owning constructors
are `BranchTermArena::{positive_function,negative_function}` in
`term.rs:1126–1167`: they validate child lineage/kind/polarity, then intern a
TermNode containing those exact four handles. `TermNode::view`
(`term.rs:228–256`) returns those same handles. Interner reuse preserves exact
node contents; it does not authorize inferring freshness of the Function Term.
The result is stored at the original complete key (`:354`).

Now fix a **direct** field whose Key endpoint is ValueRow(j) or EffectRow(j).
For an older/equal-level row, Visit stores that exact endpoint and creates no
Parent (`:92–95`). For `original_level > t`, it allocates one fresh row `c`
of the same kind at target `t` (`:114–122`). The exact local variable `copy`
is passed to `retain_extrusion_parent` and then inserted in `rows[key]`
(`:123–124`). The retention constructor destructures those endpoints directly
into RowKeys (`candidate_intrusion.rs:237–246`) and stores them without
representative normalization (`:278–286`). Therefore the Parent's raw copy
is the exact map output; canonical equality was never used for this join.

Fresh `c` differs from the input raw ordinal `j`; thus `E[i] != children[i].0`
for a genuinely copied direct field. The builder calls
`candidate_endpoint_term(copy, q[i])` (`:338`). Its row branches call
`live_value_term(q[i], c)` or `live_effect_term(q[i], c)` (`:371–386`). Those
wrappers preserve `c` (`lib.rs:10251–10268`), and
`BranchTermArena::live_variable` interns the exact
`LiveVariableView { kind, polarity: q[i], ordinal: c }`
(`term.rs:1101–1112`). This proves (3) by raw identity at the construction
owner. Fresh representative initialization in Parent retention appends identity
forest entries (`candidate_intrusion.rs:266–275`). Operational endpoint
conversion also yields `c` while representative stability holds.

This is a simultaneous field construction under one invocation's maps. It
does not select marginal semantic witnesses or merge provider, attachment,
source, BoundKey or residual lineage.

### Shared slots, nesting and selected-bound descendants

Equal complete keys share one memo output and one row-copy Parent. Different
polarities remain different keys even when the row ordinal and target coincide.
In particular, reusing one raw effect row in ArgumentEffect and ResultEffect
does not identify its opposite-polarity copies. Value and Effect namespaces
remain distinct. A Parent may supply several nested field occurrences with
the same key; no uniqueness of a field position follows from its copy ordinal.

A nested Function follows the same ordered construction. If its endpoint
changes, `candidate_endpoint_term` passes its exact returned Function Term
through (`:383–385`); if it does not change, the original field Term is kept.
Parents for grandchildren therefore occur within the invocation span, while
the immediate field is a Function Term. They are not direct row fields of the
outer Function.

An EffectView visited through a root/selected bound reads its mapped row tail
and stores an Allowance/Support/AnnotationMember endpoint with preserved variant
and member coordinate (`:182–209,260–293`).
`candidate_remapped_effect_view` memoizes `(original view ID, mapped tail)`
(`candidate_effect.rs:897–914`). Function field terms have no EffectView variant
in the actual TermView alphabet (`term.rs:170–190`), and `effect_endpoint`
accepts only effect leaves, Components or LiveVariables (`lib.rs:11466–11487`).
Consequently this proof does not pretend an arbitrary EffectView is encoded
as a direct Function field: the adapter at `:371–386` has no such case and
would return an error if a changed view were supplied there. Actual views in
selected-bound descendants stay on their distinct view/bound route. Proving
uniform Function-field support for a richer term alphabet would require a
different owning adapter, not an assumption in this note.

For a copied row, Visit snapshots selected-side lengths before installing the
opposite-side source link (`:98–113,125`) and creates `Work::Bound(copy,p,key,
source BoundKey)` plus its Visit for each selected live entry (`:126–165`).
`Work::Bound` reads its exact local child key, installs the mapped item and
transfers evidence using the saved original BoundKey (`:310–325`). Its target
BoundKey is canonicalized at the bound owner; this does not rewrite the raw
Function field or the stored Parent. IncomingAllowance is a separate
two-coordinate bound construction (`:166–177,295–308`). Its Parent descendants
likewise do not become direct fields merely because they share representatives.

`candidate_transfer_bound_origins` (`candidate_effect.rs:563–609`) reads the
source bound's contextual cursor and emits TransportWitnesses for its retained
entries; the origin-only fallback explicitly records MissingOriginAssociation.
This note derives local construction, not activation or complete replay of
those stored constraints. Scheme capture later projects exact bound cursors
and retains `source_bound` (`candidate_scheme.rs:548–594`); it is not evidence
that a particular captured bound is this root output.

### Root output and the exact Parent span

The final lookup reads `M(root)` and passes that exact endpoint to finish
(`candidate_extrusion.rs:358–365`). Under the nonempty-span and active-comparison
conditions, finish appends the new group ID to
`by_output[(comparison, output)]` and appends the PairGroup with this occurrence,
`start = parent_start`, `end = parents.len()`
(`candidate_intrusion.rs:290–308`). Under stable processing/no nested extrusion,
every Parent in this span came from this invocation and has this occurrence
and comparison, matching the constructor's debug assertion at `:303–304`.
The vector-valued index permits multiple groups for the same pair/output;
uniqueness is not proved or assumed.

The span includes copied direct fields, nested-field rows, selected-bound
descendants and incoming-allowance descendants. The constructor retains no
field-position index in a Parent or PairGroup. The direct-field proof uses the
specific child key and its first Visit, not membership in the span alone.
Recapture consumes the exact indexed output and group (`:310–343`), rather
than reconstructing it from shared canonical rows. It still does not prove a
particular runtime relation's enqueue activation.

## First unsupported stronger premise and lifecycle boundary

The local piecewise construction and copied-direct-row corollary have a
constructive derivation above. The first unsupported **uniform raw readback**
premise is that every unchanged original field's raw node ordinal already
equals the canonical ordinal used in its child key. `value_endpoint` and
`effect_endpoint` canonicalize a LiveVariable's raw ordinal, whereas the
unchanged branch keeps the original Term. For example, under a well-formed
forest with `rep(j)=k`, `j != k`, an original LiveVariable(j) at an unextruded
canonical row k leaves `E=ValueRow(k)` and stores the original raw j field.
Operational readback still gives k; raw node readback gives j. This is a
symbolic operational countercase to that stronger shortcut, **not** an
authenticated source/runtime counterexample or inference failure.

The owner is the original term/representative boundary
(`lib.rs:11428–11502`) together with the deliberate unchanged-field branch.
No new normalization requirement is imposed. The statement above preserves
the actual piecewise behavior and proves raw identity for freshly copied
direct rows where it matters. The first remaining premise for the exact
receiving-call application is the separately owned authentication of its
root output/PairGroup and exact raw field observations; this static note
does not identify `term 269` or RelationId 13.

Failure is outside the successful-return quantifier. Any allocation, identity,
kind/polarity validation or resource-sampling error may occur after private
mutation, including after finish but before the last sample (`:363–364`). The
local function drops scratch maps and releases their accounting (`:367–369`);
it does not itself roll back all persistent writes. Therefore neither `Err`
nor a retained partial group is a successful Function/output certificate.
The owning abnormal route must safely discard/stop or perform the required
rollback; full restoration is not invented as a general obligation.

`candidate_intrusion::State::rollback` truncates appended Parents/groups and
removes output-index group IDs beyond the saved group length
(`candidate_intrusion.rs:138–160`). Any certificate observation must remain in
the same live State before such invalidation. This note does not certify
coupled term/bound/context restoration, later union, completed replay,
publication, or successful suspension retention across all callers.

No two alternative proof attempts were made. A proof-obligation-economy audit
is therefore not triggered. Reconstructing field position solely from span
membership would be reconstruction debt: the owning Function builder already
has the exact child-key/slot array. This observation proposes no metadata,
semantic change or parent-gate reclassification.
