1. **Independent caller authenticity.** A separately justified introduction

## 5. Falsifiers and minimal implementation handoff

These are discriminating obligations, not executed tests or admitted original
source counterexamples:

- **Fresh equal-text parse:** create independent `P` and `P'` with identical
  text, module name and offsets. A binding introduced for `P` must not report
  successful correspondence to `P'`. The parse brands differ even if green
  syntax is shared. Accepting it falsifies premise 4's implementation.
- **Foreign module/declaration:** hold `P` fixed and request another `M`, or
  another same-name declaration/member occurrence. Success with the old
  association falsifies exact association; name/range/family equality is
  insufficient. `owns_source_key` alone is insufficient for this case.
- **Mixed owner:** introduce distinct `C1/b1` and `C2/b2`, allowing equal
  source spelling or equal family points. Swapping the retained owner while
  reporting the old owner association falsifies structural retention. Mixing
  semantic dependency/fiber references inside an opaque payload invalidates
  premise 5; the structural API cannot detect all such mixing. A malicious
  caller claiming authenticity lacks premise 1 even if keys match. Binding
  a new arbitrary payload to matching keys is not rejected as semantically
  false by this transport API; no authenticity success is reported at all.
- **Lifetime/rebinding:** release the caller's external handle while HIR,
  candidate or runtime still observes the binding. Loss of the retained
  allocation or exact keys falsifies owning retention. Payload mutation may
  change dependencies and invalidate premise 5 while structural retention
  still holds. No test of retained bytes proves semantic immutability or
  live event authority.
- **Fallback:** an absent/mismatching binding silently becoming a successful
  `empty()` binding falsifies premise 4. `empty()` compatibility alone cannot
  certify a source-bound caller context.
