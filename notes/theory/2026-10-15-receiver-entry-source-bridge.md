## 3. Direct receiving call, inner callback and repeated execution

Use the original source locator with f = cb, value binder v and Catch H:

```yulang
act tick:
    our next: () -> int
my relay cb = catch cb() { v -> v }
my answer = relay tick::next
```

This is the existing constructor-qualified shallow-Catch discriminator, not
a newly executed fixture or a wrong-subtraction counterexample. LocalSource
and preflight admit these shapes (`candidate_source.rs:99–149`); the value-only
Catch forwards the callback effect. No exact scheme or runtime success is
claimed. The same owner distinction applies to direct `relay provider` for a
known compatible callable provider.

C_in (`relay provider`) generates an upper demand on relay's callee Value;
when compared with the corresponding Lambda Function, its Argument edge
relates the actual provider Value to relay's original cb domain. That is
structural receiving incidence. The provider's own known Name supplies no
omitted-formal seed. C_cb (`cb()`) instead generates an upper demand on the
registered cb Value and receives the static directional record at its own
U.ResultEffect. Its argument is Unit. Neither the Unit nor the cb Apply
identifies the invocation of relay that received provider.

Under the selected source meaning, the original receiver for cb's receiving
boundary is the executing relay occurrence a. It is neither the static Lambda
L, nor the source call C_cb, nor the provider invocation entered by invoking
cb. Typed-boundary §6 expressly says that using a value as callee does not
make that callee's invocation a recipient of its public callee view. Private
captured bindings and actual arguments keep their own views. Hence the two
actual Function edges cannot be conflated into one boundary/receipt witness.

For repeated execution, a pure source scenario can use the same body call
twice through a wrapper (shown to explain the identity requirement, without
claiming a new executed or exhaustively admitted fixture):

```yulang
my provider ignored = 1
my relay cb = catch cb() { v -> v }
my invoke ignored = relay provider
my answer = { my first = invoke (); invoke () }
```

Its static C_in in invoke and C_cb in relay are unchanged across executions.
In the decorated source-owner model a first normal relay call enters a1,
returns through its exact delimiter, and expires a1; a later call enters
fresh a2. Thus the map “execution occurrence -> static source occurrence”
can be many-to-one. An identity function of C_in alone yields the same value
for a1 and a2 and cannot express both the expired old receiver and live new
receiver without an additional occurrence/lifetime distinction. Recursive or
raw-resumption re-entry makes the same issue relevant without distinct static
call sites. This elementary information-loss argument establishes insufficiency
of a static id alone; it is not a source-execution theorem or a proof that no
equivalent static guard interpretation can represent these distinctions.

Normal return is precisely where the gap matters even without an operation
event: neither completing `admit_lambda_fact` nor propagating its returned row
removes a source activation. No inspected source-to-native owner produces
such a completion object. The Draft owner model explicitly separates descriptor
i from occurrence a, requires fresh ordinary call entry and exact normal
return removal, and forbids reuse of an expired identity. For raw resumption
it distinguishes borrowed active spans from fresh replacement execution
spans, without rebinding old boundary receivers. Those are model obligations
available for correspondence work; they are not implemented by the listed
static constructors.
