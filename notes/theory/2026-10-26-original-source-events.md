## 4. Runtime identity, dynamic fields and description proof remain separate

`ActualKey` retains original declaration, full source occurrence route,
Binder, original actual parent path, occurrence and current core raw Runtime
operands. No decorated Event, descriptor interpretation or description proof
enters that raw key. `Assignment` has one value at each such key;
`same_assignment_same_key` proves that two descriptions cannot choose new
actual fields at the same key within one assignment.

`Description` stores frame/proof separately. `description_keeps_actual`
preserves the actual packet, while `Description.interpret` allows the
per-description proof to change its permitted decorated interpretation.
There is deliberately no blanket invariance theorem for the entire
`Event.witness`: existing `Decoded.logical` can change it, and SG explicitly
allows description-owned EventProof variation. The scratch probe changes a

`catalogue` uses one complete Joint as the index for all its field projections.
The six dynamic coordinates are eta, current runtime-witness data, scope,
authority, incidence and dictionary. They are complete output projections,
including inherited coordinates; declaring them does not invent a fresh eta
binder at every runtime transition. The original field meanings and permitted
proof interpretation remain independent.

`ownedReadout` is a computed local constructor of all six existing
RuntimeReadout fields at one registered owner/key. `owned_readout_computes_event`
proves its equation without a caller-supplied readback law. The original fiber
and eta0 come from the preceding event, and actual history/configuration come
from `Runtime.after`. `owned_invocation_current` confirms that a later
invocation uses its own raw current state rather than an exited maker frame.

This local closure captures route, parents and occurrence because the old
RuntimeReadout signature does not carry them. It is not one global lawful
readout for every source occurrence. No all-domain eventReadback law is inferred
from its local definitional equation.

## 5. Independent history data and the exact representation gap

`Initial`, `Response`, `RawResume` and `FutureUse` retain their original raw
contextual operands and a separate Joint assignment. Response and raw Resume
include the original invocation/other environment, request, operation,
original raw handle, continuation, pending suffix and response/current receipt.
FutureUse keeps actual returned provider/value/root/port, original context and
new invocation. Neither record construction nor erasure consults reached
traces, anchors, successful typing, membership or admission.

`record_roundtrip` and `raw_record_roundtrip` prove both directions of raw/
decorated record conversion. `dynamic_fields_distinguishable` permits two
separate source assignments to assign different dynamic fields to identical
raw operands. It does not choose two fields for the same key within one
assignment. `record_data_coverage` is explicitly only a data-grammar theorem.

`HistoryStep` and `RecordKey` retain all raw operation/handle/suffix and
returned-provider fields in actual identity, together with original routes,
parents and occurrence. These fields are operational data, not EventProof.
`record_assignment_shared` preserves one assignment at the same full key.
`sourceRecord` selects an actual generated owner and checks its structural
binder kind only. This sort check is independent of original semantic
admission. A record's semantic legitimacy and complete original owner relation
are not established merely by selecting a source declaration.

The formal-interface discriminator `different_operations_same_runtime`
shows two Response records with different raw operation declarations and
identical remaining operands whose `RawRecord.runtime` projections coincide.
Today's `Runtime.response` carries only ResponseData and therefore lacks these
explicit coordinates. This is **not** an original independently admitted
history counterexample: the theorem does not prove that the actual original
domain admits both records. Nor does it prove impossibility for every faithful
host interpretation; an actual original Receipt/owner relation can determine
additional fields. It identifies precisely what this bare current interface
cannot recover without that construction or richer inputs.
