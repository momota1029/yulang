## 4. Structural derivation, both formal edges and computation effects

A candidate constructor correspondence follows by induction on the finite resolved annotation value tree, conditional on an authentic port lowering at every child occurrence and the original value formation/`C_sym` derivations.

For Bool, Str, Int and Unit, `candidate_formal_value_pair` returns the existing polar leaves. For a value variable it returns two polar views of the same row obtained by `(scope,name)`. For a Function with argument `A` and result `R`, recursively obtain `(A+,A-)` at reversed variance and `(R+,R-)` at unchanged variance. Obtain each child's effect pair at that same child variance. The actual branch (:1134–1141) then gives:

```text
F+ = Fun+(A-, AE-, RE+, R+)
F- = Fun-(A+, AE+, RE-, R-)
```

Every Function child is covered: argument value, argument computation effect, result computation effect and result value. No child is skipped by the NPAIR replacement. The induction invokes N-Port-Intro only for resolved negative occurrences; ordinary positive and omitted rules remain their own cases. For multiple-symbolic cases its port premise remains open, so this is not universal formation closure.

Apply it to `A -> B -> [e] C` under the original negative formal. Both result descents preserve negative variance and both immediate argument descents reverse it. With ordinary omitted effect rows `X,Y,Z` and the adopted `Q_alpha±` over one `x_alpha`:

```text
Inner+ = Fun+(B-, Z-, Q_alpha+, C+)
Inner- = Fun-(B+, Z+, Q_alpha-, C-)
Outer+ = Fun+(A-, X-, Y+, Inner+)
Outer- = Fun-(A+, X+, Y-, Inner-)
```

`Y` and `x_alpha` are separate rows; the target occurrence is `f.result.value.Function.result.effects`. A concrete-only `[ctrl]` specializes the new row/Permission rule, not the whole domain to Unit/Int/nullary families. One shared row means the two projections of this occurrence share; it does not mean all occurrences with equal concrete sets share.

`candidate_formal_annotation` (:1191–1230) computes the **complete** pair using `candidate_formal_value_pair` at the root, reserves the domain entry, then calls:

```text

formal_domains[parameter] = Outer-
```

These are the two ordinary formal constraints `Outer+ <: P_f <: Outer-`, each with the actual Lambda occurrence and its own slot. The function checks `pair?` before either call; `formal_domains` insertion follows both. A failure between the calls is not successful pair publication. New metadata must participate in that existing publication/resource discipline; this note proves no rollback/accounting law for an unwritten representation.

The root computation row is deliberately excluded from `candidate_formal_value_pair`.
