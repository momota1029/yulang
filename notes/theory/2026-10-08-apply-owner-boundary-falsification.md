## Objective and result

Attack the inference that an authentic Gen-Call-0 record, a retained Apply,
or its same-solve candidate fact already supplies complete Application and
original CallInitial ownership. The smallest fixture-backed coverage witness
is `my grouped f = (f) 1`: the skeleton has one Apply but its direct-Use
source-call projection has zero records. The approved captured source supplies
the intended structural record; that record and its candidate fact explicitly
leave the semantic bridges unresolved. This is a missing-origin result, not
a counterexample to the selected language meaning or a source rejection.

The surviving conditional statement is: given authentic full formation and
independently supplied original initial/operator evidence, the selected
constructors and conditional source-base correspondence can be used at their
original indices. Neither the currently inspected identity carriers nor their
successful candidate solve establishes those hypotheses. No counterexample
to that correctly qualified statement was found by this bounded static method.

`Skeleton::application_source_occurrences` sees the Apply.
`resolved_call_incidences` requires its immediate callee to be `Form::Use`;
the immediate `Group` fails that match. `source_call_use_inputs` therefore
has no row, and Core `generate_source_calls` returns an empty vector.

The witness is structurally minimal for the wrapper omission: one application,
one non-Use wrapper, one callee leaf and one argument leaf. Removing the Group
gives the direct-Use route; removing the Apply removes the coverage question.
No shortest-byte claim or exhaustive grammar minimization is made. These are
inspected fixture assertions and a branch calculation, not newly run tests.

## Independence, coverage and failure conditions

The evidence is independent inspection of committed producer fields and branch
guards relative to authority documents. It is not an independent semantic
oracle. Existing fixtures share the parser, source artifact, HIR identity
machinery and candidate model. Crosswalk consistency and same-binary
noninterference cannot validate the rules they share. No checker, Oracle run,
build, compiler execution or new test was used; zero sample/process counts for
such experiments. Direct source authority is separate from the inspected model,
but conditional constructor laws were not independently proved here.

Exact implementation scope: HIR `SourceCallUseInput`,
`application_source_occurrences`, `resolved_call_incidences`,
`captured_call_input`, annotation references and default-off lowering guards;
Core pending/symbolic generators and annotation guards; solver pending Apply
inventory, `CandidateRelation`, candidate local-value emission, expression
emission and `admit_candidate_fact`; focused existing HIR/Core/candidate
crosswalk fixtures. This is not a full call-site or repository audit.

Failure conditions for this characterization: changed dependency bytes;
new immediate-callee traversal; a new complete typed owner certificate or
original initial-rule supplier in the inspected path; changed annotation
ancestry guard; or an interpretation that actually equates the candidate
effect model with the original complete invocation. Such changes need a new
scope check. Even a complete new constructor would still need its actual
well-scoped rule insertion and lawful interpretation/transport; a reference to
a Call or successful query alone would not suffice.

Unverified: actual production acceptance/execution, complete original worlds
and imports, effectful/computed callee semantics, general annotations, State,
recursion, arbitrary local generalization, all Option 2 alternatives,
source-wide emission completeness, solver discovery and principality. No
counterexample to the fully qualified H_owned conditional has been established.
The precise blocker is the absent actual original initial operator telescope
and checking-origin supplier. Another equivalent endpoint checker would leave
it untouched; redirect to that owning construction output.
