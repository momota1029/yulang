# Source-owned record boundaries with constructed recursive children

Date: 2026-10-26. Status: frozen author construction, awaiting independent review.
Baseline: `45d307a0aa01722b5aac289b07d71953630abca7`, `yulang3`.
Implementation: `lean/YulangClosure/OriginalSourceRecordBoundary.lean`.

The original parent remains whole-Yulang soundness, full Effect hygiene,
principality and inference termination. This module constructs one substantive
source-boundary component. It does not instantiate the complete original
`SourceProblem`, interpret all of `Kernel`, or claim native inference success.
The supported original language is unchanged.

## 1. Original rule and exact contribution

The represented rule is the direct record adaptation in
`docs/yulang-whole-language-semantics-ja-expanded-20261023.tex`, section
“省略可能レコードを解釈する境界意味論”, particularly its one-boundary construction,
ordered execution, nontransitivity and non-resurrection clauses. That manuscript
is a research specification, not blanket authority for a production change.
The current native static shape rule was read at
`crates/yu-solver/src/lib.rs:14593–14644`: first source-label occurrence,
increasing target index, missing optional acceptance, missing required diagnostic,
optional-to-required unavailability, and every common payload comparison.
No compiler file or expected output was changed.

The earlier `RecordBoundaryPreservation`, `NativeRecordPlan` and
`RecordBoundaryExecution` modules construct shape/plans and prove compositional
execution under supplied child contracts. The new module supplies an executable
recursive child family: identity on an independently typed leaf, and finite
nested record adaptation. It constructs the shape, fills every child from the
same recursive algorithm, executes the resulting code, and proves the child
contracts itself. The public preservation and source-application theorems do
not accept a caller's `ValidPlan`, `ChildrenSafe`, source typing derivation,
complete Call certificate or native-success assertion.

The original source ownership comes from the existing raw-source builder.
Expression annotations retain `synthesis -> writtenTarget`; binding annotations
retain `initializer.finalRoot -> binding.writtenTarget`. These are separate
operations in `OriginalSourceGeneration.sourceRules` and `bindingsRulesK`.
The construction does not equate the two input ports or insert conversions at
unannotated variables.

## 2. Independent data and executable construction

All new declarations are under `YulangClosure.OriginalSourceRecordBoundary`,
except declarations generated by Lean while elaborating imported equation
lemmas; the audit includes those by originating module.

`Ty Atom depth` presents finite nested records over arbitrary primitive leaf
descriptions. `Value Payload depth` presents their currently visible values.
The natural-number index is a representation-depth bound, with no fixed global
limit: the theorems quantify every depth. It is neither inference fuel nor a
new language rejection limit. Cyclic/regular descriptor conversion is a separate
unrepresented case.

`Typed leaf depth value type` is independent of compilation and execution.
At leaves it uses the independently supplied relation `leaf`; at records it
uses the existing `ViewTyped`: required fields are present, present payloads
have their declared types, and undeclared labels are invisible. The leaf
relation may be instantiated independently; no semantic preservation law is
required because the represented leaf operation is identity.

`Cast` is raw executable data. A record node retains:

- the original complete boundary owner;
- the ordered `NativeRecordPlan.Slot` list, including each original lower and
  upper field index and all optional bits;
- the ordered `FieldPlan` list, with recursively constructed child code.

`construct` is total structural recursion on the declaration depth. It checks
identity leaves by equality. For a record it invokes the existing exact native
shape construction and fills all its holes with recursively constructed code.
There is no runtime value in its input. Thus absence in one runtime input cannot
skip a common optional field's static comparison. Failure constructs no adapter;
it is not interpreted as a native diagnostic, source rejection policy, or
proof that the original language has no other legal conversion.

This constructor uses the native static presence branch. A missing source field
can supply only an optional target; a common optional source cannot supply a
required target without the separate original input-specific presence mechanism.
That additional mechanism is not fabricated here. All common optional payloads
are retained and checked.

`run` reads only the current visible input. It visits target fields in order,
preserves absence, applies the stored child to a present payload, and returns
only target fields. There is no backing-object lookup. Runtime execution never
consults `Typed` or a proof. Raw malformed adapter data is not certified by the
theorems; successful construction supplies the shape invariant.

## 3. Source owners and declaration readouts

`sourceOwners` traverses `sourceRules context source`, not a caller-supplied rule
tree. It registers **annotation boundaries** by pairing the actual boundary
premise with its matching `finalAnnotationFormation` atom. Other source boundary
families are outside this annotation inventory. Each `Owner` retains the exact
site, context, lower/upper ports and written annotation ID, the static child
route, and every enclosing existential, universal, Shared, initializer,
execution, publication, publication restore, alias and choice frame. Choice
frames retain their original site and branch.

This inventory is a static traversal, not a general source execution schedule.
In particular, compiling the inventory is not an interpreter for all source
constructors. The concrete sequence below applies the two constructed boundary
bodies in the original initializer-then-binding order.

`Declarations` contains only raw independently registered readouts: an endpoint's
description, a written annotation's description, and the direct conversion
identity for a boundary. It has no field asserting preservation, source typing,
complete world validity or solver acceptance. `compileOwner` uses those data to
construct a `Program`; `compileSource` traverses the complete registered
annotation inventory, failing if any registered boundary cannot be constructed.
It does not silently drop a failed annotation.

`compile_owner_readback` proves that a program retains exactly its owner,
declaration, input/target descriptions and computed code.
`compile_owners_exact` preserves the complete inventory and its order;
`compiled_source_member` connects every returned program to the raw source.

`recordKernel` is a **local generated-conversion extension**: it preserves every
old conversion as one disjunct and adds the explicitly registered source record
programs as the other. `constructed_original_boundary` supplies the original
finite grammar's `Boundary.actual` constructor for that extension. It does not
prove equality with an arbitrary pre-existing `Kernel.conversion`, authenticate
an arbitrary supplied global declaration table, or supply the other six Kernel
meanings. Its typed execution justification is the independently proved adapter
construction. Identifying this generated code with the complete original
declaration/descriptor interpretation remains a source-owner obligation.

## 4. Checked theorem applications

| Declaration | Actual premises | Constructed conclusion |
| --- | --- | --- |
| `construct_preserves` | Arbitrary leaf typing; depth/owner/descriptions; the result of running `construct`; independently typed input | The actual recursive `run` result has the target type. All recursive child preservation is proved internally. |
| `common_payload_constructed` | A built record adapter and a declared common target field | Its payload child was successfully constructed, without any runtime-presence premise. |
| `constructed_survivors` | Built record adapter and independently typed visible input | Output presence equals input presence intersected with target labels. |
| `successive_boundaries_survivors` | Two separately built adapters and the first typed input | The second consumes the first output; surviving labels intersect both intermediate and final signatures. No direct-comparison transitivity is used. |
| `pure_scan_completes` | Raw finite pure plan/input | An actual `RecordBoundaryExecution.Trace` to the `run`/`execute` result. No normal execution or termination premise is supplied. |
| `constructed_record_execution` | The constructed record adapter and raw input | The actual ordered driver reaches its returned result, retaining the exact built plan. |
| `constructed_children_safe`, `constructed_record_prefixes` | Construction and input typing where applicable | The represented children's contracts and every finite outer scan/child prefix are proved. |
| `compiled_source_preserves` | Raw source, independent declaration readouts, successful boundary-inventory construction and an independently typed boundary input | Every constructed program's actual result has its target type. No whole source derivation is an input. |

The represented operations are pure identity/record operations. Their request,
response and failure types in the instantiated driver are `Empty`; no foreign
response law is hidden in this fact. The recursive pure evaluator computes the
nested child value atomically relative to the outer driver, which records its
ordered scan/child execution. No full nested microstep correspondence is claimed.
This is not the original theorem for arbitrary effectful user-defined child
casts, whose full contextual contracts still need construction.

## 5. Concrete raw-source instance with no local proof premises

`Witness.original` is the canonical raw binding constructor:

```lean
.binding 20 30 (some 101)
  (.record ⟨10, some 100⟩
    (.recordField 11 0 (.literal ⟨12, none⟩ (.int 1)) .recordNil))
  .bindingsNil
```

Its local registered type data assigns annotation 100 the empty record and
annotation 101 the optional integer field. The integer/string leaf meanings are
defined explicitly on `String ⊕ Int`; the two Boolean leaf tags are just the
finite representation of those declarations. The input is the visible record
containing integer 1 at field 0, matching the raw literal constructor.

| Constructed boundary | Exact input port | Written output port | Enclosing scope | Conversion ID |
| --- | --- | --- | --- | --- |
| Record expression annotation | `(10, synthesis)` | `(10, writtenTarget)` | `initializerE 20` | 910 |
| Outer binding annotation | `(10, finalRoot)` | `(20, writtenTarget)` | `initializerE 20` | 920 |

`original_boundary_owners` derives that exact two-entry inventory from the raw
source. `original_source_constructs_both` runs the whole boundary compiler and
constructs both programs. `input_typed` has no premises.
`original_source_sequence_typed` then applies `compiled_source_preserves` twice,
using the first program's actual result as the second input. Neither child
safety nor intermediate typing is assumed.

`source_sequence_does_not_resurrect` computes the first output as the empty
visible record and the final output as an absent optional slot. It cannot
rediscover the original integer field. `absent_common_is_statically_compared`
computes rejection of incompatible common optional payloads even alongside an
empty runtime input. `nested_identity_and_record_construct` constructs a
depth-two adapter whose present child is itself a record adapter, and computes
its exact nested result. These are checked semantic discriminators, not a claim
that a source/native implementation test has run.
