## 1. Purpose and authority boundary

This draft addresses the first missing owner for the selected negative
concrete-formal policy. It does not select a new meaning for `[E]`, enable
general concrete-formal admission, close hygiene theorem H, certify current
candidate behavior, or authorize a production cutover.

The adopted annotation policy fixes these facts: at an actual composed-
contravariant concrete effect port, `[E]` permits attachment-local subtraction;
an independently sourced same-family contribution survives; symbolic
connections remain active. The attachment decision fixes one identity per
concrete set at one exact annotation occurrence, preserves member ordinals,
and keeps distinct residual-construction lineages and their exact tails.

The selected native signature clauses (`L-Annotation`, `A-Annotation`, and
`SF-Annotation`) consume an independently derived original annotation rule,
governed-port correspondence, and realization evidence. They do not construct
that application. The bounded source construction and source-owner audit
confirm only that this input is unprovided on the inspected Y3 route; they do
not establish a source-wide absence theorem. The proposed construction below
is therefore a candidate contract whose conservativity and source
correspondence remain unproved.

## 2. Original indices and proposed formation output

At Lambda-before-body, retain the actual Lambda, formal registration,
annotation occurrence `a`, original binder tree/scope `sigma`, inference level,

path `h`. Preserve each concrete member as `(source ordinal m, resolved E_m)`

or member by nominal equality, a solver row, a value SCC, or a later output.

The proposed formation result is a paired checking/exposed interface and one
attachment identity `A(a,C_a)` for the exact concrete member set `C_a`. It
retains the governed path `h`, member ordinals, resolved operands, original
scope, symbolic connections, and the actual source-owned route map. Creating
this interface does not create a `Contribution`, assert a provider exists,

Contribution incidence is created only when an actual original contribution
witness is transported across the actual governed-port injection. The
candidate incidence record is:

```text

```

where `w` is that same original contribution witness, `rho` is its actual
source route and introduction, `m` is the applicable resolved annotation
member ordinal, and `a,h` identify the attachment occurrence and governed
port. Its constructor must preserve the route derivation; equality of family,
row, value or SCC cannot establish `Inc`. The source rule that proves the
actual route crosses `h` is a necessary independent premise and must be
identified at its owner. The incidence is neither minted from annotation
support nor inferred from later receiver membership.

## 3. Demand and residual consumer contract

The negative annotation is not the later concrete upper-row demand. The
inspected `shadow_apply` Function demand carries an invocation effect variable;
the inspected `candidate_signature_effect` path forms an `Allowance` with its
own exact optional tail. Neither has yet been shown to produce the required
concrete `Row` upper. No demand producer is selected by this draft.

An authentic demand must retain one correlated derivation of:

```text
D = (source/check derivation, receiving source u, concrete upper heads I,
     exact upper tail t or closed-tail case, ordered context chi,
     complete contribution and route parents)
```

For each actual residual construction lineage `ell`, the consumer must jointly
retain:

```text
Recipe_ell = (ell, u, retained heads J_ell, residual context K_ell,
              gamma g_ell, source feedback,
              every actual outgoing projection g_ell -> t_(ell,j))
```

One constructor derivation must account for both the source feedback and each
exact outgoing tail projection, including cache reuse. Empty-retained and
self-tail cases require their own source rules. The consumer must preserve
existing independent contributions and admit every applicable later lower
to each retained recipe.

The source owner that lowers a real concrete upper `Row`, supplies its exact
tail and ordered context, and connects it to a live residual consumer is
currently unknown. An `Allowance` membership result, discharge identifier,
annotation symbolic variable, or family lookup cannot substitute for this
producer. This is the first explicit obstruction in the demand half of the
contract.

## 4. Required order and transport obligations

The proposed construction must preserve ordinary Simple-sub scheduling and
accumulation. For a newly registered attachment, check already applicable
lowers; for a newly arriving lower, encounter existing registrations and all
applicable retained residual recipes. Keep original parent derivations and the
actual directed replay order. Do not require eager solving at source
generation.

The same governed-port/contribution incidence and each residual lineage must
survive actual Call/output transport, directional propagation, freshening,
extrusion, and qualifying parent/copy intrusion. Fresh uses share mapped
coordinates within one use while receiving distinct local authority across
uses. Function argument ports reverse endpoints and context; result ports
preserve them. `both` requires the source-owned inferred-entry certificate.
Qualifying intrusion may equate actual parent/copy rows and transfer both
bound sides; it cannot create annotation eligibility or merge lineages.

These are obligations, not established transport facts. A complete source
Call tree, output route, actual Row demand, current/future fanout and every
relevant copy/alias path remain to be constructed and proved under the
original H quantifiers.

## 5. Discriminator and falsifiers

Use two original contribution witnesses `w_a` and `w_b` of the same resolved
family `E`, with independent introductions and source routes. Both reach the
same receiving source `u`, but only `w_a` crosses the actual governed
annotation port and receives `Inc(a,h,m,w_a,rho_a)`. The independent `w_b`
does not receive that incidence. Insert one applicable lower before residual
registration and the other after it. Construct two genuine residual events
`ell_1` and `ell_2` with distinct exact tails `t_1` and `t_2`, even if their
current source and residual heads coincide.

Acceptance requires attachment-local removal only for the licensed incidence,
survival of `w_b` in each applicable residual history, both lineage-owned
feedback/projection pairs, and propagation of each applicable earlier/later
lower. Symbolic connections remain active. A family-wide deletion, a new
license from row/SCC equality, dropped tail after a cache hit, merged residual
lineage, or fabricated contribution witness falsifies the contract.

This is a structural discriminator, not an admitted source counterexample,
reached Y3 demand, inferred scheme, or proof of H.
