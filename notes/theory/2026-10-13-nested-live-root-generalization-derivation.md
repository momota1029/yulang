## 1. Frozen objective and outcome

For a nested nonrecursive helper g formed while its enclosing recursive f
initializer is active, derive registration and generalization from the actual
constructors. f remains one live monomorphic open root. Preserve lexical
identities, the original parameter type scopes and actual event telescopes,
every complete source clause, the retained extrusion event and all its signed
pairs/equalities, and ordinary independent g descriptions. Apply the result
to the existing correlated-helper witness and the user's exact odd/even.

The source-level statement ranges over every finite lawful joint use of these
fixed sources under their genuine local constructor laws. Independent uses
may vary eligible descriptions; recursive f references cannot introduce a
second f root or polymorphic recursion. Actual providers, initialization,
receipts, witnesses, worlds, continuations, attachments and residual lineages
remain at their original scopes. The desired conclusion is an exact
registration/allocation bridge preserving the original ordinary inference and
required principal coverage. A candidate assignment is not that conclusion.

Accepted inputs from the primary's architect/audit packet: no adopted
constructor labels the active outer f as `Internal(K_g,f)` or external
`Mono/Established`; the Value-reference SCC does not define `K_g`. Legitimate
missing mathematical definitions may be proposed, but arbitrary semantic
success assumptions are unauthorized.

**Outcome:** the reference's actual g publication/use constructors determine
the answer for the native history: C is shared across independent g frames.
There is no native-allocation ambiguity. Source Generalize has no corresponding
active-outer-root capture rule from which its typed source allocation follows.
Keeping one f root by itself does not supply that rule. A root-preserving
allocation with fresh C_i is mathematically distinguishable and consistent
with the exhibited scalar clauses, but changes the actual native freshening
map. It is not an established preserving completion of Simple-sub.

The exact residual premise is the source/operational law for the **complete
helper description dependency on an active outer inference root**: does the
source interpretation retain the native shared demand coordinate C, and how
does the equality clause use that coordinate in independently allocated
helper descriptions? Sections 5–7 make this one choice concrete. No additional
generic missing-record census is offered.

Claim classes: conditional constructor-directed candidate; bounded native
allocation derivation; two conditional scalar allocation calculations. No
full Yulang derivation, principal-scheme theorem, source-qualified refutation,
independent certification, implementation authority or parent intrusion closure.

## 3. Constructor-directed candidate, with the missing clause exposed

The following registration prefix is directed by source construction rather
than Value SCC reconstruction. It is a candidate retained output, not an
adopted addition to §3.3's record catalogue.

1. On f's recursive definition introduction, register its actual binding,
   provider and **one** open monomorphic root o. Its own definition registration
   supplies `K_f`. Preserve its pending initializer/body rule program.
2. Enter g's sequential initializer while that entry is active. Register g's
   own definition component `K_g` and final-root formation boundary. For this
   nonrecursive helper, registration has one newly introduced member g; it
   does not infer a simultaneous f/g group from the Value cycle. The source
   publication event is `p_g(h)` beneath its actual enclosing f invocation h.
3. Parameter introduces `Desc(K_g,q_y,Value,sigma_y,Delta_y)`. `sigma_y`
   precedes g's own challenge/event k and retains the original enclosing h
   dependencies. The outer formal's declaration stays at its original f type
   scope; no parameter is reintroduced by a recursive Name.
4. A resolved f Name records the actual active-entry reference to o and its
   complete open dependency relation. It cannot record an independent `new`,
   an established contract that has not been installed, or a same-component
   `Internal(K_g,f)` not emitted by registration.
5. Build emits each original local clause and its complete operand telescope.
   Call keeps the actual callee computation, inert whole argument, returned
   callee/receiver, receipt, entry, designated consumption and invocation
   return. Retain guards, worlds, effects, future fields, witnesses and pending
   suffixes. An actual extrusion retains e, G/F, and its actual signed pairs;
   the qualified equality is an additional clause with those same incidences.
6. Publish g's actual final formed root after its initializer clauses. One-shot
   initializer fields and actual providers remain shared. Independent g Name
   uses may allocate g descriptions; aliases reuse their existing frame.

Steps 1–5 identify the facts the actual constructors know. Step 6 cannot be
completed by the adopted Generalize walk until step 4's **active-entry
dependency** has a law. Its missing treatment is exactly the one exercised
by C in §5. This candidate deliberately leaves that treatment explicit.

The missing record is natural construction data: the scheduler already knows
whether a callee comes from `active_initializers`, and extrusion already knows
which demand operands entered that active root's bound store. It is not a new
user-visible source distinction. Retaining those facts does not itself prove
their source-lawful interpretation.

Two tempting existing record choices fail to supply the missing law:

- `Mono/Established` applies to an actual installed certificate. f is still
  open. Treating every field currently accumulated on it as an established
  source contract assumes precisely the desired sharing conclusion.
- `Internal(K_g,f)` makes f part of g's whole validating component. The adopted
  `new` rule allocates that whole component and its eligible descriptions.
  One cannot independently copy f's tuple and simultaneously claim the same
  open recursive tuple remains monomorphic. An extra rule that pins selected
  members while copying others would again be the missing active-root law.

The adopted bare simultaneous pair and the formal-capture example in §5.3
do not resolve this case. The former has genuine two-member registration;
the latter captures an actually rebound formal contract. This f has neither
of those constructor outputs. No component or provenance tag is inferred
from provider equality, the Value SCC or a numeric level.

## 4. Exact native publication and use of the correlated helper

Keep the existing source:

```text

  let g = lambda y. (lambda z. y) (f y)
  in {a = succ (g 0), b = g true}
in f
```

The reference's actual builtins supply `succ:int->int` and `true:bool`.
All displayed AST forms are in its original grammar. This is a successful
reference typing, not a Yulang complete-Call derivation or execution claim.

The root/level/register history is forced by the cited constructors:

| Cut | Root / declarations / generated relations |
| --- | --- |
| f RHS, boundary 0 | o and outer formal A at level 1; context f maps to the monomorphic o |
| g RHS, boundary 1 | B (y), Z (z), R (`f y` result), S (wrapper App result), all at level 2 |
| Inner recursive App | Lookup returns o; generates `o <: Function(B,R)` |
| Negative demand extrusion | Creates C,D at level 1; stores `B <: C`, `D <: R`, `o <: Function(C,D)`; one retained G/F event, pairs `(C,B,+,1),(D,R,-,1)` |

| Actual g publication | `PolymorphicType(1,Function(B,S))`; there is no recursive placeholder for this nonrecursive g |
| First g use, at level 1 | Reachable B/S are freshly mapped to B0/S0; C remains itself; bounds `B0 <: C`, `B0 <: S0` |
| Second g use, at level 1 | A different map gives B1/S1; **the same C** remains; bounds `B1 <: C`, `B1 <: S1` |

`Function(B,S)` at this cut, so that native g lookup does not freshen them.

retains the inner Call even though the returned Function graph lacks those
coordinates. Identifying its full source/effect/event meaning with this native
root-reachable graph still needs the genuine complete-Call correspondence.
It cannot be justified by deleting the discarded call or its result evidence.

The first source use adds
`int <: B0 <: S0 <: V0 <: int`; the second adds

replay succeeds. In particular C has no upper edge back to B0 or V0 merely


`mu_i(C)=C` follows from the executable early return in `freshenAbove`.

This calculation does not rely on separate marginal witnesses, any new W,

For F, the whole displayed scalar constraint system, including the base
intrinsic clauses and both translated demand/equality clauses, has the joint
assignment below. Let `T=Record(a:int,b:bool)` and use semantic algebraic
top/union, not invented native SimpleType constructors:

```text
o = top -> T          A = top
C_base = B_base = S_base = int | bool
D_base = R_base = Z_base = T
B0 = C0 = S0 = V0 = W0 = int
B1 = C1 = S1 = V1 = bool
D0 = R0 = Z0 = D1 = R1 = Z1 = T.
```

The base demand holds because `(top -> T) <: ((int|bool) -> T)`;
the frame demands hold because `(top -> T) <: (int -> T)` and
`(top -> T) <: (bool -> T)`. Each wrapper accepts T and returns its own
argument description. `C_base <: A` and `T <: D_base` hold. All frame
equalities hold jointly; neither frame requires `bool <: int`.

This is a satisfiability characterization of a fully displayed scalar
constraint set, **not execution of an alternative solver**. No full Call,
effect, event-field or arbitrary-history witnesses are supplied by these
scalar assignments. The known complete original native run is the ordinary
one in §4, with independent B0/B1 and shared C and without the new equalities.

The source typing shape explaining the ordinary run is small. Give the one
recursive f assumption `(int|bool) -> T`. For a g parameter description beta
with `beta <: int|bool`, `f y` has result T; `lambda z.y` can accept T and
returns beta. Hence g has the bounded identity relationship
`forall beta <: int|bool. beta -> beta`. The use `g 0` returns int and
`g true` returns bool; the enclosing record produces T. The
`lambda x. ...` with domain int|bool discharges the same recursive f

This is an ordinary algebraic source derivation for the reference constructors
under their genuine scalar contracts. The paper's printed §5 theorem does
not prove its let-polymorphic extension, and the derivation is not a principal
public Yulang scheme or an adopted Yulang complete-Call rule. It shows why
monomorphic f alone cannot justify making beta equal to its shared admissible

Consequently:
