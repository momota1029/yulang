## 2. Separate the receiving call from the callback invocation

Fix the original source example and two different Apply occurrences:

```yulang
my relay cb = catch cb() { v -> v }
my answer = relay tick::next
```

L is relay's Lambda, C_in is `relay tick::next`, C_cb is `cb()`, H is its
Catch, and v is the original value-arm binder. These locators illustrate the
unmodified quantified claim; this assembled input was not executed here.
Let u_L denote the invocation of relay created by C_in. Under typed-boundary
§6, the relevant parameter receipt is

```text
Receive(u_L, slot_cb, actual_received_cb_view, M_in)
```

It is created when u_L obtains its actual argument view, not by inspecting the
callee of C_cb. At C_cb the actual argument is Unit; its negative Function
demand constrains cb's invocation. A record authenticating that cb is C_cb's
formal callee does not authenticate its receipt as C_in's argument. Using cb
as a callee also does not make cb's own invocation a receiver of cb's public
view; its private bindings retain their own views. This is the explicit
callee/binding distinction in typed-boundary §6.

Likewise, E_L <= R_L is relay's inferred argument-entry flow. E_L describes
forcing the computation supplied as relay's argument, before rebinding cb.
It is not itself the latent invocation-effect position exposed by `cb()`.
Identifying these positions would attach the wrong context, even if their
eventual rows happened to be equal.

## 4. Fresh uses and the exact consumer boundary

`prepare_candidate_fresh_use` (`candidate_scheme.rs:1009–1137`) uses one
canonical row map per use. Eligible local generic rows receive new rows;
nongeneric/older coordinates reuse their representative. Attachment bundles,
effect operands/views, local weights and context inputs have separate per-use
remaps. These are actual existing maps; they are not a demonstrated map of
typed receiving-view evidence.

At `:1173–1188`, Function reconstruction uses only the four reconstructed
child Terms and polarity, calling `positive_function_term` or
`negative_function_term`. Those constructors (`lib.rs:10287–10314`) accept
four Terms only. They do not allocate or validate u_L, slot_cb, a boundary
profile, its type-position incidence, M_in or a receipt. No authentic source
formal/profile-to-reconstructed-Function association is returned here.

`begin_candidate_fresh_bound` (`candidate_scheme.rs:1253–1301`) creates a
fresh transport relation with mapped context and bundle links. It imports the
captured evidence snapshot as antecedent and retains use origin/source bound.
This preserves the specified bound ancestry; `EvidenceSnapshot` records bound,
relation, admission/emission heads and coverage
(`candidate_context.rs:362–367`). Import merely interns that snapshot
(`:1587–1592`). Neither import nor physical bound restoration is a receipt
of an actual source value by an invocation. Stored antecedents alone do not
establish activation or complete replay of a new profile.

The real Function comparison creates four field pairs with reversed argument
endpoints and preserved results (`lib.rs:12520–12547`). Its dispatch calls
`candidate_function_port_admit(task, field)` (`:12667–12695`), whose inputs
are the child task, field and retained processing parent. The consumer
(`candidate_context.rs:2653–2705`) takes the parent's post-check context,
swaps argument fields, preserves results, prefixes a local checking wrapper,
and records the FunctionPort dependency. It consumes an inherited context;
it neither derives a source boundary nor checks a receiving-view witness.

This is a missing consumer operation, not proof that original formal incidence
cannot be recovered from retained source-bound transport. It is not a reason
to add a global lookup keyed
by reconstructed Function Terms or canonical rows. Profile incidence belongs
to an exact view/path and its source receiving boundary; structural equality
can coexist with distinct boundary views. Bound ancestry and Function shape
cannot silently be assigned the meaning of `Receive`.

## 5. Static receipt candidate: actual bounded derivation

The primary requested an explicit check whether the authentic argument-port
constraint could supply the narrow static source correspondence, without
requiring dynamic Receive or full Call. That distinction is valid. The
following bounded derivation follows the real constructors for a successfully
admitted `relay tick::next` comparison; it assumes no callback profile.

Write F_L = Function4(A_cb-, E_L-, R_L+, V_body+) for the original L
constructor. L slot 2 admits F_L+ <= root_L-. Capture retains its current
Function-bound item F_cap in `source_bound`, together with the structural
node. At an untransformed L slot-2 bound F_cap is F_L; if prior extrusion
replaced it, correspondence to F_L additionally requires that actual prior
transport derivation. Equal child rows cannot establish it. The captured
Function identity is therefore retained in bound provenance even though absent
from the structural node. For a captured bound with a retained relation,
fresh-bound restoration pairs that source bound with the rebuilt Function
endpoint in
`TransportWitness { from, to, reason: FreshUse }`
(`candidate_context.rs:3242–3252`). The source child indices and one per-use
row map supply a structural domain map domain(F_cap) -> domain(F_cap^use)
while it is a row. Identifying its source with original A_cb requires the
authenticated L-domain derivation just described. No equality-based
authorization is used here. When a captured bound has no relation, its
`source_bound` and imported snapshot remain, but this restoration path creates
no Transport dependency.

C_in generates the actual demand
Function4(V_arg+, Q_arg+, I_in-, V_out-). When the native drain compares
rebuilt F_cap^use against it, the real argument child is

```text
V_arg(C_in)+ <= domain(F_cap^use)-
```

The supplier is `lib.rs:12520–12527` followed by
`candidate_function_port_admit`. Its FunctionPort dependency records the
actual parent relation and Argument field; child endpoints are precisely those
operands. `relation` inherits the processing parent's source events
(`candidate_context.rs:2296–2303`); replay retains both parent dependencies
and FreshUse transport retains `from`/`to`. Thus this is genuine static
source-to-native type-position correspondence. Absence of a complete dynamic
receipt does not invalidate it. Unknown domain rows suffice; no eager solve is needed. This establishes what
the actual comparison emits when dispatched, not executed reachability of the
assembled source string or complete prior extrusion/source-formal lineage.

Those source events are Value-graph Call associations,
`Association { origin: owners[index], receiver: expression_value(callee) }`
(`candidate_value_graph.rs:159–169`). They authenticate Value incidence
for intrusion, not callback view/profile incidence. The argument child is an
available carrier for source-owned protection. It does not itself introduce
the omitted profile or its applicable effect-position domain; the consumer
swaps only already inherited context. Typed-boundary §6 explicitly separates
boundary introduction from typed transport, and receipts create ownership
edges without creating boundaries/contracts.

The answer is **yes for the bounded static argument type correspondence**;
**no for the original protection conclusion from the existing records**.
The exact first missing static judgment is

```text
The omitted contract at original (L,cb) introduces profile b on its
applicable typed paths, and the authentic C_in Argument correspondence
carries that same b/view incidence into A_cb^use on those paths.
```

This static judgment does not require a dynamic u_L or full Call closure.
Its actual producers must be source boundary formation and the binding of
its incidence to the existing correspondence. No reached omission action or
Function-port consumer introduces that incidence. Alias/return paths, multiple
fresh uses and future demands still require original H1/H2 preservation; the
bounded constructor derivation above does not close those quantifiers.

## 6. Additional dynamic receipt judgment and its actual owner

The required source bridge contains distinct judgments:

```text
J0  Authentic omitted source formal (L, cb, scope, A_cb).
J1  Source boundary b and applicable profile rooted at that unknown formal.
J2  Typed value/path correspondence through each actual capture/fresh use.
J3  Actual C_in receiver binding:
    Receive(u_L, slot_cb, same_received_view, M_in).
J4  Observe(q, executing_view, matching_effect_path) from actual C_cb CallView.
J5  Profile + matching Flow/Receive/Observe + exact activity => Path/Inc.
```

J0 has actual producers. J1 is already unsupported by the reached omission
route. In addition to §5's missing static profile incidence, no inspected
authentic supplier of J3
relates C_in's actual argument view to reconstructed L's formal binding and
its current invocation owner. J2 is also not supplied for profile packets;
structural/per-use row maps prove only the bounded type-position part in §5.
J4 is a separate observation
premise. The existing reviewed transport theorem justifies J5 only after
those source judgments exist under the same assignment; it cannot emit them.

This is visible at the intended Call seam, without assuming its completion.
`candidate_call::observe` (`candidate_call.rs:285–440`) validates authentic
Apply operands, occurrences/scopes and NativeInterface polarities; for direct
formal uses it authenticates the original formal registration and the
Group/Ascription/Block routing spine. It returns `CandidateSourceCall`,
expressly not a complete Call certificate (`:131`). A local alias or returned
callee has no such direct-formal hint. More fundamentally, even the direct
hint authenticates C_cb's callee, not C_in's actual parameter receipt.

`PendingCallConstruction::suppliers` (`:224–245`) requests
`OriginalGenCall0`, `ArgumentReifyAndWholeCarrier` and
`ReceiverDispatchAndCompleteResultFutureInterfaces` for every source Call.
Its OriginalGenCall0 input list (`:93–128`) still requires the original
argument interface, complete demand, declaration and complete output position,
among other coordinates. No returned field supplies J3. Substituting its
`checking_occurrence`, `native_registered_root` or `source_level` for a current
receiver/typed-view receipt would assert the very supplier this interface
marks pending.

Owner: actual source Call argument-entry/receiver-dispatch construction at
`candidate_call`/`shadow_apply`, coupled to `admit_lambda_fact`'s formal
binding and `candidate_scheme`'s path-preserving capture/import. Consumer:
`candidate_function_port_admit` plus actual observation/context discharge.
This does not make whole-Call closure or a new registry a prerequisite to
ordinary inference. It says that *this proof's receipt* must be supplied by
its real owning operation. A bounded constructor supplying that operation
could establish a bounded H1 bridge without claiming full Call completion.

Claim class: bounded constructor correspondence, source/construction obstruction and proposed preservation

## 7. Economy audit and one decisive next action

Original H1 is A/B. Discarded source formal/view incidence creates D risk at
structural Function reconstruction, but renaming H1 as D cannot close it.
Retaining the source-known L/cb/omission fact is natural at source formation.
The actual receipt is known only when the source operation obtains its typed
argument/binding view; retaining an L ID earlier does not supply that fact.
The two obligations have different producers and cannot be merged into one
invented profile token. No extra reconstruction calculus, eager type solving,
blanket invocation protection or restriction on aliases/returns is justified.

The static discriminator is one authentic C_in -> parameter profile incidence
-> C_cb path under the same sigma: demand the source boundary producer's
output and its incidence on the already-derived Argument correspondence.
Dynamic receipt/receiver activity remains a separate source bridge. Validate that cb(),
alias cb, and returned cb preserve that same profile through their matching
typed paths, while a local direct operation has no such path. The exact first
failure is inability to introduce and carry the omitted boundary profile at
the real source binding, rather than failure of a checker that assumes it.

One next action for the primary: assign the missing source profile introduction
and incidence on C_in's authentic Argument correspondence to its owning source
construction lane, with a
minimal reversible source-qualified certificate/observation slice if needed.
Require its source output before another preservation proof or H3 activation;
keep dynamic J3/J4 suppliers separately OPEN.
Do not request another profile-assuming lemma or claim that inventing a field
layout establishes the receipt. Fresh independent compiler-referee review of
this frozen obstruction remains required; this producer cannot certify it.
