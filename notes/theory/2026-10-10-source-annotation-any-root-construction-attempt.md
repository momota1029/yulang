## 3. Required package and original fields

Let `q_as` be this annotation, `q_type` its complete written Type subtree,
`sigma_q` its original lexical/type scope, and `T` the original binder tree.
Use the original static fiber `xi=(nu,K,D)` and actual event `e=(eta0,h)`;
`e` denotes the event, not the Value certificate. Let `pi_Int` and `pi_Any`
denote distinct input/output certificate fields when the local law does so.

The following is a required-data schema, not a proposed Rust API or a new
membership clause:

```text
WrittenTarget(q_type, sigma_q, T)
  -> resolved completed Value(Any) contract
  -> actual ordinary root v_Any with that contract's registered interpretation
     and a checked incidence from this q_type at sigma_q
```

The formation owner must retain:

1. **Source/resolution:** actual `q_as/q_type` identity, full Type subtree and
   range, original lexical resolution/environment, resolved semantic target
   identity, and its introduction/import route. Endpoint equality or spelling
   alone does not supply this incidence.
2. **Root/interpretation:** the actual complete ordinary record at `v_Any`,
   Value head, typed descriptor operands, independently registered membership
   interpretation, and original scope map. The annotation design does not
   require a fresh allocation per occurrence; authentic reuse would require
   its actual scoped incidence evidence. PE's fresh Function-frame rule must
   not be imported as a new annotation allocation policy.
3. **Guards/dependencies:** every guard in the genuine Any membership contract
   and Top law at their original scopes, original registration/incidence,
   world/authority dependencies where required, provider/hereditary and
   compatible-future obligations, and complete free dependency telescope.
   An ordinary Value Any target receives no invented Function inlet,
   receiver or invocation equations. This does not remove the source
   operand's complete Function/carrier guards when such an operand is used.
4. **Evidence:** complete input/output/intermediate witness telescopes, genuine
   local law/choice fields and every original binder dependency. Prior
   initializer evidence stays Shared/OneShot where its owner introduced it;
   local logical evidence stays Check/ViewLogic/EventProof at its actual
   introduction. Empty residuals of a literal Call example do not justify
   deleting this annotation's dependencies or changing those classifications.
5. **Boundary linkage:** `u_Int` from this literal, `v_Any` from this Type,
   original same value/provider, `E_in`, and the finite Top term bound to
   these exact operands and full tuple. Direct validates the supplied pair;
   it supplies no reverse inference that either owner constructed them.

This is the most exact package supported by the inspected selected rules.
The records do not enumerate a concrete exhaustive Any guard/evidence
signature for this Type formation. Filling that signature by assumption is
precisely the open premise, not a completed constructor. In particular,
`V(Any)=true`, guard-free Top, or a certificate erased to a boolean would be
new claims rather than consequences of this audit.

## 4. Explicit conditional derivation

Hypotheses, kept separate from established constructor facts:

- **H0 (source instance):** the exact program is parsed/resolved with an
  authentic annotation occurrence and complete Type subtree. No parse was run.
- **H1 (operand):** the original literal owner supplies the actual ordinary
  `u_Int` and full hereditary membership `pi_Int` for value 0/provider p at
  `(e,xi)`, together with its true source incidence and prior evidence. PE §8
  establishes the ground Int pattern, not an executable annotation caller.
- **H2 (open target):** source written-Type formation at this actual
  `(q_type,sigma_q)` resolves completed ordinary Value(Any) and supplies its
  complete actual root/interpretation/incidence package from §3. A root name,
  negative Top term, scheme, or printed type does not satisfy H2.
- **H3 (local law):** the registered hereditary Top law has its independently
  valid full signature at exactly `(u_Int,v_Any,e,xi)` and transforms the
  same decorated value's complete Int evidence to complete Any evidence,
  retaining all guards/dependencies and intermediate choices. CE and PE
  select consumption of that law; this audit supplies no missing leaf law.
- **H4 (native consumer):** the selected PE §6.1 finite Value consumer receives
  these authentic records/term. This is the defined native consumer, not a
  claim that a production F5 caller exists.

Under H0–H4, the proof is the following finite construction:

```text
literal occurrence --H1--> (u_Int,0,p,pi_Int,E_in)
written Any q_type --H2--> (v_Any,Value(Any),scope/incidence package)
(pi_Int, original full tuple) --H3 Top--> (pi_Any, local E_top)
(u_Int,v_Any,Value(Top term)) --H4--> Direct certificate at q_as
SRC annotation final formation --> selected final target v_Any,
                                  same 0/p, retained E_in + E_top
```

The last two steps use actual source and target records; the source root
does not become Any merely because a query succeeds. `E_in + E_top` means
retaining both dependent evidence packages at their own original binders,
not concatenating or flattening their telescopes. No conversion is executed.

**Conditional conclusion:** if those hypotheses hold, the selected source
annotation/Top/Direct rules complete the proof-only Any boundary on the same
value/provider and preserve its prior and local evidence. The diagram is
also a minimized open derivation: it has one literal, one Type and one Top
check, and already contains the undischarged H2 target-introduction leaf.
Removing the literal or annotation removes the assigned boundary question;
adding id, Call, frames or solver models cannot discharge H2.

## 6. Evidence independence, checks and limits

This is source/constructor correspondence, with no checker, probe or oracle.
The conditional derivation shares the selected SRC/PE/CE local semantic-law
assumptions; it independently traces who produces each operand but does not
prove those independent membership laws. Instantiating an assumed Any leaf
in a toy model would only verify consistency of that supplied premise.

Commands were bounded `cat`, `sed`, `rg`, read-only Git identity/status/diff
inspection, and `sha256sum`, with one lightweight shell process at a time.
No tests, builds, source parses, seeds/ranges, enumeration, mutation runs,
performance samples, scratch outputs, delegation or Git mutations occurred.
Coverage is the exact constructor families and three production files named
above; searches are not exhaustive over legacy inference or all repository
sources. Output captures were bounded; truncated locator output was followed
by narrow reads of the relevant sections. CPU time/peak RAM were not measured;
no heavy process was started. Wall time was not instrumented.

Failure conditions for the conditional claim include unresolved or differently
scoped Any, missing complete root/leaf signature, missing Any/Top guard law,
wrong source incidence or target record, stale/different operands, erased
hereditary/world/dependent witnesses, unlawful binder relocation, or use of
an executed conversion in place of the selected proof-only step. Exact parse
acceptance, concrete Any name-resolution policy, full descriptor-root
constructor, production caller/store/lifecycle, resource/failure policy,
arbitrary annotations, Call and aggregate inference gates remain unverified.

Recommended next action: the primary should assign one narrowly scoped
written-Type/Any descriptor owner design that supplies the actual
`q_type/sigma_q -> completed Value(Any) -> ordinary root` package. Reuse the
existing membership meaning only with its full authentic signature; if that
requires a new semantic clause, return that exact clause for the separate
narrow decision required by the one-case design. Another conditional Top
checker leaves the same H2 premise untouched.
