## 2. Actual coordinates, fields and constructors

`Graph` (:38–54) owns nodes, row records, bounds, copied EvidenceSnapshot values, attachment references/spans, context views, negative-Function indexing, source frontier/owned region IDs, root/live_root and boundary. Graph-local indices are meaningful only with that exact Graph. `CapturedEvidenceRef(usize)` is explicitly Graph-local. A graph node index is not a universal source-term ID or an annotation descriptor identity. Capture canonicalizes endpoints (:347 onward); arbitrary source terms cannot be inverted from a node index. `negative_functions` supplies only its actual captured negative-Function associations.

`FreshUse` (:165–175) has exactly the following fields. A map miss below means only that this construction map has no such key.

| Existing field and query | Actual source coordinate | Actual answer and target owner |
|---|---|---|
| `rows: Vec<RowKey>`; index lookup | exact Graph row index | typed Value/Effect row ordinal in session row owners |
| `terms: Vec<Option<Term>>`; index lookup | exact Graph node index | optional constructed Term, resolved through the same session/batch term owner |
| `effect_operands: HashMap<usize,EffectEndpointKey>` | exact Graph EffectOperand node index | Contribution / Allowance / Support / AnnotationMember endpoint into effect algebra |
| `bundle_remap: HashMap<AttachmentBundleId,AttachmentBundleId>` | actual source bundle ID listed by Graph | target bundle ID in context State.bundles |
| `context_remap: HashMap<ContextId,ContextId>` | actual context IDs visited by shared reconstruction | target context-expression ID in context State; zero is identity |
| `evidence_remap: Vec<EvidenceSnapshotId>` | Graph.bound_evidence index | imported snapshot ID in context BoundEvidence |
| `scope_remap.regions/scopes/inputs` | respective owned runtime source IDs | copied region/scope/input IDs in ScopeInventory |
| `scoped_relations: HashMap<RelationId,ScopedFlow>` | actual captured parent relation ID | copied flow value, containing transformer ID and optional demand |
| `context_use: usize` | this successful construction | use counter value allocated by context.begin_use |

`prepare_candidate_fresh_use` (:1104–1378) constructs these before returning the FreshUse. Construction/resume does not rebuild the maps. Row construction first resolves `intrusion.rep(row.key)` and deduplicates that current representative in a temporary `canonical_rows`. A new row is allocated at use_level only when `row.local && current_level > graph.boundary && !metadata.non_generic`. Otherwise it retains the current source representative. Thus `rows[i]` is an image of the captured row occurrence through the current representative, not necessarily the original numeric key. Multiple source indices may share an image. No injectivity or provider identity follows. Later representative changes can change canonical interpretation without changing the stored row ordinal.

Effect operands are constructed before terms. Each captured Contribution node produces a new native Contribution instance with cloned effect and SourceNodeKey origin (:1177–1196; candidate_effect:949–970). This gives a native source-node-to-target-endpoint association. It is not the semantic provider/observation/assignment/lineage tuple w. Different native nodes are processed separately; original family/origin equality does not authenticate identity of w. Allowance/Support/AnnotationMember preserve their endpoint variant/member while copying the effect view with a mapped tail. The temporary view cache is keyed by `(old view ID, mapped tail)`; it is discarded before FreshUse returns, so Qmap does not offer a general old-view-to-new-view query. Only the existing endpoint answers and Graph context payload associations are available.

All non-EffectOperand graph nodes receive `Some(Term)` on successful construction. EffectOperand nodes deliberately remain None in `terms` and have their answer in `effect_operands`. Row terms use their mapped rows with original polarity. Function reconstruction uses all four children `(argument value, argument effect, result effect, result value)`. Leaves use the actual leaf/constant constructors and may share terms. A copied structural Function or contribution and a shared row anchor are different cases; a shared row does not imply that all graph nodes or dependent semantic objects are shared. The term owner, rather than FreshUse, owns constructed term payloads.

Bundles copy occurrence and set entries into a separately retained native bundle (:1150–1166). Shared context reconstruction is rooted in captured bound relations and maps only the visited context-expression closure, using temporary weight/view remaps. It is not a total mapping of every context or LocalWeightId in the session. `evidence_remap[i]` imports Graph.bound_evidence[i] by snapshot interning; it need not allocate a distinct snapshot if an identical one already exists. Snapshot identity and snapshot coverage are preserved; authentication is not added.

Scoped mode calls `ScopeInventory::fresh` on graph.owned_regions. It reserves identities, preserves copied internal parents and attaches copied roots whose parent is outside the map to the caller (candidate_source:212–270). Origins retain original scope/input coordinates in separate vectors. These origins are not unique inverse keys: different uses can have the same origin. With scoped mode disabled, scope maps and scoped_relations are empty; this is not evidence of lexical eligibility or absence of source scopes.

The actual scoped-flow consumer (:1288–1318) applies identity fallback to unmapped scopes/inputs. Its demand has separate `original_call`, `use_instance`, `root`, `output_scope`, `input` fields (candidate_context:203–215). It remaps root through Graph.negative_functions and `terms`; changes use_instance only if the original input belongs to the input-map domain; and preserves it for an external input. Retain domain membership as well as the mapped value. Identity fallback is justified only at these inspected consumer operations, not as a new default for arbitrary queries. The region map distinguishes copied regions; the lexical original and target coordinates must remain separate. This construction does not prove source typing or eligibility.

## 3. Restoration, publication, lifetime and rollback

`begin_candidate_fresh_bound` (:1380–1428) consumes exact term/effect-operand images, original bound kind/side and source BoundKey. Owner/item orientation is preserved. For a parent relation it creates a target relation through `candidate_context_fresh_transport_scoped`, using context_use, mapped relation context and optional mapped scoped flow, and attaches mapped bundles. It passes the imported snapshot, use origin, source bound and optional mapped relation to `BoundAdmissionCause::FreshUse`. **FreshUse contains no source-bound-to-target-relation map.** Target admissions/relations can retain further information in their own owners, but this note does not invent a direct restoration receipt query in Qmap.

`route_candidate_local_run` (:1505–1567) captures and constructs before placing a frame in GraphState.local_use. `step_candidate_local_use` (:1664–1710) restores represented bounds in order, then admits the mapped root-to-local-value link, reserves local-route publication storage and marks complete. No initializer is rerun. The production route has no injected pause; the script/census is cfg(test) and is not production retention.

`lib::finish_route_transaction_with_candidate_accounting` (:9281–9331) commits a completed frame only after successful fallible work. `GraphState::commit_local_use` (:266–291) pops it and moves slot/local/occurrence/Graph/fresh.rows into LocalFreshRoute. The other maps, context_use, frame value/level/cursor are dropped. Surviving native rows, term payloads, views/contributions, contexts/relations/weights, bundles, imported evidence and scope inventory are not destroyed merely by this map drop: commit itself does not truncate their owners. Completed replay operations may be retired by `commit_replay_operations` before frame publication; they are not safe permanent references merely because an ID existed precommit.

The lifetime is session ownership, not a raw Rust pointer into a Vec. Appending or moving vectors can relocate payload addresses while retaining index identities. A safe structural lookup uses IDs and re-resolves in the same live owner, or independently pins an immutable allocation; retaining a borrowed address across vector growth is not justified. A retained Graph-local index must carry its owning Graph association, not a bare index or matching source origin. Slot/local/occurrence do not establish a global session-generation identity. No new generation field is assumed here.

Rollback facts limit every retention claim:

- `lib::rollback_route_transaction` (:9445–9482) restores the intrusion checkpoint and prior cursor for a preexisting retained frame, or clears a newly constructed frame. It truncates committed-route vectors to checkpoint lengths and restores the old local_routes allocation by moving entries back. Row-level and metadata vectors are truncated (:9564–9569). Store rollback also precedes these operations. A failed new attempt has no committed route; a resumed failed attempt restores the prior continuation frontier.
- `candidate_effect::State::rollback` (:253–294) truncates contributions/views. `candidate_context::State::rollback` (:1780–1885) drains newly added bundles, contexts, relations and other indexes; BoundEvidence.rollback (:572–595) removes imported snapshots/admissions/emissions introduced after its checkpoint. IDs into removed suffixes cannot escape as persistent references. In particular `uses` and `next_replay_operation` are rewound; source-support IDs have a separate nonrewinding allocator. The Draft candidate's general monotonic-session-identity sentence is not an established fact for these actual IDs.
- ScopeInventory is not a field of the inspected context Checkpoint and is not rewound by that rollback implementation. Fresh copied source inventory can therefore remain as charged private inventory after failure. Its survival does not publish a successful use or provide a reverse per-use map. Exact capacity restoration and reclaiming every failed inventory entry are not required semantic conclusions.

Later transactions whose checkpoints already include the committed route and all queried referents preserve their existing prefixes through this rollback mechanism. This is a useful local lifetime case, not a theorem about arbitrary outer rollback, session replacement, independent invalidation or escaping references. Those require explicit ownership premises.

Accounting is explicit: FreshUse.bytes (:176–183) charges capacities of the three scope maps and scoped_relations/rows/terms/effect_operands/bundle/context/evidence maps; inline scalars are covered by their containing frame size. Commit subtracts `FreshUse.bytes - rows.capacity * size_of(RowKey)` and keeps Graph/rows. Route storage is reserved in the final fallible step; refresh_bytes (:292–319) enumerates frame/route structures plus owned payloads. Target algebra/context/ScopeInventory objects are separately accounted by their owners; moving an ID map does not transfer their payload ownership. Any proposed retention must change the drop charge and frame/route inline sizes consistently, include map capacities once, and preserve allocation rollback. This is a structural accounting obligation, not a measured peak or exact allocator-byte theorem. Source uses capacity-based formulas; HashMap bucket overhead is not proved exact physical memory here.

## 4. Qmap and the retention theorem

Fix a successfully constructed frame F, its exact Graph G, a finite set of registered queries and the current live session owner S. **Qmap** permits only: direct index/key lookup in the fields of §2; Graph metadata lookup; reading existing fields of the returned native objects through their actual owner; and finite tuples/compositions of these operations where every intermediate ID resolves. Option/membership answers are structural. A missing term/entry never means missing At, no future contribution or permanent ineligibility. Dereference queries must enumerate their exact read projection and transitively referenced existing objects; arbitrary semantic evaluation is outside Qmap. Mutable canonical-row interpretation is a different query from returning the stored RowKey.

**M1 (actual construction correspondence).** On successful return of prepare_candidate_fresh_use, every Qmap direct answer is the value emitted by the actual constructor branch described in §2, with its original map domain and Graph/owner coordinate. This follows by the source loops: row push order is Graph.rows order; term slots and endpoint keys use node indices; bundle/context maps use source IDs; evidence vector order is Graph.bound_evidence order; scope maps use copied owned IDs. Each restoration consumer uses those same coordinates. No induction step supplies an unrepresented descriptor or source derivation.

**M2 (existing-map retention, conditional).** Suppose immediately before successful commit a retained owner takes the existing queried maps/values, or a faithful restriction preserving each registered query's keys, values, misses and membership; preserves their association with G and S; and publishes them atomically with the use. Suppose further, until query evaluation, (i) G and every referenced native object remain in their original owner identity and have not been removed/reused by rollback or owner destruction, (ii) no raw address invalidated by relocation is used, and (iii) every dereferenced read projection is unchanged, or queries explicitly read the same version and invalidate otherwise. Then each registered Qmap answer after commit equals its precommit answer. No FreshUse-only reconstruction is needed.

Proof: direct field lookup returns the same stored index/key answer, including None/miss and owned/external membership, because retention preserves that exact map domain and association. ID dereference returns the same projected fields by (i)–(iii); identity constants require no array dereference. Induct over the finite query expression to prove equality of tuples/compositions. A retained row ordinal remains numerically equal even if a later representative changes; canonicalization is equal only under its separate unchanged/version premise. Dependency cycles are not unfolded into proof objects: a query returns the actual stored references or finite read projection only. Atomic publication prevents observation of a partially transferred map collection. End proof.

**Current-code corollary.** For Graph/row direct queries, current commit supplies the retention premise by moving G and rows verbatim. Therefore the immediate postcommit answers match, conditional only on the identified live route/session coordinates; their subsequent native dereferences need (i)–(iii). For all other FreshUse fields, current commit fails the retention premise. M2 is a constraint on a possible unapplied retention proposal, not a claim that current code already retains them. Merely finding the target payload somewhere in a session does not restore the lost crosswalk or identify the correct use.

M1 is the new source input to R1, rather than a second assumption that arbitrary semantic packets existed. Applying R1's finite-query factorization to Qmap requires only the retained map/projection and lifetime/publication premises of M2. It establishes structural lookup equality for those actual constructor outputs. It does not establish R1(a) for the old full Q: the descriptor/provider/At/dependency categories in that Q have no producer in these maps. No API or storage layout is selected by this theorem.
