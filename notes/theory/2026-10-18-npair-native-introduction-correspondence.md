## 3. Recursive path/variance induction and the shared row

Write A/R for `FormalPortStep::Argument/Result`. For a structural child path p,
let `a(p)` be its number of A steps. Root value recursion starts with negative
variance, so the composed source variance at p is negative exactly when
`a(p)` is even. This includes the final step naming the child **effect row**.

**Induction.** At the root the A count is0 and variance is negative. At each
Function, argument value recursion and argument-effect construction receive
the reversed variance and path pA. Result value recursion and result-effect
construction receive the existing variance and pR. A therefore flips both
parity and variance, while R preserves both. These are exactly the four calls
in `candidate_formal_value_pair` (1170–1212). For each call the caller saves
`base`, pushes one step, stores the Result, truncates to `base`, then applies
`?`. Restoration therefore occurs before either success or error propagates.
No sibling inherits the preceding sibling's suffix.

The actual allocation/construction order remains:

1. argument value at pA;
2. result value at pR;
3. argument effect at pA;
4. result effect at pR.

A Function's own computation-effect row is processed by its parent at the
path naming that child; recursive value formation does not process it twice.
The entry calls `candidate_formal_value_pair` directly, so its root computation
row is not collected as a nested Permission. The separate entry rule remains
separate; this is not an omission of a child Function effect slot.

For every negative nonempty concrete-only row, the internal guard permits
exactly the approved shape. At its exact effect-port invocation (1215–1255):

- `port=fresh_effect_at_level(level)` runs once;
- the source row's `position` and entire concrete vector are copied, together
  with parameter/occurrence/source_owner/scope and the current exact path;
- after temporary record assembly, the branch returns
  `(live_effect_term(Positive,port),live_effect_term(Negative,port))`.

The fresh helper in lib (10263) takes the current effect-row length as ordinal,
appends ordinary default bounds, stores the **same supplied formal level** and
fresh metadata. It does not iterate the concrete IDs or emit a lower, upper,
closed row, emptiness or equality constraint from them. One successful new
allocation increments row length, so distinct concrete-negative invocations
in the same live construction get distinct raw ordinals. Resource failure
returns an error and requires the existing enclosing rollback; it is not a
successful permission introduction.

Each retained Permission was pushed only by this negative branch. Hence its
path is nonempty and has even A count. Omitted rows and singleton symbolic
rows follow their existing shared-row branches without such a Permission;
positive explicit rows use their existing signature views. No theorem for
mixed/multiple-symbolic/explicit-empty negative source cases is added.

**All four children.** If child pairs are `(ap,an),(rp,rn)` and effect pairs
`(qap,qan),(qrp,qrn)`, the actual result is

```text
F+ = Fun+(an,qan,qrp,rp)
F- = Fun-(ap,qap,qrn,rn).
```

Lib's Function helpers pass those four arguments unchanged. Term arena
constructors (term.rs1120–1186) validate all four kind/polarity/lineage
requirements before interning; TermView exposes all four children unchanged.
No discarded argument/effect/result child or endpoint-only reconstruction is
used by this proof.

## 4. Unique association and retained recovery

### 4.1 Actual binding including source_row

For one successful invocation let A be its actual annotation argument. Each
published descriptor D is created from the unique child effect occurrence of
A at its recorded p: `source_row=row.position`, `concrete=row.concrete`,
`source_owner=A.owner`, with unchanged parameter/occurrence/scope. The record
is constructed **inside that row's allocating branch**, not inferred later
from a family match. The two terms of the fresh ordinal are inserted into
that row's exact sibling effect fields by the recursive induction above.
The same invocation retains its completed negative root with those records.
This directly proves the binding between the exact source-row identifier,
path and raw ordinal; no source-row label need be encoded in TermView.

Collision checks at this boundary:

- In one input tree each non-root child has one A/R address. Its single
  optional effect row is processed once; one record stores the full concrete
  list. There are no two record emissions for the same parameter/path.
- Multiple concrete members of one row intentionally have one shared port.
  They are kept in its copied vector, not separately allocated inflow rows.
- Equal family IDs or equal row keys at **different** structural occurrences
  do not merge paths or fresh rows. The pair builder has no such lookup.
- `formal_domains.contains_key(parameter)` rejects a second retained formal
  publication for that parameter before recursion. A different occurrence
  does not bypass this guard; no existing negative root is overwritten by a
  successful second publication. Different parameters have different map keys.
- The occurrence/source owner/scope copied into D are exactly the invocation
  fields. Their equality across two parameters is not a row association.
  Whether an upstream source can reuse an occurrence/slot ID is outside this
  producer's source-admission claim; such a request must still succeed in
  both ordinary link calls before publication.

These statements concern authentic records produced in the retained state,
with the corresponding root intact. They do not claim an arbitrary external
record with a forged source_row can be authenticated just by walking terms.
They also do not extend this association across an unproved later
capture/fresh-use, row transformation or consumer lifetime.

### 4.2 Recovery algorithm and polarity proof

For authentic D, lookup `t=state.formal_domains[D.parameter]`. At each proper
prefix of D.path, inspect either Function variant and follow its argument
**value** for A or result **value** for R. At the last step return the matching
sibling `argument_effect` or `result_effect`. Inspect that effect with
TermView and require `LiveVariable(kind=Effect,polarity=Negative,ordinal=x)`.
A missing root, ground/non-Function before the endpoint, empty path, wrong
kind/polarity, foreign or invalid term handle rejects recovery. None arises
for a successful authentic publication by the preceding induction.

Function polarity flips when traversing an argument value and stays at a
result value. The last sibling effect follows the same flip rule. Starting
at F-, its endpoint polarity is negative times `(-1)^a(p)`; the permission
criterion makes a(p) even, so the endpoint is negative. Starting at F+ gives
positive with the identical ordinal x. This calculation works even when
intermediate nodes alternate Function variants; an algorithm assuming every
visited node is NegativeFunction would be wrong.

Examples: p=RR keeps a negative inner Function then its negative result-effect;
p=AA enters a positive Function through the first argument, then selects its
negative argument-effect. Both paths are negative source occurrences. AR/RA
have odd argument count and do not emit this concrete-negative Permission.

TermView `LiveVariableView` exposes exact component kind, polarity and raw
ordinal; no canonical-family comparison is involved. `term_view` uses the
arena's checked lookup, rejecting ArenaMismatch/InvalidHandle. Function
hash-consing does not erase a fresh concrete-negative child: its fresh ordinal
is part of the live-term node. This proves deterministic unique recovery for
authentic retained D. It is a mathematical algorithm over existing APIs, not
an implemented new decoder or a permission/contribution authentication API.

A stronger inference is false: terms alone do not reconstruct source_row.
Two alternative constructor inputs from the same native prestate can differ
only in a concrete row's SourceNodeKey and keep all native type/effect shapes
and allocation order equal. Their solver trees/ordinals then agree while
retained descriptors differ in that key. This does not collide two authentic
records in one published state; it explains why the actual descriptor and
constructor binding, not TermView alone, supply source provenance.

## 5. Publication, owned bytes and rollback

At entry the formal's existing level is read and duplicate parameter rejected.
Permissions initially live in a reserved temporary vector; completed pair
formation alone publishes neither records nor `formal_domains`. After pair
success the code reserves state-vector/map and undo-key capacities, executes
link43, then link44. Only after both successful calls does it:

1. recompute retained path/concrete backing capacities and require equality
   with accumulated permission bytes;
2. check scratch ownership-transfer subtraction and retained-byte addition;
3. drain the complete records into state and insert exactly F- under parameter;
4. journal the newly inserted map key, transfer backing accounting from scratch
   to retained state, then perform the final fallible resource sample.

The drain/insert portion uses previously reserved storage and checked counts;
no fallible Result operation intervenes between vector publication and map
insertion. This is ordered internal publication, not an independent thread
or reentrant observer atomicity claim. The existing exclusive session/route
ownership is the boundary; this function is not a standalone transaction API.

`State::checkpoint` captures the old Permission length and backing bytes
(candidate_effect260–275). `State::rollback` truncates Permission to that
length, restores `formal_permission_bytes`, and removes every newly journaled
formal domain key (281–285). Therefore failure after publication removes the
new descriptors/root together and preserves earlier entries. Failure after
only link43 has published no descriptor/root; enclosing route rollback must
still remove that first edge and new rows/terms.

At the route boundary lib's error arm invokes rollback; the pinned route
implementation restores the store's fact/provenance suffix and term arena,
uses the existing intrusion undo path, restores rows, then truncates fresh
effect/value row/level/metadata/mark suffixes. The effect-state checkpoint and
rollback above are the approved existing effect-algebra undo mechanism; this
proof does not introduce a second journal or bypass its wrapper. A direct
internal call without the required enclosing route does not get this guarantee.

The byte invariant is exact for retained backing ownership:
`formal_permission_bytes = sum(path.capacity*sizeof(step)+concrete.capacity*sizeof(id))`
for retained records. After transfer those nested allocations belong to state,
while the still-live outer temporary allocation stays scratch until dropped.
After a post-publication error, the new backing vectors are dropped by
truncation and the checkpointed backing count is restored. `State::bytes`
continues to charge retained outer-vector capacity separately. Reserve growth,
physical capacities and peak counters need not shrink to their old values;
this is semantic rollback with correct surviving-capacity accounting, not
byte-for-byte physical memory rollback.

Ordinal reuse after a failed route is not a collision among surviving
Permissions: that route's records/root/terms are removed. No guarantee is made
for leaked stale handles outside the approved lifetime. None is published as
an authentic later consumer certificate by this producer.
