## 1. Current owners remove the delayed-Graph shortcut

Capture canonicalizes endpoints and row keys at
`candidate_scheme.rs:289–331`. Each representative receives one Row entry;
`local` means `level > boundary && !non_generic`. Nonlocal rows stop at
`expand_row` (`:572–573`): their mutable bounds remain shared and are not
recursively captured as that row's saved block.

For a local Value row, `expand_row` (`:577–619`) invokes `bound` in this order:
**direct lowers, direct uppers, exact lowers, exact uppers**. `bound`
(`:522–567`) interns endpoints and appends relation-specific captured entries
with original `source_bound` and evidence snapshots. Interning schedules nodes;
it does not recursively expand another row's bounds during this block. The
outer loop (`:745–779`) expands each row once. Consequently each Value row's
saved entries form one contiguous block; all its saved exact lower entries
precede all its saved exact upper entries. Relation multiplicity preserves
this order; it is not a claim that physical duplicate slots retain distinct
captured entries after `bound_keys` deduplication.

The actual DefinitionUse route (`:945–960`) reads the stored graph's
`live_root,boundary`, **recaptures the current live graph**, then calls
`instantiate_candidate_graph`, whose `:1277` invokes `freshen_candidate_graph`.
The LocalUse route (`:1373–1374`) likewise captures immediately before
preparation. The production caller inventory is:

```text
route_candidate_graph -> capture -> instantiate -> freshen -> prepare
route_candidate_local_run -> capture -> prepare -> step_candidate_local_use
```

`freshen` and `step_candidate_local_use` are the two restoration loops
(`:965–976,1505–1524`). They complete each owned restoration before advancing
the saved bound cursor. Test-only calls accepting an older `&Graph` do not
establish a delayed production route.

Capture has immutable session access. Between that immediate capture and the
row loop in preparation there is no typed constraint or intrusion settlement;
`begin_use`, scratch accounting and capacity reservation do not merge rows.
Thus captured representatives, levels and genericity still agree at
`:1006–1019`. Local rows each receive one new empty identity, as established by
`fresh_value_at_level` (`lib.rs:10156–10184`); distinct captured representatives
receive distinct new rows. Nonlocal rows remain their shared representatives
and have no saved Value-owner block. Representative coalescence of an old
stored Graph is therefore **not a current production pre-restoration premise**.
Later restoration callbacks and intrusion remain separate operations.

A useful corollary: if the captured root is local, has no direct lowers and
its first exact lower is `g`, the first root lower restoration cannot begin
with exact uppers `f1,f2` supplied by that same root block. The fresh root
starts empty; any preceding root direct-upper restorations have zero lowers,
so execute no child callback. Saved exact uppers occur later. This excludes
the root-only private shortcut. It does not exclude earlier blocks supplying
uppers to a **non-root** row, as the following construction shows.

## 2. Actual producer construction and captured Graph

Allocate `b,a,r` using the real empty allocator. Construct the following signed
Functions with `positive_function_term` / `negative_function_term`
(`lib.rs:10230–10300`); table entries are actual signed ports:

| Function | Polarity | Argument | Argument Effect | Result Effect | Result |
| --- | --- | --- | --- | --- | --- |
| `g` | positive | negative row `r` | EmptyEffectNegative | EffectBottomPositive | IntPositive |
| `f1` | negative | positive row `a` | EffectBottomPositive | EmptyEffectNegative | IntNegative |
| `f2` | negative | BottomPositive | EffectBottomPositive | EmptyEffectNegative | UnitNegative |
| `H1` | positive | negative Function `f1` | EmptyEffectNegative | EffectBottomPositive | UnitPositive |
| `H2` | positive | negative Function `f2` | EmptyEffectNegative | EffectBottomPositive | UnitPositive |
| `K` | negative | positive row `a` | EffectBottomPositive | EmptyEffectNegative | UnitNegative |

Through `admit_candidate_value_link` (`candidate_scheme.rs:1334–1342`), with
valid distinct occurrence slots and causes, first admit `H1 <= b`, `H2 <= b`,
then `b <= K`. Each first lower is stored without opposites. The last upper
replays both lowers through the ordinary queued owner. Complete its typed
drain before the next seed admission. Function contravariance is the actual
child definition at `lib.rs:12498–12538`:

```text
H1 <= K  ->  a <= f1
H2 <= K  ->  a <= f2
```

Other ports compare bottom effects to empty effects and Unit to Unit. Since
`a` has no lowers, both negative Function bounds are retained without a
Function/Function comparison. Structural extrusion sees only equal-level rows
and creates no parents (`candidate_extrusion.rs:86–102`).

Next admit and drain `g <= a`. Ordinary `candidate_replay_bound`
(`candidate_extrusion.rs:763–803`) queues both `g <= f1` and `g <= f2` before
this outer worklist executes their callbacks. `g <= f1` generates `a <= r`,
stores a direct upper `r` on `a`, and replays `g <= r`, storing `g` on `r`.
`g <= f2` generates `IntPositive <= UnitNegative` and retains the actual
incompatible-value witness (`lib.rs:12381–12399`). That branch returns `Ok`;
it is a diagnostic, not an availability failure. No equality merge occurs:
`settle_candidate_intrusion` has its empty-parent return (`:358–374`).

The resulting relevant physical stores are constructed, not assigned:

```text
b: exact lower [H1,H2], exact upper [K], no direct bounds
a: direct upper [r], exact lower [g], exact upper [f1,f2], no direct lowers
r: exact lower [g], no other bounds
parents: []
```

Call the real capture owner on root `b`, boundary 0. Root `b` is interned
first and expanded as graph Row 0. Its block interns `H1,H2,K`. Pending
Function expansion discovers `a` from K's argument before expanding any later
row; the f1 argument also points to the same canonical `a`. Expansion of `a`
discovers `r` through its direct upper and g's argument. Hence the captured
row order is `b,a,r`, all local. Its saved bound block order is exactly:

```text
b block: H1<=b, H2<=b, b<=K
a block: a<=r, g<=a, a<=f1, a<=f2
r block: g<=r
```

## 3. Genuine FreshUse reaches the live-index discriminator

Use the actual freshening producer on that captured graph, use level 1.
Preparation allocates empty `b',a',r'`, one `context_use = u`, a shared term
map `theta`, shared context/bundle maps and imported evidence map. In this
identity-context/effect-leaf case, there are no effect payload views or
attachment bundles to remap; identity contexts remain identity. The same
`theta` reconstructs every occurrence of each row and all six Functions.
`f2` is row-free and can retain its original interned term; g, f1 and K retain
the correlations to `r',a'` rather than independent witnesses.

For each bound, `begin_candidate_fresh_bound` (`:1221–1266`) constructs its
mapped endpoints from **this** FreshUse. Where an original relation exists,
`candidate_context_fresh_transport` (`candidate_context.rs:3145–3155`) attaches
the mapped relation and records the actual FreshUse transport dependency with
original `source_bound` and `u`. The insertion additionally records its physical
admission with imported antecedent and mapped relation. The mapped fiber and
the physical admission's relation are not assumed distinct or identical;
ordinary relation interning can coincide in this identity example while the
transport dependencies and admission causes remain retained.

Restoring the first b' block first inserts H1',H2'; restoring K' consumes both
real replay children. Their argument ports store `f1',f2` on **a'**, before its
saved block begins. These comparisons create no a' lower or extrusion parent.
This is the earlier-block producer absent from the root-only shortcut.

The a' block then inserts its saved direct upper r'. Its opposite lower count
is zero. Next it genuinely restores g' with FreshUse evidence:

```text
before g' insertion:
 a'.upper.direct = [r']
 a'.upper.exact  = [f1',f2]
 a'.lower       = []
```

The restoration inserts g', saves `N=3`, then reads the live indices:

1. Index 0 selects r'. Its synchronous child `g' <= r'` stores g' on r';
   r' has no upper. No change to a'.
2. Index 1 selects f1'. The real Function argument child is `a' <= r'`.
   A prior direct upper insertion did not itself process this typed pair, so
   the child appends another physical direct upper r'. Physical insertion does
   not deduplicate that slot (`candidate_extrusion.rs:406–567`). Ordinary replay
   can reuse the already current g'<=r' relation; this changes no a' lower.
3. After that synchronous child returns, current vectors are
   `direct=[r',r'], exact=[f1',f2]`. At index 2 the live lookup subtracts the
   current direct length 2 and selects f1' again. Saved N remains 3.

Thus this genuine preparation/capture producer trace selects
`[r',f1',f1']` rather than its initial `[r',f1',f2]`. The f2 comparison is
unselected by **this lower restoration**. This is the previous discriminator
with a retained direct row from original ordinary propagation; it uses the
selected §4 behavior without a vector fixture or arbitrary FreshUse cause.
The trace is static and conditional on the stated admitted seed interfaces;
no actual parsed source instance or runtime execution is claimed.

## 4. Later upper restoration supplies real contextual compensation

The same authentic Graph still has two later saved entries in the a block.
Restoring f1' again may reuse its current comparison. Its four children can
append uppers, not direct lowers at a', in this construction. After the g'
lower restoration and any f1' duplicate, the complete a' lower list is exactly
`direct=[], exact=[g']`: g'<=r' acts at r', a'<=r' acts on a's **upper** side,
and both remaining result/effect children create no Value row lower.

Now `begin_candidate_fresh_bound` restores the saved f2 upper with its genuine
captured antecedent and theta-mapped relation. It inserts f2, saves lower count
1, and its **first** live lookup selects g'. There is no earlier callback in
this restoration that can shift that lookup. Consequently the actual replay
inputs are the ordered keys:

```text
lower_input = (a', Positive, g')
upper_input = (a', Negative, f2)
task        = g' <= f2
```

Let L and U be the captured original g<=a and a<=f2 relations. Their authentic
transported relations L_theta and U_theta are attached to those respective
BoundKeys before replay. `candidate_context_begin_replay`
(`candidate_context.rs:2911–2991`) rereads both fiber heads with incoming-use
`old=(None,None)`. It therefore includes the **joint** pair
`(L_theta,U_theta)` and records
`Dependency::Replay { child,lower=L_theta,upper=U_theta,lower_input,upper_input }`.
For nonidentity inputs it constructs the ordered Replay context; here both
contexts are identity so the child context is identity, with ordered inputs
still retained. This argument uses one shared preparation; it does not choose
two unrelated marginal transports or infer activation from stored endpoints.

The saved replay operation owns its child. Restoration calls
`candidate_context_drive_replay(...,Some(occurrence,cause))`, whose retained
child owner starts and finishes the actual typed drain before advancing
(`:3008–3123`; restoration `candidate_extrusion.rs:716–759`). Context admission
precedes memoization (`candidate_context.rs:2727–2758`). An endpoint memo alone
cannot skip a fresh uncompleted relation (`lib.rs:11463–11474`). Original
`g <= f2` involves old r; g' contains distinct r', so it is not that old pair.
The earlier a' restoration did not dispatch g'<=f2.

Function dispatch now generates the actual result comparison
`IntPositive <= UnitNegative`, retaining its incompatible-value witness. Thus
this specific missed lower-restoration selection is compensated at a later
real contextual consumer; it does not escape into a conflict-free export.
The public candidate facade explicitly invalidates graph export when
candidate conflicts exist (`shadow_apply.rs:119–129`). Candidate conflict is
not, by itself, the original source rejection judgment.

This proves bounded child generation/consumption and retained input dependencies
for the stated construction. It does **not** certify complete original physical
incidence coverage: captured key deduplication, admission-group evidence gaps
(including ReplayUseAntecedentsNotRetained at `candidate_context.rs:545`), and
nonidentity transport validity require their own owner laws. Equal relation IDs
are not proof that original physical emissions or attachments have collapsed.
