## 1. Statement frozen before the induction

Fix one shared satisfying assignment xi=(nu,K,D) over the evidence of the
finite interaction (prefixes use its restrictions), original resolved
declarations and original source formal identities. Consider any finite source syntax with explicitly
annotated single-parameter functions R(t:[S] int), where S is a finite resolved
concrete family set and the outer annotation selects Computation(E,Int).
Incoming E is open: it is not capped by S. At each forwarding edge the whole
actual argument is the resolved computation Name of the current formal.
There may be arbitrarily many such edges, repeated calls of one original
function, and arbitrarily many simultaneously live receiving invocations.
There is no fixed chain-length bound. The proof covers every finite execution
prefix, including repeated well-typed raw resumptions, rather than termination.

Between those edges, use the ordinary source constructors: ground return,
operation, designated consumption of the formal, Bind, call, and shallow
handler with typed patterns/arms and raw continuation invocation. A handler's
ordinary matching/guard/value-arm computation is included in its source
suffix, not assumed pure. An input computation or raw continuation may
remain latent/pending; this proof retains its existing source interface.
It does not construct new general higher-order function/field interfaces.

Base hypotheses are explicit: the initial ground computation and operation
declarations have their source monomorphic typing derivations; each supplied
operation response and raw-resumption argument has its declared type; and
the ordinary primitive/Bind/pattern typing contracts preserve those base
types. No proof of these general source typing contracts or progress is
claimed. Start with no protection invented for the base computation: each
boundary profile used below is generated by an actual annotated receiving
entry in this fragment. Existing retained profiles are those generated by
earlier such entries, including independent ancestor entries.

The required conclusion is preservation of original boundary ownership,
source-generated typed routes and request evidence, together with the
necessary eligibility condition for an actual operation-arm selection.
It is not eventual execution of an incoming effect, constant visibility,
equality of total emitted effect sets, or eventual handling of every request.
Unused delayed input and discarded continuation suffixes need not execute.
This fragment is the scope of the positive lemma, not a restriction of the
supported language or a narrowing of the original parent obligation.

## 3. Positive local theorem

For every source and typed finite interaction in §1, the constructors in §2
and the selected source transition rules preserve the following invariant I.

1. Every retained root profile has exactly its constructor-generated lineage;
   every matching retained input route contributes its indexed image. Each
   b keeps its original receiver and explicit source permission. No equal row,
   function name, fresh observer or executable owner creates a grant.
2. Retained latent/pending packets preserve original source/event/provider,
   symbolic endpoints and joint K,D. Administrative forwarding changes only
   the declared typed view/control position. An emitted request can be live,
   saved inside ordinary pending matching, completed by source handling, or
   abandoned by ordinary source control; these cases are distinguished.
3. A request's current incidence is obtained from a matching actual executing
   View observation and actual receipt/typed correspondence for the same
   packet/position, filtered by the exact current handler, owner and original
   receiver activity. An actual operation-arm selection requires the selected
   source Visible test and matching arm for that event at its yielding boundary.
   Static permission alone does not authorize that transition.
4. Ending an owner never renames b.receiver or revives an ended entry's grant.
   It preserves retained packets and other receivers' independently matching
   witnesses. It may change Visible: activity and local grants are contextual.

Consequently an actual internal handler cannot select a protected received
request without a source-derived applicable local grant. Normal/abrupt exit
does not erase the request, reown it, or erase another live receiver's profile.
Such an exit may legitimately make an outside candidate eligible by changing
the current incidence. Source-directed abandonment of pending code is not an
operation-arm selection and is not forbidden by the theorem.

This is a positive first local effect-hygiene safety/preservation result for
the source-generated root-forwarding fragment. The base typing assumptions
above and the previously established operational owner/transport results are
used explicitly; native realization of these source transitions is separate.

## 4. Proof by generated source route and transition induction

**Initial state and entry.** Initially the base has no fabricated b. At an
actual entry, §2 derives its source schema from original syntax and adds only
its fresh instance and receipt. Old routes are unchanged; freshness separates
simultaneous and repeated entries. No argument code executes. Hence I holds
and the displayed profile formula holds for the first entry.

**Name/Delay/Argument step.** The exact forwarding syntax generates the three
maps in §2. Apply indexed-image identity, composition and source-tagged union
([typed boundary](../design/2026-10-02-typed-boundary-realization-draft.md)
§6, uniform transport). The old formula becomes its image plus the next
entry's fresh singleton, which is precisely the formula at n+1. The argument
does not replace any original receiver or collapse overlapping entries. This
proves the formula for arbitrary finite chains, rather than postulating a map
for every chain. Branches/repeated uses apply this construction to their own
actual route; unrelated aliases are not globally unioned by value identity.

**Actual consumption and operation.** An actually executed formal Name read
loads its original binding into its current owner, creating the ordinary
receipt for that read's output view. Execute_RootComp consumes that same view
at the designated position; executing View projection supplies Observe for
that packet/position when an operation emits. Those are the actual matching
witnesses, not an assumed pre-query environment load. Force executes one
layer and retains the complete dependent suffix. Its eventual Int result
has no RootComp port: I requires only the maps on matching paths, not copying
the old profile onto Int. An ordinary source operation allocates its own
event with declared typing/current state, not a reused observation of another
request. Events outside an executing received view gain no incidental Path.

**Bind, return and nonhandler forwarding.** Apply the ordinary state-threaded
Bind equations: Return enters its actual dependent suffix; Request retains
the exact original q and appends that suffix to its continuation. Complete
callee/receiver pending contexts are retained in source order, not replaced
by a return. Thus administrative forwarding cannot consume q. An ignored
formal remains inert, and a discarded raw continuation may discard its
unexecuted suffix. Neither case asserts a hypothetical request executed.

**Handler and pending matching.** Apply the selected outside-image equations
in [source owner](../design/2026-10-02-typed-source-owner-realization.md) §6:

```text
eligible H[Request(q,k)] = MatchRequest_H(q,k) >>= Finish_H(q,k)
Finish(Accepted arm) = Run(arm.body); Finish(NoArm) = Forward(q,H[k])
MatchRequest emits qg -> Request(qg, lambda a. kg(a) >>= Finish_H(q,k)).
```

The eligibility test concerns q's yielding boundary. Accepted additionally
requires the actual ordered source match and typed arm; only that accepted
operation-arm transition handles q. Ineligible/NoArm forwarding retains q and
its source-prescribed future wrapper. Matching/guards/arms execute outside H;
their events are new events, independently tested at their actual candidates.
If matching suspends, the exact original (q,k), cursor and bindings remain
pending in Finish. An outer handler discarding qg's continuation may abandon
that whole pending computation. No false claim that q was forwarded/handled
or must eventually finish follows. This proves I.2 without an exhaustion into
only “forwarded” and “handled”.

**Exit and raw reentry.** Apply source-owner §§2–4's proved control induction
over Hole, Bind, Owner, ForwardHandler and View. Completion/unwind ends only
the exact owned occurrence; leaving a borrowed live span does not end it.
The control map rho changes executable slots only, never old b.receiver,
receipts, request origin/event or K,D. A dead saved Owner enters fresh u';
this resumes after the old entry and introduces no b_u'. Restoring a handler,
environment or View alone creates no Receive. A later actual Name lookup
creates its ordinary receipt; a genuine new source call creates a genuinely
new boundary. Each raw invocation has its own pending frames/rho.

A saved View restores observation for its original packet, with fresh observer
identity. A ForwardHandler installs the source-prescribed fresh handler under
the resolved owner; it never restores the selected shallow handler. After its
body returns it runs its ordinary VALUE arm, then parent suffix. That arm may
emit new requests, covered by the operation/Bind cases, so forwarding does
not imply equality of the total emitted effect set. Multi-shot reuse repeats
these same cases without renaming retained evidence or replaying completed
children. These exhaustive control cases establish I for every finite prefix.

**Eligibility consequence.** Boundary §6 defines Protected by matching current
Inc, Grant by such Inc plus b.receiver=owner(h) and explicit admission, and
Visible by active candidate plus (not Protected or Grant). I.1–3 supplies
only genuine source-derived witnesses to those definitions. Hence Protected
and absent Grant prevents operation-arm selection. If receiver r expires,
only incidences requiring its activity fail; a distinct live s and its exact
unchanged candidate/Path still have their witnesses. A changed handler/owner
can change Grant and Visible; no blanket protection-set invariance is used.
The original expired receiver identity can never satisfy Active again, even
when executable code reenters under a new owner. This establishes I.4 and
the theorem's local safety consequence. No additional algebra is assumed.
