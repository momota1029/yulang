## B. Independent interpretation of native work states

Use the same algebra, fixed before considering Rust execution. A native Value
endpoint denotes its assigned Value term; positive/negative atom endpoints
denote the same base atom; Function endpoints denote the finite four-port
constructor with recursively interpreted children, without following row
bounds. Effects denote their assigned finite sets, and both pure distinguished
endpoints denote `∅`. Thus cyclic row incidence does not require recursively
unfolding a type or asserting a finite solution exists.

For a same-sort task `q=(l,u)`, write `φ(q)` for `⟦l⟧ρ ≤V ⟦u⟧ρ` or
`⟦l⟧ρ ⊆ ⟦u⟧ρ`. For an owner-side key `k=(o,p,b)`, define independently:

```text
β(o,Positive,b) = (b ≤ o),
β(o,Negative,b) = (o ≤ b).
```

This agrees with actual `bound_pair` (`candidate_effect.rs:485–502`); it is
not defined using solver acceptance. A physical incidence projects to `β` by
its addressed owner, side and payload. Different physical slots, source fibers,
occurrences and relations retain their distinct concrete identities. Their
conjunction may contain the same algebraic inequality twice; idempotence of
conjunction does not establish provenance or temporal coverage.

For a native state including its active driver continuations, let `H(S)` be
the conjunction of the following actual logical obligations:

1. **Stored bounds `B(S)`:** project all existing Value/Effect direct lower/upper
   row vectors and exact lower/upper endpoint vectors by `β`. Include the same
   projection for retained owner-side bound keys with attached relations.
   Attachments may precede physical append; this representation is then
   redundant with the active obligation, not absent. Scalar summary flags,
   occurrence evidence and diagnostic-origin attribution are not additional
   inequalities merely because they contain IDs.
2. **Typed work `Q(S)`:** `φ(item.task)` for each `typed_worklist` item.
3. **Active requests/processing `P(S)`:** the initial request and current item
   of each live TypedDrainFrame; any separately retained pending dispatch item;
   designated processing pairs/relation pairs and the previous processing
   pair/relation saved in each active frame; and an admitted source or work
   task held in a live caller/local transfer slot before its publication into
   a frame, bound or queue. This is an operational-continuation interpretation,
   not a historical set of all source constraints. A popped Rust local still
   holds its task until `frame.current` is set. Inactive historical relation IDs
   or a typed memo alone do not establish an obligation or a proof.
4. **Retained replay work `R(S)`:** for each nonretired ReplayOperation and
   each child slot `consumed ≤ j < children.len()`, its stored `operation.task`.
   Its relation must name that task's pair. Slots before `queued` can also
   occur in Q or P; this is deliberate redundant ownership during transfer.

Retained structural-dispatch child data, if present in another suspended frame,
can also be interpreted as its explicit remaining child tasks; those frames
are unchanged throughout the present transition family. No preservation result
for creating, solving or retiring those structural children is asserted here.

The common valuation domain is the same existing kinded row set. Representative
maps and all structural term meanings are fixed during the family below;
valuations respect existing row aliases (mutual comparison for Values, equal
sets for Effects). This is a fixed entry well-formedness premise, not a proof
that a representative-changing operation preserves solutions. Raw/canonical
origin and witness identities are not collapsed by this semantic equality.

Define `Sol(H(S))={ρ on this row set | ρ satisfies all those obligations}`.
No nonemptiness is assumed. `H(S)` is neither source typing nor runtime safety.
There is no inference from `solve=Ok` or a successful context operation to
`ρ⊨H(S)`.

## C. Source admission is a distinct semantic update

`admit_collected_fact` clones the authentic occurrence, successfully admits it

existing endpoints according to kind, and calls constrain-live Value/Effect
(`lib.rs:11481–11529`). The cross-kind error arm is outside the kind-correct
family. The semantic event accepting a **new source** inequality q is:

```text
H_after = H_before ∧ φ(q),
Sol(H_after) = {ρ∈Sol(H_before) | φ(q)}.
```

This may shrink solutions. It is not solution-family equality. After that
successful admission, the occurrence is still held in the caller and becomes
the live constrain request. `constrain_live_value/effect` reach
`run_candidate_typed_drain` (`13719–13727`, `13950–14005`).
`start_typed_drain` retains `initial` in a frame, seeds the source relation and
enqueues that exact item (`14186–14232`; frame constructor
`candidate_context.rs:2249–2258`). These publications and provenance updates
copy an already-present q. They preserve the **enlarged** solution family.
This argument concerns the successful source-admission boundary and following
native publications; it does not purport to verify every internal operation
of ConstraintStore's transaction implementation.

Typed dequeue is also a transfer, not discharge. `pop_worklist` returns the
exact front item (`lib.rs:15166–15173`); Transport stores it in
`TypedDrainFrame.current` (`14301–14331`). Between those statements the Rust

## D. Owner recording preserves the exact inequality

`apply_value_task` and `apply_effect_task` route candidate state to the native
candidate functions (`lib.rs:16193–16201`, `13729–13738`).
`candidate_apply_value/effect` canonicalize endpoints without changing the
fixed representative map and select owner/side (`candidate_extrusion.rs:
1115–1176`):

| Existing inequality | Selected owner/side/payload | Projected inequality |
| --- | --- | --- |
| row `a ≤ b`, equal K0 levels | `(a,Negative,b)` | `a ≤ b` |
| nonrow `l ≤ b` | `(b,Positive,l)` | `l ≤ b` |
| row `a ≤ u`, nonrow upper | `(a,Negative,u)` | `a ≤ u` |

The general first guard selects the negative side when
`level(b)≤level(a)`; when that guard fails, the other row-owner arm still
projects to the same inequality. For authentic K0 all levels are 1. Only one
physical side is installed; no paired adjacency or transitive-closure edge is
inferred from this selection. Equal identical endpoints are tautological and
can return without storage. No-row terminal/Function comparisons are not the
bound-recording arm; they require their own dispatch/diagnostic preservation
lemmas when extending N.

`candidate_insert_bound` retains the current processing cause and invokes
`candidate_insert_bound_with_evidence` (`635–645`). The latter:

- checks owner/kind/index and selects one of eight Value/Effect × lower/upper
  × row/nonrow lanes (`730–748`);
- admits the exact BoundKey's origin/relation before append (`750`);
- appends the exact payload to the selected vector, with no deduplication
  requirement (`754–852`);
- reads the addressed physical slot back and checks the full BoundKey against
  the expected key before emitting its receipt (`854–872`).

`candidate_bound_origin_with_evidence` in ordinary mode calls
`candidate_context_bound` regardless of the evidence-cause alternative
(`candidate_effect.rs:530–552`). `candidate_context_bound_for` constructs
`bound_pair(bound)`, retains the identity/default child and attaches it to
that same BoundKey (`candidate_context.rs:3898–3937`). `attach` deduplicates
identical **relation membership**, not physical vector occurrences
(`3283–3295`). Diagnostic origin keys also have their own deduplication; none
is a proof that the physical vector has unique entries.

Let `B` be the old bound conjunction and q the active inequality. Each new
logical bound or physical incidence projects to q. Hence at these boundaries:

```text
B ∧ P ∧ q   ≡   B ∧ q ∧ P ∧ q.
```

When the current-item copy is subsequently removed, the stored q remains.
Summary flags, dirty markers, evidence IDs and duplicated attribution do not
add a different inequality. The source readback excludes a reversed or
different emitted key in a successful constructor. This is the promised local
record/transfer invariant; it establishes no completeness of other owners.

## E. Every selected opposite-bound consequence is entailed

`candidate_opposite_count` reads the current canonical owner's opposite direct
row vector length plus opposite exact vector length (`878–902`).
`candidate_opposite_bound` reads one addressed direct/exact entry (`904–938`).
`candidate_replay_bound` captures **one count**, then iterates `0..count`
(`1070–1112`). This is a saved-count physical-index loop; it is not a theorem
about every logical opposite bound forever, every future append, or unique
coverage of logical obligations. Duplicate physical entries can select the
same inequality again.

For any actual selected entry, both orientations are valid in the independent
preorder/set inclusion:

```text
new lower:  b ≤ o, existing upper: o ≤ u  ⇒  b ≤ u;
existing lower: l ≤ o, new upper: o ≤ b  ⇒  l ≤ b.
```

The premises occur in B after insertion (and q is still active).
`candidate_replay_bound` sets precisely `(bound,other)` for Positive and
`(other,bound)` for Negative, preserves the sort, and orders lower/upper
BoundKeys accordingly. It constructs a Value or Effect task in those exact
directions (`1081–1109`). Each generated task is therefore entailed by H.
The proof works for arbitrary finite symbolic Effect sets, including nonempty
sets, using only subset transitivity. No base-atom, Function-inversion or
record-compatibility law is needed here.

`candidate_context_begin_replay` computes the task's canonical pair and walks
the actual lower/upper **retained-fiber** cursors, with the two newly-retained
fiber quadrants (`candidate_context.rs:3992–4056`). For each selected fiber
combination it constructs that same task pair with identity context/default
flow by R337 J, records its dependency and retains the child relation in
`ReplayOperation.children`, alongside the exact `operation.task`
(`4057–4074`). Missing or previously recorded fibers can yield fewer children,
including zero. This proof establishes that every emitted child is entailed;
it does not establish that every required temporal/fiber comparison is emitted.
Specifically, the ordinary branch checks `dependency_keys` before pushing the
child into the retained vector (`candidate_context.rs:4053–4056`). For the
present logical-update lemma its skipped consequence is already entailed by
the two actual stored antecedent inequalities. A duplicate-key hit is not
evidence that its earlier typed child remains queued, was solved, or has valid
cache/coverage history. No such scheduling claim is needed for the local
solution-family equality, and none is inferred.

Since these new R obligations are all consequences of existing B and q,
adding any finite number of them preserves the solution family. Recording
dependency keys, replay heads or duplicate fibers changes scheduling and
evidence, not the inequality denoted by each child. The exact before-recursion
lemma is:

```text
Sol(H(S_before_record)) = Sol(H(S_after_record_and_enqueue)).
```

Both sides already include the admitted q, have the same rows/representatives,
and differ only by its equivalent stored form and entailed replay obligations.
Forward inclusion uses transitivity above; reverse inclusion uses retention of
every old stored/pending/processing obligation or its identical stored copy.
Thus the conclusion holds even if either solution family is empty.

## F. Retained replay queue and typed worklist are different owners

The ordinary bound-replay call is
`candidate_context_drive_replay(replay,None)` (`candidate_extrusion.rs:1110`).
The None-provenance branch of `candidate_context_consume_replay_child`
(`candidate_context.rs:4170–4200`) reads
`replay_operation_queue_next`, which selects `children[queued]` and carries
the stored task plus its exact replay acknowledgement (`2369–2376`).
`enqueue_item` prepares evidence/capacity, advances the queue-transfer cursor
and performs the infallible queue insertion (`lib.rs:15223–15250`;
`transfer_replay_child`, `candidate_context.rs:2384–2396`). The retained
unconsumed child remains in R while the same task is added to Q. Its cursors
separate generated, queued and consumed work; a transfer is not completion.

`candidate_context_drive_replay` may transfer successive available children
one at a time, then return `Queued` while they remain unconsumed
(`4206–4227`). It does not recursively solve those ordinary children. Therefore
the selected parent's bound vectors/representatives are not changed by child
solving during this saved-count generation call. Relation/evidence allocations
are separate from Value/Effect-row allocation. This is neither an atomic
batched-worklist publication nor a claim that each child drain returns before
the ordinary loop advances.

The **Some(provenance)** restoration adapter instead invokes/steps a child
TypedDrainFrame and uses the Running/Ready acknowledgement barrier
(`4097–4170`). Its recursive child solving, saved-count/live-index restoration
and terminal acknowledgements are outside this family. The historical failure
of unique-slot scanning is not reused as a theorem about this queue-only
generation prefix. Likewise no result about ordinary queue publication proves
the restoration adapter or the whole replay driver correct.
