## 1. Frozen statement and scope

Use the authentic source graph

```yu

```

Fix the actual first Call, its original f/provider U/captures, original
alpha/E_A/E_R/F_beta, source declarations/roles, current state and active
runtime references, actual source annotations, executed choices and historical
installed contracts. Fix one original joint assignment/strategy over all
shared and description-indexed fields, with original K/D and binder scopes.
No actual fixed field is rewritten when a logical checking description A_i
is formed. Any real dependency of an installed contract remains fixed and
retained as a clause/dependency; this theorem grants no eligibility bypass.

Construct a finite family of **source-owned open** caller contexts C_i with
hypothetical g:Value(A_i), before observations. Each has its actual independent
source/checking clause program Phi_i and conjoined arbitrary well-scoped client
W. No satisfiability of these clauses is asserted. For each original scoped
strategy satisfying the jointly retained independent context/carrier clauses,
assemble its d_i before receipt or execution. The required local conclusion
is equality of the execution-input projection pi_exec defined in §3, then
fresh elimination of the same f membership at each independently assembled
d_i. This is not transport of P_F(d_0) to P_F(d_i).

Providers may be arbitrary valid/opaque callables. Source-only providers,
closed alpha, termination, direct-only effects, empty captures or empty W
are not assumed. Arbitrary independent non-source contexts are not reindexed
by this source-constructor lemma. The original broad-context forward theorem
and all its domains remain as stated separately. A different actual conversion

effects, placement and dependency closure must be retained. The theorem is
pointwise for each actual source elaboration/Executed choice, rather than
identifying executions of different conversions.

## 3. Decisive invariant: pi_exec does not read A_i

This is an actual constructor read argument, not signature-only erasure or an
axiom that arbitrary U ignores a changed argument. Inspect [ordinary semantics
§§2–3](../design/2026-10-02-ordinary-computation-semantics-package.md),
[typed core §3](../design/2026-10-02-typed-computation-core-elaboration.md) and
[owned Call §§4.2,12.3 Call](2026-10-07-owned-call-contribution-construction.md).

Define the execution-input projection at this source invocation explicitly:

```text
pi_exec(d_i) = (
  actual Act(v,U,r) and retained executable/private operands,
  whole carrier t: code, environment, runtime references and lineage,
  actual C1: executing code/environment, live store and current activations,
  current executable port/delimiter references,
  installed active-view/profile/boundary/receipt operands and entry schema,
  producer-declared role, entry/body/native-return/designated-consumer operands
).
```

These are the actual operands read by the first receiver constructor, including
current typed runtime references. A not-yet-executed receipt contributes its
actual source schema/preconditions, not an already performed receipt event.
Only actual current delimiters/views occur in this projection. Complete
IF_i, d_i, ReturnFutureRef_i and typed future domains are **not** asserted equal;
their description-indexed proofs and independent obligations remain retained.

| pi_exec component | Its owning read/construction on this graph |
| --- | --- |
| Actual callable/provider and private contracts | Name f looks up the same registered binding. Act(v,U,r), closure environment and actual operation declaration are read from that same value, not inferred from A_i. |
| Whole carrier code/environment/lineage | Call constructs Delay of the entire original Unit computation and original lexical references. Unit code has no g or A_i occurrence and runs no prefix during construction. |
| Live store/configuration and active frames | Name/Return and inert Delay do not change the store or install a receiver/handler. The existing caller frames, current activations and actual typed references are the same. g is not yet an installed binding. |
| Actual receipt/boundary schema | The invocation uses the same source call and f's original F_beta/slot/profile correspondence, together with U's actual declaration/entry. The inferred result description is not a source annotation or a new receiver contract. |
| Entry role, body and rebound references | ExecuteCallable dispatches U's actual entry; Value entry forces that same carrier then rebinds its actual Unit result, while retained entry stores the same carrier. No dispatch examines A_i or a solved result shape. |
| Native return and designated result consumer | A closure uses its stored body computation port. An operation uses its original declaration-derived consumer after native Return(MakeRequestThunk). A function variable retains that executable definition. AppTarget(A_i) is not this consumer. |
| Complete executing CallView | It encloses the same actual argument/entry/body/native-return/declared consumer sequence under the same installed source contract. No A_i annotation/view delimiter is installed before the result. |

The proof is direct evaluation of the source constructors in that order.
The Name result is the same value/current C1. Delay is the same whole code and
reference tuple. `ExecuteCallable` therefore receives the **same U, t, C1 and
actual declaration/entry/consumer data**, including existing installed runtime
view and boundary references. Thus pi_exec(d_i)=pi_exec(d_j), rather than
equality of the complete dependent challenge/interface records. This is not
just matching erased type heads. If U is opaque, it is still the same
operation with identical declared executable operands. No theorem transporting
an opaque operation across different operands is used.

The pending outer Bind does retain A_i in its **logical typed result/suffix
proof**. It has not installed g or its checked result evidence. Its raw source
suffix is the same Name-g/Unit/Call code and the same pre-existing references;
its description-indexed typing is not asserted equal. Actual conversions,
Shared dictionaries, installed Mono contracts, real callback annotations and
their free dependencies are not erased into that logical suffix. If one of
those actual fields depends on an old A1, it remains that original field;
its dependency can constrain or prevent a proposed generalization independently
of this first-invocation lemma.

`ReturnFutureRef_e(h)` in owned Call §4 is retained in IF_i as the original
dependent result/future contract; its typing argument can vary with i. The

`CalleeRef_e(h) >>= ExecuteCallable(actual_f,WholeArgRef_e(h),C1)`;

The actual Unit filling has its independent literal/Return/Delay proof at

```text

```

All its fields are assembled at their original scopes before receipt or any
observation. ActualAdm, dynamic receipt, desired output, P_F truth and native

rule, not a new missing constructor or a postulated action on d_0.

Now eliminate the **same full hereditary f certificate**, at each d_i:

- semantic-input §3.1 clause2 supplies fresh ActualAdm(U,d_i);
- clause3 supplies P_F_beta(d_i) for **every observation of the actual
  ExecuteCallable(U,t)** and its admitted developments, with the complete
  joint typed-state envelope.

By §3 these are observations of the same first invocation, not newly executed
calls selected from a subset passing F. An original complete raw witness z,
or pending raw prefix q/k, can therefore be used unchanged whenever its
independent event/development premises for this constructed frame hold.
Its new final guard proofs are supplied by the fresh clause3 elimination at
d_i. We never infer P_F(d_i) by transporting the old P_F(d_0) proof handle.

This distinction is decisive for opaque guards. Each invocation's actual
whole observation is the same operand of a newly justified predicate at d_i;

still proves no guard. The same quantifier is used at later actual compatible

## 5. Return, pending requests, Resume and distinct future domains

For a complete first return, the unchanged raw invocation supplies the same
z, actual returned provider/private references and current C2. Fresh P_F(d_i)
gives the original full alpha certificate at that event. When the actual local
source checking clauses provide the full same-value alpha-to-A_i check, apply
it to this identical decorated object. The existing Result rule uses both
tagged inputs jointly,

```text

```

The inputs and original tags are the same; matching typed maps belong to
their actual IF_i positions and need not be equated across i. Their legitimate
source construction and fresh guard proofs replace no private contract.
ResultBind/Lemma W then gives the logical g:Value(A_i) entry at that same C2.
The selected AppTarget introduction also consumes its actual local outward
guarantee clause; this lemma supplies no reverse from actual support to
nominal E_R inclusion. Arbitrary other finite checking alternatives retain
their actual clauses and independent obligations. In particular this is not
the still-open normalization of every finite Function check to uniform ports.

For Request, no g is installed. The same first-receiver q and raw k are
retained; ordinary Bind appends the original raw suffix in source order:

```text
Request(q,C,k) >>= suffix

```

The logical typing of that pending suffix is indexed by A_i and its independent
clauses; it is not a new request/receipt or a copied proof at changed arguments.
Raw Resume continues the original k with the current response/store C'; it
does not snapshot a store, restart entry, reinstall an expired shallow handler
or manufacture a second receipt. At each actual compatible response/Resume
development the same source constructor/read argument and fresh membership
elimination applies. Divergence retains finite prefixes without a fictitious
Return or g.

This does **not** identify all future domains. The original operation/response
contracts, installed private views and historical admission witnesses remain
actual fixed fields. A future use of the returned value at A_i has that
view's own independently admitted demand/response/future domain and current
activity. It is not equated with an old A1 or another A_j domain merely because
the provider is the same. An old arbitrary history cannot be reused at d_i
unless its original independent compatibility premises hold there. The source
schema keeps these premises universally at their original binders; no history
is removed to make checking succeed. This is pointwise construction of each
legal source checking frame, not an action on every opaque external context.

## 6. Raw/logical projection and the earlier whole-d dependency

The actual source construction supplies the following separation:

| Retained field | Treatment at this constructor |
| --- | --- |
| f/U/captures, actual source code and registered roots, carrier, live state/activations, actual installed contracts, dynamic event/receipt/response/raw continuation | Shared original actual inputs/outputs; retain complete genuine dependencies. |
| C_i's independent typing/checking derivation, hypothetical g:A_i, IF_i substitution, d_i assembly/admission proof, P_F(d_i) certificate | Description/event-scoped logical proof fields constructed at those rules, with original dependencies on A_i and preceding shared inputs. |
| Source boundary or actually installed Mono/Shared contract, including any historical record containing d_0 | Retain exactly its existing complete value and all free dependencies; this construction does not relabel or erase it. |

The complete d_i is a dependent logical admission record **formed before**
execution; it is not wholly an actual dynamic receipt merely because actual
runtime fields occur inside it. This is derived from its assembly inputs and
the actual execution read set, not asserted by the absence of a runtime field.
Actual invocation establishes the dynamic receipt using the unchanged schema.
One may then store a logical proof about that event without making every free
checking description an installed execution input.

This supplies the source-owned construction absent from the repaired local
proposal: rebuild C_i and d_i, prove equality of pi_exec, then freshly type
the same invocation. It does not certify that every occurrence of d_0 in an
arbitrary installed private contract has this logical classification. If a
genuine fixed contract retains it, SOURCE-GENERALIZE follows that contract's
full dependency closure. Eligibility and native capture/freshening still need
their own application of that walk to the actual publication package.

## 7. Exact scope of the result and handoff

fresh elimination of the same full f certificate. Return/Request/Resume and

claim that every future history admitted at d_0 is reused at d_i.

This result does not close local Generalize eligibility, universal native-use
correspondence, source finite-check normalization, native MODEL establishment,
full reverse FIRST-RESULT, general copy/context applicability, C0, principality
or production/F5. It preserves all original source/checking clients and their
real executed choices/dependencies. It does not authorize suppressing a fixed
dependency because an unannotated source binding is convenient to generalize.

No new source definition or competing observable semantic choice is proposed.
