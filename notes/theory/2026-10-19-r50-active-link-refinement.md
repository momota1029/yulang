## Candidate protocol: typed source origin plus current-action proof

The following are **proposed premises**, not current source fields or approved semantics.

**P1, source origin.** When and only when the active-map branch emits a recursive Name Link, collection seals an `ActiveLocalLinkOrigin` for that exact Name occurrence `o`. It records source owner/schedule `S`, Name expression, `HirLocalId l`, local slot `s`, initializer endpoint `r`, Name target component `v`, initializer source region `R`, link action index `i`, and the owning initializer's installation boundary index `k`. Its constructor checks the HIR Name resolves to `l`, the binding is the parameterized local whose initializer owns `r`, the Name region descends from `R`, and the emitted action at `i` has exactly `(o,r,v)`. Record or derive `k` only from the owning `Install`/`LocalAnnotation`; do not infer it from numeric solver levels. A definition-body Link receives no such origin. The frozen plan is immutable during source execution. A map by exact occurrence is one possible representation; the same sealed fields could be stored adjacent to the source action and looked up through a precomputed index. Mere `bool active` or an untyped `Action::Link` is insufficient.

**P2, successful execution.** The only way to produce an ephemeral `ExecutedActiveLink` for scoped Apply is the guarded source step at its current `Action::Candidate(recipe)` position `j`. The guard verifies the same frame schedule/attempt `S`, `Stage::Execute`, `Frame.next == j`, the recipe and `ApplySourceInput` agree, and `i < j < k`. The frame's monotone successful-prefix invariant must cover the Link at `i`, including its slot-30 admission and actual constraint propagation. Either pass this checked action context directly into admission or otherwise prove that no alternate caller can impersonate the current source step. `lib.rs:11220-11235` has an additional `admit_candidate_fact` caller, so a bare `graph.source.is_some()` check is insufficient. A failed or unexecuted Link cannot advance to `j` under the guarded driver. A new attempt needs a new frame identity; a stale plan entry alone never authorizes admission.

**P3, scoped consumption.** At `candidate_call::authenticate_scoped_apply`, first retain the existing HIR peeling and exact `LocalCalleeRoute` checks. For a candidate active branch additionally require that `input.callee` is the **bare** Name expression `o`, its `callee_value` is the Name value endpoint for `v`, the checked recipe is the current `j`, its owner/local/slot equal P1, the source region has the P1 ancestry, the open `graph.locals[s]` is still absent, and the binding's initializer endpoint equals P1's `r`. Exact stable endpoint identity is needed; a solver-equal endpoint, common spelling or a route for a sibling occurrence is insufficient. Only then may the new **approval-dependent** rule admit that Apply with the current open monomorphic root. The rule creates no `LocalScheme`, `LocalUse`, FreshUse, retained route or new type root. If the callee is an installed generalized local, preserve the existing exact `LocalFreshRoute` plus scheme/use-instance branch and all its checks; a failed route check must not fall through to the active branch.

**P4, lifetime.** The ephemeral execution evidence is usable only for the current Candidate action before `k`, never stored as a durable property of the Name or scheme. Install ends this active interval; a later Name is served by ordinary Local routing. On failure of the current source action or a later intrinsic action, no candidate is published and the private session is discarded. A route transaction may restore its own later Local work without rewriting the earlier intrinsic Link. If same-session source retry, invalidation, or production suspension is later introduced, it needs its own attempt generation and proof that no stale successful-prefix evidence survives; current test-only synthetic support does not provide this contract.

### Conditional refinement lemma

For any accepted source schedule and **any** scoped Apply whose callee is the exact bare local Name `o`, suppose P1-P4 hold and the Name was resolved to an active initializer binding `l` in the current source attempt. Then the proposed active branch accepts only an Apply whose own callee occurrence is `o`, whose recorded local/slot are `l/s`, whose Link at `i` successfully constrained the Name from the **same** open initializer endpoint `r`, and whose Candidate action `j` executes before the owning Install `k` in the permitted nested source region. The admission step adds no copy or fresh use of `r`; the previously admitted Link and subsequent ordinary Apply relation remain the only relevant new value constraints. Thus this *candidate admission extension* preserves the approved single-root monomorphic construction at that occurrence. It does not prove that the constraints are satisfiable, complete, principal, or evaluator-correct.

Proof: P1 seals the active branch and exact HIR/region/root identities; the other Link constructor cannot supply P1. P2's guarded successful-prefix induction on `Frame.next` establishes that action `i` completed before current `j`; no failure step advances the frame. P3 matches every independent coordinate of the Apply witness to P1 and rejects any altered coordinate. P4 bounds the token to this current action before installation. The new admission branch performs no capture/freshening by its stipulated operation, and the ordinary Link still targets `r`. Existing generalized locals cannot enter this branch because they lack a current active origin and open uninstalled slot; their exact FreshUse authentication is unchanged. This establishes a conditional *structural admission and noninterference* statement, not a theorem of the existing compiler.

### Direct and nested cases; falsifiers

For the R49/R50 fixture's direct `loop x`, P1 would identify its Name occurrence `o_d`, `loop` local/slot, and outer initializer endpoint. Its Link precedes the direct Apply Candidate and outer Install. For `helper y = loop y`, the nested Name occurrence `o_n` is distinct, and its source region is a descendant of the still active outer initializer region. Its own Link and Apply precede the helper's Install **and** the outer `loop` Install. The helper's later uses receive their own installed-local `LocalFreshRoute`s. They cannot witness `o_d` or `o_n`.

| Attack | Required rejection in P1-P4 |
| --- | --- |
| Sibling `loop` Name, helper Name or copied occurrence | Exact owner/schedule, HIR expression, occurrence, local, target and current Apply recipe mismatch. A sibling's Link or FreshUse route is never borrowed. |
| Stale occurrence after outer Install or from another attempt | `j < k`, uninstalled slot and same live frame/attempt fail; a plan entry alone has no execution authority. |
| Substituted initializer root or merely solver-equal endpoint | P1's exact binding initializer endpoint and action tuple disagree; endpoint equality after solving is not source provenance. |
| Premature Install, including annotated publication | Current `j < k` and open slot fail. The published scheme cannot be treated as an active root. |
| Failed or unexecuted Link | The guarded frame cannot advance past `i`; a static source origin or fabricated flag has no successful-prefix proof. |
| Definition-body Link with same opcode | No P1 active-map origin; the terminal Link is not an active-local producer. |
| Copied `active: true` boolean | It supplies none of the sealed origin, frame, successful action or exact consumer equalities. |

The first five rows are falsifiers for any concrete implementation: if it admits one, P1-P4 have not been realized. A positive fixture must reach the actual scoped `session.execute().unwrap()` on the unmodified source, show both exact Links before their Applies, preserve zero FreshUses for those Names and distinct exact FreshUse routes for later helper Names, and trace the first native Apply admission. Such a run would test implementation correspondence, not prove the full parent theorem.

## Exact stop premise and owner handoff

The **first unsupported premise** is an authority-backed rule allowing an *executed, exact active-local Link* to authenticate its matching scoped Apply without an installed `LocalScheme`/`LocalFreshRoute`. The approved recursion decision selects the monomorphic producer but does not define this consumer interpretation. P1's typed origin and P2's guarded proof are also **unimplemented**; the current Link action omits the needed local/scope/interval fields and `authenticate_scoped_apply` has no active branch. Neither endpoint equality nor `Frame.next` by itself supplies authority. Luna owns the design/semantic approval boundary. Later, under a new exact code contract, the minimal provisional implementation TODO would be: seal active-branch origin at `candidate_source::emit_candidate_source`, carry guarded current-action execution proof through `candidate_source::step_candidate_source`/`execute_candidate_action`, consume it in `candidate_call::authenticate_scoped_apply` via `shadow_apply::admit_candidate_fact`, and account for source-attempt and transaction lifetime in `candidate_scheme::GraphState`/`lib.rs`. The falsifier is any of the attacks above or any positive recursive Apply whose exact source Link cannot be shown to have completed. No compiler edit is authorized by this note.
