### 3.1 Preparation congruence: a bounded operational result

Fix one successful collector input, its source environment/namespace,
definition/root/component seeds, existing registrations and chosen candidate
mode. Change only an external expected-receiver description Θ that no existing
constructor reads. Then the collector's structurally meaningful artifacts are
the same, up to consistent fresh internal allocation names: exact source
occurrences/binders, component and parameter sharing, action sequence, original
annotation scope, source regions, selected numeric levels and source Value
reference associations are preserved. This is a characterization of actual
preparation, not a statement that it is B-correct for both descriptions.

Proof by the actual work expansion:

1. The initial scans at source 539–636 allocate components, parameter recipes,
   registrations and aliases from source indices, parameter syntax, bindings
   and annotation scopes. Each lookup joins the same original source key.
   Primitive preparation reads the actual annotation tree, not an inferred role.
2. Each Visit reads its source form, current source level/region and already
   indexed endpoints. It pushes the same finite continuations/children.
   Lambda entry registration is syntax determined; Catch binder aliases come
   from the original scrutinee/pattern; local region/level derives from the
   original initializer boundary. These are substantive branch dependencies.
3. Each CatchArms/Initializer/Install/Finish row in the table reads those same
   inputs and appends the displayed facts or unchanged recipe operands.
   All branch/result/initialization effects remain included in the same places.
   Ordered relative actions, including annotation prefixes, are preserved.
4. `Plan::region/computation_scope` (49–80) allocates a nominal source forest
   from that work expansion; Group/Ascription/Block aliases use original child
   scopes. `candidate_value_graph::retain_source` derives its original Value
   vertices, Name edges and Apply associations from those same source children.
   Neither derives them from solved type endpoints or invents a new Value.

Thus the induction is nonvacuous for every form that the current successful
collector reaches, and recursive named references remain references. It proves
neither resource-equivalent execution after adding a new consumer nor equality
of raw constraints with B's role-dependent semantics. A profile/context consumer
could make an existing plain relation mean something different; congruence of
raw preparation does not discharge that equation.

## 4. A genuine commuting body subcase

This subcase concerns an original literal body consisting of one primitive
literal, or its own fixed Value-bound parameter Name. It is not a restriction
on the parent. Freeze the source Γ, parameter endpoint A and all original
witness scopes. Receiver Θ does not change that Value entry/binding.

For a primitive literal of type T, typed core §6 gives `I=Value(T)` and
`Result(I)=Comp(empty,T)` by its literal and Normalize rules. The actual source
Finish literal emits, with fresh body value/effect positions v/ε,

```text
T+ <: v       v <: T-
bottom_effect <: ε       ε <: empty_effect.
```

The source branch chooses precisely the same T on both sides. These are body
constraints and mention neither β nor a receiver effect endpoint. Their source
occurrences and cause slots are fixed. For the literal's own Value parameter
Name, Γ(x)=Value(A) after syntax-selected entry; the actual endpoint aliases A
and only the same pure Name effect bounds are emitted. Typed core's name and
Normalize rules give the same body interface, without deriving it from a
solved empty row.

Therefore these constraints may be prepared before Θ without changing their
truth, body interface or source evidence under any fixed original joint
assignment. For any later independently valid boundary formula Q on that same
assignment and scopes, conjoining these already justified body constraints
before or after Q leaves the same joined formula and complete solutions.
This proof does not hide separate marginal witnesses. There is no operation,
provider choice or new annotation attachment in this body subcase to replace.

This is body-only commutation. It expressly does not identify ε with J_call,
derive Handler Function ports, prove arbitrary Q is B's boundary formula, or
claim that a Value-entry invocation with this body has no effects. The received
argument can request effects or diverge before this body is reached. Thus even
identity does not discharge the original full-literal B parent.

The typed core's endpoint-substitution theorem can also be reused at its exact
scope: admissible endpoint substitution preserving original interface tags,
typing premises and binder/path structure commutes with Result/Normalize and
the source result skeleton. Θ changes receiver introduction/authority, not
merely a value/effect endpoint substitution. Treating Θ as such a substitution
would assume the missing factorization premise.

## 5. The first unresolved semantic constructor

The actual delayed operations are not an unspecified neutral interpreter:

- `admit_candidate_fact` (shadow_apply 1521–1691) validates original source
  fields, constructs and actively propagates the ordinary Function demand,
  then admits callee/invocation effects into application effect.
- `admit_lambda_fact` (lib 11271–11443) allocates entry/returned rows, admits
  entry-to-return and body-to-return inclusions and actively admits the
  completed Function into its literal root. Its entry selection uses syntax
  Value/Computation, not a proved Pure/Handler port elaboration.
- `candidate_context_seed` (candidate_context 2875–2939) creates the actual
  relation context from the native pair/allowance and original source
  association, retains source flow and occurrence. In scoped mode an omitted
  formal call gets its original demand/output scope/input route; an Apply
  result-effect edge gets the source argument-scope release transformer.
- `candidate_function_port_admit` (3001–3067) reads the parent's **post-check**
  context, applies Swap or Preserve and prefixes child-local wrapper authority.
  Its actual FunctionPort dependency is not supplied by a four-port shape.
  A scoped omitted demand constructs the existing argument stamp/result-body
  protection transformers from its original source call.
- Annotation/effect constructors (`candidate_effect` 1113–1168, 1237–1288,
  1313–1464, 1466–1689) retain original lexical scope, composed polarity and
  resolved annotation/declaration position before creating support/allowance,
  source weight, attachment bundle and checks. They do not synthesize Θ's
  Handler role from a matching row.

The earliest required semantic consumption is the role-selected boundary and
Function-interface interpretation of L, before deriving its typed effect-view
relations. In a factored native route, that interpretation must be available
when the first affected body/entry relation is seeded; carrying it only on the
later `Action::Lambda` completion cannot be assumed sufficient. Existing body
actions precede that completion, and their relation contexts/source dependencies
have already been constructed. The existing code contains no demonstrated
operation that retroactively replaces those relations by the B ones.

This does not prove every body relation needs a new context, or that late
immutable preparation is impossible. The exact missing equation is:

```text
source-selected Handler(β,Slots(β)) at L
  -> the native relation/Function effect-view construction for the same u,
     original body/entry paths and joint assignment,
such that interpreting Prep(e) there yields exactly B's obligations/evidence.
```

No inspected actual constructor establishes this equation. Charter §24 leaves
the effect-port elaboration proof open; source-indexed §6 supplies valid
projections/attachments as hypotheses. Neither the primitive lemma nor the
collection congruence supplies them. The equation concerns a bounded local
source-role consumer, not a newly imposed universal Function-membership or
complete Call theorem. The profile-constructor lane can supply its own exact
part of this premise; authentic same-use instantiation remains the separate
supplier gate.

There is consequently no established source-generated **noncommuting** body
artifact in this pass. Catch's known conservative forwarding and provisional
raw-continuation bound are reported honestly, but they are not fabricated into
a counterexample to phase ordering. Nor is absence of an existing Handler field
proof that no equivalent preparation/consumer design exists.

## 6. Consequence for the next owner action

The raw-artifact pass replaces the prior scheduling-only method. It localizes
the remaining premise to a real semantic construction point. The economy audit
keeps before-body role/evidence conformance in A/B; recovering β/source-use
identity after discarding it is D debt. It does not reclassify this parent C or
add another proof-only relation. A third chronology or passive-context test
would leave the new missing equation untouched.

The source owner must now provide that role-indexed local constructor, using
the separate retained-profile/source-use result as applicable. At its first
actual body/entry relation admission, compare its generated relation/effect
views against the selected B constructor under the same original fiber. That
is one concrete next action; no production seam is certified implementation
ready by this partial note.

If an owner-level implementation experiment is authorized, defer at least the
role-dependent interpretation/emission of Function effect views, attachment
incidence and source relation contexts until Θ is available. Defer raw body
constraints only where that comparison shows they depend on Θ or encode a
wrong projection. This pass justifies retaining original source/binder/region
inventory and the §4 primitive preparation; it does **not** justify either
reusing every existing body fact or restarting/recollecting the entire body.
The correct amount of deferral is unresolved at the displayed equation.

Falsifier for any proposed full factorization: a B-admitted joint assignment or
evidence choice removed by the prepared native relation, a native assignment
or authority unavailable under B, changed attachment/provider/residual lineage,
wrong same-use β image, independently chosen port witnesses, endpoint-copy
strengthening, or a supported nested constructor whose role/view dependencies
cannot be supplied before its affected relation is seeded. Primitive body
commutation cannot excuse such a failure. Private resource failure must not
publish a fabricated consistent contextual literal; complete rollback is not
introduced as a new goal.
