## 5. Derivation and exact non-entailment

**Conditional reference calculation.** Suppose the exact primitive, Name and
ambient occurrence trees are supplied and finite, with owner-preserving child
inclusions. Define a reference occurrence presentation for the displayed L
Call production by preserving those trees and adjoining the five distinct
local head occurrences `L.wf`, `L.value`, `L.argument`, `L.receive`,
`L.result` in the original scoped conjunction/existential structure. The
five heads and their source origins are introduced by that reference
production. Its inverse selects one of those five local heads or a supplied
child/inherited occurrence. Hence this **chosen reference presentation** is
exhaustive relative to its own explicit production and supplied leaf trees.
Legal action transports all five heads, leaf fibers and dependencies together.

Proof: forward generation synthesizes the actual Name/literal children,
normalizes them at their fixed Value tags, allocates one scoped F_c and emits
the five listed conjuncts. Each new occurrence has its constructor position
as a distinct label. Case analysis on that explicitly defined presentation
gives inversion. Substitution into the whole scoped production gives the
action equation. This proves a conditional reference presentation theorem;
the definition of its labels is not a theorem about original source rules.

There are three exact missing arrows to H-inventory:

```text
literal §4.1 copying an existing relation
  -/-> a concrete exhaustive primitive occurrence/alternative tree;

five emitted reference Call heads (+ supplied G.cert in the other envelope)
  -/-> exhaustive inversion of all original Application occurrences;

Code-Call construction from original operand/result/suffix origins
  -/-> generation or enumeration of the original inventory it retains.
```

The first premise is only a reference to an existing primitive, not its
equations. The second lacks an original owner introduction plus a coverage
eliminator; G.cert is additionally a supplied decorated package, not a source
production of its contents. The third follows from Code-Call's exact input
interface: it expressly preserves a separate result obligation even though
Check projects only the VIncl/argument origins. Its Theorem S applies to that
already supplied source derivation and cannot invert an unspecified atom
grammar. The adopted O0/O1 outputs change none of these interfaces.

This is also a logical distinction between relation equality and occurrence
equality. Even an equality of conjunction truth sets does not entail a
bijection of their indexed proof occurrences: idempotence of conjunction
erases multiplicity, and existential projection erases proof alternatives.
The §5 G_call inversion is explicitly restricted to a fixed decorated Call
rule whose premises are the displayed ones. It proves agreement with that
rule envelope. It does not assert that every original atom, attachment or
licensed proof has a preimage in it. A coverage/bijection premise must be
proved at the original owner, not extracted from semantic truth equality.

Granting actual flat emission, all five head origins, or successful checking
would not supply the missing exhaustive inverse. Conversely this argument
does not prove that a genuine additional original atom exists, nor license
one. It proves the precise bounded conclusion: the named clauses contain no
complete original occurrence presentation or coverage rule from which the
required equality/bijection follows. A selected exhaustive owner rule with
concrete leaf trees and origin/attachment inversion would defeat this stop.

The smallest source witness used is the standalone `my apply f = f 1`:
one Application, one Name callee and one primitive argument. No out/id use,
capture, multiple Call or recursion is needed to encounter these absent
enumeration premises. This is a minimized premise witness for this method,
not a semantic counterexample or globally shortest-source claim.

There is no remaining user choice about already selected protection, roles,
whole arguments, actual entry, complete invocation or Q independence.

original inventory**, should the primary choose a new rule rather than
locating an existing one:

- Supply a previously fixed original owner grammar and concrete primitive /
  certificate occurrence trees, then prove authentic insertion, inversion and
  old-family correspondence. This yields a proof route without inventing new
  original equations; its supplying source is currently absent from this packet.
- Present a complete candidate original owner rule for explicit review and
  user approval, retaining the entire old family, literal branches, inherited
  owners and all required result obligations. This makes the candidate's
  exhaustive scope a new definition selection. Merely approving the five
  displayed heads would leave the unspecified leaves and old correspondence
  untouched, so that is not yet a fully spelled approval object.

These are process options, not two proved competing complete Yulang meanings.
Authority permits legitimate construction, but this research assignment
does not adopt new original equations or install a rule. Conditional
reference completeness does not supply H-original-install.

**Recommended next action:** ask the owning constructor lane to supply one
concrete finite original presentation for the primitive leaf and Application
owner, with exhaustive origin/attachment inversion and old-family retention,
then adjudicate whether it is an established original rule or a complete new
candidate requiring approval. Stop equivalent Call probes until that supplier
exists; another checker assuming these inventories would leave this premise
untouched.
