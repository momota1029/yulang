## 3. Local descriptor derivation on the same tuple

Take an arbitrary admitted challenge and any actual source-base observation
or independently admitted finite response/raw/future development.

**Admission before receipt.** Project gamma and its independently formed
schema from the challenge. `PackGeneric(kappa,gamma)` injects that exact
record into the fixed actual inlet, with unchanged IF0 intrinsic guards.
This constructs ActualAdm at the same carrier/current event. It assumes no
Function membership of U, safety of its body or successful Direct. A
checked schema is not asserted equal to the fixed generic inlet.

**Start and receipt.** The independent initial world/registered holes/IF
preconditions give VP-Start. The actual lawful receipt/frame action gives
VP-Receipt. Neither record contains a formal value or completed result.
The source's actual Pure role is a formation field of this specific closure;
Value entry supplies no generic Pure-role inference.

**Force and pending entry.** Eliminate gamma's Car(J) execution field at
the same independent designated demand/current event. Apply its finite
whole-image Delta proof and result-port map to each complete or pending J
member. This gives T_I at the same observation tuple, with every original
guarantee, operation/response/raw-handle and live-world predicate. VP-Force
therefore types the entry observation. A divergent prefix needs no returned
value or operation handle when no request has been exposed.

For Request(q,k), the original Bind equation retains q and k and appends
only the unfinished suffix. At each admitted response/raw demand, eliminate
J's continuation certificate and that event's Delta subtree before applying
VP-Develop. The continuation executes at its current configuration, then
rebind/body/return. Receipt is not replayed and no formal is installed before
the entry Return. Induction covers every finite development and lawful branch.

**Completed entry.** J's Return elimination supplies the same actual
payload/provider and current W. Apply gamma's hereditary result check to
obtain V(A) without replacing that payload/provider. The independent
BindIntro installs precisely that value at the formal slot; its old bindings
restrict to the same compatible current event. VP-Entry gives EntryValue/Body.

**Id body.** Independent ProjectIntro reads that installed field of W;
RestrictIntro applies its hereditary certificate at the actual read event.
Pure ReturnIntro produces ReturnMem_A of the same decorated value at the
body-result port. Its prefix constructor asserts no result before completion.
Since B=A under the one frame assignment, VP-BodyReturn applies with that
same V(A). Echo follows from the actual raw alias equality; it does not equate
different proof choices or merge original body/outward descriptor ports.

**Pick body.** The formal is still the actual forced A-value. Project and
restrict the established captured J_z field in this same current W, obtaining
V(B_z,z,p_z). Pure ReturnIntro and VP-BodyReturn use that same z/provider;
Fixed follows at its original capture incidence. Restriction retains the
import's rigid coordinates and complete contract. A matching endpoint or
opaque identity cannot replace this projection. Static capture lineage
does not supply live handler/receiver authority.

**Outward return and future.** InvocationReturnIntro removes exactly this
invocation's current own occurrence, projects its valid world and restricts
the same body's hereditary result certificate to the original outward port.
It preserves the decorated result. VP-InvocationReturn types Done; Echo or
Fixed remains true. At every independently compatible future demand, V(A)
or J_z's V(B_z) supplies the same returned provider's complete/pending
observations at its later current world. VP-Future applies. A nested
provider's own result is checked by its own contract, never by outer Echo/
Fixed equality to the id argument or captured z.

The independent elementary Bind/Project/Restrict/Return/InvocationReturn
records are explicit in [native certificate constructors](2026-10-08-native-projection-certificate-constructors.md)
§§4.1–4.4. This derivation uses their semantic record introductions and
eliminations; it does not infer certificate uniqueness or erase additional
original finite checking terms/intermediate witnesses.

Thus each actual template observation satisfies the selected ordinary
descriptor's independent field checks on the same whole tuple. For the

its active equations. Applying contextual Function introduction additionally
