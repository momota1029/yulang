## Lookup, duplicates, shadowing and visibility

The body cursor and lexical reference resolver use different selection rules:

- module_table/mod.rs:731–759 delegates value_at to select_decl over the name vector and propagates Found/Private/Missing. query.rs:1256–1301 orders candidates at/before site by descending order, followed by after-site candidates in ascending order, then returns the first visibility-allowed candidate. Inaccessible candidates are skipped; an inaccessible My candidate is retained as a possible Private diagnostic if no allowed candidate is found. This is more precise than an unconditional “latest preceding declaration” shortcut.
- module_table/mod.rs:706–729 checks My by descendant-or-same module ancestry, Our by the supplied route's same-band predicate and Pub unconditionally. These literal rules do not by themselves prove every caller supplied the appropriate route or actual module/band identity.
- lexical_value_at at 825–848 tries local value_at, then imported_value_at, then moves to the parent with the parent's declaration site. Found and Private stop the search; only Missing permits the next branch. It does not collapse Private into Missing.
- query.rs:785–806 and 1327–1370 select imported records with the analogous site order and visibility/private-origin checks. This reads already-built import views; a complete alias/re-export construction/fixed-point theorem is not supplied here.
- value_path_at at module_table/mod.rs:850–877 returns Missing on empty path, uses lexical lookup for a singleton and otherwise resolves the module prefix through imports. It then tries target-module value lookup, falling back to exported values only on Missing. Prefix traversal in query.rs:544–599 preserves Found/Private/Missing at each step.
