## 1. Source-component obligation and transparent authority correction

For every originally supported, known ordinary `Value(Function)` formal,
construct the known callback context from its original source component:
formal/annotation/scope/shared-root identity, source-generated upper exposures
with justified protected-variable seeds at those exposures and designated
`outEff`, independently justified annotation-profile constructors, and existing
typed transport. Preserve its original static `beta,Slots(beta)` and instantiate
only through the original source use's coherent substitution. Deliver that
known context before generating the **receiving literal's** body constraints;
independently synthesize the literal under B and retain its final completed
interface inequality. Source from the callee's definition and original uses
may help construct this context before delivery. B does not require that the
annotation alone construct it before the callee's own body is examined.

The previous version of §§1/5 demanded a complete annotation-only observation
inventory, including all eventual symbolic/latent shapes. That premise was
overstrong under the already selected
[directional addendum](../design/2026-10-06-directional-inferred-effect-protection-addendum.md)
§§2–6. Section 6 expressly retires the unconditional
`Applicable_original -> p0` target in favor of source-justified directional
exposures and their original seed witnesses. This is a correction of this
note's governing obligation, not a new semantic choice, parent closure or
narrowing of supported B sources. The finite coordinate, successful paired
constructor and acyclic capture/FreshUse results below remain unchanged.

Fix original owner `d`, formal `x`, annotation occurrence `a`, its original
binding scope `S`, and one joint assignment `xi=(nu,K,D)`. An occurrence is
identified by its structural path from this annotation, in addition to those
original identities. Symbolic variables shared by that scope stay shared;
operation-local rigid binders and existential dependency scopes stay at their
original positions. No segment receives an independently selected witness.

The parent includes the original supported Function annotation domain. The
finite structural claim below does not replace it with the current native
preflight subset. In particular, unsupported native negative concrete rows,
unknown symbolic shapes and higher-order results are not declared invalid
source. `Value(Function)` is never replaced with `Computation(E,A)`.

Excluded conclusions: query success, principality/soundness, generalization,
actual entry/receipt/Observe, native annotation-pair/FreshUse conformance,
runtime execution and complete Call implementation. These remain separate.

## 3. Constructive finite annotation-coordinate lemma

**Claim class:** independently reviewed constructive structural derivation.
Its conclusion is a coordinate inventory, not the full callback profile theorem.

Let `FunOcc(a)` be the finite explicit Function occurrences in the original
annotation graph, keeping occurrence paths through sharing. At a Function
occurrence `pi`, construct records

```text
c_A = (d,x,a,pi,AE,S, sign=-s, original argument annotation row)
c_R = (d,x,a,pi,RE,S, sign= s, original result annotation row)
```

where `s` is that Function occurrence's composed variance. A formal starts at
`s=-`; traverse Function argument with reversed sign and result with unchanged
sign. Record the complete original concrete family operands and symbolic
references of each row. An omitted row gets its own open coordinate reference
`kappa_(d,x,a,pi,port)`; it does not get an empty row or a permission. These
references name omitted coordinates, not newly quantified runtime boundaries.
An explicitly repeated symbolic variable refers to the same `(S,name)` binder,
even when the two position records differ. Distinct omitted AE/RE coordinates
remain distinct before later source constraints relate them.

**Derivation.** Traverse the original finite annotation structure once. A
primitive or unresolved symbolic value leaf introduces no explicit Function
coordinate. The Function constructor introduces exactly the argument and
result row positions, then recursively visits its two child annotations with
the signs above. These are the carrier/input reversal and invocation/result
preservation derived from primitive interaction in typed core §9; composing
the signs gives annotation integration §1's nested polarity. Original explicit
rows are copied as records, with their original family operands and binder
references. Missing rows are distinguished by the port tag and occurrence
path, so AE cannot alias RE merely because both are omitted. Back references
retain registered original nodes and occurrence edges, rather than unfolding
recursive executions. Structural induction proves each explicit Function
occurrence contributes exactly two records and every such record is visited.
For a finite annotation tree with `n` Function occurrences this gives `2n`
records, with work linear in that tree and its written row operands. This
does not bound arbitrary future inferred shapes at a symbolic leaf.

For any independently established applicable position with negative composed
sign, its written concrete members give exactly the selected local subtraction
permission; a positive concrete member has the selected allowance meaning.
Symbolic variables do not become concrete permissions. Concrete-list admission
uses source-realization §9's finite disjunction under the same `nu`, including
invariant family arguments. This proves the policy calculation at a supplied
position, not that variance alone determines applicability.

For the anchor `f:int -> int`, the records are `AE(kappa_A,+)` and
`RE(kappa_R,-)` with distinct open coordinates, original formal identity and
no written concrete permissions. The known Function itself supplies an
executable complete `J_call` position by typed core §§3,9; omitted capture
does not authorize a local handler there. This explicitly annotated formal
intentionally has no `OmittedFormal` seed; absence of that record proves
neither missing protection nor an empty callback profile. Its independent
annotation-profile construction and source/typed evidence retain their own
responsibility. Thus “no written effect row, hence empty callback profile”
does not follow. This local consequence neither
identifies AE with `J_call` nor proves that these two printed ports exhaust
all profile positions for every Function annotation.

### Native construction correspondence, with its actual coverage boundary

**Claim class:** source-to-constructor derivation for a successful invocation
of the current paired formal constructor. Its domain is exactly the
annotations that this invocation accepts, including its resource/preflight
conditions. This local theorem does not restrict the original parent domain.

For every explicit Function occurrence `pi` visited by that invocation there
is one recursion-frame association `J(pi,AE)=(qap,qan)` and
`J(pi,RE)=(qrp,qrn)`. If child pairs are `(ap,an)` and `(rp,rn)`, the returned
Function pair is exactly

```text
P_pi = PositiveFunction(an, qan, qrp, rp)
N_pi = NegativeFunction(ap, qap, qrn, rn).
```

The signs used to build these effect pairs are the composed signs of §3.
Every omitted port allocates one fresh row and gives its positive/negative
terms to this one pair; two omitted ports allocate different row ordinals at
construction. This is an allocation identity statement, not permanent
inequality of representatives after solving. Every singleton symbolic port
reads the same `(S,name)` row table, so repeated names share their actual row.
For an accepted positive explicit concrete-bearing row, its two polar wrappers
share the `views[row.position]` signature view, retaining the resolved concrete
members, attachment polarity/scope and the same optional named tail. The
wrapper rows need not be equal. Those source positions are not collapsed by
equal concrete support.

**Proof.** Induct on the successful recursive call tree of
`candidate_formal_value_pair`. Its Function branch first obtains the child
pairs at reversed/unchanged variance, then calls `candidate_formal_effect_port`
once for each original child row, and builds precisely the two terms displayed
above. The omitted branch calls the append-only fresh-row allocator once;
`lib.rs:10221–10246` selects the current effect-bound-vector length and appends
one row. The singleton symbolic branch calls the scope-keyed table at
`candidate_effect.rs:1058–1073`, which reuses an existing row or installs one
fresh row. The explicit covariant branch calls `candidate_signature_effect`
twice with the same `views` table. At `1560–1697` the annotation context uses
the same scope-keyed tail table and the view cache keyed by the original row
position, retaining its concrete operands and attachment source. Finally the
Function constructors receive these exact local variables in the displayed
order. Leaves preserve their original primitive/variable constructors. These
cases exhaust a successful paired constructor. No pair is selected from an
independently solved graph, and no FreshUse or observation premise is used.

For the anchor `f:int -> int`, this proves that the native paired constructor
already creates the two distinct omitted row allocations; an empty concrete
set is not a source-to-native disappearance of AE/RE.

**Construction-time handoff.** No compiler change is required to establish
this correspondence: the source tree, scope and recursion frame supply all
its operands. Nor does dropping temporary `views` prove that per-coordinate
metadata is needed. FormalAnnotation retains the source tree/scope/parameter;
`formal_domains[parameter]` retains its exact negative root `N`. The following
forward zip uses those existing roots and ordered children. Any earlier
suggestion that losing a temporary path table establishes a need to persist
every coordinate is withdrawn. No new semantic profile follows from this zip.

The existing `candidate_scheme.rs:1057–1099,1195–1249` reconstruction handles
structural Function nodes with one use's child/row maps. It demonstrates a
candidate transport seam for an already authenticated coordinate association;
it does not authenticate original source paths by itself. A decisive falsifier
for a proposed retention handoff is two original omitted port keys selecting
one allocation before any equality, repeated `(S,name)` selecting different
rows, reversed Function child orientation, or a FreshUse coordinate selecting
a term from another use. Required future verification belongs to the primary;
none of these probes or tests ran here.
