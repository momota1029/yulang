## 3. Concrete construction attempt and explicit grants

Use the existing discriminator's source sketch only as a locator:

```text
my id x = x
my zero u = 0
my one u = 1
my result = (id zero) ()
```

Let `p0,p1` be the complete original provider packages for `zero,one`.
Their distinguishing behavior is a future invocation on a pure Unit carrier,
returning respectively the integer values `0,1`. Different endpoint IDs are
not a reason to regard the packages as observably different. This is an
existing source-core derivation relative to typed admission/primitive laws,
not a compiler acceptance experiment.

Fix one original `xi`, the actual receiver/configuration, caller, result port,
whole incoming carrier `t0`, final projection and legal instantiation `q:=q*`.
The designated argument demand on `t0` returns `p0`. The intended interface
`q*` has actual ordinary Pure role, Value Unit entry, Value Int result and the
complete challenge/guarantee/provider/dependency envelope. Writing
`Unit -> Int` does not specify that envelope or prove membership in it.

To isolate replacement as the obstruction, grant the following stronger
hypotheses; they are **candidate assumptions**, not suppliers established here:

1. `p0,p1` both satisfy the same independently defined complete `q*`.
2. The initial carrier/receipt and the prospective future Unit call at either
   returned port are independently admitted; all scope, authority, ownership,
   operation and joint dependency obligations are available.
3. The proposed transformed descriptor has a valid independent active ordinary
   interpretation; both putative observations would satisfy its typing guard
   if an independently licensed transport existed.

These grants remove the previously identified interface and immediate
`DescMem` difficulties from the attempted inference. They do not grant result
replacement, complete domain equality, exhaustive production membership,
projection separation or a public required view.

The attempted conclusion is an original-scoped license for returning `p1`
after the fixed demand returned `p0`. The identity constructor instead gives

```text
receipt; demand(t0) returns p0; typed rebind x := Value(p0);
resolved Name x; Value Result(p0); invocation Return(p0).
```

Constructing `p1` in the caller environment makes its contract available.
It creates no source edge from this `id` invocation's rebound formal to `p1`.
The actual client does not call `one` here. Choosing that lexical root for the
body would change the source definition being generalized.

## 4. Derivation invariant and failed constructive step

Define `Delta` before final projection on whole invocation tuples: either no
designated invocation Return is present, or its returned package is the
designated demand's package through the original typed rebind/result transport.
This is package identity under that transport, not equality of raw endpoint
names. Thus prefixes without a Return satisfy `Delta` without asserting an
invented result package.

**Source-base characterization.** For the fixed projection body and admitted
typed primitive/path laws, every source-base completed invocation satisfies
`Delta`. This is the already selected source result fact, used here as an
invariant for the construction attempt. Its justification is the fixed Name
operand followed by the Result emission clause. The Call/Bind equations append
that suffix to original requests and resumed state; they do not replace its
provider. Argument alternatives may return other packages, but each completed
suffix returns the package of that same demand. No equation asserts that the
argument is pure, terminating or single-valued.

The available construction routes have the following exact boundaries:

| Proposed route | Why it supplies no `p0 -> p1` result license |
| --- | --- |
| Source primitive/literal or Lambda for `one` | Constructs an independently rooted package `p1`; it is not an alternative of the resolved formal's Name/Result clause. An additional original primitive with that replacement conclusion would be new input. |
| Name/Result, ordinary Call/Bind | Their recorded provider operand is `p0`; changing it violates the source incidence/emission inventory. |
| Whole injective freshening or legal graft | Moves all incident operands together; a repeated original provider remains one repeated transported package. Instantiating `q` supplies type/interface structure, not a second provider at the existing result incidence. |
| Equivalent rewrite or total fresh-coordinate definition | Preserves the original relation, or defines new coordinates without replacing the fixed original output. A newly defined `p1` coordinate is not the invocation's existing result port. |
| Joint hiding of the local rebind witness | With caller demand fixed to `p0`, `exists v. demand(t0,v) and transported_same(v,o)` still returns `p0` on this demand. Dropping the demand conjunct or hiding/changing the fixed caller tuple is a different comparison. This statement is restricted to the identity suffix and its retained caller premises. |
| §5.3 Guarantee/Absorb | The leaf is `Bound_j(E,u)` versus `Bound_j(A,u)` for exactly the **same** whole provider `u`, with unchanged future input domain and non-coverage envelope. Substituting `u=p0` on one side and `u=p1` on the other fails the rule's operand test. |
| Primitive `Eq`, constructor congruence, registered equation pairing | Require matching original operands and complete alternatives under one map; they transport supplied licenses rather than introduce a new result alternative. |
| Successful `Direct` | Checks a supplied whole relation; source incidences/admission/license cannot be created by its success. |

In particular, even if `p0,p1` have identical guarantee bounds, coverage
reflexivity cannot change the provider operand in Guarantee. Conversely, an
independently proved equivalence of two providers would not be this behavioral
discriminator: the proposed future integer results differ.

This is a bounded obstruction for these routes, not an exhaustive impossibility
theorem over arbitrary primitives. §3.2 explicitly allows conservative
alternatives at a primitive leaf when its original contract supplies them;
§3.7 allows additional independently licensed abstract rules. Neither passage
supplies a particular replacement license by itself.

## 5. Smallest missing original rule and closure ownership

The first missing conclusion, after the grants in §3, has the form

```text
original independently specified result/provider-transport contract L
fixed carrier/demand p0, complete q*, original typed result port
L's authority, scope, ownership, joint K,D and future-domain premises
----------------------------------------------------------------
LicensedResultTransport(q*, p0, p1, original result port; xi).
```

This is a required **supplier interface**, not a proposed adoption of that
inference rule. The current `Ret_val` candidate refers to such a license; it
does not derive it from `Val_q*(p0) and Val_q*(p1)`. A contract may license the
pair, prohibit it, or have another result abstraction. The pinned sources do
not select which case holds.

The operand `p1` is the minimal missing addition for this provider-replacement
method. Giving the primitive only identity instances discharges source
containment but leaves this construction empty. Replacing a package may also
change reachable history coordinates, so its original complete domain
certificate must accompany the conclusion; equal displayed challenge types
are insufficient.

A finite-derivation boundary makes the owner of any eventual escape explicit.
Suppose the diagonal root's base obeys `Delta`, and consider an off-diagonal
whole tuple in its §3.7 closure. Follow the finite unary `W` predecessor chain
backwards. Either the leaf is a licensed off-diagonal `Z` extra, or the chain
contains a licensed `W(x,y,z)` with `Delta(x)` and not `Delta(y)`. A base leaf
cannot be the first escape. Guards only reject tuples; they cannot introduce
one. This is a **conditional derivation extraction lemma**, assuming the exact
positive grammar and the base invariant, rather than a new saturation model.
For the complete-value root there is the additional possibility that its base
first escapes through the just-missing `LicensedResultTransport` clause.

Therefore an actual off-diagonal witness must name its first independently
licensed escape clause and all original operands. The construction cannot
insert a `W/Z` pair or choose an empty grammar to avoid this obligation.
No actual exhaustive `W/Z/G` is supplied here. Even proving every abstract
rule provider-preserving would not prove the future `0/1` discriminator:
an abstraction might change future integer observations while preserving the
returned provider. Absence of the proposed projected `1` requires the full
observation invariant, not just `Delta`.

## 6. Actual-root query and separation remain unsupplied

The intended comparison is at the actual root decoded from
`forall q. q -> q`, with the fixed caller and the original projection. The
conditional result-discriminator note already states the needed query
consequence. This attempt establishes neither a formed diagonal public target
nor the suppliers needed to apply that consequence.

Source contracts §5.3 requires matched whole interface, checked finite
admission `Eq` and complete membership `Le`, including ordinary descriptor
membership and all production alternatives, at the submitted roots. Its
acceptance is an additional local resolution-conformance hypothesis. No
identity proof for a hidden source Lambda can supply this decoded-root query.
No semantic containment assertion can replace the finite proofs.

In particular, the proposed future `1` must belong to complete guarded
membership of one actual root, survive the fixed caller and final projection,
and be absent from **every** projected witness of the other root. The source
result `p0`, base-clause inequality and our construction obstruction establish
none of these full separation conditions. The present result is not an
approval-ready result-law choice or a reason to weaken ordinary inference.
