unconditional exact-root semantic equivariance. It does not invent that
interpretation or select a smaller supported language.

## 3. Two different actions

Let a finite selected PE-ID presentation include the export, a finite decoded
use graph and its transparent certificate records. A presentation name is an
internal spelling of a coordinate/reference in that graph. It is not a new
source binder, runtime provider, installed binding, event or registry primitive.

Choose a bijection `h` on the explicitly identified alpha-local presentation
names. Preserve their sorts, original scope/binder edges, node/field order and
all sharing. Extend it simultaneously to every reference in the selected
transparent graph. Fix constructor tags, semantic field names and all actual
rigid objects in `Omega`.

For an assignment `eta` to those coordinate names, define

```text
(h_* eta)(h(x)) = eta(x).
```

This is a change of coordinate spelling. It does not change the semantic
value assigned to a coordinate, instantiate a different type description,
allocate a different runtime closure or assert a new admissible event.
In particular, it is much narrower than a theorem that arbitrary eligible
semantic images may be substituted into an interface.

Transparent terms below have actual coordinate references, fixed constants,
ordered tagged records, field projection, reference edges and the explicitly
listed whole-tuple equations. Their relabeling `h(t)` replaces references
consistently. It does not recurse into an opaque semantic predicate's private
code or an opaque certificate's internal representation.

For transparent expressions, direct induction gives

```text
eval(h(t), h_* eta) = eval(t, eta)
```

after identifying their internal presentation labels by `h`. At references
this is the definition of `h_*`; fixed constants are unchanged; ordered
records/projections commute componentwise. An equality test compares the same
two evaluated objects; alias/reference sharing is preserved by injectivity.
The inverse is the same construction using `h^-1`.

A semantic operation can additionally inspect an internal name itself.
Evaluation equality of its *displayed operands* does not prove invariance of
that hidden inspection. Such a case lies at the explicit frontier in §7.

## 4. Elementary dependent-record lemma

Separate each constructor's supplied typed semantic/guard fields from the
transparent equations and record assembly imposed by its selected definition.
The former remain actual inputs. The lemma transports the latter; it does not
create typed world, hereditary, compatible-history or authority evidence.

| Selected constructor | Explicit equations/assembly transported | Supplied semantic inputs retained |

| BindIntro | `C1=Install(C0,b,(v,p))`; same retained value/provider; old binding projections and new `beta1` reference one joint record | Completed entry, actual V/W witnesses, registered rebind/receipt/path/scope/current guards and compatible hereditary action |
| ProjectIntro | `beta=omega.environment[b]`; `Lookup(C,b)=(v,p)`; exact binding projection | Actual world/binding typing and registered incidence |

| InvocationReturnIntro | `C_out=ExitOwn_IF(C,r,e)`; same returned `(v,p)`; exact world/hereditary projection references | Actual current-occurrence/order/scope guards and lawful supplied IF image |

**Lemma ER-alpha.** For each displayed constructor, if its supplied typed
input package has a corresponding package under `h`, preserving the actual
objects, guard witnesses and their dependent incidences, its transparent
constructor equations and field assembly hold before renaming iff they hold
after renaming. Its conclusion is the corresponding exact record, retaining
every supplied proof choice and intermediate field.

**Proof.** Expand its selected record definition. Every reference, projection,
ordered field and equality listed in the table is a transparent expression of
§3. The retained compatible/history/IF operation instance is the corresponding
*same supplied instance* in the input package; the lemma assumes no existence
or validity of a different instance. Evaluation equality proves each record
equation in the forward direction. Applying `h^-1` proves reflection. The
conclusion map copies all fields bijectively, so different Identity/Compose
tags, intermediate witnesses and proof choices remain different. QED.

This lemma proves the constructor step once input transport is available.
Its hypothesis is not a whole-export equivalence premise. It explicitly
leaves semantic evidence transport, where not already supplied by a selected
whole action, unproved. The Install/Lookup/Exit entries likewise do not prove
a new operational covariance law for independently fixed implementations.

## 5. Extraction, aliases and decoding

**Lemma X-alpha (transparent algorithm commuting square).** Apply a
presentation renaming `h` consistently to the actual finite source-owned
record/schema inputs of PE §4.1, retaining source/provenance identities,
eligibility decisions and all rigid semantic inputs. The transparent output
of extraction is the corresponding relabeling of its original output.

For steps 1–2 the designated source root and fixed-dependency/eligibility
decisions are the same supplied decisions; no new eligibility theorem is
asserted. Step 3 selects the same source-owned record by its unchanged origin
and tag. ER-alpha covers its expanded record assembly relative to its supplied
inputs. For step 4, let `s` be the actual total forced-alias graph. Renaming
all its domain/range references defines `h(s)` and direct term induction gives

```text
h(t[s]) = h(t)[h(s)].
```

Thus elimination substitutes the same alias graph everywhere, including
predicate operands. It never inspects or changes an opaque predicate's code.
Steps 5–6 keep the same certificate-family tags and original telescope edges,
discard exactly the corresponding private source nodes, and install the same
public grammar. Every step is reversible as a comparison of its corresponding
transparent outputs. This proves the commuting square; it does not claim
that extraction itself is an invertible source-program transformation.

The same substitution equation proves that PE's F/G raw-alias maps commute
with `h`, wherever those maps are defined on their supplied full input tuple.
No proof witness is normalized in this comparison.

**Lemma D-alpha (exact public-root record correspondence).** Given the same
real source frame and its corresponding whole-frame input package, the
decoder in PE §4.2 produces corresponding records at its actual newly
allocated ordinary public roots. The comparison includes every root reference
and the exact inlet/result/admission/production/proof fields; it does not
replace that root by the private source root.

Pair the fresh presentation root name `u_i` with a fresh name `h(u_i)` outside
the corresponding finite graph. All fields are the same grammar instance
with the same frame inputs; §3 transports their references, and ER-alpha
transports transparent certificate assembly. Aliases reuse this same paired
root. A second distinct new frame is paired with a distinct root, since the
name extension is injective. Fixed `Omega` fields remain the same objects.
This proves exact *record* correspondence. The decoder's independently
supplied whole-frame semantic action is retained, not proved anew.

## 6. Honest consumer consequence

PE §6.1 dispatches by the checking-proof constructor, reads the actual root
records and validates complete scopes/operands and premise subtrees. For the
transparent part of a finite certificate-recognition tree, D-alpha and §3
preserve the dispatch tag, named root references, signature operands,
scope checks, equality/sharing tests and ordered subtree structure. A witness
naming the private source root in place of `u_i` remains a mismatch after
renaming, because both the root reference and comparison target move together.

Identity and Compose skeletons retain the same decorated tuple and intermediate
interface/evidence references. Structural union/intersection/record skeletons
retain their actual branch/field tags, sharing and child proofs. Top retains
the actual independently typed membership/guard package. None of these facts
creates its semantic local-law witness.

Consequently, **conditional on preservation/reflection of the actual local
law/evidence validation at its remaining leaves**, finite bottom-up certificate
recognition preserves and reflects acceptance and rejection. The proof is
induction on that finite tree, using the leaf laws only at the leaves and
ER-alpha/D-alpha at the transparent steps. It covers the Value wrapper when
all its leaves meet this condition. Computation and complete Function checking
remain outside the proved consumer consequence, as do recursive equation
rules, plugins, methods/adapters/annotations and executed conversions.

In particular, this is neither a proof-search completeness result nor a full
semantic `Direct(u,V)` equivariance theorem. The active Function root's whole
admission/production phase action is already supplied by phase-construction
§6; full local proof-kernel and evidence transport is a separate premise.

## 7. Identity inventory and precise remaining supplier

For the finite transparent records, the inspected identity observations are
coordinate equality/sharing; ordered record/field tags; reference lookup;
scope/telescope incidence; actual named-root comparison; registry/tag dispatch;
and the actual binding/port/provider/current-occurrence references in §4.
Their transparent transport is proved above. Actual source origins/binders,
providers/captures, intrinsic permissions, IF/source slots, registry identifiers,
world/event/receipt lineage and fixed external operands are retained rigid
objects; relabeling their presentation references never changes those objects.

This is an exhaustive list for the **displayed transparent skeleton**, not an
exhaustive list for its opaque input implementations. Remaining suppliers are:

1. Actual V/W/T/Car/hereditary/compatible-history evidence transport where the
   existing selected lawful action does not already supply it.
2. Identity-observer and preservation/reflection laws for every local checking
   operation actually used in Delta, its whole observation-image proof and
   the retained L terms. Certificate constructors §3 permits extra authentic
   primitives and open catalogues; §4.5 retains opaque input certificates.
3. The corresponding complete Function/Computation/recursive-equation consumer
   laws if those consumer cases are to be included.

An operation that also tests whether an alpha-local identifier equals a
fixed internal spelling can be independently typed while failing the claimed
renaming law. This is a logical countermodel to “typing implies equivariance,”
not a discovered active native implementation. The actual operation must either
have its observer/law proved, or that identity must be demonstrably fixed on
the permitted action. This note does not silently choose either repair.

The smallest next supplier is the actual closed local-law inventory for one
concrete id inlet/Delta and Value certificate, with all identity observers
enumerated. That would turn §6's leaf condition into a checked premise for
that instance. No original literal Result/Application constructor is involved.
An unconditional full PE-ID/CI-use theorem would still require every active
operation in its chosen complete interface and consumer.
