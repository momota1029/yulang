## 1. Result and exact premise

A mandatory provider-diagonal result law for every applicable value arrow
`q -> q` cannot preserve the captured return below **if** its independently
admitted complete source tuple and its arrow-view formation are supplied.
The body returns the captured provider of `y`, whereas entry obtained the
distinct supplied provider of `x`. Equal complete value interfaces do not
identify these providers.

This is a conditional design countermodel, not a source-admitted compiler
failure. No selected complete constructor/admission package for this exact
source was established here. Parsing, ordinary-looking currying, or the
typed-core rule table does not establish current implementation acceptance.

The attacked premise is stronger than the isolated `id` derivation:

```text
GLOBAL-DIAG:
  Every admitted returned observation of every function viewed/decoded
  at an applicable Value-entry q -> q satisfies typed SamePackage(input,output).
```

Candidate §4 explicitly proposes a global canonical interpretation for all
eligible exports of its scheme shape. Its §6 theorem, however, assumes an
isolated, capture-free `id`. Neither section establishes GLOBAL-DIAG for all
monomorphic same-interface arrows. The document remains a Draft alternative,
not an adopted arrow meaning.

## 3. Conditional derivation and smallest witness

Source-shaped witness:

```yu
my const y x = y
```

Use its nested-lambda reading only as an explicit hypothesis; no grammar or
production lowering claim is made. Its already-captured core is smaller:

```text
Gamma(y) = Value(q), carrying rigid captured package Y
lambda(Value(q), result(name y))
```

Required hypotheses:

1. The outer binding elaborates to ordinary nested lambdas, and the inner
   name resolves lexically to the outer rebound `y`, not to `x`.
2. In one coherent original assignment/configuration, `Y=(v_y,p_y)` and
   `X=(v_x,p_x)` have the same **complete** value interface `q`. Their typed
   package transports are distinct: `not SamePackage(X,Y)`. This distinction
   is an incidence/value fact, not unequal raw endpoint spellings.
3. Capturing `Y`, demanding the inner whole carrier which returns `X`, and
   transporting captured `Y` to the actual result port are independently
   licensed with their original receipt, ownership, authority, scope, `K,D`
   and current-world obligations. The initial complete challenge is admitted
   independently of membership and `Direct`; required future-provider
   contracts are valid even though no future event occurs in this witness.
4. Constructor typing proves the emitted tuple meets the source's independent
   descriptor/complete guard. Ordinary same-interface arrow-view formation
   admits this inner function at the proposed `q -> q` decoding/use position.
   This last step is not inferred from a printed type.
5. GLOBAL-DIAG is mandatory at that position and source-preserving export/use
   must include this returned tuple, on the same admitted history/fiber.

Under hypotheses 1–4, the §6 table gives the following body/result skeleton:

```text
Gamma_inner(y) = Value(q)[Y]       Gamma_inner(x) = Value(q)[X]
Synth(name y) = Value(q)[Y]
Normalize(Value(q), name y) = result(name y)
inner interface skeleton = Fun(Value(q), Comp(empty,q))
```

Brackets here record provider incidence, not a new source type or refinement.
Before specializing endpoints, the skeleton is
`Fun(Value(A_x),Comp(empty,A_y))`: the ignored input does not constrain its
value endpoint to the captured result. Setting complete `A_x=A_y=q` does
not identify `X` and `Y`. This lane asserts no principal `const` scheme;
in particular, it does not replace the accepted negative-Top behavior of an
unconstrained argument with a demanded quantified argument.

The §9 entry expansion then derives the returning execution, conditionally on
the whole licensed package:

```text
receive original inner carrier t_x
Force_argument(t_x) = Return(X, current_state)
RebindResultPath(t_x, X, current_state) binds x
Run(result(name y), Gamma_inner) = Return(Y, current_state)
ReturnFromInvocation(Y)
```

The outer entry had previously obtained `Y` and the inner closure captured
that immutable binding. Inner entry executes once even though `x` is unused.
No latent value is recursively forced. Both providers remain attached to one
assignment; generalizing or freshening local endpoints cannot freshen the
rigid captured package into the supplied package.

Thus the complete source tuple has argument package `X` and result package
`Y`. Hypothesis 2 makes `Ret_diag(q,X,Y,C)` false. Hypothesis 5 requires it true.
That is the contradiction. Rejecting this initial challenge merely because
`X` differs from captured `Y` would replace the admitted input domain, rather
than prove domain correspondence for the proposed arrow rule.

The semantic witness needs one inner lambda, one captured name, two distinct
same-interface packages, one returning argument demand, and one result. The
outer lambda only provides a natural capture construction. Removing the
capture or making its returned package equal to the input removes the
discriminator. Requests, recursion, State, handlers and future calls are
unnecessary for this returning witness, although complete transport still
requires their relevant latent contractual obligations.

A construction-time lexical certificate can establish for isolated `id`:

```text

```

That is a uniform source-constructor rule instantiated at `id`, not an

the export to retraverse the complete definition.

Two candidate routes remain consistent with that direction. A common arrow
interpretation can license independently certified same-interface result
transport, including identity, while the construction certificate proves
`id`'s one-way inclusion. Alternatively, if identity information is actually
needed at use time, a compact typed transport certificate could be proposed
as additional information. Its necessity, composition, domain and full
production/query adequacy would need proof and approval; retaining a renamed
whole-source relation would not satisfy q1. Neither route is adopted here,
and neither yields the stronger complete equality theorem automatically.
