# `'label` を受け取る値 (`'l => a`) の構想 (2026-11-08)

状態: 構想（ユーザーとの雑談）。spec ではない。構文は不安定で、意味論は未確定。M1（Lean の核）の範囲外。

## きっかけ

`sub 'done:` は `sub \'done -> ...` という「label を束縛するラムダを受け取る関数」の呼び出しだ、という読み。
`for 'label x in xs:` は `xs.for \'label x -> ...` と同じ。label は「持ち出し不可能」にするのが一番きれい。
一方で `last 'outer` のように label を**渡す**形もしたい。label を渡す形と渡さない形の二つをどう扱うか。

## ユーザーの構想（2026-11-08）

- `'l => a` は、`->` とは別の、かなり特殊な型。**label を受け取る値**の型。普通の値を引数として渡すことはできない（受け取るのは label だけ）。
- 値 `a` は、`'l => a` へ cast できる。**組み込みの cast**（`cast` 宣言ではない）。cast された値は label を**無視**する（定数関数）。実行時の費用は、消去・無視であるべき。
- label は制御構造のものなので、**同時に複数は受け取らない**（`'l => 'm => a` は想定しない）。
- `'l => a` の値について、**label を受け取るか（使うか）でパターンマッチできる**。受け取る場合は、呼び出し側（`sub` など）が、入れてよければ label を入れる。
- こうすると、label を渡す形と渡さない形が、一つの関数・一つの cast に畳まれる。`#labeled` のような複製された名前は要らない。

## 改訂 (2026-11-08、ユーザー): 特殊な型ではなく、普通の enum と cast にする

`'l =>` を特別な型にせず、次の**普通の enum**にする（記法は仮）:

```yulang
enum labeled('l, 'a):
    labeled ('l -> 'a)      // label を受け取る
    raw 'a                  // label を受け取らない（無視する）
// cast: 'a <: labeled('l, 'a)   （raw に包む）
```

- 値 `a` は `raw a` へ cast できる。label を受け取るラムダ `\'l -> ...` は `labeled` の側。**型として求められたときにしか cast は行われない**（spec 6.5 の cast と同じ規則）ので、意図しない箇所で変換されない。漸進的型付け（gradual typing）で、境界の型に合わせて変換が入る形と似ている。
- 「label を受け取るか」の観察は、この enum の**普通のパターンマッチ**になる。観察は、関数が引数の型を `labeled('l, 'a)` と宣言したときだけ起きる（Option を受け取るのと同じで、opt-in）。コールバックの中身が変わって呼び出し先の挙動が変わる、という心配は、関数が自分で観察を選んだときに限られる。
- 特殊なのは `'l`（label の型）とその持ち出し不可だけ。`sub` などは `sub : (forall 's. labeled('s, 'a)) -> 'a` のように rank 2 の剛体の型変数で label を渡す。
- これで、前の未決 1（組み込みの cast か）は、普通の `cast` 宣言で書ける形に近づく。実行時は enum の tag で、型が静的に分かるなら消去できる。

## 型の筋（雑談での私の見立て、未確認）

- `'l => a` を `forall 's. label 's -> ['s の effect を含む行] a` のように読む。`'s` は rank 2 の剛体の型変数で、結果の型に出ないので、label は型の上で持ち出せない（ST モナドと同じ形）。既に spec 4.6 で struct field の rank 2 を決めているので、新しい種類（第二級の値）は要らない。
- label の操作（`return`、`last`、`next`、`redo`、`again`）は、`'s` を持つ effect として行に載せる。`sub` などが引き受ける。レキシカルに束縛される label で effect の instance を区別する路線（"Binders by Day, Labels by Night"、POPL 2020、Biernacki ら。Effekt の capability、OOPSLA 2020、Brachthäuser ら。いずれも記憶による参照で、要確認）。

## 未決
