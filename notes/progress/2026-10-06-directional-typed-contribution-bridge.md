## 1. Result

The selected directional rule supplies **an exact static protection profile
fragment**, not only an uninterpreted pending marker:

```text
ProtectedVarAt(k,v,sigma,u)
SourceUpperUse(u,v,U,sigma)
------------------------------------------------ Dir-Protect
Gamma_dir(k,beta,u) = { outEff(U) |-> Protected }
```

`Gamma_dir` is notation for this rule's contribution to the original static
profile. It is not a new inference carrier or the assertion that the complete
`Gamma_original` or `Slots(beta)` consists of one position. The source rule
already says to protect this occurrence. Treating its static marking as an
unspecified additional semantic choice would retreat behind the user's
decision. The fragment has no concrete removal grant and does not mark the
input effect or an arbitrary latent result position.

For the selected ordinary Apply, the existing reviewed `Gen-Call-0`
construction supplies its root, output-effect address and original scope.
The fragment is consequently an original source-owned static contribution
at that address, independently of successful checking. It still does not
identify a particular dynamic boundary instance, received provider view or
request event.

The strongest downstream result is constructive **conditional packet
correspondence**. Given the source-certified realization of this fragment at
the actual receipt of the original formal, and the matching typed
environment association, entry rebind, closure capture and captured read
compose one path image. That image preserves the fragment, provider evidence,
origin and the original `xi=(nu,K,D)`. A request acquires candidate protection
only through its own pre-dispatch executing-view observation, the matching
receipt and exact live receiver. The original receiver, later local-function
receiver and actual provider invocation stay distinct.

The first remaining source bridge is therefore **static upper-fragment to
the original formal's dynamically instantiated boundary/received view**.
After a supplied typed receipt, the captured-environment association is a
separate unresolved source leaf. These are definition/proof interfaces for
already selected behavior, not a request to choose E/R or new semantics.

This reduces the old footprint obligation: the initial upper-output static
mark is now available. It does not close event contribution matching,
complete profile formation, seed/refined full-solution preservation,
generalization, admission, all-world adequacy, all-view principality or
production Option A/2 containment.

## 3. Static source contribution: the part which now follows

Fix the selected resolved component:

```text
my apply f = { my step x = f x; step }
u_f -> d_f; u_x -> d_x; c = Apply(u_f,u_x)
```

The original source/contract scope `sigma` is not the textual scope of the
later captured Name, and is not a runtime invocation. Core §6 generates
`d_f:Value(A_f)` and `d_x:Value(A_x)`; Name reuses these endpoints.
Source-call §4 generates

```text
R_f at (component,d_f,A_f,sigma)
beta = (d_f,R_f)
u_c: A_f <: F_c
p0 = (beta,call.effect)
ElimOrigin(c,u_f,d_f,R_f,p0,p_out(c))
```

Here `u_c` includes the original source certificate for the emitted upper
demand, rather than a successful inequality. `F_c` is one dependent complete
Function variable. `p0` is its immediate complete-invocation output-effect
occurrence, including actual entry and designated result consumers when a
typed realization exists. It is not a bare closure-body row.

With the selected variable-stage seed at this exposure, `Dir-Protect`
contributes exactly `Gamma_dir(k,beta,u_c)(p0)=Protected`. Its witness retains
`k,beta,u_c,sigma,p0` and the original source direction. This is enough to
identify the marked *static* source contribution and its address. It is not
necessary to know the completed latent shape of the returned value or solve
the Function comparison first.

For a lower-first recursive history retain both records:

```text
L = e -> [g] h     L <: A_f       provider/lower origin ell
A_f <: F_c                      source/upper origin u_c
```

The new static fragment belongs to `u_c` at `p0`; it does not mark `g` from
this seed. Independent provider protection at `g` survives. Even if `g` and
the upper output eventually have equal denotations, neither origin is erased.
The full `L <: F_c` constraint remains a direct whole-Function obligation;
two successful endpoint comparisons are not its proof.

This has a useful operational qualification. A lower provider's event may
later be observed under the upper executing view **if an actual typed
correspondence establishes that view**. Candidate protection then comes from
the upper profile/path, while the event retains lower/provider origin. That
does not retroactively mark the provider's own `g`, rewrite its profile or
prove that every event it can produce has the upper observation. Static
no-backflow and conditional upper-view observation are different claims.

## 4. Smallest dynamic realization cut

Write `r_A` for the invocation of `apply` receiving `d_f`, `s` for the local
closure constructed in that invocation, `r_S` for a later invocation of
`s`, and `r_G` for the actual callable invocation at `f x`. They are distinct
even when a backend shares representations. Two different `apply`
invocations can capture the same underlying callable with different source
boundary instances. A static `beta` is therefore not a dynamic receiver ID.

The selected static fragment and source ownership give an **owner schema**:
if it is realized as the callback-formal boundary of `d_f`, its receiver is
the actual invocation receiving that formal, namely `r_A`. A later `step`
receipt must retain this receiver reference; it cannot replace it with
`r_S`. The provider's invocation `r_G` is not made a recipient of its public
callee view merely because it executes its body (typed-boundary §6,
“Receiving ownership and observation”). These constraints exclude wrong
realizations, but do not establish that such a realized view exists.

The smallest missing source judgment can be stated without demanding a
complete original profile:

```text
original seed/exposure (k,beta,u_c,sigma,p0)
Gamma_dir(p0)=Protected
actual source invocation receiving d_f, and its typed receipt derivation
same original contract/use and original xi=(nu,K,D)
---------------------------------------------------------------- required realization
an original boundary instance b=(r_A,d_f,beta,...)
and the typed received/rebound formal view whose profile contains
  this source-tagged fragment at the matching upper position,
  with b.receiver=r_A and no new concrete grant;
provider-origin evidence is retained as a separate input;
typed use c opens the matching complete upper view.
```

The ellipsis contains remaining profile data only if independently generated;
it is not a premise that complete `Slots(beta)` has already been supplied.
This rule interface does not choose a carrier, allocation strategy, marker
depth or algorithm. It names the exact source relation still missing:
the static formal/exposure fragment must be associated with this actual
formal receipt and executing typed use, under one original fiber. In
particular it must distinguish contribution of the inference upper fragment
from the supplied callable's own inherited profile.

Why the existing boundary constructor cannot discharge this from syntax:
typed-boundary §6 begins “At a source callback boundary” with a supplied
signature profile and then introduces `b`. If that complete typed source
premise is independently supplied, its constructor is usable and
`b.receiver=r_A` follows from the actual receiving invocation. The static
`Dir-Protect` record does not supply the receipt, source-boundary realization
or view association which this premise contains. Core §6 provides the outer
entry skeleton; its nested receipt paths are explicit admitted premises.
Source-call §5's `TypedCallCert_Dec` imports these facts rather than deriving
them. Charters §13/§16 require their preservation and entry placement; they
do not provide a constructor from the static record to the actual instance.

This is a bounded first-introduction argument for the named rule inventory.
Starting with the static fragment and ordinary skeleton alone, transport can
only move existing dynamic-boundary/view incidences; `Receive` adds ownership
to an already typed view; `Observe` records a request from an already
decorated executing context; checking creates none of them. The only
inspected dynamic-boundary introduction consumes the absent source-certified
boundary premise. Hence no finite composition of this inventory first
establishes this fragment's actual boundary/view association without that
premise. This is not an independence theorem for all possible Yulang rules,
nor an accepted-source counterexample.

## 5. Constructive capture/rebind/read proof after that cut

Assume the realization in §4 and a source-certified typed environment
association for the selected closure `s`. The latter is the already isolated
[capture attachment leaf](2026-10-06-q-independent-capture-source-rule-attempt.md):
lexical capture fixes the value reference, while the typed source judgment
must attach that exact received/rebound view to `s` and relate its later
captured read to the same view. A new annotation or new concrete grant is
not needed. The proof below uses the existing common transport operation,
not a separate capture semantics.

Let `T_in` be the actual received argument packet. Whole-argument
reification executes nothing. Within `r_A`, receipt precedes Value-entry
force. Force yields the provider value and entry rebind transports its
corresponding result paths by `M_rebind`; this does not force latent
descendants of that provider. Let `T_f` be the typed rebound formal view:
its original-upper fragment comes from §4, and its provider packet comes
from that actual force/result correspondence. Those are separately tagged
inputs to the indexed image, not an unqualified union by pointer equality.

Write `chi_f=chi_upper union chi_provider` with the source indices retained.
For this fragment, the realization supplies
`chi_upper(p0,b)` carrying `k,beta,u_c,sigma`. `chi_provider` is exactly the
independent evidence actually transported from the argument/provider. `K`
remains a shared ledger and `D` retains predicate identity and path incidence;
the upper fragment does not erase provider predicates or assert that they
are new protection grants.

At closure introduction, the supplied typed capture association gives
`M_cap` from this formal view to the retained environment view. At later
entry/read, `M_read` maps that environment view to the exact `u_f` occurrence.
For the selected same-type Name/capture route the dependent address schemas
are identities on tagged `Paths(A_f)`; the tags and original owner reference
remain significant even when the path maps are identity. Thus:

```text
chi_env = (M_cap)_* chi_f
chi_read = (M_read)_* chi_env
         = (M_read o M_cap)_* chi_f
D_read = (M_read o M_cap)_* D_f
K_read = K_f; L_read = L_f
```

If the rebind/result map is made explicit at its earlier source positions,
the provider-source term is
`(M_read o M_cap o M_rebind)_* chi_in`; the separately introduced upper
term starts at its realized formal position. The typed-boundary §6
multi-input image distributes over these source-tagged terms. Every output
incidence has its actual input and intermediate-path witnesses; this proves
that the evidence retained at capture is the evidence read later, instead
of merely saying that packets should survive.

Sequential local binding and final `step` Name return the same closure
descriptor `s`, without executing its latent call or exposing its private
environment as public profile paths. Later invocation `r_S` establishes its
own receipt for captured `f` and separately receives/forces/rebinds its own
`x`. That new argument does not certify the historical capture. Nor does the
public view of `s` get pasted onto every private captured binding. The
captured-view receipt is a use owned by `r_S`, retaining the original
boundary receiver `r_A` in `b`.

The actual provider at the captured read retains its own role and entry;
`r_G` uses that entry, body and designated consumer. The complete view at
`c` observes the generated output-effect position when its typed realization
opens it. Value entry of `step` does not imply that this provider is Pure,
and the inferred-formal role refinement does not rewrite the provider.

For a request `q`, the decorated pre-dispatch observation rule gives
`Observe(q,o.view,o.port,o)` precisely when this complete executing view is
among `views(EC(C_emit(q)))`. Joining the transported fragment with that
same view's receipt for an owner yields `Path`; at the actual candidate
configuration, `Inc_C` additionally tests the exact handler, owner and
`b.receiver`. This derives the candidate consequence from concrete witnesses.
It does not infer an observation from outward row support or reuse a
completed call's observation for a future latent result.

Two lifetime cases follow conditionally without a new rule:

1. If `r_A` and the matching candidate/owner remain active, the transported
   upper fragment can contribute protection for an event with the matching
   observed/received view. A handler owned by `r_S` has no grant from an
   outer `r_A` contract merely by inheritance; a current independently
   explicit local contract requires its own join.
2. If `apply` has returned before `s` is called, `r_A` has expired. The
   closure can retain static metadata, latent origin and `K,D`, but
   `Active(b.receiver,C)` fails. No original activation is resurrected, and
   this fragment supplies no active protection/grant rooted in `r_A`.
   Later independent current boundaries may apply by their own witnesses.

This proof establishes preservation and exact use/observation consequences
for supplied typed realizations. It does not manufacture the §4 realization
or the initial closure-environment association.
