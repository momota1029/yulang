### M1: type formation is not guard evaluation

The initial proof classified semantic references separately from recursive
formation edges and allowed an earlier guard to use a later decoded object.
For example, an original field of type

```text
G(P, decode_P(k_image))
```

needs a typed Image argument even when no guard truth is evaluated. The
proposed Formal-to-Data-to-Result-to-Image order did not supply that later
argument when forming the Formal schema. A full registry API that contains a
typed decoder has the same issue before that decoder is constructed. Raw
registry syntax, domain and lookup alone do not provide it.

This is a typing-stage defect, not an undecidability result or an actual
selected source counterexample. Moving the field beneath a new event binder,
retaining an uninstantiated variable, or renaming the missing proof a semantic
reference would not repair it.

The accepted repair must account for every type-level argument dependency,
including complete opaque declaration applications. It must construct the
actual source interfaces in the displayed earlier contexts, or supply a real
deferred interpretation with its own formation proof. The selected source
rules show the outer operand order; they do not prove that every independently
fixed opaque kernel can type against a newly chosen raw registry. Any new
local registry API is an explicit candidate choice, with its own bounded
conformance statement.

### S1 and proof-choice precision

The initial role table and decoder require Image rows at both `u_f` and `a`,
but the concrete emission recursion named only the literal Image. The repair
must explicitly emit the Name Image after its Result and traverse its actual

registry or create a fresh formal choice at each Name use. This clarification
belongs to the same typing/staging repair.
