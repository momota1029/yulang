## 2. Minimal caller and explicit hypotheses

Take the source definition `my id x = x`. Charter §21 fixes its parameter to
`Value(A)` before body synthesis. Specialize the derivation at one assignment
`nu(A)=Int`; this is a semantic instance, not a newly executed F5 constraint.
The source identity is

```text
f = lambda(Value(Int), result(name x))
I_f = Value(Fun(Value(Int), Comp(empty,Int)))
n_f = result(f)
```

The displayed Function result is the closure body/result skeleton. It is not
the complete invocation result independently of the argument. Generate a
caller by `call(n_f,ca)` and puncture its completed callable and whole delayed
argument positions. Its invocation schema is `ExecuteCallable(H_f,H_arg)`:
fill `H_f` with the whole closure and `H_arg` directly with `t0` or `tE`, with
their original derivation/path evidence. No wrapper is manufactured around a
filled carrier. This context can be typed before filling `H_f` with `id`; its
declaration does not contain the pending Function comparison as a premise.
The integer source argument is generated by `ca=result(literal 1)`.

Use these hypotheses explicitly:

1. The literal, closure, parameter binding, call and designated carrier
   elimination have finite well-formed typed-core derivations and their
   original typed paths/owner views. `id` has no captures or adapters.
2. For the request argument, a monomorphic operation declaration
   `op: Value(Unit) -> Comp(E,Int)` is independently admitted, with one request
   instance `q`, an Int response port and its native result consumer.
3. The initial configuration `C0` and all environmental values are compatible;
   no eligible handler consumes `q` in the selected observation. A supplied
   response `r:Int` is admitted at that original request and current state `C1`.
4. Both sides use one original assignment and joint witnesses. The monomorphic
   no-capture example requires no family type equality or local existential
   binder, so `K` can be true and the nontrivial shared type-dependency part of
   `D` empty. Original request/response/continuation incidence and activation
   references still must be retained; this simplification does not erase them.
5. The two punctured contexts are independently admitted by the selected
   complete rules. The source-generated certificate route below is a candidate
   sufficient justification for these cases, not a construction of exhaustive
   approved production admission.

The last premise is intentionally visible. The broad domain decision requires
independent compatibility, not automatic admission of any syntactically
written request argument. This audit does not discharge that premise from F5.

## 3. Integer and request reductions

For the integer carrier, `t0=Delay(Return 1)`. Creation is inert. Within one
actual `id` activation, receipt and source boundaries precede entry force:

```text
Force(t0,C0) -> Return(1,C0)
typed RebindResultPath(t0,1,C0)
Run(result(name x), x:=Value(1)) -> Return(1,C0)
ReturnFromInvocation
```

Here `J_body=Comp(empty,Int)` and the finite observed invocation has no request.
The body returns the exact rebound Int value/provider. Int has no latent
callable/force subgraph, so this instance has no returned future-use port;
there is no proof here for latent instantiations of `A`.

For a source operation application take

```text
ca = call(result(operation(op)), result(Unit))
tE = Delay(X[ca])
```

By typed-core §3, `X[ca]` invokes the operation and, after its native return of
`MakeRequestThunk`, executes its declared result port. Merely returning that
thunk would not produce the argument's Int. This explicit consumer remains
inside `tE`, which executes only on `id`'s entry demand. Let its one-request
prefix be `Request(q,Cq,k_arg)`, with `k_arg(r,C1)` returning `r:Int`.

Then typed-core §9's bind equation yields

```text
ExecuteCallable(f,tE,C0)
  -> Request(q,Cq,k_call)

k_call(r,C1) = k_arg(r,C1) >>= S_id
S_id(a,C) = typed RebindResultPath(tE,a,C);
             Run(result(name x), x:=Value(a));
             ReturnFromInvocation
```

The continuation retains the operation instance, response port, request origin,
original `(nu,K,D)`, current resumed state and pending rebind/body/return suffix.
Resuming it does not replay the receiver receipt or restart entry. With the
chosen response it finishes with the same `r` and current `C1`. The body result
remains pure while the complete call exposes `q`. Thus, conditional on §2,
this is a smallest finite witness against `J_call = J_body` or interpreting
the parameter's value row as the complete carrier. It has one parameter, one
body name and one request; removing the request removes this distinction.
It is not a production acceptance counterexample or a claim of global source
minimality.

For completeness, an explicitly annotated identity
`id_E (x:[E] Int)=x` has `P=Computation(E,Int)` and a distinct source entry.
It retains `tE` at entry; name synthesis gives `Computation(E,Int)`, and its
body result consumer is `eliminate_p(name x)`. The request then arises during
body consumption, with the corresponding body/result-return suffix. Lookup
and synthesis remain inert. For an empty carrier both identities return Int,
but this does not license converting plain `x` into retained entry. Nor is
equal request origin or boundary activation between these two different
source callables claimed. Production's plain-header gate does not currently
admit the annotated identity recipe.

whole received carrier `t0` or `tE`. A checked description may require the same
`Value(Int)` entry and Int body result as a control case. Its call observation
still must be the complete image indexed by the whole carrier, context and
history. A checked inlet cannot infer `t0`-like purity from the actual pure
body. Checked and actual descriptions are interpreted at the same original
tuple, not with separate choices of response/family/provider witnesses.

No production call-site `F_actual <: F_checked` is generated for either
caller today. F5 can compare constructed Function terms, but that comparison
capability is separate from generating these actual/checked caller artifacts.

## 5. Candidate source route and Option 2 residual

A candidate bridge for these two instances can allocate source labels for
the existing identity/literal nodes, then derive the absent call, delay,
designated consumer and operation nodes from typed-core §§3/6. It must retain
the original HIR binder map, source entry, whole carrier, receiver receipt,
operation witness, response port and continuation suffix. Separate initial,
response and raw-resumption admission clauses use the punctured context,
not success of `F_actual <: F_checked`. Theorem C §3 gives such a sufficient
source-certificate route for its decorated immutable envelope.

This is a proposed derivation/representation bridge, not authorized compiler
work. Even completing it proves only that the generated observations belong
to the chosen source base `R` and satisfy descriptor constraints at their
original scope. It does not prove that approved production membership equals
that base or that every broad-domain independently valid context has a
source-certificate form.

Source contracts §3.7 separates `R`, the complete hard envelope `G`, and
independently licensed extra/rewrite rules `Z,W`. The paired-positive-grammar
theorem additionally needs complete alternative accounting, paired invariant
parameters, `R subset G`, guard inclusion, abstract-provider future admission
and whole scope-preserving transport. Existing four ports/rows/name provenance
do not supply these clauses. A source-only derivation cannot discharge an
unanchored `Z` observation because such a derivation is deliberately not its
membership premise. Nor does absence of current `Z,W` objects prove that a
new carrier is necessary: both source contracts §9 and the approved answer
leave formation over the existing complete relations possible.

Thus two different gaps remain: ungenerated source call/request cases, and
uninterpreted complete membership/admission with its permitted extras. The
first is observable in concrete production source. The second is an open
semantic formation/correspondence premise, not established by that absence.
