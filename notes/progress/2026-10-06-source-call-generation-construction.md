1. A source-only singleton role relation with an explicit inverse-map proof;

   decorated semantic basis, retaining the actual Name-return argument root
   and the complete `ExecuteCallable` image.

The initial Call association need not remain an assumed certificate. The
source Call constructor can produce it. However, this is not a completed
source-generation theorem: exact original profile inventory/interpretation
and independently typed initial context admission still lack their source
constructors. The resulting record is not permission to equate all compatible
decorations with original source solutions. No complete Authority-consistent

not assert that a new user decision is proved necessary.

The positive result below is the **initial slice**, not a renaming of complete

## 3. Exact input, roots and whole-argument distinction

Fix the approved resolved component `C`, its original scope tree `sigma`, and:

```text
u_f -> d_f                 u_x -> d_x                 u_step -> d_step
c = Apply(u_f,u_x)
Gamma(d_f) = Value(A_f)    Gamma(d_x) = Value(A_x)
I(c) = Computation(E_c,A_c)
```

`A_f` is the outer formal's shared endpoint, not a fresh endpoint for the
captured read. The core skeleton is the already selected nested Lambda/Bind/
Result/Call term. Construct its source roots by the existing Name and Return
images:

```text
J_f = ReturnImage(Name(d_f), original environment)
J_x = ReturnImage(Name(d_x), original environment)
printed interface of J_x = Comp(empty,A_x)
```

Keep **both** `J_x` and its printed interface. The latter is not an exact
source image: an empty request allowance does not rule out a pure divergent
carrier, whereas this inner Name reads and returns its already rebound value.
A later invocation of `step` first follows step's actual Value-entry rule;
its external carrier is not silently replaced by the inner returning name.

All coordinates use one original `xi=(nu,K,D)`, including the captured provider
root, environment, continuation, owner/view, role and evidence dependencies.
A local existential remains inside every rigid binder on which it depends.
There is no per-port choice of `xi`, provider, scope or continuation.

## 4. A source-only role and initial-elimination constructor

### 4.1 Interpreted singleton role factor

Let `X_sigma` be the raw non-role coordinate domain with the selected source
identities/scopes; it is not a completed `Phi_C`, `Omega_S` or admitted source
solution set. At the exact one-use unannotated pattern define:

```text
Role_0 = {
  (x, R_f, ProtectedHandlerSeed, NonHandlerFormal, source_certificate)
  | x in X_sigma
}
```

Here `R_f` is one inferred-contract root belonging to `(C,d_f,A_f,sigma)`, and
the certificate names this resolved Call, its ordinary Value argument and
annotation absence. The seed and refined coordinates refer to the same root.
They do not assert any actual provider's introduction role or parameter entry.
The relation is not defined by a test of a pending comparison.

For each raw `x`, append its canonical records by `lift(x)`. Let `erase` forget
only these records. On normalized generated records:

```text
erase(lift(x)) = x
lift(erase(z)) = z
```

Thus projection is exactly `X_sigma`. The relation includes every raw
assignment satisfying these selected role facts and excludes the wrong role
record. It is the least restrictive role factor for this exact pattern. This
is **principal role/record extension**, not preservation or principality of a
completed original source relation. A later semantic profile constraint may
still restrict the non-role coordinates.

### 4.2 Generate the initial typed address through Call

Introduce **one variable** `F_c` for a complete Function description at `R_f`.
It is generated at the shared original scope, not supplied as a solved
`F_cb`. The Function-elimination constructor determines its immediate complete
invocation effect position before the result's latent structure is known:

```text
resolved singleton Call(c,u_f,u_x), u_f -> d_f
I(u_f)=Value(A_f), I(u_x)=Value(A_x), original scope sigma
---------------------------------------------------------------- Gen-Call-0
R_f : original inferred-contract root at (C,d_f,A_f,sigma)
F_c : one dependent complete Function variable at R_f
beta = (original d_f, R_f)
p_0 = (beta, call.effect)
p_out(c) : complete-invocation effect address of c
ElimOrigin(c,u_f,d_f,R_f,p_0,p_out(c))
```

The semantic content of `ElimOrigin` is limited and explicit: this source
Function elimination uses that shared contract, and its **immediate complete
invocation** corresponds to the signature's `call.effect` position. Under a
well-formed realization of `F_c`, both addresses have that observation-port
sort and the constructor maps them to each other. It does not identify all
result coordinates by type equality and does not equate `E_c` with a bare
callee-body row. Complete invocation includes actual entry and consumers.

This is syntax-directed typed elaboration of an actual source elimination,
not generation from solved type shape alone. The mandatory Function-call
position is independent of whether `A_c` later contains another Function or
Thunk. Typed-boundary §6 distinguishes `call.effect` from
`result.latent.effect`; returning a value does not map the former onto the
latter. No latent descendant is added by this rule.

`ElimOrigin` is a **static schema**, not an actual runtime `Flow` or `Observe`
edge, receipt, activated receiver, live authority, or full original profile.
It can be generated even if the call constraints later have no solution.
The dependency on `F_c` is retained; an arbitrary label without the
Function-elimination interpretation would not establish this result.

### 4.3 Initial protection policy and exact non-conclusions

The selected unannotated singleton supplies this initial policy:

```text
InitialSeedSlots(beta) = {p_0}
SeedPolicy(beta,p_0) = FullProtection
AnnotationRemovalGrant(beta,p_0) = None
SeedRole(R_f) = ProtectedHandlerSeed
RefinedFormalRole(R_f) = NonHandlerFormal
```

`InitialSeedSlots` names only the contribution made by this Call constructor.
It is deliberately distinct from the complete original `Slots(beta)`.
No-annotation grant absence remains true after role normalization: a change
of internal role does not create an annotation or a permission. The initial
source policy record can also be retained unchanged. These facts do not yet
prove that this record is the complete final receiving-side operational
profile. In particular, administrative seed erasure does not establish a
solution-preserving transformation of a previously undefined full profile.

The policy governs the complete typed invocation position. It is not computed
from outward event support. Typed-boundary §4 exhibits a receiver-owned
handler installed inside a protected callback view by raw resumption. That
handler can consume an event before it reaches the view's outward boundary.
Protection must therefore use the pre-dispatch observation:

```text
Observe(q,o.view,o.port,o) iff o in views(EC(C_emit(q)))
```

An event may have this observation even when the view's outward support never
contains it. Initial slot/policy generation is static; later observations
come from the same typed executing context, before handler selection. Neither
an empty row nor successful internal handling deletes the slot. This is the
existing decorated control witness, not a newly accepted raw-source program.

### 4.4 Uniqueness, scope and capture schema

For the exact singleton, `R_f`, `beta`, `p_0`, `p_out(c)` and their occurrence
incidence are unique up to one coherent fresh-name renaming. Every output
record is a deterministic dependent term over the same source occurrence,
contract variable and original scope. Erasure/reconstruction are inverse on
these canonical records, so adding the address records imposes no additional
restriction on the already emitted semantic operands. This proves the static
schema's conservativity, not existence of a satisfying Function description.

A uniform substitution acts once on `F_c` and every dependent coordinate.
Generalizing the local `step` cannot quantify the externally captured `A_f`
into a new independent provider. Original source labels are retained or
consistently transported; numerical naming is immaterial.

The name/capture route admits a dependent identity-address schema on
`Paths(A_f)` at each tagged occurrence. Any supplied typed packet is moved by
that same map, retaining its `chi,K,D,L` and original source tags. A symbolic
path domain avoids enumerating an unknown higher-order result. This schema
can be produced from the typed Name/binding constructors, but **lexical
capture does not instantiate its packet or certify an original receipt**.
Actual evidence-environment attachment, receiver activation and lifetime
remain typed realization obligations. Private closure fields do not become
public profile paths.

## 5. Genuine semantic call-constraint generation

On the independently interpreted decorated descriptor domain of typed-core
§7, generate the following relation rather than an uninterpreted `Callable`
atom:

```text
G_call(xi; A_f,A_x,E_c,A_c) = exists_sigma(F_c,e).
    WF_Dec(F_c;xi)
  & VIncl(A_f,F_c;xi,e_value)
  & WholeArgCompatible(J_x,CarrierContract(F_c);xi,e_arg)
  & CIncl(ExecuteCallableImage(J_f,Delay(J_x),F_c,e;xi),
          original result Comp(E_c,A_c);xi,e_result)
  & TypedCallCert_Dec(c,F_c,e;xi)
  & Role_0 and the canonical Gen-Call-0 records
```

`WF_Dec`, `VIncl`, complete argument checking and `CIncl` mean their existing
independent decorated semantic propositions; they are not new solver atoms
or a declaration that current production implements these predicates.
`TypedCallCert_Dec` explicitly retains the **supplied decorated** receipt,
profile, operation, observation and correspondence premises beyond the
initial source incidence constructed in §4. It is not a source-generation
conclusion disguised as a predicate.

`ExecuteCallableImage` is the existing constructor image: evaluate the
callee, construct the whole argument inertly, establish actual receipt,
execute provider-owned entry, body, designated result consumer and return.
Request suspension retains the entire pending suffix; responses and raw
resumption use the same handle and current state. It covers complete
observations and finite prefixes, not only successful returns. Actual
callable role/entry can remain a later premise as allowed by the task.

Two quantifier restrictions are essential:

- `VIncl(A_f,F_c)` covers **all the same decorated values** represented by
  `A_f`, not existence of one callable in an otherwise noncallable alternative.
- The image and its bound cover all independently admitted joint executions
  at the same `xi`. One successful argument/trace, or witnesses chosen afresh
  at different ports, do not define this relation.

This expression is a semantic relation even if empty or not effectively
solvable. It introduces `F_c` before solving. It requires no transitivity of
successful concrete inequalities and does not query pending `Q` to create
its records or domain.

For a fixed representation-preserving decorated Call rule whose independent
premises are the ones displayed, inversion extracts `F_c,e` from the rule;
reconstruction applies that same rule from `F_c,e`. Constructor images give
the same complete behavior. Composing with Name, Result, Lambda and Bind by
structural induction gives equality between generated constraints and that
**decorated rule envelope**. This factorization is a conditional consequence
of the existing decorated calculus, not another claim to have produced its
raw-source premises. Conversions that execute adapters need their separately
open normalization/completeness bridge; same-value checking does not cover
them by assertion.

The correction is substantive: the remaining source problem is not how to
introduce an unknown Function constraint. It is the reverse implication from
a complete satisfying decoration to the original source profile and complete
source context domain.

## 6. Why independent admission still has an initial cut

Source-contracts §3.3 orders initial punctured contexts, typed responses,
original raw resumptions and source-typed future calls/forces. Once its
independent constructor predicates are fixed, finite history extension is
not mysterious. If every extension strictly increases history length, then

```text
A = Initial union Post(A)
```

has exactly the finite histories reachable from `Initial`. Proof: reachables
belong to every fixed point by induction on construction; any fixed-point
history repeatedly traces to a strictly shorter predecessor until an initial
history is reached. Thus least and greatest fixed points coincide on this
finite, ranked history domain. A zero-length self loop would invalidate the
second induction. Changing the fixed-point convention cannot supply a
missing `Initial` rule.

A mutually defined environment/provider domain has a separate negative
Function dependency. Failure of product-order monotonicity does **not** rule
out a guarded, mixed-order or biorthogonal construction. Step indexing can
define successive semantic stages from earlier ones. Double orthogonality
is a genuine monotone closure. Neither method supplies the atomic typed
world/import/profile interpretation, nor proves equality with Option A/2.

In particular, testing at all finite horizons against lower-index-valid
environments can be stricter than testing against environments valid at every
index. A provider may pass an early horizon and fail later; its early context
can then constrain the indexed candidate while being absent from the final
environment domain. A carrier-specific adequacy/saturation theorem could
exclude that logical discriminator. It cannot be replaced by the assertion
that all indices were taken. Likewise `forall n. exists witness_n` is not
`exists witness. forall n`; original `xi`, world and source witnesses must be
coherent across horizons.

The existing [concrete-compatibility candidate](../design/2026-10-03-concrete-compatibility-boundary.md)
§8 already exposes these exact imported-world, source-transition and
finite-horizon adequacy obligations. The
[ordinary execution package](../design/2026-10-02-ordinary-computation-semantics-package.md)
§§2–3 and [source-interface adequacy](../design/2026-10-02-source-interface-adequacy-theorem.md)
§2 execute supplied typed inputs and range over admissible environments; they
do not independently define all those inputs. Production-only Option 2 tuples
need not have executable source bodies. Restricting them to source traces, or
declaring a safe indexed envelope exact, would be an additional semantic
restriction without a completeness proof.

## 7. Smallest remaining constructor interfaces on this route

There are two independent cuts. This is minimality by dependency elimination
on the displayed route, not a cardinal-minimum axiom theorem or proof that
no other formalization can work.

### P: original profile completion at the generated Call root

The next source clause can take the **already generated** `R_f`, `F_c`,
`beta`, initial `p_0`, source Call incidence, annotation absence, both same-root
role records, and original scope. It no longer needs to take initial Call
origin as an unexplained premise:

```text
C,d_f,c,sigma; R_f,F_c,beta,p_0,ElimOrigin; NoAnnotation; Role_0
---------------------------------------------------------------- P
Slots_original(beta;xi)
Gamma_original(beta;xi)
original contribution/path interpretation and its same-root
seed-to-refined receiving-view normalization
```

The output must answer, for each dependent typed position `p`, whether this
source contract contributes a slot and which original contributions it
governs. It must distinguish newly introduced profile from inherited actual
provider/result packets; give the initial policy its precise final-view
interpretation; and preserve unrelated evidence. Realized protection uses
original receipt/liveness and pre-dispatch typed observation, not outward
row support. Actual provider/entry and dynamic activation may remain later
premises; this clause must produce their source-owned static input.

`Slots_original={p_0}` is **not** proved by displaying the seed singleton.
Nor is the opposite all-latent-descendants rule proved. A second latent slot
needs an independently source-applicable contract position; merely drawing
one gives no Authority-consistent semantic countermodel. Annotation absence
already fixes no concrete removal grant and full protection at its applicable
positions. The unproved part is the exact applicable-position/contribution
relation and its complete realization, not a request to reconsider that user
decision.

### A: independently typed initial challenge

Even after P, the admission seed still requires:

```text
original P-generated contract/profile and one fixed xi
independent provider and caller holes, original scopes
independently typed surrounding source context/environment
whole carrier, current state, typed result/path and provider roots
---------------------------------------------------------------- A
InitialChallenge_original(beta,holes,context,carrier,state;xi)
```

The surrounding context judgment must be a constructive rule over source
constructors and independently interpreted imports; it cannot mean that the
pending call/comparison already succeeds. Its membership clauses must retain
the original endpoint, continuation, ownership and live evidence constraints.
The later positive history constructors then have a real base. For production,
independent Option 2 member/domain clauses and containment remain separate;
source-witness-only admission is not their definition.

P cannot be replaced by generic descriptor well-formedness; A cannot be
recovered from the existence of a locally successful decoration. In the
representation-preserving fragment, omitting these original-source clauses
produces an envelope of compatible decorations, not proved equality with
original source solutions. Adding the words `OriginalSourceCertificate`
without its constructor merely renames P/A.

### What closes the main gate after these clauses

A successful continuation must establish both directions of local source
inversion, then compose the existing constructor equations at the same
original scope. Soundness needs every generated solution to realize P/A and
all relevant complete calls. Source completeness/principality needs every
independently admissible original view to lift to a **single joint** generated
solution; record-layer inverse maps alone do not prove that coverage.
Capture, generalization and use instantiation must retain that whole relation
and the actual source provider. Production requires separately
`D_C(xi) subseteq D_A(xi)` and
`forall h in D_C(xi). P_A(h;xi) subseteq P_C(h;xi)`, including Option 2
members. Effective finite presentation and B-equivalent scheduling are later
proof gates, not premises inserted into source generation by solving Q.

No incompatible complete meanings have been certified. A user question about
singleton versus every latent descendant, profile deletion versus arbitrary
retention, or least versus greatest admission would therefore be premature.
If constructing P or A exposes incompatible observable/acceptance/principal
outcomes not selected by Authority, that concrete clause and alternatives
must be reviewed and presented for approval. This follow-up adopts none.

historical frame or one aggregate predicate. Thus even the Oracle evidence

algorithm. Its frame tables, subtraction IDs, family/depth markers and public
upper projection are all erased from this proposed current judgment.
