## Result and claim boundary

An authentic source constructor/consumer route returns a right-POP context to
the same annotated callback Function slot. In the natural-count lift, a fixed
three-edge circuit yields callback bounds with counts `q = 1 + 4k`, for every
`k >= 0`. The concrete Function lower endpoint prevents Oracle's Var-only
alias support admission from collapsing this circuit. Thus neither absence of
same-variable aliases nor absence of a cyclic pure-argument-effect edge proves
that source-owned Value callback contexts have bounded counts.

This is a source-derived constraint certificate. The source was not parsed or
executed in Oracle, and no public type or successful acceptance is asserted.
The certificate proves an infinite subderivation of the unbounded arithmetic
rules, not that every context generated by the entire source is in this
arithmetic progression. Oracle uses `u32` saturating arithmetic; that separate
implementation fact is not a natural-count termination proof.

The annotated callback does **not** reach the `both_from_right` branch: its
negative argument-effect interface is `Neg::Row([], Neg::Top)`, not the
syntactic `Neg::Bot` tested by that branch. Its ordinary argument-Effect child
targets that empty row under the swapped context. This source-derived
certificate therefore supplies cyclic right debt and linear Value growth;
it supplies no actual copying child and no conditional power-of-two copying
grammar from `bracketed-replay-decision-obstructions.md`.

## Source and ports

```yulang
type io
my loop(x: (('c -> [io] 'c), int)) =
  \(f, _) -> {
    my unused = (loop x) x;
    (loop x) (f f, 0)
  }
```

Compared with the earlier tuple-pattern source, the callback has the same
symbolic Value variable in its argument and result, and the callback result is
passed as the callback component of the returned lambda's next invocation.
These are ordinary constructor and consumer operations; there is no synthetic
unary edge standing in for a Function rule.

Let `P` be outer `x`, `Z` the returned tuple-pattern formal, `F` its callback
component, `C` the annotation's shared Value variable `'c`, and `R` the Value
result of `f f`. `P`, `Z`, `F`, `C`, and `R` are separately allocated source
ports; only the two written occurrences of `'c` intentionally share `C`.
Let `T` be the closed `[io]` annotation's inner Effect row, `Earg` the pure
effect of the argument occurrence of `f`, and `Ecall` the call return Effect
target. The annotation constructs one attachment `i`, family `{io}`.

Write `L_q = (POP_i^q, identity)` and `R_q = (identity, POP_i^q)`. The paired
annotation callback's positive interface is

```text
A+ = Fun(arg=C-, arg_eff=NegRow([], NegTop),
         ret_eff=Stack(T+, PUSH_i[{io}]),
         ret=NonSubtract(C+, POP_i / filter{io}))
```

The application demand for `f f` is

```text
D- = Fun(arg=F+, arg_eff=Earg+, ret_eff=Ecall-, ret=R-).
```

All of `P,Z,F,C,R` are Value ports. `T,Earg,Ecall` are distinct Effect ports
in this source: `'c` is not used in the annotation effect row.

## Fixed circuit, exact recurrence, and admission

Retain only seed `S` and the fixed upper aliases

```text
F --L_1--> C --R_2--> R --R_1--> F.
```

For any retained concrete lower `A+ <: F-` under `R_q`, replay through the
first fixed alias gives `A+ <: C-` under `R_(q+1)`: directed mix appends the
single left POP to the right debt. Replay through the second gives
`A+ <: R-` under `R_(q+3)`; the third gives `A+ <: F-` under `R_(q+4)`.
Every step has the concrete positive Function `A+` as its lower endpoint:

```text
A+ <: F- @ R_q
  -> A+ <: C- @ R_(q+1)
  -> A+ <: R- @ R_(q+3)
  -> A+ <: F- @ R_(q+4).
```

Hence

```text
q_0 = 1
q_(k+1) = q_k + 4
q_k = 1 + 4k.
```

This recurrence does not rely on retaining the later argument-child aliases
`F <: C` at `L_q`, or later return-result aliases at larger debts. Oracle may
support-subsume those alias variants; the fixed admitted aliases suffice.

## Kind boundary: actual successor and Oracle distinction

Value and Effect annotation maps. Value variables allocate Value rows;

`:845–866` currently rejects explicit effects and allocates Value variables

actual annotation constructor selects the ordinary Row-target branch, so
there is no copying child whose kind must be used to exclude a return route.
The typed distinction does not exclude this Value replay circuit and does not
decide all Effect grammar cycles or finite residual endpoint generation.

builder has a single name-to-ID map; `annotation/constraints.rs:316–322`,
`:434–440`, and `:602–607` use `annotation_var` for both Value occurrences and
symbolic Effect tails. A source using the same written variable in both
positions can therefore share an Oracle endpoint. No universal rejection or
accepted-program property for such a source was established. This certificate
does not use that ambiguity: `C` stays Value and the Effect row stays `T`.
