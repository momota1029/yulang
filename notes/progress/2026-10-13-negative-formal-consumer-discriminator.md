3. `candidate_apply_effect:840–863` chooses the normal level/polarity bound
   owner, inserts the bound, then calls `candidate_replay_bound:763–805`.
   Registering an upper after `a` compares it with existing lowers. Inserting
   `b` after that upper compares it with existing uppers. This follows from
   `candidate_opposite_count` and the polarity-selected `(lower,upper)` order;
   it is conditional on completed insertion and scheduling, not a universal

4. `candidate_context_begin_replay:2911–2982` combines new lower fibers with
   all upper fibers, then old lowers with only new uppers. It constructs

   itself license forgetting a lower or using an arbitrary tail. Relation/fiber

## Oracle discriminator: cache reuse still emits each actual tail

Direct immutable-source inspection of
`crates/infer/src/constraints/row_effect.rs:88–234` confirms the following
conditional owner lemma. Suppose two normal invocations reach the
nonempty-retained weighted branch with the same source, retained families and
residual left weight, while their actual tails are `t1` and `t2`.

The key at `180–184` excludes tail and right weight. The second invocation can

```text

g <: tj       @ normalize_directed_mix(K,Rj)   for the actual invocation j
```

Each invocation retains its derivation. This refutes the **source-code shortcut**
“gamma cache hit means its outgoing projection is already installed”: the
second exact-tail enqueue occurs after the reuse branch. It does not prove
source reachability of two such invocations or their completed replay, and
does not transfer Oracle's gamma coalescing to Y3. Approved Y3 lineages remain
distinct even when current keys agree.

The all-entry transformation at `1190–1216` preserves each supplied stack ID
while modifying every active PUSH payload by the retained removed families.
It receives no separate lower-fiber eligibility argument. Therefore this
owner supplies exact feedback/projection arithmetic but cannot alone establish
which original same-family contribution is licensed. Copying this arithmetic
into a toy checker would assume the open source association.

## Exact absent transition and stop

At Y3's atom/Allowance discharge, no inspected operation takes the joint actual
attachment/fiber parents and Row-upper demand, creates a lineage-owned gamma,
then installs **both** source feedback and that demand's exact gamma-to-tail
projection. The executed matching atom branch simply returns; the contextual
discharge retains only ContextId; the actual replay transports their existing
relations. In particular, an outgoing tail `tj` cannot be recovered from the
discharge record `RelationId -> ContextId` alone. Actual relation dependencies
may retain other provenance; this does not make that map a recipe installer.

This is the stopping point: source-qualified cancellation cannot be tested
against the named current consumer until this authenticated joint transition
exists. Its absence is an implementation/correspondence gap, not semantic
impossibility and not a refutation of H. The required theorem also cannot be
closed by claiming existing membership checks or replay already implement it.

Recommended next action: the assigned prover should derive the joint owner
transition from actual negative source formation, preserving independent
same-family fibers, then make per-lineage feedback and **each exact demanded
tail** explicit proof outputs. Keep the production/admission gate OPEN; no
new semantic choice or implementation lease is proposed here.
