### Constructional derivation and descendant ownership

For a freshly generated no-provenance r, q=c=0. Each successful queue selection takes q, transfer increments it, and infallible back insertion follows. Repeated driver calls therefore append r's indices 0,1,… in order. Function front work carries no ack; new replay generations allocate a different r. FIFO pop preserves each existing operation's projection, and pop appends its occurrence to A before any memo/equality omission. Thus r's occurrences enter one active F's A in increasing order, without a second copy generated from F.current. Terminal processing preserves A order and c==index rejects a duplicate or later-index-first consumption. Once d passes an occurrence, A's outstanding suffix begins at the new c for that r.

For the retained provenance R, only one exact child i is transferred while Running. Its initial ack is appended to F before context/dispatch. All descendants generated during that work use ordinary Q, including fresh no-provenance replay operations; they are owned by this same F's drain until Q is empty. No native call inside Dispatch, Context, extrusion, or intrusion drives another existing restoration's R. The only production no-provenance replay callers are `candidate_replay_bound` (`candidate_extrusion.rs:760–802`), reached by value/effect application (`805–860`), filter execution (`candidate_context.rs:2787`), and intrusion merge (`candidate_intrusion.rs:603`). All execute within current typed-stage work or its empty-queue intrusion settlement. Scheme freshening invokes provenance restoration separately (`candidate_scheme.rs:965–975,1221–1270`), before proceeding to its next captured bound. Its production Local action stays synchronous; the retained helper resumes its saved B/R rather than constructing another fresh use.

At Transport with no current item, the common driver settles intrusion when Q is empty, then pops newly generated work. It enters Diagnostics only if no item remains and intrusion is no longer dirty (`lib.rs:12189–12221`). Function.next advances on successful enqueue, leaving its pending item/Q owned until Transport drains it. Diagnostics runs effect conflict replay, diagnostic completion, occurrence witness reporting and clear before changing to Acknowledgements (`12257–12270`). The inspected conflict reporter (`candidate_effect.rs:558–619`) and witness reporter (`lib.rs:13684–13704`) report diagnostics rather than enqueueing replay children. This establishes the exposed control barrier; correctness/completeness of the diagnostic algorithm and of memoized work remains the atomic semantic premise, not a consequence of ack order.

No-provenance drive deliberately returns Queued (`candidate_context.rs:3115–3118`); its caller does not return restoration completion. At c<|H| it cannot retire merely because q=|H|. Final terminal consumption can set retired, but Running/Ready keeps the designated R alive until receipt release and B advancement. No native generation or transport path removes operations; rollback removes only route-created operations after reversing snapshots (`1585–1615`). Referenced pre-route operations survive commit while c<|H| or Running/Ready, or while linked to unfinished B. After final ordinary Idle consumption the operation can be reclaimed because no outstanding r occurrence remains on a lawful constructed history. Historical completed A entries need not retain an operation for future completion: preparation and consumption resume at d.

This is a constructor argument with explicit call-flow scope. It is not an acknowledgement-prefix re-proof, an all-state transition checker, or a semantic completion theorem. The imported successful inverse premise remains necessary after rollback; this packet did not audit inverse correctness again.

### Minimized attacks and result

The low-level transfer rule accepts an already queued a when c≤i<q: with |H|=1, Idle, c=0/q=1, a second `enqueue_item(a,false)` would place a duplicate into Q without advancing q. Likewise an Idle operation's low-level `complete_replay_child(a,…)` does not check the identity of the calling frame. These show why local API checks alone cannot establish H3. They are **candidate malformed-call attacks**, not source counterexamples: the native producer uses the new q, the native provenance producer installs Running before exposing a step, Dispatch strips its ack, and the sole native completion caller uses its owned A[d]. The cfg(test) queue-next/callback harness can construct other states, but that is not constructor-qualified language execution.

No constructor-qualified duplicate, out-of-order terminal acknowledgement, foreign consumption, or premature retirement was found in this bounded pass. Absence is not an exhaustive grammar search or all-source proof.
