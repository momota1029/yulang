## Smallest port-collision witness

Let `E` and `T` be distinct fresh Effect rows at one level. An actual Lambda
owner supplies an entry-to-return seed `o: E <: T` with its inferred-entry
origin. Consider a positive Function with its argument-Effect port `E-` and
return-Effect port `T+`, compared with a negative Function whose corresponding
ports are `T+` and `E-`. Value ports can be arbitrary compatible fixed ports;
they are not needed for this collision.

```text
o = E <: T                  authentic Lambda entry seed
P = Fun(..., E-, T+, ...) <: Fun(..., T+, E-, ...)

P --ArgumentEffect / Swap-----> c = T <: E
P --ResultEffect / Preserve---> c = T <: E
```

One parent and one child relation suffice to lose the operation discriminator;
the Lambda seed is the smallest extra record needed to expose the danger of
authorizing an arbitrary edge by an origin elsewhere in the same component.
With equal levels, the seed and child can store upper bounds `E -> T` and
`T -> E`, hence the intrusion endpoint graph has component `{E,T}`. This says
nothing about whether either edge carries the approved recursive operations.
The authenticated source flow remains `E <: T`; it is not the ordinary
argument-Effect child `T <: E`. A written interface comparison at `P` cannot
receive entry authority merely because the component contains `o`.

For a future authentic parent context consisting of one left `PUSH_i[S]`, with
All filter and empty right word, the selected detached equations give:

```text
ArgumentEffect: swap(PUSH_i[S]) = identity
ResultEffect:   preserve(PUSH_i[S]) = PUSH_i[S]
```

Thus recognizing only the identity child can omit the productive PUSH path;
recognizing only the preserved path can omit the ordinary Swap incidence.
Existence of a favorable subpath does not establish the complete component
required by §5. These are conditional false-negative/false-positive witnesses
against a recognizer that discards a port label or uses component-wide entry
authorization. They do not show that this exact negative interface or
nonidentity parent is generated by a currently accepted source program.

  this behavior is not evidence that a nonidentity port transform executes.
- `State::relation:1118–1135` interns by pair plus context. Both current
  children therefore share `c`. `State::dependency:1154` sends both labeled
  incidences to `edge(parent,child)`, and `State::edge:1184–1186` deduplicates
  that adjacency. `State::children:1215–1221` returns endpoint pairs only.
  The operation distinction survives in `dependencies`, but not in this API.
- `candidate_effect.rs::candidate_bound_origin:327–370` retains both the
  context-bound relation and the diagnostic pair origin. The latter map is
  keyed by `BoundKey` and `TypedPairKey` (`:57–58`), so it cannot independently

  upper relation IDs and both input `BoundKey`s. These richer records must not
  be flattened to adjacency when recognizing a complete circuit.
- `candidate_extrusion.rs::candidate_apply_effect:724–747` chooses one bound
  side by levels; insertion at `:422` records origins and `:482–497` installs
  the selected row bound. Candidate insertion does **not** mirror every row
  constraint into two reciprocal stored edges. A single ordinary row edge is
  consequently not the witness here.
- `candidate_intrusion.rs::settle_candidate_intrusion:415–438` follows stored
  lower and upper references without their relation contexts; `:445–468`
  follows Function ports without field/operation labels. Its SCC algorithm

  equality at `:474–486`. It is not a generated contextual-circuit certificate.
  With no recorded parents, `:370–372` skips even this SCC construction. The
  displayed SCC is a property of that projection when constructed, not a

## Premises, coverage and failure conditions

The structural collision follows directly from the Function child constructor
and retained-record identities. Source reachability of the chosen negative
ports and nonempty parent context is an explicit candidate assumption. No
Oracle execution, parser execution, full source fixture, concrete contribution
seed, complete approved SCC, downstream filters/sharing, or successful scheme
publication was established. The witness fails to demonstrate a bug in a
recognizer that examines both labeled incidences, authenticates the exact
origin-to-operation use, and validates the complete dependency closure.

No independent oracle ran. The PUSH/Swap discriminator uses the selected
operation equations; it is not a new derivation of those source semantics.
There were no enumerated seeds/ranges, mutations or executable probes. Static
inspection covered the named Lambda and Function producers, relation/bound
ancestry, replay and intrusion projection; it did not cover arbitrary source
reachability, generalization or all fresh-use paths. The construction removes
all unnecessary Value-port structure and uses only two Effect rows, two port
incidences and one entry-origin seed. No alternative toy search was launched.
