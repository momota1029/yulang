## Small mutation witness against a frozen-entry model

Use the positive callsite with receiver `w` at level 0 and positive Function `F` at the lower endpoint. Its argument is a negative live view of value row `v`, its result a positive live view of that same row, and `v` has level 1 and initially empty lower/upper bound vectors. Both effect ports are valid constants. This is a valid candidate native graph pattern; no source-program reachability claim is made. Reverse-pushing the four child Visits makes the argument run before the result.

1. Visit `(v,Negative,0)`: snapshot zero selected uppers; allocate `n` at 0, retain `(n,v,Negative,0)`, memoize, append `n` to `v.lower` through the opposite-polarity source link.
2. Visit the two effect constants: structural anchors.
3. Visit `(v,Positive,0)`: its selected lower snapshot now contains `n`; allocate `p` at 0, retain `(p,v,Positive,0)`, append `p` to `v.upper`, schedule the recorded lower entry `n`.
4. Visit `(n,Positive,0)` reuses the level-0 anchor. `Work::Bound` installs `n` in `p.lower` and transports the source link's evidence.
5. Rebuild `F` with argument `n` and result `p`, then retain the output group.

Thus entry bounds are empty while a copied selected bound exists at return. A theorem saying that only entry-snapshot bounds are copied is false. This does not falsify the assigned operational invariant: the correct relation uses visit-time snapshots and includes source-link mutations. The dual negative-root pattern reverses signs. Distinct positive/negative copies are required by memo keys and are not broken sharing. This witness uses one shared high row and one Function; removing either shared occurrence or its polarity difference removes this interaction.

The bound snapshots are lengths read before source-link insertion, followed immediately by indexing the selected vectors. The insertion mutates the opposite side of that row. No intervening work item executes during that indexing loop. Later row Visits can see earlier links, as above. Bound copying into fresh owners and incoming Allowance remapping can add more operation-created state; a global immutable-graph premise is unsupported.

## Remaining attacks and observations

- Keys include kind-qualified endpoint, polarity and target. Value ordinal 0 and Effect ordinal 0 cannot collide. Row memo publication precedes selected-bound traversal. Anchors at/below target do not traverse their selected bounds, so a claim that *all reachable graph rows* have level at most target would require a stronger, unproved entry invariant. The code establishes fresh-copy level and anchor reuse, not such a transitive claim.
- Function children use `[-p,-p,p,p]` for argument value/effect and result effect/value. LIFO ordering finishes structure before pending bounds. Recursive bounds can name an enclosing Function through a row because that row is memoized before its bound work resumes. No wrong port/kind transition was found in these arms. - Effect-view endpoints preserve Allowance/Support/AnnotationMember tag and member index while remapping the tail. The view map is keyed by old view ID and mapped tail, not contents. Incoming capture incidence is scheduled only while copying a positive high Effect row, and targets its fresh tail. `candidate_register_capture_bound` installs incidence only for negative row-to-Allowance bounds. No synchronous equality/typed dispatch was found inside these operations. Complete view attachment/lifecycle validity is unverified.
- `candidate_insert_copied_bound` differs by mode: unscoped uses OwnerEmission; scoped imports a snapshot carrying MissingOriginAssociation and uses BoundTransport. `candidate_transfer_bound_origins` first transports attached executable fibers, then separately preserves diagnostic origins without inventing their relation association. - Each allocated row retains a parent before copying its bounds. `finish_candidate_extrusion` indexes the returned output only when there are new parents and active comparison processing; otherwise it returns without a group. The production drain's comparison ownership matters. Assuming universal output indexing for arbitrary direct callers is false and outside the assigned production scope.

## Replay ownership and cost discrimination

`candidate_replay_bound` enumerates physical opposite entries and invokes `candidate_context_begin_replay`. The latter stores generated child RelationIds in a ReplayOperation before queue transfer. `candidate_context_drive_replay(id,None)` invokes the non-synchronous consume branch; `enqueue_item` reserves queue/undo first, advances queued, then performs infallible insertion. None of those steps executes the child.

For a fresh nonempty operation with successful execution of that drive and no interleaving mutator, every iteration advances queued by one until queued equals children length; consumed stays zero, and drive returns Queued. Zero children retire the operation. A strict transferred prefix plus remaining unqueued children can occur if a fallible enqueue aborts the drive. The assigned contract's weaker prefix-retention formulation is safe; it must not be turned into synchronous completion. No lost-child trace was found on the successful path.

The actual later handoff is `step_typed_drain` Transport pop/ack retention, then Context/Dispatch, with `candidate_step_typed_drain_terminal` (`12736ff`) owning Acknowledgements and ReturnReady. Intrusion settlement is called when that outer worklist is empty. This identifies owners only; complete drain termination and acknowledgement progress are outside scope.

A linear bound in distinct mapped endpoints alone is unsupported. With one incoming remapped Allowance, one opposite lower bound, and respectively m and n attached executable fibers, `candidate_context_begin_replay` visits their m*n pairs when prior heads are empty. The smallest discriminating case is m=n=2: four pair iterations despite two physical bounds. More generally actual work includes visited selected physical entries, capture records, transferred fibers and origins, per-replay new/old fiber products, context/source/scope operations, copied view payloads and Function interning. Relation/dependency dedup can reduce retained children without removing all pair-construction work. This is a conditional native cost witness; admissibility of arbitrary fiber counts from source was not established. No compiler-wide complexity theorem follows.
