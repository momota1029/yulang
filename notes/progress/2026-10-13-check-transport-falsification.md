## Objective and result

The assigned claim starts with a finite selected local checking derivation
and seeks, for a provisional relative family S, the maps

```text
D: d in D_checked(e) -> the identical d in D_source(e)
P: o in P_source[S](d) -> the identical o in P_checked[S](d).
```

The source, actual value/provider alternatives, world, original assignment,
entry/receipt/context guards and all independent challenges and developments
must stay fixed. Ordinary membership of the recursive source value and a
VIncl oracle are unavailable. The current singleton seam is cO, with cE
also requiring its actual check tree.

**Result:** the selected grammar does not by itself supply an interpretation
of every finite checking proof at S. The first precise obstruction can occur
in a positive returned-value child, before nonpositive children or recursive
equation pairing: a check changes the descriptor index of an S.V obligation.
Its ordinary same-value inclusion action takes V* evidence, whereas the
relative Return clause supplies S.V evidence. A local proof of the unfolded
structural clauses supplies Phi(S) evidence, which is also different from
membership in S. An explicit closure property of S under these actual check
actions, or an equivalent jointly proved relative action, is still required.

This is an exact check-tree obstruction, **not** a source-qualified
counterexample to cO/cE and not a proof that a suitable jointly constructed
family cannot exist. Those actual trees were not supplied at this baseline.
In particular the complete relative background B_H may already discharge
some affected tuples. This pass does not exhibit a missing tuple in B_H.

## Smallest selected check-tree obstruction

Use the actual §3.2(2) record-width constructor as the positive result child
of §3.2(4) Function checking. Let the source result view be
G = `{a:A, b:B}` and the checked result view H = `{a:A}`. The check retains
the same actual record u and its decorated tuple `(u,r,e)`; it does not
construct another runtime record. A schematic minimal proof tree is

```text
width:       ordinary ValueMem_G(u,r,e) -> ordinary ValueMem_H(u,r,e)
domain-id:   d in D_F(e) -> identical d in D_F(e)
FunctionCheck(domain-id, result-width, unchanged remaining full conjuncts).
```

This is a selected constructor pattern, not an assertion that these are
cO's actual endpoints. The unchanged remaining conjuncts are genuine
premises, not automatically true: all captures, providers, guards, pending
ports, effects and futures must have their original proofs. The obstruction
does not use a convenient choice of provider or independent witness.

The selected Return readout is exactly

```text
PhiT(PureReturn(G), Return(u,r,C,w), e)
  requires S.W(C,w,e) and S.V(G,u,r,e).
PhiT(PureReturn(H), Return(u,r,C,w), e)
  requires S.W(C,w,e) and S.V(H,u,r,e).
```

Thus the first changed positive Return premise is

```text
theta_width[S]: S.V(G,u,r,e) -> S.V(H,u,r,e).
```

The width proof at ordinary membership establishes theta_width[V*]. It
does not instantiate a theorem universally quantified over arbitrary S.
Unfolding the record clauses can establish
`PhiV(G,u,r,e)[S] -> PhiV(H,u,r,e)[S]` by dropping the b field. Neither
displayed Phi clause is the required atom `S.V(H,u,r,e)`. If the enclosing
observation contract first exposes an S.T atom, its check action must
likewise transport that exact indexed atom before or together with this
Return readout. Renaming these layers does not discharge the premise.

Monotonicity compares Phi(S1) and Phi(S2) at the **same** descriptor index
when S1 is contained in S2. It does not compare G and H inside one S.
Even a postfixed assumption `S subset Phi(S)` supplies the wrong direction
for introducing an S atom from a Phi(S) readout. Assuming theta_width[S]
as an opaque leaf would simply assume the missing positive child of P.

A candidate may instead include every same-tuple checked result index in
S, using the actual finite proof tree and all original event scopes. That
is a candidate construction premise. Every added tuple then creates its
own Phi(S) obligation. It requires a simultaneous closure/readout argument;
an ordinary successful comparison does not prove that argument. The result
above does not exclude that route or claim it has been constructed.

continuation, carrier and future child, including off-diagonal fillings.

**Nonpositive children and recursive references.** §3.2(4) demands their
actual equality/domain proofs. Positivity of Phi does not supply those
local laws. §3.4 permits finite equation references but additionally
requires genuine L4 for recursive hereditary certificates. If an actual
cO proof uses the target O membership/L4 certificate to supply such a
child, that occurrence is circular for the original introduction goal.
No such actual child was exhibited, so this is a precise stop condition,
not a finding that the unknown cO tree is circular.

**Methods, adapters, annotation/final formation.** An actual conversion in
§3.2(5) has its own code, effects and output handle; §3.4 preserves the input
binding object separately. A theorem about the same callable/provider
cannot silently interpret an executing conversion as a proof-only check.
A registered proof-only choice needs its real full local relation and
relative action. No actual method law is supplied for these unknown trees.
Final formation exports the written target and retains intermediate proof
evidence; replacing it with the synthesized root hides, rather than proves,
