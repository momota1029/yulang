## 1. Question, result and exact limits

The input is the complete conditional continuation in
`notes/theory/2026-10-12-fixed-term-intrusion-quotient-proof.md`, especially
action H in section 4 and its first-App cut in section 5. The source is the
fixed nested recursive `odd`/`even` term in that note. Its approved occurrence
origin is E, receiver O, and retained pairs are `(C,B,+,1)` and `(D,R,-,1)`.

The current candidate does **not** realize H literally. It redirects C to B
and D to R, mutates the surviving parent levels to 1, retains immutable
Function descriptions, settles at an empty worklist, and uses current
RelationId completion generations. H instead uses immutable low anchors C/D,
transports live descriptions before extrusion returns, and preserves the
reference's literal raw comparison cache.

That representation difference alone is not a fixed-term counterexample.
For the exact empty-bound scalar cut, a class interpretation maps candidate
representatives B/R to H anchors X/Y and matches the inspected value-row
consumers' level tests, selected bounds, Function variance coordinates,
boundary-1 anchor reuse and per-use map partition. An explicit delayed-union
commutation calculation appears below. No high descendant requires lowering
in this cut. In particular the reference's lazy structural-level problem
cannot simply be assigned to the candidate: the inspected candidate traversal
does not use a cached maximum Function level.

The first absent source transition remains earlier than those scalar
consumers: the actual extrusion constructor does not create an occurrence
record containing the source origin/receiver and all produced pairs, and
settlement consumes a graph of solver bounds/ports instead of that source
certificate. Current source inputs contain useful owner and callee syntax,
but no inspected consumer connects them to the parent records. This audit
does not turn a manually supplied merge into a source-qualified execution.

Nor is the positive scalar calculation a complete candidate-to-H theorem.
The candidate has source occurrence facades, four Function ports, effect
entry/return construction, contexts, attachments and retained continuations.
H's note proves a two-port native Scala continuation. No total simulation of
these extra operations or candidate final-interface simplifier was supplied
or established here. No genuine current Yulang source counterexample is
claimed from an arbitrary hand-installed store.

## 4. The fixed-cut class interpretation

Suppose, explicitly as a conditional input, both approved pairs are supplied
to the candidate merge owner at the first-App seam and no other scalar merge
occurs. Suppose the scalar allocations, selected bounds and original levels
are those in the reference note. All rows have `non_generic=false`, and
nontrivial effects/contexts are excluded from this scalar calculation.

Candidate `merge_candidate_rows(C,B,...)` makes B the representative and
sets its level to `min(2,1)=1`; similarly R represents D/R at level 1
(`candidate_intrusion.rs:525–534,586–591`). Define the interpretation I:

```text
I(rep(B)) = I(rep(C)) = X (the H level-1 anchor C)
I(rep(R)) = I(rep(D)) = Y (the H level-1 anchor D)
I(other scalar row) = the corresponding unchanged H row.
I(Function term) = Function of the interpreted live child endpoints.
```

This is a many-to-one semantic interpretation of allocated records, not an
injective renaming of every historical allocation. Historical B/C and R/D
records remain distinguishable; their common live class gets one H anchor.
The baseline note's injective original allocation naming still applies to
the pre-action reference trace. It must not be confused with this quotient.

This correspondence needs two sorts. A separate injective historical identity
map J keeps candidate raw B,C,R,D allocations aligned with distinct reference
raw B,C,R,D records. J preserves the raw Function-child distinction and actual
parent/copy provenance; I identifies only live canonical classes. No single
global alpha-renaming can serve both roles. Moreover J is not an isomorphism
of the full leveled raw store: candidate changes B/R's stored levels to 1,
while reference/H historical B/R keep immutable level 2. `Parent` records
retain target 1 but no original parent level; extrusion's `original_level`
at `candidate_extrusion.rs:81–94` is a transient read, not retained history.
The raw diagnostic keys, RelationKey, polar Key and Parent records inspected
here contain identities/context/polarity/target rather than a past parent
level, and therefore their key distinction does not require that lost level.
Live copying/classification reads the current representative level. A consumer
requiring the original parent level would need separately retained evidence;
the current Parent record does not supply it. The Lambda raw-level access
discussed in section 6 is a concrete current-level consumer, not a history key.

The two rows have no nonempty lower/upper products at union. C has no bounds,
B has only upper C, D has no bounds, and R has only lower D. After redirect,
the canonical live lists are `U(B)=[B]` and `L(R)=[R]`. The candidate preserves
physical source arrays but all inspected live row consumers go through the
representative. Under I these lists are precisely H's `U(X)=[X]`,
`L(Y)=[Y]`. No other row level changes; no descendant-level closure is needed.

Both-sided append-union occurs before redirect at
`candidate_intrusion.rs:548–574`; canonical owner/bound installation occurs
at `candidate_extrusion.rs:432–433`; future list counts and elements
canonicalize owner and item at `:570–630`. The post-union merged-lower replay
at `candidate_intrusion.rs:599–604` has zero products for both exact pairs.
This calculation is specific to the fixed cut, not proof that min-level
union preserves the bound-level invariant in stores with high descendants.

## 5. Why delayed settlement commutes at this cut

H performs the pair actions before returning `F(C,D)` to the comparison
owner. Current candidate settlement is called when the typed worklist is
empty, at `lib.rs:11993–11996` and `:12225–12229`. The rewritten comparison
has already been enqueued at `:12443–12454` and inserted through
`candidate_apply_value` at `candidate_extrusion.rs:808–831` before that
empty-worklist settlement. Therefore current timing differs from H.

For this scalar first-App cut, compare two orders:

1. Union the two empty-product classes, then insert the transformed upper
   `F(C,D)` on o.
2. Insert that upper on o, then union those same two classes.

o has no lower in either order, so upper insertion creates no Function replay.
The two unions have no products in either order. `canonical_value` leaves
Function term identity unchanged (`lib.rs:11440–11445`), so the physical
upper is the same historical transformed Function in order 2. Its children
are interpreted through the representative at live consumption. Both orders
therefore have the same scalar live store under I, and every live bound level
at the cut is at most its owner's level. This proves only the fixed-cut
commutation of insertion and these unions; it does not choose SCC scheduling
for other programs, bounds, pending operations or publication boundaries.

## 6. Live structural identity and levels

The candidate does not mutate/re-embed all existing structural Function
terms at union. `canonical_value` canonicalizes rows only; a Function
endpoint retains its `Term` ID. A suspended Lambda later constructs terms
from stored parameter/body ordinals (`lib.rs:11233–11260`), so its raw
Function can still mention original B/R allocations. This is not H's
literal `F(X,Y)` representation.

The following consumers nevertheless observe the fixed-cut quotient:

| Consumer | Actual lookup | Fixed-cut consequence under I |
| --- | --- | --- |
| Component or live-variable term | `lib.rs:11382–11413` canonicalizes row at translation | Historical B/R and C/D terms all reach the shared classes |
| Function variance | `lib.rs:12493–12522` translates each raw port via value/effect endpoint | Value children yield the H X/Y coordinates |
| Structural extrusion | `candidate_extrusion.rs:81–94,224–253` traverses Function children and checks each current row level | B/R representatives at 1 are retained at target 1; no B'/R' extrusion |
| Capture of a Function | `candidate_scheme.rs:289–290,458–513` interns each translated child canonically | Raw `F(B,R)` and `F(C,D)` yield equal live value coordinates |

Unlike `Typer.scala:209–214`, candidate Function descriptions have no
inspected lazy maximum level used by these paths. The dispatch always calls
candidate extrusion for a structural-to-row comparison
(`lib.rs:12414–12439`); the row's own current level controls copying. This
avoids the direct stale-lazy-level objection for these consumers. It does not
prove all downstream candidate consumers treat structural identities modulo
I; historical Function IDs still affect diagnostic/relation keys.

One relevant limit is visible at `lib.rs:11267–11272`: Lambda entry/return
effect rows are allocated using the **raw** parameter ordinal's level. For
these two fixed supplied unions the original parameter B is the surviving
parent, so its stored level is 1 and the raw access agrees with its current
representative. In an arbitrary later chain redirecting B elsewhere the same
argument is unavailable. No claim is made about that chain's source
realizability or about effect scope preservation after this level change.

## 7. Historical keys versus current relation completion

The literal Scala cache calculation in H is correct for its specified
reference state: old `(o,F(B,R))` and returned `(o,F(C,D))` are different raw
keys (`Typer.scala:100–123`). It is **not** the current candidate cache law.

Candidate raw endpoint-pair keys continue to own diagnostic memos, while a
processing `RelationId` owns semantic completion. A relation is interned by
pair plus context (`candidate_context.rs:2232–2249`);
`candidate_context_pair` changes top-level rows but leaves Function IDs
(`:2471–2481`). `pair_is_current` requires both a raw memo and completion of
the currently processing relation at the current intrusion generation
(`lib.rs:11463–11472`). A merge increments that generation
(`candidate_intrusion.rs:530,594`); it does not rewrite the raw diagnostic
memo map. `mark_candidate_pair` records completion only for a canonical work
item, not a raw alias (`:223–255`). Raw aliases are admitted diagnostically
and forwarded to canonical semantic work (`lib.rs:12355–12362`).

At the first-App prefix, the original and copied Function term IDs remain
distinct because their raw children differ. Thus the old raw demand does not
by itself suppress transformed insertion. After a supplied merge, a previous
completion generation alone also cannot suppress current work. This rules
out transporting H's *specific* rewrite-the-pending-key failed-insertion
example to the candidate merely by replacing its names.

An additional current owner matters on later replay:
`lib.rs:12364–12374` reuses the stored transformed diagnostic child for an
already extruded non-Function/Function comparison. This keeps the original
extrusion copy graph from being allocated again. `candidate_extrude`'s polar
maps themselves are operation-local (`candidate_extrusion.rs:29–35,364–365`),
so “preserve the polar memo forever” is not a candidate invariant. Parent
records retain actual raw allocations, but `TransportReason::Extrusion`
identifies an initial type endpoint, polarity and target rather than an
approved source occurrence (`candidate_context.rs:220–222`).

These facts are a bounded cache discriminator, not a proof of every stale
relation, resumed replay, completion acknowledgement, attachment or abnormal
path. In particular scalar class equality does not authenticate all evidence:
the export inspection itself keeps row-map/equality qualification as an
external lifecycle obligation (`candidate_context.rs:985–999`).

## 8. Generalization, captured environment and fresh maps

Capture canonicalizes each row and classifies it by current representative
level and metadata (`candidate_scheme.rs:301–326`). Nonlocal rows stop
bound expansion and retain their session bounds (`:567–572`). Local scheme
installation stores a root and the original boundary, not a closed deep
copy (`:1316–1334`). Both definition and local use recapture their live root
at that boundary (`:947–960,1362–1378`). Thus the original source boundary
need not move when the represented classes change level.

On the H cut, boundary 1 classifies X/Y as nonlocal and e at level 2 as
local. With I, candidate B/R representatives at 1 receive the same
classification; only e is copied. The fresh map canonicalizes each source
representative once, rechecks current level and `non_generic`, and reuses
nonlocal rows (`candidate_scheme.rs:1008–1019`). Each new invocation gets a
new map at `:984–986`. Function reconstruction uses its mapped child terms
at `:1137–1157`. This is the exact boundary-1 shared-anchor partition that
H needs, conditional on the supplied scalar cut and unchanged boundaries.

At boundary 0, the reference's reachable scalar classes are o,A,X,S,Y,
all at level 1. The same representative map rule would allocate one fresh
row per corresponding class, at use level 0; revisiting a self bound or cycle
uses the same map entry. This is a map-partition fact, not a derivation of
the candidate's complete reachable graph: effect/context payloads and source
facades can add nodes, and restoring captured bounds runs real constraint
owners (`:972–975,1221–1265`). No candidate final `Top -> Bot` result was
executed or proved here.

Captured root reuse therefore addresses one real H transport obligation.

There is also an explicit suspended source slot:
`candidate_source.rs:624–647` retains `Stage::PublishLocal { slot, exposed:
Term, boundary }` and later passes that same exposed Term to installation.
`install_candidate_local_term` translates it through `value_endpoint`
(`candidate_scheme.rs:1320–1322`), so a raw exposed row still receives the
current canonical interpretation at installation. The immutable source plan
retains Candidate/Lambda recipe indices and Link/Local operands; execution
dispatches them through actual admission/use owners
(`candidate_source.rs:660–680`). The Lambda recipe reuses raw parameter/body
ordinals as described in section 6, while Links reach `admit_candidate_value_link`
and its endpoint translations (`candidate_scheme.rs:1337–1343`). These are
real consumer points for live transport; the existence of the slots does not
derive the missing mapping from native `f_ty/a_ty/res` to candidate facades.

It does not prove that previously constructed fresh-use frames are safely
remapped by a later merge: those frames retain their construction maps
(`candidate_scheme.rs:129–140`) and their restoration owner rereads a live
canonical owner at a saved count/index
(`candidate_extrusion.rs:695–739`). The fixed H continuation creates the
inner frame **after** the supplied pair actions, so this stale-frame case is
outside the calculation. Arbitrary-frame transport must remain a separate
obligation rather than being assumed from successful recapture.
