## Undo, capacity and failure reconciliation

**Start failure.** `candidate_prepare_replay_wait` (`candidate_context.rs:2993–3002`) retains the old slot/q/c/retired before starting. Initial enqueue also reserves worklist undo before transfer (`lib.rs:12790–12812`). A failure in start leaves the new frame inside the route's creation frontier; context rollback truncates new F and reverses operation snapshots before removing new operations. F.destination is installed only after start succeeds. It belongs to a new frame, so rollback needs no separate old-field snapshot for that initial assignment.

**Running or terminal-ack failure.** Shared nonterminal/terminal preparation captures old F before changing it. `candidate_context.rs:1746–1758` now copies `replay_destination` into the replacement while retaining the original F/A allocation in TypedDrainUndo. Each replay snapshot includes waiting_child as well as q/c/retired (`1840–1846`). Partial preparation, accounting failure or an exact ack mismatch therefore propagate to the route owner with stage/destination and replay undo intact. The imported lawful-ack/prefix lemma remains a premise, rather than being proved again by this copying code.

**Ready publication failure.** ReturnReady reserves both F update and exact replay-return undo before mutation. Ready publication, F pop and P restoration have no fallible call between them. Any later injected/semantic route failure restores original F, including destination/A allocation and stage, then restoration snapshots, then replay snapshots (`candidate_context.rs:1585–1607`) before creation-frontier removal (`1608–1614`). If the previous route already committed c=i+1 in Running, this rollback restores that checkpoint c=i+1 with F, rather than incorrectly rewinding to i. If ack completion occurred within this same route, its earlier snapshot also restores c=i. Both cases match the conditional proof's checkpoint-specific rollback argument.

**Delivery/parent failure.** Delivery reserves a replay snapshot before clearing Ready, and restoration reserves its own snapshot before any child step (`candidate_extrusion.rs:703–708`). Final delivery plus B pointer-clear/n increment can occur in one retained route. Failure reverses both, reinstating exact Ready/a/j/receipt and B's pointer/cursor. Local's cursor is captured by the outer route (`lib.rs:9131–9136`) while the retained helper keeps L in its vector; rollback restores it (`9370–9375`). If restoration completion later returns e and Local clears/increments, failure likewise restores that cursor. Production Local temporarily pops L only within its atomic owner and pushes it back before error propagation (`candidate_scheme.rs:1390–1401`); the retained helper never pops L during child/receipt execution (`1474–1484`).

**Synchronous cleanup.** The synchronous wrapper's error tail (`candidate_context.rs:3069–3079`) truncates newly started child frames, clears their slot and reinstalls saved P before propagating failure. It is not a semantic commit: prepared operation/frame undo remains live for the surrounding route. Existing retained Running frames are not dropped because their frame count was already part of that entry. This cleanup alone is not exact whole-route rollback; the common finish owner still performs that job.

**Q/D/P and frontier capacity.** The earlier bridge's owning workspace events remain actual source: queue push/pop/growth and diagnostic admission/growth/clear use `lib.rs:12652–12812,13461–13485`; inverse events and index rebuilding use `12741–12776`. Old Q/vector/index allocations are retained and swapped back, preserving their exact named capacities and ordered mathematical contents. The new destination is inline in the old/new F snapshots; old F/A capacity is restored even after removal. Context checkpoint and effect checkpoint restore both P lanes through intrusion/effect rollback (`candidate_intrusion.rs:106–133`, `candidate_effect.rs:182–210`). Existing D is the ordered delta/index/memo/errors projection, not partial call-local Diagnostics scratch.

Typed-drain stack, replay/restoration maps, undo vectors, other semantic allocations, spare journal capacities and historical peaks may retain growth after rollback. The source does not establish exact pre-route capacity for every allocation in the session, and this note does not claim it.
