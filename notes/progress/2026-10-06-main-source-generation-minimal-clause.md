## 1. Result and precise limits

The existing rule inventory does **not** derive the main original
source-generation judgment. Its first missing semantic step can be isolated
at **one unannotated formal's one ordinary-value call occurrence**, before
closure capture, dynamic entry, or any pending Function comparison:

```text
resolved callee use of the shared formal A_f
  + the whole argument interface Comp(empty,A_x) at this source occurrence
  + annotation absence + original source scope
    -> an independently interpreted, active inferred-formal use constraint
```

The unresolved content is the **whole-tuple interpretation of that local
constraint**, including the relation between the provisional protected
Handler inference view and its ordinary-value refinement. It is not the
allocation of a registration identifier or the execution of an already
typed call. Section 5 states its exact rule inputs and output.

The approved singleton outcome is already fixed. This report does not ask
whether `apply f x = f x` should determine `NonHandlerFormal`, whether `step`
captures `f`, or whether a known callback literal follows B. It isolates the
missing definition that makes the selected outcome a constraint on the
complete shared relation. That definition is not supplied by a Boolean
role conclusion alone.

There are further, separately visible source-definition holes: the original
typed-position/contribution footprint and independent typed-context
admission. Supplying only the local formal refinement would not close the
whole main gate. Section 6 separates their exact inputs and outputs from
later preservation/proof obligations.

This is the second requested outcome: a missing semantic-clause interface,
with the largest currently justified source prefix and a bounded
non-derivation argument. It is **not** a proof that no completion can work,
that the example is untypable, or that new language behavior must be chosen.
In particular, no two complete source semantics satisfying all Authority
have been exhibited. The next clause may formalize the already intended
meaning; adopting an additional meaning requires its own explicit authority.
No new conditional callback theorem is counted as closing source generation.

## 3. The maximal justified source prefix

Use exactly the approved nonrecursive source component

```text
my apply f = { my step x = f x; step }
```

Let `sigma` retain its original binder tree and source identities. Its
resolved incidence is

```text
u_f -> d_f; u_x -> d_x; u_step -> d_step
c = Apply(u_f,u_x)
CaptureUseIncidence(lambda_step,d_f,u_f,position(u_f)).
```

Both ordinary parameters lack annotations. The following judgment is proof
notation for the established prefix, not a new language rule:

```text
S ; C ; sigma ; resolved-incidence ; annotation-incidence
  |-skel (I_0, N_0, O_0, L_0).
```

`I_0` contains symbolic source interfaces; `N_0` the ordinary core skeleton;
`O_0` unresolved complete-call/bind obligations; and `L_0` the source/lexical
map. Its premises contain no completed Function, semantic valuation, typed
capture map, receipt, active receiver, admission predicate or `Q` result.

**Construction.** Charter §21 gives `d_f:Value(A_f)` and
`d_x:Value(A_x)`, with fresh symbolic endpoints at the original scopes.
Core §6 Name reuses those same endpoints at `u_f,u_x`. Thus

```text
Result(I(u_x)) = Comp(empty,A_x)
I(c) = Computation(E_c,A_c)
O_c = (d_f via u_f, whole argument Comp(empty,A_x),
       complete-invocation endpoints E_c,A_c, occurrence c, scope sigma).
```

The empty effect in this equation belongs to this **ordinary name's**
`Result` interface. It does not assert that arbitrary arguments passed to an
actual Value-entry callable are pure; nor does it select that callable's
role or entry. Substitution making `A_x` latent preserves its source Value tag.

Lambda synthesis constructs the body/result skeleton
`Fun(Value(A_x),Comp(E_c,A_c))`. Sequential Bind puts its result at `d_step`;
the final name returns that same function value. The approved core shape is

```text
lambda(f,
  bind(step,
    result(lambda(x, call(result(name f),result(name x)))),
    result(name step)))
```

Core §6's administrative reify/Normalize pairs can be retained. No
unjustified boundary contraction or effect-row union is used. A symbolic
binding effect `E_b` retains its Bind obligation. The lambda body/result
skeleton is not identified with a completed four-port invocation descriptor.

Each structural rule uses the original source references and introduces
only fresh symbolic names. Induction gives one such skeleton up to one
uniform fresh-name renaming. There is no per-port semantic witness to
combine. The block constructs and returns the local closure without invoking
its latent call, and it retains the same outer lexical `f`.

This is the largest justified prefix in the inventoried ordinary rule
family. It is an obligation derivation, not a successful typing derivation.
In particular `O_0 != Phi_C`, `L_0` is not typed `Flow`, and neither is
`Omega_S`. General source relevance, recursion, polymorphism and other brace
forms are not added to this envelope.

## 4. Why further reuse of the existing rules cannot introduce the kernel

### 4.1 Restricted rule-inventory lemma

Let `H` consist of the parameter/Name/Result/Normalize/Lambda/Call/Bind
generators of core §6, the source-contract §2.1 relation operations, and its
§§3.2–3.5 conformance consequences. Read their typed and independently
interpreted premises literally; an emitted obligation is not a certificate
that the obligation holds. The initial environment is that of §3, with no
independently certified external original Function/profile/admission kernel
at `A_f`.

**Claim.** `H` contains no finite derivation that first supplies an
independently interpreted original inferred-formal certificate at `A_f`.
It consequently supplies no completed original profile/admitted fiber for
that formal from the skeleton alone.

**Last-rule proof.** Parameter generation introduces a source tag, endpoint
and entry skeleton, while retaining its nested typed-flow premises. Name
copies its input interface. Result/Normalize preserve supplied interfaces
and designated ports. Lambda introduces an inert constructor/body/result
root; it leaves the captured callee `A_f` unresolved. Bind reuses its result
root. Call emits Function/whole-argument obligations and retains the required
typed-contract inputs. None has a conclusion interpreting this original
unknown formal from its source occurrence.

Conjunction, union, joint renaming, scoped binding and constructor image
operate on already interpreted relations; the local primitive and typed
owner/view kernel interpretations remain premises. A Primitive instance
explicitly requires its independent whole-tuple relation. Recursive reference
refers to a registered relation; finite positive-recursion derivations do not
create a primitive interpretation. C-realization requires the §2
interpretation and decorated conformance before concluding correspondence.
Therefore every possible last rule either lacks the required conclusion or
needs the missing interpretation earlier. Induction on finite derivation
height proves the claim.

The lemma is a precise property of this named inventory, not a formal
independence theorem for every possible reading of Yulang. Known-context B
also starts with the missing formal/profile; transport and Receive likewise
consume the original typed input. Adding them does not provide a first
unknown-formal introduction. User-selected outcomes constrain a future rule,
but do not supply its unspecified interpretation by themselves.

### 4.2 The following are not the missing semantic choice

* **Registration timing.** Early/late allocation is administrative under one
  rule family and a whole renaming; the schedule result assumes that family.
* **Actual supplied callable role.** It remains the provider's role. The
  internal provisional seed is not an equation `actual_role = Handler`.
* **Certified capture survival.** Given matching typed maps, packet transport
  is already specified. The missing premise is their source derivation and
  original environment association, not permission to delete the evidence.
* **Complete execution after decoration.** Core §§3/9 already construct
  `J_call`: actual receipt/entry/rebind, body, declared consumer and return.
  The constructor cannot type its own source inputs retrospectively.

These eliminations leave the first source **interpretation** rule, rather
than another scheduling, runtime or storage design question.

## 5. The smallest local missing rule

Define `SingleUnannotatedFormalValueUse` using only the facts constructed in
§3: the exact component, its complete singleton callee-use inventory, shared
`A_f`, call/argument occurrence, annotation absence, ordinary argument tag,
and original scope. It contains neither inferred admission nor a solved type.

The local rule interface still needing a semantic definition is

```text
SingleUnannotatedFormalValueUse(S,C,sigma;d_f,u_f,c,u_x,A_f,A_x)
O_c = (A_f, Comp(empty,A_x), E_c,A_c; original source incidences)
-------------------------------------------------------------------
Gamma_shape ; S ; C ; sigma |-emit-at c Delta_formal(A_f,A_x,E_c,A_c)
```

`Delta_formal` must be a **semantically active local constraint**, not a
marker saying that registration will eventually be done. Its interpretation
must define, on one original whole tuple, a relation of the form

```text
U_c(xi; inferred_seed_view, inferred_refined_view,
         whole_argument_view, complete_invocation_view),  xi=(nu,K,D).
```

This notation names the needed interpretation; it does not supply or adopt
it. The two inferred views share `A_f` and its dependencies. They are not two
independently solved endpoints and are distinct from the actual provider's
role/entry coordinates. The clause must say **which correlated tuples the
source use permits**, not just return a role tag or a printed arrow.

Its required singleton specialization is already authoritative:

1. the internal initial view has the specified fully protected Handler
   treatment because the annotation is absent;
2. this occurrence's ordinary-value evidence determines `NonHandlerFormal`
   on that same inferred formal/use relationship;
3. this neither rewrites an actual callable's entry/role nor erases unrelated
   source constraints and profile dependencies.

What is not fixed is the predicate connecting those stages and complete
ports/evidence. The rule may add a source-entailed constraint to a provisional
presentation or give a justified seed-to-final interpretation. It need not
preserve every provisional candidate. It must preserve the independently
defined original source solutions. If it instead restricts an already
completed source relation `Phi` to `N = NonHandlerFormal`, preservation is
equivalent to `Phi subseteq N`; a Value tag alone does not prove that premise.

For a larger component the rule must additionally define eligible use
incidences and their aggregation. The singleton decision is not a generic
Value-entry-implies-Pure rule. “Retain alternatives jointly” is a preservation
condition, not a third choice beside existential/universal triggering.
No mixed-use outcome or new acceptance/rejection rule is selected here.

**Minimality meant here.** This is the first absent local rule head after
all the supplied ordinary generators have run. It already occurs with one
formal and one call, without annotations, recursive relevance, method
selection or a captured call at runtime. Removing the call removes this
producer obligation; moving to later capture/admission does not discharge it.
This is dependency-order minimality within `H`, not a claimed cardinal-minimum
axiomatization of all Yulang semantics.

## 6. Residual source-definition clauses, without hiding them in U_c

The first clause is not sufficient for every output in the user's arrow.
The following table makes the remaining definition boundary explicit.

| Clause needing a definition | Inputs available before the clause | Exact missing output | What existing rules already determine afterward |
| --- | --- | --- | --- |
| **Local formal-use interpretation `U_c`** | Shared symbolic formal, complete source-use incidence, argument source interface, annotation presence/absence and scope | The active whole-tuple inferred-formal constraint, including its seed/refinement meaning | Relation composition can retain it jointly; known-context B can consume a completed compatible formal. |
| **Original typed footprint / incidence** | Source contract occurrence and the inferred contract's own structured relationship, original scope, declared annotations and lexical/use map | A derivation relating original source positions/contributions to typed signature positions, paths and static owner/receiver/receipt schemas; a complete slot/profile inventory | Position plus its contract gives stable slot identity; existing profile laws and typed packet images preserve the derived incidence. |
| **Independent typed-hole/environment admission** | Independently interpreted original interfaces/footprints, fixed original fiber, a separately typed finite caller/provider context and its whole argument | The initial/context-reentry admission judgment and exhaustive descriptor/environment clauses for those contexts | The existing response/raw-resumption/future-use inventory constrains complete histories. Its completeness still requires proof. |

These are three distinct missing kinds of source-definition content, not a
proof that three independent language decisions are necessary. They may be
defined by one mutually supported rule family. Merging their signatures into
one `OriginalRegistration` assumption does not remove any of the content.

The resulting rules still need a finite symbolic presentation of the complete
invocation and higher-order/store challenge relations. The existing operational
constructor equation alone supplies no such presentation (typed-core §9's final
paragraph; the clarified [call-image boundary](2026-10-06-source-call-image-producer-boundary.md)).
Likewise, pointwise preservation for compatible dynamic instances does not
prove that every independently admitted source entry history has an instance.
The [entry-coverage record](2026-10-06-source-entry-instance-coverage.md) isolates
the additional obligation
`forall h in H_S. exists rho in R_C, delta in Dyn(rho). Corresponds_S(h,rho,delta)`.
Admission of `H_S` cannot be defined by the existence being proved. This asks
for representatives of admitted histories, not realization of every abstract
row. It preserves the existing source-contract §3.5 theorem's conditional scope.

For the exact unannotated case, the footprint can be stated particularly
narrowly as

```text
Foot_S(d_f,c,p;xi)
```

where `p` is an original **typed effect-observation position/contribution**
of the completed inferred contract, in the receiving profile governed by
this source occurrence. Once this is independently derived, annotation
absence requires protection on that footprint and supplies no concrete
annotation grant. That is static profile content, not current receiver
activity. The definition must explain the domain of `p`; it cannot use all
equal families, all row-support members, every latent descendant, an arbitrary
empty profile, or the label `c` as a substitute for the source-to-typed map.
Present annotations also need their exact original contribution association;
the approved `[io]` permission is neither actual removal nor a grant for
unrelated effects.

The admission clause must retain the approved all-context domain, including
divergence and finite future/resumption developments. A successful return,
the current program's reachable calls, or compatibility at the four printed
ports is insufficient. Definition of a production-only member remains
governed by Option A/Option 2, not by a universal source-constructor-witness
requirement.

`Phi_C` and `Omega_S` may ultimately be presented by all jointly satisfying
assignments of independently generated/interpreted constraints. This is
legitimate **after** the predicate, coordinate domain and original scope have
been defined. Two unsuccessful shortcuts must be distinguished:

* Taking all decorations satisfying only the known preservation requirements
  gives at most an upper envelope; equality with original source solutions
  has not been proved.
* Defining compatibility as “has the completed source view/profile and is
  admitted” invokes the very judgments being constructed and is circular.

No choice of one satisfying `xi`, including a convenient Q-successful one,
is a replacement for the relation over all its admissible fibers.

## 7. Joint preservation and the genuinely later obligations

The first original relation must retain the following together:

* original binder tree, rigid/scoped coordinates, formal/use/call/annotation
  identities, provider roots and shared descriptor references;
* original `nu`, shared predicate identities `K`, all dependent incidences
  `D`, typed paths, profile/slot identities, and source origin/lineage;
* distinct internal inference stages, actual provider role/entry, static
  receiver schemas and dynamic activation/receipt identities;
* whole argument, designated Force/rebind, body, result consumer, return,
  original request/resumption witness and continued current state.

The packet is not a Cartesian product of port projections. Typed transport
acts on the packet `(v,t,chi,K,D,L)`; it retains the shared `K` ledger under
the same `nu` while transporting matching `D`/profile incidences. Generalizing
one local function must preserve its captured external root. Fresh use moves
all locally quantified dependent coordinates in one coherent renaming while
fixing the appropriate environment/rigid coordinates. The Oracle algorithm
for doing so is not required.

After static generation, an actual entry and admitted instance are still
needed for a receipt. The capture lane A must establish the original
certificate's environment association and the matching typed rebind/capture/
read maps. Their packet image is then governed by existing transport laws.
Neither a lexical capture nor a static slot revives an expired activation.

Before any production adoption, the following proofs remain necessary:

1. **Local interpretation and source coverage.** Each emitted constructor and
   alternative has independent descriptor typing and source correspondence;
   exhaustive source admission covers all required finite histories without
   Q-derived restrictions. Finite probes do not prove this coverage.
2. **Original solution preservation.** Formation, generalization, freshening,
   hiding and any early propagation preserve the original joint solution
   relation and scope. A scheduling optimization satisfies normative B's
   acceptance, principal-solution, method/adapter and residual/evidence
   equivalence, rather than equating independently generated endpoints.
3. **Production containment.** Exhaustive actual/checked membership and
   admission include Option 2's production-only members. At each original
   fiber, prove `D_C(xi) subseteq D_A(xi)` and
   `forall h in D_C(xi). P_A(h;xi) subseteq P_C(h;xi)`.
4. **Principality at the actual export.** Legal common descriptor formation
   requires `forall xi. forall s in S_xi. exists a. Q_xi(s,a)` on the
   stated envelope. All-view factorization requires
   `forall independently valid V. exists m_V`, with every required direct
   comparison at the designated exported root and witnesses at original
   scopes. The existing `V_alloc` sufficient cases do not establish all-view
   coverage. A shared witness may not be reselected per port or challenge.

These are not extra source semantics selected by this note. Their separation
prevents an original source-base result from being promoted to complete
production containment, principal inference or implementation authority.

### 8.1 A persistent formal-keyed annotation-contract path

The historical chain is more specific than ephemeral annotation frame weights.
In frozen `crates/infer/src/lowering/expr/lambda.rs:1357–1434`,
`lambda_annotation_argument_effect_contract` accepts a Function annotation and
traverses it to collect `ArgEffectContractMarker` values. Each marker records
an effect-family path, Function nesting depth and `PreserveMatchingPath`.
Equal markers are deduplicated. The same file's `896–908` stores the result
in `poly.arg_effect_contracts` under the resolved lambda formal `DefId`.

This is a concrete **annotation-to-formal contract producer**, not merely
printing or the application solver. However, those family/depth markers do
not identify an original annotation occurrence or a full typed path: parameter
and result branches can have the same depth, and equal markers are merged.
They contain no current complete `beta`/`Slots(beta)`, typed owner/receiver
schema, independent admission or original joint `(nu,K,D)` certificate.

While this submission was under review, upstream `2d378d0c` independently
added the [argument-effect contract channel](2026-10-06-frozen-oracle-argument-effect-contract-channel.md).
Its overlapping producer/consumer characterization is retained; no unique
discovery is claimed. The companion additionally distinguishes the separate

retains a source contract.

The consumer and exact freshening distinction are recorded in the companion
[Oracle crosswalk addendum](2026-10-06-main-source-generation-oracle-crosswalk.md).
In particular a known-definition argument-receipt path must not be silently
identified with contract lookup at the inner `f x` call of an unknown formal.
That distinction is essential to deciding which source producer remains
missing.
