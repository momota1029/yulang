## Candidate constructor: separate reservation, guard formation and anchor

This is a proposed proof-construction recipe, not an adopted inference rule
or a new interpretation of independently fixed guards. No production data
representation is selected.

1. **Reserve source references.** From Hres, a source-owned introduction
   action would reserve r, q, n and ell, together with a provenance map back
   to s/sx/sn and the definition's Lambda occurrence. The component C_src is
   introduced at definition registration; its singleton incidence must be
   justified by this actual nonrecursive definition. Freshness alone only
   establishes distinct references. HIR DefId/ParameterId or SCC count cannot
   be relabelled as these semantic records.
2. **Form original scopes and port declarations.** Extend the caller's
   existing scope/dependency evidence at its authorized definition insertion
   point. Construct the pre-Parameter source scope and registered source-slot,
   Value-entry and designated consumer/receipt/receiver/formal port schemas.
   These are candidate pre-formation reservations/declarations, not an earlier
   emission of Parameter's selected Intrinsic output. Establishing the exact
   partition between this registration data and Parameter-owned fields is
   part of the missing local schema. Preserve the full caller dependency
   closure. Later receipt, rebind, body
   and invocation-return scopes are dependent source-event schemas, not actual
   executed events or fresh unconstrained effect/profile variables.
3. **Derive each original registration guard.** At each scope above, use the
   actual local formation/license/registry/scope/incidence rule with its full
   operands and predecessor proof trees. Retain every original guard under
   its original dependent binder. A finite catalogue must list each atom;
   `RegistrationValid`, `IF0Valid`, `JointWF(extended)` or successful Q is not
   a new successful leaf. Preserve caller-owned fields by reference, without
   assuming they prove guards mentioning new r/q/ports.
4. **Emit the pre-formation registration output.** Only after steps 1–3
   would the owner emit r/C_src/T/port incidence and fixed raw registration
   fields IF0, together with their guard proofs. IF0 contains no completed
   Parameter description, raw closure, challenge witness or installed own-root
   membership. Its independent dependency inventory must establish this fact;
   it cannot be obtained by deleting fields from a complete IF.
5. **Consume the selected later constructors.** Parameter uses that output
   to form `Desc(C_src,q,ValueEndpoint,sigma_a,Delta_a)` and the full inlet
   I_q[a;Delta]. Lambda subsequently constructs U_g using the same original
   registration and IF0, and an Internal description edge. Only that actual
   construction can yield the inert closure anchor. A returned-installation
   anchor additionally needs its real Executed/OneShot/world evidence.

Thus the proposed dependency order is

```text
E0,h0 + resolved source
  -> source reservation + original scope/port guard derivations
  -> pre-formation registration/IF0
  -> Parameter Desc and inlet
  -> actual Lambda U_g
  -> actual inert or returned-installation anchor
  -> source publication.
```

This order resolves a structural circularity in the **recipe**: it does not
take U_g or its anchor as the evidence that permits U_g's own registration.
It does not establish any arrow lacking a local law. A pre-formation source
reference is not yet the actual closure anchor required by SG §3.

## Small logical discriminator for the missing implication

Claim class: established elementary **non-entailment in an abstract extension
test**, not a counterexample to selected Yulang meaning, source acceptance or
any reviewed semantic theorem.

Hold one old context E0, h0 and resolved source fixed. Reserve one new semantic
reference r disjoint from E0. Retain one new guard atom g(r,E0), representing
one as-yet unspecified registration license/incidence obligation. Consider two
extensions that agree on all supplied premises and every old-context field:

| Interpretation of the unprovided new-guard law | JointWF(E0) | r fresh | g(r,E0) |
| --- | --- | --- | --- |
| M+ | true | true | true |
| M- | true | true | false |

Because g's introduction/elimination law is absent from these premises, both
extensions satisfy exactly this reduced assumption set. Hence
`JointWF(E0) and Fresh(r,E0)` does not entail g(r,E0). One old context, one new
reference and one guard suffice; no caller values, challenges or execution
are needed. This is a reduced logical witness, not a claim that an actual
Yulang guard may arbitrarily vary. Once the genuine local guard law is
specified, M- may be disallowed; that law is precisely the missing dependency.

The discriminator does not prove the source rules by assuming transitions.
It uses only propositional independence of an unprovided atom. It does not
justify accepting either extension as a lawful source registration, and it
does not replace the full guard family by this one-atom abstraction.
