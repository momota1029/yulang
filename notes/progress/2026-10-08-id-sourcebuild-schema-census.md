## 1. Objective, method and premises

Make the storage obligation of the proposed exact `my id x=x` SourceBuild
producer concrete by a source-document census. Count explicitly enumerated
families and original incidences; do not invent a Rust layout or expand runtime
histories. The selected [Generalize definition](../design/2026-10-08-source-generalize-definition.md)
§§2–4 and [source proof](../theory/2026-10-08-source-generalize-definition-and-proof.md)
§§3.3–5.2 govern scopes, dependency traversal and allocation. The
[id instance](../theory/2026-10-08-id-sourcebuild-instance-candidate.md)
§§1–3 supplies this exact source case under H-source. The
[owner draft](../design/2026-10-08-id-sourcebuild-owner-design.md)
§§3.1–4.1 is a proposed representation, not authority or an authentic supplier.

H-source is genuine Parameter/Lambda/Name/Result/generic-inlet formation and
L1–L5 at their original scopes, one valid immutable initial world, and no
fixed free dependency on the ordinary formal description. There is no import,
capture, annotation, conversion, recursion or installed payload dictionary.
H-bridge remains the independent identification of a future compiler producer
with those source constructors. Neither premise follows from a retained ID,
a solver row or this count. Accepted source meanings are used without change.

The result is a **bounded structural characterization** and a **conditional
one-template derivation**, not an exact storage bound, reviewed theorem,
production correspondence, or executable source-semantics experiment.

## 3. Binder and scope census

The available definitions fix categories and ordering, but not total binder
arity. The id instance §2.2 expressly leaves authentic logical binder counts
to their owning source rules. Source proof §3.3 and §5.2 distinguish these
categories; none can be merged merely because both use existential syntax.

| Region/category | Required retention | Count justified for the exact source |
| --- | --- | --- |
| Base initial-world/registration/initializer | Actual fixed anchors and original `Shared` telescope once | One base region; total original binders/operands unspecified. Shared need not be fabricated (id instance §2.1). |
| Ordinary type scope `sigma_a` | `Desc(C_id,q,ValueEndpoint,sigma_a,Delta_a)` before challenge | Exactly one fresh ordinary Desc; complete Delta arity unspecified. |
| Description logic `ViewLogic` | Below its Desc dependencies, before its challenges; one region per incoming frame | Category and order fixed; number of witnesses not given. |
| Independent challenge `h` | Complete prechosen inlet presentation and actual carrier/current-event inputs | One challenge schema role; not one retained actual runtime challenge. |
| Actual event `Event` / `EventField` | Receipt, Force, response/raw handle, Return/rebind, current world and suffix in their original event telescopes | Finite schema categories; no exact event-node or field count. An actual invocation need not occur at publication. |
| Description-owned `EventProof` | Under same actual event; key also includes incoming frame and original proof region | Category fixed; number of proof witnesses not given. Runtime EventFields are shared across descriptions of one event. |
| Local `Check` / authorized `Specialize` | Actual finite grammar and original proof scope, only if introduced by its source rule | No arbitrary additional binder is licensed; number/necessity not enumerated for this instance. |

Request-opening rigid telescopes, inference existentials and operational
identities are never ordinary templates (source proof §§3.3,5.1). Their
introduction counts in independently supplied challenge/response/future laws
are outside the four-origin source count. Registered development references
support arbitrary finite raw-resumption/future histories; histories cannot
be multiplied into publication-time storage counts (§5.2; id phases §4.2).

## 4. Typed edges and storage ownership

Source proof §3.3 supplies typed record families and full dependent-field
edges. For id, these are the essential edge categories; the table counts
categories, not edge occurrences.

| Category | Meaning / walk mode | Static schema versus bound data |
| --- | --- | --- |
| `Description(C_id,q)` | Entire I_a and incident constraints; retain the complete component relation | Edge rule and target slot static; C/q and original Delta incidences resolved from the source owner. |
| `Internal(C_id,r)` | Complete own-component description in retain mode even if raw provider is fixed | Edge rule static; component/root origins bound per source instance. |
| `Intrinsic` dependent-field edges | Slot, role/entry, ports, receipt/receiver/formal and IF0 incidences fixed | Field names/constructor static; actual registration/role/port/scope operands owned by authentic formation. |
| Fixed anchor/free dependency edges | Actual world/allocation/lifetime/captures, and actual OneShot fields if installed | Traversal rule static; complete immutable formation payload per owner. Returned installation must preserve b, arm, Executed/OneShot and same-world tuple. |
| Binder dependency/parent edges | Original Delta, Shared/ViewLogic scopes, event parents, EventField/EventProof proof regions | Category/order static; authentic telescopes and runtime event operands are not replaceable by tags. |
| Same-value/port-action edges | Rebind → Name → Result → invocation Return, same decorated value/provider and current-world action | Protocol/equality action static; actual value/provider/world/event fields bound at their original future scopes. |
| Registered development references | Carrier continuation and hereditary future laws, no eager unfolding | Reference/action schema static; actual independent carrier/handle/provider certificates remain supplied dependencies. |
| FinalRoot/publication incidence | Authentic p_id selects complete `(C_id,R_id)` and links to separate anchor | Constructor shape static; publication/event/root/component/anchor owner identities bound per source instance. |

`Established` differs from `Internal`; actual installed external contract
fields follow fix traversal with every free coordinate. For this source
there is no such source-introduced external contract. Returned installation
can still have OneShot data, while its separate own description is Internal
(id instance §2.1; source proof §§3.3,5.1). Omitting a genuine fixed free
dependency on a invalidates H-source and changes the one-template result.

The draft §4.1 lists seven logical schema origin slots: root, q, n, ell, C,
p_id and anchor-owner output. Its proposed `IdSourceOrigins` has seven
physical fields (parameter, name, lambda, component, publication_owner,
final_root, publication); root is recovered from the parameter and the
publication owner links the anchor. These are two different sevens. The
static `IdRuleSchema` and borrowed view avoid copying a second per-module
graph only if they actually encode the complete source schema. The proposed
outer publication record and separate anchor record give two displayed owner
roles, not an allocation bound: their payloads and transitive dependencies
remain placeholders. Neither 88/96-byte origin arithmetic nor these counts
bound owner payload, Arc control blocks, capacity or lifetime extension.

## 5. Derivation and precise blocker for an exact storage census

Under H-source, retain starts at whole `N_id,R_id,T_id`; fix starts at
U_g, Intrinsic/IF0 and genuine base anchors. The generic raw inlet binds its
description index and has no free a. No other genuine fixed contract depends
freely on a. Description/Internal retain all clauses; therefore d_a is reached
and unmarked by fix, giving exactly one template at sigma_a. This uses the
already selected source walk (§5.1), not a new source-law proof.

The source proof §4 guarantees a finite intensional rule schema **when** local
catalogues are finitely presented. It expressly does not prove an effective
finite representation for every catalogue or an inference complexity bound.
The id instance does not enumerate Delta/IF0 telescopes or the numbers of
ViewLogic/EventProof/Shared witnesses. The owner draft says IdRuleSchema is
the complete §3.1 graph, but supplies no concrete node/edge tables or full
owner types. Consequently no exact node, clause-occurrence, binder, scope,
edge, allocation or retained-byte total follows from these documents.

The minimal missing definition is a frozen **IdRuleSchema storage manifest**:
each stored node/binder/port/edge with its category, owning source rule,
origin-slot substitutions, dependent telescope arity, and registered-reference
versus inline-payload boundary; plus complete immutable publication/anchor
record field types and transitive ownership/capacity manifest. It must state
which full original contracts are references and which storage is newly
allocated or retained longer. For resource closure, also include peak live
snapshots across construction, validation, F5 coexistence and terminal
transfer; temporary worklists/maps and clone/allocation counts; and bounded
teardown depth/work under transitive ownership. This is a representation
proposal requiring its own H-bridge/resource review; the census cannot select
or implement it.
Do not obtain an exact number by counting Markdown bullets or treating Delta,
IF0, J, world or local proof grammar as a one-word constant-size object.

## 6. Independence, failure conditions and coverage

This derivation shares the selected source constructors and H-source with
the instance. It is not independent review of those laws and uses no runtime
oracle. Enumerated source tables ground the inventory independently of a
toy transition checker; a checker given their transitions would only check
consistency of that input. No experiment, mutation, seed or search range ran.

A later manifest is falsified if it drops any checked-inlet family/guard,
places a below h, replaces actual publication or formation by a schema tag,
creates a formal before completed Force Return, conflates body/outward ports,
replays receipt on raw resume, duplicates Shared or runtime EventField per
frame, omits a real free fixed dependency, or ignores transitive owner storage.
These are prospective failure conditions, not executed witnesses. No second
or third equivalent probe is warranted while the concrete manifest is absent.

Coverage is only the exact source, selected governing sections and named
candidate representation. No production files were audited anew or modified;
no compiler/build/test/benchmark or Git mutation ran. No complete source
schema or resource theorem is claimed. One lightweight process at a time;
zero heavyweight processes. Numerical CPU/RSS and total wall-time were not
measured. The parent set a target under two minutes and a stop after this
scoped derivation/check pass; no search or compute expansion occurred.

Recommended next action: produce one frozen concrete IdRuleSchema and
publication/anchor storage manifest, preserving the source rules and marking
all unresolved authentic suppliers, then perform a focused resource review.
