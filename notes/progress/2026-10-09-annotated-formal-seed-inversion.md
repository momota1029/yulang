## Objective and bounded result

For exactly `apply(f: _ -> [io] _, x) = f x`, invert the selected
annotation-absence seed constructor and enumerate the other constructor routes
listed in the governing directional derivation. The absence constructor cannot
apply to this original formal. Its listed conservation extensions cannot repair
that failed premise by transporting the same annotated origin. This excludes
one seed lineage; it does **not** prove that no seed or protection applies to
the annotated formal.

The nontrivial reduction is that extending this particular failed lineage by
Name lookup, role refinement, generalized transport, multiple Calls or certified
saturation cannot discharge A6. An authentic independent seed origin, or an
exhaustive owning rule that proves no seed applies, is still required.

## Explicit hypotheses and inversion

H1. The source tree is the exact displayed annotated definition, and name
resolution maps `n` to that original binder `b`.

H2. Annotation presence refers to the actual written binder annotation and is
retained with original identity. The lack of an annotation on the later Name
does not change the binder's presence fact. This is the source identity policy
in call views lines 98–109 and the annotation constructor lines 71–75.

H3. The constructor being inverted is exactly the selected §3.1 arrow of the
joint source judgment. Its annotation-absence premise is necessary for that
arrow; the arrow is not asserted to be the complete source seed calculus.

**Bounded exclusion.** There is no application of that annotation-absence arrow
with conclusion `Seed(k,b,v_b,R_b,sigma)` for this actual original binder.

**Derivation.** Assume such an application. Inverting the displayed arrow yields
actual annotation absence at its original binder `b` (joint source judgment
lines 146–151). H1 supplies the actual annotation `a: _ -> [io] _`; H2 keeps
that annotation present at `b`. Presence and absence of the same actual binder
annotation contradict each other. Therefore that application cannot occur.
This uses only the absence premise; it does not need a solved type, Call
satisfiability, a provider endpoint, or an annotation-normalization rule. QED.

This is an inversion of a selected source constructor, rather than the
unsupported converse “annotated implies unprotected.” Annotation holes do not
erase the annotation. Permission to remove `io` is not a presence test for a
seed, and success of the annotation check supplies no missing absence premise.

## Conditional conservation of the exclusion

H4. Consider only finite derivations extending the selected absence-seed route
by the source-conservation steps listed below. All transport maps preserve the
original binder/annotation correspondence; injective alpha freshening changes
eligible owned coordinates while retaining their original provenance. No
unrelated seed or `ProtectedVarAt` certificate is introduced as an input leaf.

**Conditional lineage lemma.** Under H1–H4, these derivations cannot produce an
absence-origin `ProtectedVarAt(k,v,sigma,u_c)` for the original annotated formal,
nor its certified alpha image with that same original annotated provenance.

**Proof by derivation height.** Its only allowed fresh seed leaf would be the
§3.1 application excluded above. The Name/Call applicability composition needs
that existing seed and same-root correspondence (lines 185–204). S2 retains
an existing seed/certificate (lines 266–278). Alpha transport maps a prior
certificate and reflects it on its image, retaining origin (lines 335–352).
Multiple-use composition reuses an already registered seed (lines 231–245).
S3 consumes fixed certified seed-at-exposure facts and produces Dir-Protect
heads, rather than new applicability facts (lines 364–386). Each possible
extension therefore requires a shorter authentic absence-origin derivation;
induction reaches the impossible leaf. QED.

H4 defines a bounded derivation family; it is **not** an established assertion
that the complete language has no other seed constructor or inherited input.
Dropping H4 by supplying an independently justified protection origin exits
this lemma's scope. An assumption of `ProtectedVarAt` would not prove that
origin from source.

## Smallest site, independence, failure conditions and omissions

The displayed one-formal/one-annotation/one-Call site is the exact witness to
failure of applying the absence constructor, not a counterexample to accepted
semantics. Deleting the annotation changes the failed premise; deleting the
Call removes the requested exposure. No compiler acceptance or rejection is
claimed. The ordinary value `x` supplies no replacement protection origin.

There is no executable oracle. The proof shares the selected constructor's
necessary absence premise and the listed transport's origin-conservation
premises; it does not independently establish their complete source adequacy.
No seeds/ranges, numeric enumeration, mutants or experiments were executed.
The named shortcut mutations are erasing binder annotation presence at Name
lookup, treating surface holes as absence, changing seed identity through
alpha transport, or making permission/check success create `ProtectedVarAt`.
They would invalidate H2/H4 or introduce an unsupported constructor.

Failure conditions: a different actual original binder; an independently
justified seed input outside the bounded family; a selected constructor that
does not require absence; or transport that changes original provenance.
Any such evidence requires delta adjudication, not reinterpreting the current
user-approved permission. The selected definitions are not a closed complete
rule calculus, so a global absence result cannot be recovered by more finite
checks of these same assumptions.

Unverified: complete annotation normalization/current endpoint and Name export,
annotation classification A5, independent annotated seed origin A6 or an
exhaustive no-seed judgment, contribution/typed-scope permission correspondence,
actual removal, complete recursive formation, solver behavior, source adequacy,
principality and production conformance.

Recommended next action: the primary should obtain the owning annotated-formal
source judgment's exhaustive seed-origin cases and actual current/export
endpoints for this exact definition, then review whether it supplies A6 or a
bounded no-seed judgment. Repeating a checker with supplied applicability would
leave this premise untouched.
