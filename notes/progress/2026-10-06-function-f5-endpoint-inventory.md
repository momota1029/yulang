## 4. Smallest admitted derivation and discriminating seam

Use the complete unannotated source binding:

```yulang
my id x = x
```

Hypotheses for this derivation: the ordinary parser supplies the recovery-free canonical identifier parameter header; lowering's namespace/ownership checks succeed; allocation and identity arithmetic succeed; and the body resolves to this parameter. This is a code-path derivation, not a newly executed parser/solver experiment. The existing pinned test `f5d_identity_lambda_admits_exact_effect_and_function_facts` (`lib.rs:20282`) is supporting source text, not a test result from this lane.

Let `r` be the definition value row, `p` the parameter value row, `e_b` the body effect row, and `e_l` the lambda evaluation effect row. `emit_lambda` emits exactly four collected effect pairs and one deferred Function fact:

```text
EffectBottom+ <: e_b       e_b <: EmptyEffect-
EffectBottom+ <: e_l       e_l <: EmptyEffect-
Function(p-, EmptyEffect-, e_b+, p+) <: r
```

The shared live ordinal `p` in both ports is derived from the parameter-body case; it is not two independent freshly chosen endpoints. The Function constructor contributes one positive structural term. Under the F5 generalizer this is the familiar pure identity scheme with one shared quantified value coordinate. The store receipt derives from the last ordered pair and its lambda slot/cause. None of the five pair inputs includes `J_arg`, a whole incoming computation, a receipt from actual invocation, or any punctured context.

This witness is minimal within the admitted ordinary Function recipe in the useful sense that it has one plain binder, one name leaf and no captured definition, call, annotation or operation. Removing the binder removes Function introduction; removing its complete body removes the complete Function recipe. It is not a minimized language counterexample and does not separate accepted production programs under two semantic choices.

For a discriminating next bridge, independently type a context that calls the callable hole on an integer carrier, then a compatible computation carrier with a finite request prefix. Under the approved broad context decision those challenges must be judged by independent admission, even when the original identity program never calls `id`. The typed-core §9 rule explicitly says `P=Value(A)` does not imply that `J_arg` is pure. The current five facts cannot be cited as proof that either challenge is admitted or rejected. Adding `my use = id 1` to this source reaches an associated application that `lower_simple_chain` rejects as non-leaf; it does not yield an actual caller endpoint today. This last conclusion is derived from the non-leaf guard, not an execution result.

Thus the exact seam is Function introduction/name transport versus complete invocation/admission, rather than a choice between narrower meanings of an already approved inlet domain.
