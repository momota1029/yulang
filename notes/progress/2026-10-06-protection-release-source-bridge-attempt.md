## Strongest derivation, with explicit hypotheses

Fix the following hypotheses under one joint `ν,K,D`:

1. A known callback contract supplies original static slot `β` and profile;
   activation supplies `b=(receiver,slot,Γ,endpoints)` at typed position `p`.
2. Independently supplied executable source decorations expose fresh event
   `q` in view `v` at position `p0`. Its current emission context contains
   the corresponding view occurrence.
3. A matching typed-flow derivation carries `χ_b(p,b)` to `p0`; invocation
   `u` receives that same view; candidate `h` is owned by `u`; `h`, `u` and
   `b.receiver` are active at the actual query configuration `C`.

Callback introduction supplies the original static contract before the body;
typed-boundary introduction supplies the dynamic profile once activated.
The decorated-context theorem gives the event-specific `Observe` witness
from hypothesis 2. Typed-flow transport and matching receipt in hypothesis 3
then give `Path(q,u,b,p)` and `Inc_C(q,h,b,p)`. Thus the displayed protection
query is true. A receiver-local explicit contract admitting the operation
also gives `Grant`; neither clause needs an exact-origin filter.

These are conditional consequences of supplied source profiles/decorations,
not a theorem that raw annotations construct them. More importantly, none
has conclusion `AttributedTo(q,'e)`. The static component term `'e`, the
event's source origin and the boundary's typed effect position are distinct
objects. Their preservation does not create a judgment relating them.

The compatibility same-fiber subsection expressly assumes a source map from
an abstract component to its complete port projection. Section 9 then
selects a mixed-row fragment while leaving annotation-to-port occurrence
rules open. Therefore sharing the term `'e` across polarities is insufficient
to discharge this first missing premise. The existing source tags and full
`Rel_C` may support the required map; this audit does not show they lose it.

For release, two additional independently grounded hypotheses are needed:

4. The source annotation/component derivation relates this original marked
   occurrence `(s,'e?)` to this qualifying contribution of `q`, retaining
   its attribution and exact existing protective witness or witnesses.
5. A source computation/control derivation identifies an actual outward
   crossing through `s` for that same contribution, and entails the end of
   the associated protection at subsequent candidate queries, including its
   continuation/result scope. Independent protections remain intact.

Hypotheses 4 and 5 are **missing judgments**, not candidate definitions of
the language. Attribution cannot be replaced by family equality, origin
identity or a typed route. The marked occurrence cannot supply its own
emission premise. Once these judgments construct the existing filter note's
`Release_s(q,w,C)`, that note yields a protection-only query change with raw
incidence and grants retained. This is the exact conditional consequence;
it selects no update mechanism, pop count or carrier.

## What the existing transitions actually establish

| Existing source/control operation | Established consequence | Missing release conclusion |
|---|---|---|
| Callback literal introduction / completed comparison | Original boundary precedes body generation; independently generated full interface is checked | No component-to-event attribution or marked-slot crossing clause |
| Request creation in decorated `View` | Fresh event identity and observations of executing enclosing positions before search | No assignment of that event to an abstract row occurrence; no marker update |
| Forwarding | Original event and recorded observations persist; source-prescribed handler re-entry is saved | No judgment that forwarding traverses this particular marked output occurrence or ends its protection |
| Capture and raw resume | Only crossed observer scopes are saved; re-entry makes fresh execution occurrences under current context | No identification of which marked protection has already ended for the resumed contribution |
| Normal view completion | Exactly that executing observer occurrence is removed | This is view control completion, not a rule updating retained event protection or latent-result profiles |
| Typed result transport and later force | Matching result positions retain actual-value and callee-result evidence; the later event receives its own observation | No source clause deciding whether the earlier marker applies to that later contribution |
| Receiver/handler expiry | Current incidence, protection and grant are filtered by exact inactive identities | No release rule while the same receiver and candidate remain active |

This table audits the displayed transition conclusions. It does not choose
before-search, forwarding, delimiter-exit or result-return as the meaning of
the crossing. Several enclosing views can observe a single emission, and
resumption can reconstruct only a crossed subset; existing control evidence
must be joined to the original annotation occurrence before it can establish
a specific marked crossing. Removing an executing observer frame does not
erase the event's recorded observation witnesses.

The production correspondence is weaker still at the targeted entrypoints:
`yu-hir/src/lib.rs` retains generic associated syntax and the annotation
association barrier; `yu-hir/src/module.rs`'s `HirParameter` has only identity,
name and range, and its `ResolvedExpr` variants are Lambda, Integer, Name and
Error. Those displayed forms supply no complete effect component/profile or
marked crossing derivation. This is an audit of these exact definitions,
not a repository-wide assertion that no future or test-only representation
exists. The syntax observation is not needed for the semantic conclusion.

## Eligibility, selection and failure conditions

Given independently proved release, an active covering handler can become
query-eligible when no unreleased protective witness remains. A receiver-local
explicit grant can already make it eligible despite protection. Release adds
no grant and preserves that raw grant calculation. Actual selection still
uses ordinary handler order and source matching/guards; the selected arm's
compatibility and complete image remain separate obligations. Eligibility
does not imply consumption or absence from outward row support.

The conditional derivation fails if the component-to-contribution map is
absent, the marked crossing is absent, the protective witness is not the
one associated with that occurrence, typed intermediate ports or receipt do
not match, the common assignment is incompatible, or relevant exact
activations have expired. A concrete grant can mask sticky protection, so
successful capture at a concrete input contract is not evidence of release.
Even correct local release does not prove the complete-program frame after
ordinary handling changes the downstream computation.

No minimized source counterexample, independent Oracle experiment, seeds,
ranges, enumeration or executable mutation campaign is claimed. The method
shares the selected decisions and the existing source packages' supplied
profile/decoration hypotheses. It independently checks which conclusions
their written rules provide; it does not independently validate those rules
against raw programs. No checker assuming a crossing rule was run.
