Here `j` retains the original binder tree, `xi=(nu,K,D)`, source occurrences,
capture/local-use edges, Application/check origins, Return/reify origins and
complete dependent callee/argument/receiver/result/future incidence. The event

Zero local execution does not imply empty global history. The dependent
result/rebind/receiver suffix is suspended; no actual callee Return, argument
Delay, checked challenge, receipt, receiver or result binding is available.

The complete I0 telescope is not formed by naming a Boolean `Valid0`.
[I0 derivation](../theory/2026-10-08-callinitial-i0-telescope-derivation.md),
Maximum sourced input and Named unavailable owners, distinguishes conditional
environment projection W from independent world/admission introduction.
K0/P0 must expose all original output decorations and evidence. Candidate
signature §6 separately requires, for each independently legal joint action g:

```text
K0(g_F(F),g_I0(a)) = g_O(K0(F,a))
P0(g_F(F),g_I0(a)) = g_pi(P0(F,a))
```

with identity/composition or the appropriate certified relational transport,
dependent equality transport, original scopes, rigid binders, full K,D and
one correlated world/evidence package. Source identifiers or pointer equality
alone do not establish these semantic laws.

## 4. Discriminating requirement and separate F5 boundary

The smallest discrimination remains the formed pure Name/Name Call at zero
local steps. Grant genuine formation and an independently valid initial input;
look for an owner returning the **original** K0/P0 at that same complete tuple.
Every inspected output above can retain source identities without carrying
that output. This is a missing correspondence instance, not a source-program
counterexample or proof that the granted world is inhabited for arbitrary syntax.

**Falsifier for this bounded conclusion:** a concrete already selected source
owner or code API on the inspected route that supplies the exhaustive I0/O0
signature, independent guards and initial head, plus the original witness/scope
action laws, with a genuine interpretation at these exact original indices.
An inhabited conditional kernel instance can witness a narrower positive
result. A fresh tag, an assumed C_c/M_E input, a pending stub, a successful
Function query or a shape-only map does not satisfy this falsifier. A supplier
outside the inspected route requires a bounded follow-up; it is not excluded
by this audit.

The production F5 question is different: the actual current solver must retain
and transport source-generated constrained presentation and evidence through
solving/generalization/fresh use/finalized export, with the required original
meaning. The inspected current path builds generalization from a verified
definition's live root component and finalizes a GeneralizationDraft into a
closed scheme (`lib.rs` around 15480–15558). That evidence is actual compiler
behavior, but it neither introduces CallInitial nor proves the redesign's
semantic correspondence. Conversely an original CallInitial supplier would
not prove those F5 preservation/correspondence obligations. The approved owner
answer explicitly preserves F5 and excludes its replacement/cutover authority.

Classification: P.CallInitial is an unsupplied original constructor/semantic
input on this proof route. Retaining its actual append/lookup record at the
chosen source owner will later address reconstruction debt **once the original
rule is supplied**. F5 production correspondence is a separate implementation
bridge. Neither a metadata extension nor changing current F5 discharges P.
