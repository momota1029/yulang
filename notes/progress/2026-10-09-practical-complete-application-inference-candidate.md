## 4. Concrete phase sequence, conditional derivation and stopping points

The following is an implementation candidate under explicit hypotheses H1–H6:

H1: authentic resolved immutable formal/typed environment and source registration
at the actual component; H2: N §3's complete independently interpreted modules,
including literal Return/Delay and the instantiated checking kernels;
H3: lawful N-to-active-consumer realization where those consumers are used;
H4: effective solving rules sound for those full contracts and adequate for the
ordinary slice, with source seed/exposure and literal-use refinement rules;
H5: Generalize's complete local laws and legal whole actions for this component;
H6: finite invoke public extraction/decode, ordinary use evidence and the
required completed-contract principality result. H1–H6 are not established by
current HIR/F5 or this note.

1. **Collect source facts.** Register `invoke` and its ordinary Value formal
   `f`, retain annotation absence, actual source positions/scopes, and one
   shared formal root `R_f`. Keep lexical Name `u_f` distinct from the Call's
   checking occurrence `u_c`. Register one actual Call `c` and literal `a=1`.
   Validate the complete dependency telescope before publishing a typed owner.
2. **Construct the N owner.** Apply Formal-N/Name-N/Literal-N, the two Result-N
   constructors, ArgDelay-N and Demand-N. Build Checks-N, Output-N, Elim-N and
   Receive-N. Install `P_N`, `Q_N` and their complete occurrence table together.
   Explicitly include result reify/consumer ports and dependent actual-provider
   suffix. This step emits constraints even if their semantic fiber is empty.
3. **Emit the four independent obligations.** At the same tuple emit
   `WF_Dec(F_c;xi)`, `VIncl(A_f,F_c;xi)`,
   `WholeArgCompatible(R_a,CarrierContract(F_c);xi)` and
   `CIncl(Image_c(n_f,Delay_a,F_c,e_f,e_a),Comp(E_c,A_c);xi)`.
   The result witness may depend on the value and argument witnesses. Receive
   is separately retained static schema evidence. Full contract references

   four-scalar implementation contract.

5. **Produce and retain source-scoped protection/refinement evidence.** Under
   the actual source rule, seed the unannotated higher-order formal's internal

   covariant output effect. Preserve provider lower marks independently:
   protection must not flow back into supplied provider effects. Ordinary-value

   step 4, not post-solve markings; the numbered list does not select a global

   fixed. Preserve shared and view-logic scopes, source event binders,
   `xi`, whole residuals and all incidences. The Call body is not the final

## 5. Failure, atomicity and minimal behavior matrix

Candidate internal outcomes distinguish malformed/incomplete construction,
semantic inconsistency, unresolved implementation supplier and resource failure.
These are research phase states, not selected user diagnostics:

- `IncompleteContract(t,field)`, ill scope, incompatible registry reuse,
  missing incidence or invalid whole action prevents installing a typed owner.
- A fully formed owner with no satisfying solution does not produce solving
  evidence or an export. Formation success cannot prove satisfiability.
- `MissingProducer(owner,field,indices)` records an unavailable realization,
  rule or export supplier; it is a development blocker, not a negative typing
  judgment on ordinary `f 1`.
- An approved deterministic resource rejection must precede unsafe allocation,
  exhaustion or partial publication. Numeric work/byte/depth caps, concrete
  diagnostics and retry/storage policy are not selected by this note.

Stage owner installation separately from semantic/public publication. Failure
in solving, Generalize or extraction leaves no new externally usable scheme
or dangling new incidence. Already published unrelated roots remain intact.
The candidate requires checked staging and rollback, but selects no concrete
Rust transaction API or allocation policy. Current F5 component drafts
(`crates/yu-solver/src/lib.rs:15475`), finalization (`:15508`) and `finish`
(`:15740`) are lifecycle seams to study; they do not already preserve the new
full package. `SolvedModule` (`:7333`) owns a closed arena and scalar schemes;
`ClosedValueScheme` (`crates/yu-types/src/lib.rs:630`) contains arena identity,
quantifiers, recursive bounds and one positive predicate. Adding a private
