## Candidate family and the exact first missing input

The strongest nonselecting candidate is a dependent family over **all original
descriptors compatible with the formal's original context**, retaining actual
decorated values and provider/evidence indices in its fibers. Schematically:

```text
Delta_f |- a : OriginalValueDescriptor
Delta_f, a |- T(a) : CompleteDependentInterface
R_f := one registered family root over (a,T(a))
```

These are candidate declarations. Their right sides cannot serve as their own
formation derivations. Using the independently interpreted descriptor domain
as an explicit parameter makes symbolic binder introduction possible in
principle, and requires neither final type solving nor selecting one provider.
The inspected Call construction already demonstrates this conditional pattern.

The exact missing input at parameter allocation is a well-sorted original
family with its complete original fields/evidence/reference relations, plus
an interpretation linking the shared native Value row to that family at the
actual source binder context. The link must preserve every admitted original
alternative and original correlation and commute with each lawful joint scoped
substitution. Calling the original family `Dec`, `T(a)` or an opaque predicate
does not supply that input. Supplying it explicitly would be an additional
independent hypothesis, not a contradiction of ordinary Simple-sub generation.

No injective map from providers into native types is required. A native type
may classify many decorated values/providers; a relational or dependent
interpretation can retain their distinctions. Consequently this audit does
not establish that a *new* separately stored descriptor object is necessary,
or that no existing semantic domain can eventually be instantiated. It finds
no constructor in the inspected route establishing that instantiation and
its native correspondence. A new durable representation or observable rule
would need its own authority; the missing input alone forces neither choice.

## Small conditional separations and candidate failure conditions

These are mathematical tests of shortcuts, not admitted Yulang programs or
independently realized descriptor models. Their hypotheses remain explicit.
They give no source/runtime falsification and do not invent original licenses.

**Same native shape.** Suppose two independently valid original entries
`s0,s1` have the same native projection `erase(s0)=erase(s1)=n`, and some
original contract coordinate `C(s0) != C(s1)`. Any reconstruction satisfying
`C(s)=h(erase(s))` for both entries would imply
`C(s0)=h(n)=C(s1)`, a contradiction. Two entries and one differing coordinate
are sufficient. The premise that such entries occur in the admitted source
domain is not established here. More importantly, a family indexed by the
original entry satisfies neither factorization premise nor contradiction:
it may retain both fibers over `n`. The accepted Function semantics expressly
allows preserving actual decomposition evidence despite projected equality.

**Output-dependent future.** If two original arm outputs introduce different
providers `p0,p1`, their future fields have types `J(p0),J(p1)`. A candidate
which replaces both with one structural provider's future relation needs an
original typed conversion preserving both contracts. Equal erased result types
do not supply it. Keeping `(p,J(p),future_relation(p),license(p))` together in
the fiber avoids that shortcut. Source-interface construction §3.1 and the
definition §3 already retain these dependencies. This test does not assert
that `J(p0)` and `J(p1)` are necessarily unequal for any concrete source pair.

**One shared assignment.** Let an original shared coordinate range over
`{0,1}`. Two use conditions `P0(b) := b=0` and `P1(b) := b=1` separately have
witnesses, while `exists b. P0(b) and P1(b)` is false. Thus replacing one
joint assignment by independent witnesses at each use changes the relation.
This two-value/two-use separation is minimal for these equality predicates.
It attacks publication or a claimed joint realization, **not** generation of
an unsatisfiable open constraint graph: generation may legitimately retain
both conditions and later report inconsistency. Fresh use-local variables
also remain allowed where the original scoped substitution permits them.

These tests do not enumerate future clients or require their execution. No
alternative is removed because it lacks an execution or a convenient proof.
