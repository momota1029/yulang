# Identity-scheme incoming extension for production value incidence

Date: 2026-10-04
Status: source-generation theorem extending a restricted structural
projection; no implementation or semantic authority
Scope: current F5 value projection for error-free binding HIR with
integer, closed-result, identity, or alias-cycle cross-SCC targets
Depends on: [current HIR value-skeleton incidence theorem](2026-10-04-production-f5-value-skeleton-hir-incidence.md), Theorem S in [the source-generated theorem package](../design/2026-10-04-source-generated-callback-structural-theorems.md), and the current `yu-hir` / `yu-solver` generation rules

## Result

### Additional premise isolated from the failed unrestricted search

The useful source-checkable premise is an incidence condition, not the desired
regularity conclusion: after F5 value projection, routing, and rational
equality normalization, every retained inequality is between roots in one
free/free component or between such a root and that component's sole
descriptor anchor; each component has at most one anchor, and
descriptor-child references are constructor-guarded. A finite
resolved-HIR/SCC analysis can check the restricted incoming-target grammar
below and establish this condition without asking whether the package has a
regular solution. The observed obstruction outside the premise is competing
anchors in one free component; the present evidence does not establish that
the condition is absolutely weakest.

**Conditional witness theorem.** For a finite projected package with this
incidence condition, preserve all descriptor nodes and child links, assign
each component its unique anchor (or an existing closed node if anchorless),
and redirect all roots simultaneously. Every retained inequality then has
identical endpoints. If child-reference cycles cross constructors, the
result is a finite guarded graph and therefore a regular witness. This
argument proves existence directly; it does not infer it from an assumed
regular solution or extend Theorem S's signature.

**Separate source-generation theorem.** The HIR/SCC grammar below is a
decidable sufficient condition for the incidence premise on the current F5
value projection. The source-generation clauses prove the classification;
the witness theorem then applies. This does not establish that arbitrary
Yulang source satisfies the grammar.

The incoming-`Int` theorem has a useful non-extrema extension. Consider its same finite HIR grammar and the same value projection, but allow each cross-SCC resolved use to target one of:

1. an alias-only chain ending at an integer binding; or
2. an acyclic closed-result chain ending at an integer. Each name-binding
   step is either a one-name alias or a one-parameter lambda whose body is a
   resolved module name and does not refer to its parameter; or
3. an alias-only chain ending at an own-parameter identity lambda,
   `f p = p`; or
4. an alias-only chain ending at an alias-only cycle.

For cases 1, 3, and 4, the walk follows only resolved one-name bindings.
Case 2 may additionally follow non-parameter lambda-result edges, but it
must end at an integer without repetition. Identity-lambda and cycle
terminals are admitted only on alias-only paths. No other cross-SCC target
shape is admitted. The finite HIR/SCC walk decides these cases independently
of structural satisfiability or any regular witness.

After actual F5 routing and rational-equality normalization, every generated value projection in this fragment has a finite regular witness. Integer routes contribute closed `Int` anchors. A closed-result chain contributes one closed descriptor `D`, generated by `D ::= Int | Function(Top,D)`. Identity routes contribute exactly one open positive `Function(q,q)` anchor per retained use component. Alias-cycle routes contribute no value inequality, so their use-side component has no incoming value anchor. The fresh identity `q` is unanchored and occurs only as a Function child.

The construction uses a proof-only extension of the finite witness graph:
preserve F5's materialized `Top` endpoint as an opaque zero-arity token. It
has no global subtyping or lattice rule and is not identified with a
successor-language value type. Keep all generated descriptor nodes and
constructor-child links. For each free/free incidence component, redirect
every free root and occurrence root to its sole descriptor anchor, if one
exists; give an anchorless component the existing closed `Int` node. This
also applies to open Function anchors: their descriptor children still point
to the corresponding redirected components. The construction therefore
assembles the whole graph at once rather than applying Theorem S to a graph
outside its declared signature.

This is a sufficient source condition, not a rejection policy or a claim of necessity. It strictly admits a structured polymorphic cross-SCC scheme excluded by the previous incoming-`Int` restriction. It still does not cover arbitrary structured schemes, full Function effects, or the coupled four-port package.

## Source-generation lemmas

**Identity terminal.** For the current unannotated source `f p = p`, HIR resolves the body to the same `HirParameterId`. `emit_lambda` and `admit_lambda_fact` generate the positive value descriptor `Function(p,p)`; the F5 generalizer closes it as one quantified variable shared by argument and result, with no recursive bounds. The existing source assertion at `crates/yu-solver/src/lib.rs` (test `f5d_source_identity_boxed_and_flat_candidates_agree`, near line 20591) checks this exact output. For this value projection, its effect children are omitted; in F5 the source test also confirms the pure effect children.

**Closed-result chain.** A finite chain with an integer binding at its end and only aliases or one-parameter lambdas returning the next module name generates a closed predicate of shape `D ::= Int | Function(Top,D)`. The integer base follows `emit_integer`. Each lambda step emits one `Function(p,body)` fact; because `p` has no source occurrence in the body, generation creates no value bound on that parameter row. Generalization materializes this unconstrained argument as the existing closed `Top` endpoint and retains the body's one closed descriptor as the result. Alias steps instantiate one closed, unquantified, bound-free predicate and add only the occurrence-to-root fact, so they preserve `D`. Induction over the finite chain proves the scheme shape, with zero quantifiers and zero recursive bounds at every step. The existing source assertions for `f p = 42` and `f p = n` with integer `n` check the first Function step; this induction covers finite nested result chains.

For the incidence witness, a closed-result route injects one finite closed descriptor `D` at the source occurrence. Assign every free root in that use-side component the same `D`. Each retained free/free or free/descriptor inequality then has identical endpoints and is witnessed by reflexivity. In particular, `Top` in `Function(Top,D)` is merely a preserved constructor child of the identical descriptor; this proof does not give it a top/lattice interpretation or compare it with a different descriptor.

This source-specific construction needs only exact-endpoint reflexivity. By
the incidence classification, every retained inequality is between two
free roots in one component or between a free root and that component's sole
anchor. After redirection both endpoints are the same graph node, so every
original bound is `D <: D`; no comparison decomposes `Top` or combines
distinct concrete endpoints. Descriptor-child edges are the only edges
remaining between graph nodes. Every cycle therefore passes through a
constructor node, and the assembled graph is finite, guarded, and regular.
The generated value package has no equations, rigid-name permissions, or
fixed-endpoint comparisons. The proof adds a representation token only for
the already emitted F5 endpoint and assigns it no language meaning.

**Acyclic alias preservation.** Induct on the finite alias-chain length from a cross-SCC use target to that identity terminal. The terminal case is the identity scheme above. Each preceding alias definition has exactly the generated occurrence-to-root fact `v_o <: r_d`; its resolved use is routed from the finalized target scheme. Instantiation allocates one fresh row `q'` for the single target quantifier and, because the scheme has no recursive bounds, routes exactly `Function(q',q') <: v_o`. The alias component therefore has one positive Function lower descriptor and no independent upper/closed value fact. Generalization preserves this single shared child row as one quantifier, again with no recursive bound. This proves that every target root along the admitted acyclic chain has the same scheme up to quantifier renaming. The induction uses the actual finite generation and generalization clauses; it does not test or assume regular satisfiability.

The route shape follows `route_incoming_inner`, `instantiate_and_route_closed_inner`, and `closed_parts` in `crates/yu-solver/src/lib.rs`: a quantified positive Function is reconstructed once, and recursive lower/upper restorations are absent. The broader positive-union Cartesian expansion and recursive-bound restoration paths are not reachable from this generated scheme.

**Alias-cycle terminal.** An alias-only SCC has no integer or lambda producer. The current F5 generalizer materializes its empty positive root expansion as `PositiveValueView::Bottom`; a finite acyclic alias prefix ending at that SCC has the same no-lower-bound result. When this target is used cross-SCC, `route_incoming_inner` takes its Bottom-trivial branch and emits no value inequality. The source occurrence-to-root clause remains, but no Bottom/`Never` value-type interpretation is introduced into this structural theorem. This is only a characterization of the existing route's no-op value projection.

## Incidence extension

Retain the source alias graph and post-routing cut distinction from the incoming-`Int` theorem. A name-binding root has at most one outgoing resolved-name edge. Every edge on an acyclic alias chain is between distinct SCCs: an alias-only strongly connected component has no terminal exit, and the identity lambda has no module-name body dependency. Each such cross-SCC edge is cut by routing; the source-side alias root is not connected to its target root. A cut whose target lies in an alias-only cycle also contributes no value edge, by the Bottom-trivial dispatch described above.

A source-side alias/result fragment has at most one outgoing cut because each admitted definition has at most one resolved body-name use. In the admitted grammar its edge is itself the use being routed, so no component can accumulate two distinct anchors through separate cuts. A lambda-body use is also its definition's sole resolved use; when it crosses an SCC boundary, it contributes no free/free edge to that target root. The lambda root's Function descriptor reaches the body only by a constructor-child edge, so it does not become a competing anchor in the body's free/free component.

The source component classification gives at most one anchor in every component: integer and closed-result routes supply closed anchors; retained lambdas supply their one Function descriptor; identity routes supply one open Function descriptor; alias-only cycles and unused parameters are anchorless. Internal name uses add free/free edges only within a component. A cross-SCC use is cut and contributes only its one classified incoming anchor or no edge for an alias cycle. Function children do not merge their free incidence components. There are no generated equations. Thus the simultaneous redirection above exhausts and satisfies every generated inequality.

## Separate HIR/source-generation theorem

The source condition is decidable from the finite resolved HIR and its SCC
plan: a finite-state walk distinguishes alias-only prefixes, closed-result
edges ending in integer, identity terminals on alias-only paths, and
alias-only cycles. The source-generation lemmas above show that the collector,
SCC router, scheme finalizer, and incoming instantiator emit exactly the
admitted anchors or no value edge. The simultaneous graph construction then
provides a regular witness without solving the package.

This source theorem extends the previous value-projection theorem to closed-result schemes, incoming identity schemes, and alias-cycle no-op routes. It does not prove that every current Yulang module satisfies the condition. In particular, productive recursive lambdas, direct arbitrary annotations, effects, and other structured schemes remain outside this source fragment. No counterexample to regular completion is established.

Independent compiler-referee review identified the alias-scheme preservation
and one-cut obligations; both are proved above. A separate spec audit
confirmed the source clauses and component classification, and its delta
review confirmed the simultaneous witness construction. No compiler code or
tests changed or ran.
