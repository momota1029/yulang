## TEST-A: lazy assertion effect

- 開始: 20:14:22 JST
- 正本: `notes/design/2026-07-25-test-facility-design.md`
- 方針: `test` を host capability にせず、字句 handler の外へ escape した要求だけを扱う
  root effect registry で通常実行時の discard を実装する。

### Blocker

- `assert` の bool thunk は、通常実行では副作用を起こさず、明示 handler から強制すると
  `println` を実行することを確認した。
- `assert_eq` の generic value thunk を二つ effect payload に載せると、handler 内の
  `left()` / `right()` は値を返す一方、thunk 内の `println` effect が実行されない。
- 単一 thunk で値の tuple を返す案は effect row が `[]` と衝突する。bool-only へ縮退すると
  失敗時の実値を渡せず承認済み設計を変えるため、未 commit のまま停止した。

### 訂正（同日、Claude によるレビュー時）

上記 Blocker の診断は誤りだった。切り分けの結果、thunk は無関係である。

効果操作のペイロードが**タプルであること**が原因で、中身が thunk でも普通の `int` でも
同じように壊れる。ハンドラの腕で分解すると腕が一致せず未処理効果になり、丸ごと束縛すると
引数の対応が崩れる。単一ペイロードはスカラでも thunk でも正しく動き、thunk 内の効果も
ハンドラが強制した時に実行される。

詳細と4つの判別実験は `notes/bugs/2026-07-25-effect-operation-tuple-payload.md` に記録した。
`assert_eq` はこれが解決するまで保留とし、`assert` 単独で TEST-A を着地させた。
