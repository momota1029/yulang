## F5c shared producer-walker design review

Code-level inspection confirmed that the active `F5cGeneralizer::walk`
produces boxed values, so a separate module cannot consume its leaf/exit
decisions as flat IDs without either converting after Box construction or
copying the task interpreter. The latter would create a second producer
source of truth. A Reviewed proposal now uses one shared task interpreter with
the existing boxed compatibility sink and an uncalled tagged Local/Shared
flat candidate sink. It moves the generalizer, summary memo/transaction,
raw-root forest coordination, and `build_inner` ownership into
`f5c_generalization.rs`; `lib.rs` keeps component invocation and outer solver
installation orchestration.

Three independent M3 reviewers (compiler-referee, specification, performance)
found blockers in the first draft. The primary repaired and delta-reviewed:
ordered full raw-root retention/materialization; deterministic first-reentry
owner order with lower-before-upper (the bounds map is lookup-only); an
edge-index chronological memo undo log; idle active-conflict restoration;
pure/invalid effect and complete Q/R/raw-forest witnesses; and explicit
source/memo/draft/scratch accounting categories. All blocking/major findings
closed in the final focused delta round. This is design review, not
implementation certification: rollback, deep flat drop, boxed hot-path cost,
and §15 physical/resource measurements still need implementation evidence.

No code or tests ran. `git diff --check` passed; benchmark/resource-probe
budget used remains zero. The design is not yet Authoritative: explicit user
approval is required before changing the active internal producer path. §44,
indexed finalization, F5e, and F5c/F5e closure remain open.
