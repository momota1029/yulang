# 2026-09-18

## Gate 1 shadow CST diagnostic interpreter — implemented

Working tree change: new `crates/yu-syntax/src/structural_diagnostic.rs` and
`crates/yu-syntax/src/tests/structural_diagnostic.rs`; modified
`crates/yu-syntax/src/lib.rs` (private `mod structural_diagnostic;`),
`crates/yu-syntax/src/expression/delimited.rs` (three `DelimitedOwner` role
methods made `pub(crate)`, no body change),
`crates/yu-syntax/src/tests/mod.rs`, and
`crates/yu-syntax/src/tests/recovery_output.rs` (the test-local
`shadow_occurrences` helper now delegates to the production collector).

Gate 1 is now closed at implementation level. The production whole-tree walk
derives structural recovery from the Rowan CST alone: zero-width `Missing`
nodes, maximal adjacent same-immediate-parent raw `Error` token groups, and
structured `Invalid` preorder over the node's own nonempty extent. It assigns a
global source/preorder ordinal that keeps same-slot same-offset encounters
distinct, and reports the ancestor kind path from the root to the immediate
structural parent. It never consults the temporary parser recovery ledger,
replays parsing, relexes `Error` text, or creates synthetic recovery nodes.

### Precise catalog rows encoded

The mapped bounded rows are encoded directly:

- ordinary expression-delimited `Missing` (`ParenthesizedExpression`,
  `CallTail`, `IndexTail`): the ordered child phase selects `Item`
  (`Expression`), `Separator` (`DelimitedSequenceSeparator`), or the terminal
  `Close` (matching close punctuation), read from the nearest structural
  sibling because trivia is not an ordered child phase;
- expression-delimited raw `Error` groups over the five owners
  (`ParenthesizedExpression`, `CallTail`, `IndexTail`, `ProjectionTupleTail`,
  `ProjectionRecordTail`): a direct owner group projects the owner `Item`
  expectation, a group under `ExpressionDelimitedSeparator` projects the owner
  separator expectation, and a group under `ExpressionDelimitedForeignClose`
  projects the owner's matching-close expectation.

Everything else — including the two mapped structured `Invalid` owners, which
have no encoded precise row yet — takes the conservative generic fallback. The
fallback carries only CST-derived facts (kind, range, ordinal, ancestor path),
so it is total and deterministic while the precise catalog remains incomplete.

### Focused evidence

`crates/yu-syntax/src/tests/structural_diagnostic.rs` covers the representative
subset required by the gate: precise `Missing` in each ordered phase across
three owners; precise raw `Error` groups in the direct, separator-wrapper, and
foreign-close-wrapper slots; a maximal multi-leaf raw run and a retry
continuation; a reachable structured `Invalid` (`{1, b}`) proven to precede its
nested children; a deliberately uncataloged `Missing` (`my x =`) proving the
generic fallback and its determinism; UTF-8/CRLF byte-accurate ranges; and the
trivia-interleaved forms of the mapped row.

The three earlier test-level shape witnesses in `recovery_output.rs` are
unchanged in assertion content; only their helper now delegates to the
production walk, folding a structured `Invalid` back into the binary
`RecoveryKind::Error` shape those tests were written against.

`2026-09-17-syntax-freeze-and-vertical-implementation-amendment.md`,
`2026-09-09-successor-cst-derived-diagnostics-amendment-draft.md`, the two

catalog row. The reviewer also noted the deferred structured-`Invalid` precise

## Gate 2 effective syntax-table unification — implemented

Working tree change: `crates/yu-syntax/src/operator_compilation.rs`,
`crates/yu-syntax/src/operator_table.rs`, `crates/yu-syntax/src/full_parse.rs`,
`crates/yu-syntax/src/root_statement.rs`.

The full-parse operator planner is now non-diagnostic:
`effective_full_parse_operators` builds the one immutable effective table
(imported capabilities first, then local headers in source order, first accepted
capability wins), and `conflicting_local_operators` derives conflicts by reading
the accepted site in that exact table. The previous
`FullParseOperatorCompilation`/`compile_full_parse_operators_recovering` pair,
which produced the conflict vector as a merge byproduct, is removed.

`ParsedFile` retains the effective table as `Arc<OperatorTable>` and exposes
`operators()`. `parse_file` passes that exact table to `parse_root_candidate`
and then derives the conflict diagnostics from it, so parsing and analysis
consult the same accepted table/site without recompilation or a retained
conflict vector.

`OperatorTable` gained `pub(crate) fn fixity_sites`, and `OperatorTrie::find`
lost its `#[cfg(test)]` because the production lookup now uses it.

Focused witnesses added in `full_parse.rs`: the retained site is the one
analysis reads (local/local duplicate with equal binding powers), an
imported/local duplicate keeps the imported site, mixed fixities for one
spelling stay accepted, every rejected duplicate is reported in source order
with sequential ids, and operators after the header cutoff are excluded. The
`operator_compilation.rs` planner tests were rewritten to the new API.

Review: one `compiler_referee` pass found the gate satisfied and behavior
preserved (effective table, conflict vector content and order, diagnostic
ordering/IDs). It noted two coverage gaps: multiple rejected declarations (now
witnessed) and the parser half of "same accepted site". The latter is not
witnessable at the CST level because operator chains are flat and binding
powers do not change the tree (`tests/operators.rs`,
`dynamic_operator_lower_bp_handoff_preserves_trivia_and_flat_output`), so that
half rests on the shared table instance plus analysis agreement.

Verification: `cargo test -p yu-syntax --lib -- full_parse` passes;
`cargo test -p yu-syntax` is 1448 passed / 6 failed, the same pre-existing
failures. `cargo fmt -p yu-syntax -- --check` is clean; `cargo build -p
yu-syntax` succeeds with only pre-existing warnings in
`declaration_companion.rs`/`operator_chain.rs`/`cursor.rs`; `cargo clippy -p
yu-syntax --all-targets` has no hits for the changed non-test files.
