  `notes/design/2026-08-20-phase2-parser-fixture-schema.md` に定め、§4.2.2 / §18 との整合を

- `tests/contracts/phase2-parser/v0/` に第一 slice を追加した。`leading-use-plain`、
  `infix-operator-header`、`malformed-header-followed-by-valid-header`、
  `header-full-diagnostic-identity` を含み、この段階では Yulang2 oracle anchor は置いていない。

### 最初の実装と scanner の見直し

  `crates/yu-syntax/src/lib.rs` に追加し、`leading-use-plain` と `infix-operator-header` の fixture

  この slice の対象外とした。コミットは `e1737368`。

### 最小 full parse と chasa 必要性の確定

- Rowan は §4.2.1 / §4.2.2 の lossless Rowan bookkeeping と Yulang2 の `rowan 0.15` 採用により、
  既決の依存選択であることを確認した。`SyntaxEnvironment`、`ParsedFile`、`parse_file` を追加し、
  header discovery と full parse が同じ `HeaderCursor` lexer を共有することで header / full parity を
  構造的に保証した。対象 fixture に lossless `rowan::GreenNode` を生成できることを確認した。
  コミットは `7022ed27`。
- しかし dynamic infix `+!` と prefix `+` / `!` では、`a+!b` は `a +! b`、`+!a` は
  `+ (! a)` と読む必要がある。同じ文字列 `+!` の token 境界が parser position に依存するため、
  context-free maximal-munch の `scan_symbol_end` / `starts_distinct_item` は正しくないと分かった。
- `yulang2-oracle` が `chasa 0.5.0` と NUD/LED-dispatched operator scanner、
  `TrieState::longest_match_then` の checkpoint / rollback を実際に用いていることを確認した。
  chasa を用いる設計へ切り替える必要があると判断した。

### chasa-based parser architecture の提案と改訂

- `notes/design/2026-08-20-yu-syntax-chasa-architecture.md` の v1 では、flat token vec をやめ、
  direct chasa character-stream parsing、NUD/LED Pratt dispatch、event buffer を経た Rowan CST 構築を
  提案した。コミットは `8c5acd92`。
- v2 では、chasa は exact pin ではなく workspace crate として vendor し、rollback より
  `choice` / `or` を優先する実装規律を定めた。operator declaration は header-scoped のため、
  header discovery 後に immutable `OperatorTable` を一度だけ構築する。最初の slice から
  prefix / infix / suffix / nullfix を含む `BpVec` 相当の fixity を扱うこととした。
  また oracle の judge-table logic は変更せず採用し、event buffer / replay は廃して、speculative
  branch が CST を出力できない `Probe` / `CommittedCst` capability split を採用した。コミットは
  `93384066`。
- v3 では Yulang2 parser source tree と約 8,400 行の test suite を広く調査した。statement、lambda、
  `catch` / `operation, k ->`、pattern / type / rule、string / Yumark、role / impl / derives を含む
  grammar に対して core architecture が成立することを確認した。一方で `ParseLocal` の rollback
  ownership は input position だけでは不足し、`line_indent`、`inline` / `ml_arg`、Yumark の
  quote-depth / continuation など layout / scanner state 全体を戻す必要があると明確化した。
- header-mode の opaque body scanner も、delimiter depth と indentation だけでは heredoc、
  string interpolation、rule literal、Yumark 内の brace / newline を誤認するため不十分だった。
  lexical-region-aware scanner を要求し、これらを含む operator body の後に valid header が続く
  required-test-case family を追加した。コミットは `86f02267`。

## Phase 2: chasa parser foundation の継続実装

### Dependency wiring と基盤モジュール

- `chasa` を crates.io dependency として exact pin の `=0.5.0` で追加した。crate README が
  experimental API と明記しているため、意図しない API upgrade を避ける目的である。vendoring は
  不要とするユーザー判断に合わせ、architecture 文書の Workspace integration も local workspace crate
  ではない方針へ訂正した。コミットは `639bf1fa`。
- `input.rs`、`session.rs`、`operator.rs` を追加した。`SourceInput` は `&str` 上の byte-positioned
  chasa `Input` / `SeqInput` 実装、`ParseEnv` / `ParseLocal` は Gap-1 revision の rollback 対象である
  line / indentation state、`inline` / `ml_arg`、stop-set / delimiter stack、comment / string /
  heredoc / interpolation / rule-literal / Yumark / fence を含む embedded lexical mode stack を保持する。
  custom `RollbackStack<T>` は clone ではなく inverse operation を記録して状態を戻す。
- speculative branch が CST を emit できない `Probe` / `CommittedCst` capability split もこの slice で
  導入した。`OperatorTable` は Yulang2 の `BpVec` に対応する prefix / infix / suffix / nullfix の
  immutable table とし、`chasa::parser::trie::TrieState` による `longest_match_then` traversal adapter
  を備える。old `HeaderCursor` / `lex` / `FullCstBuilder` は未変更のまま引き続き使用される。
  コミットは `4be4d2b4`。

### 直接 Rowan sink

- event buffer を貯めて replay する CST 構築は memory / time の無駄であるという明示的なユーザー判断に
  従い、`RowanSink` を追加した。`rowan::GreenNodeBuilder` を包む `DirectCstSink` 実装であり、Pratt の
  既出 left operand を親 node で包む場合は Rowan の `checkpoint()` / `start_node_at()` を直接用いる。
  custom marker / event system は置かない。
- debug build では連続する token emission が contiguous、source-order、source-backed であることを
  assert する。コミットは `26f4ccca`。

### shared scanner の段階的実装

- `scan/trivia.rs` は Yulang2 oracle の実装に照合して、`//` line comment、`/* */` nested block comment、
  `/*/` 形式の overlap prevention、CRLF / CR / LF newline を実装した。newline ごとに oracle と同じ
  trivia-consumption side effect として `ParseLocal::LineState` を更新し、comment nesting に対応して
  `EmbeddedLexicalMode::{LineComment, BlockComment}` を push / pop する。`--` / `---` は通常 trivia では
  なく declaration-level doc-comment token と確認したため、この shared scanner では扱わない。
  コミットは `e4f36384`。
- `scan/word.rs` では oracle に unconditional keyword がゼロであることを確認した。`use`、`infix`、
  `my`、`if` など約 30 の keyword-shaped word は plain identifier として scan され、後の grammar が
  position と stop-set に基づいて reclassify する。identifier は Unicode XID rule のため
  `unicode-ident` を normal caret-range dependency として追加し、scanner は identifier recognition
  のみに限定した。`"if"` が特別分類されない test も追加した。コミットは `c6c23f5b`。
- `scan/punctuation.rs` は `(` `)` `[` `]` `{` `}` `\\` `'` `,` `;` `.` `::` `:` の 13 fixed token を
  認識する。`::` は `:` 二つより先に選ばれる。`.`, `::`, `:` は fixed punctuation とするユーザー判断に
  従い、`=` は prelude の `infix(=) ...` で定義されうる operator territory に残した。scanner は
  recognition のみを担い、grammar-owned delimiter stack を mutate しない。コミットは `430b2c3e`。

### Pratt site-aware operator scanner

- `scan/operator.rs` に `scan_operator(site: OperatorSite, ...)` を追加した。`OperatorTable` の
  `state().longest_match_then(...)` と oracle の `judge_nud` / `judge_led`、`boundary.rs` check をそのまま
  用い、`contains(PREFIX | NULLFIX)` による value-start rule の AND semantics も architecture v2 の
  revision に従って維持した。
- `+!` (infix)、`+` (prefix)、`!` (prefix + nullfix) を登録した test で、NUD site の `+!a` は short
  candidate `+` へ fallback して remainder `!a` を残し、再帰 NUD scan が `!` を prefix と認識するため
  `+ (! a)` へ分解できることを確認した。LED site の `+!b` は long candidate `+!` を infix として
  受理し、`a +! b` になる。rejected long candidate が input position と trailing-newline state を戻し、
  unrelated delimiter / lexical-mode state を乱さないことも確認した。コミットは `16ae09d6`。

### header-mode opaque operator body scanner

- `scan/opaque_body.rs` の第一 slice は Gap-2 のため、oracle の `skip_op_def_body` より広い lexical
  awareness を持つ header-mode operator-body skip を実装した。`session.rs` の grammar-owned delimiter
  stack には触れず local delimiter depth を追い、comment は `scan/trivia.rs` を再利用し、normal string と
  oracle の opening-quote-count sentinel による heredoc を distinct region として扱う。
- ordinary string 内の `{` が depth を延長せず、string 閉鎖後の真の body boundary を見つける test と、
  heredoc 内の newline を top-level boundary と誤認しない test を追加した。interpolation、rule literal、
  quoted / block Yumark、raw / Yulang fence は follow-up slice へ明示的に deferred とし、module doc comment
  に known gap として残した。コミットは `6d2b13b7`。
