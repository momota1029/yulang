## Gate 3 first HIR operator-chain association — implemented

The approved first `yu-hir` slice is implemented in `crates/yu-hir`. It adds
the `yu-syntax -> yu-hir` dependency and exposes `AssociatedChains`: a minimal
pre-HIR product of owned, range-preserving associated expressions. It does not
introduce `HirModule`, declarations, names, `DefId`s, types, diagnostics, or a
`yu-types` dependency.

`associate_operator_chains(&ParsedFile)` reads the exact immutable operator
table retained by parsing through the new read-only `OperatorTable` definition
view. It handles prefix, infix, suffix and nullfix roles under one association
authority; fixed postfix/ML continuations; annotation and terminal-tail
barriers; nested chains; and recovery `Missing`, raw `Error`, and structured
`Invalid` facts without changing the Rowan CST or reissuing parser diagnostics.

### Ownership amendment

A performance audit found that retaining every chain in a flat result while
also embedding owned nested results could make valid deeply nested input retain
quadratic duplicate trees. The user selected top-level-only `AssociatedChains`.
The authoritative decision is recorded in
`notes/design/2026-09-19-hir-associated-chains-ownership-amendment.md`: nested
chains are associated once and retained only in the enclosing owned `HirExpr`.

## Gate 4 simple HIR module resolution — implemented

The first immutable `HirModule` slice is implemented from the user-approved
simple-binding design. Its focused input is `my x = 1; my y = x`, preflighted
through the public parser for byte-identical CST, no published syntax diagnostic,
and no CST-derived recovery occurrence.

`lower_module` accepts explicit source-root identity and empty semantic imports,
plans direct-root plain identifier bindings in a first pass, then resolves
integer/name bodies against the completed namespace. It keeps body failures as
error values without dropping admitted identities; nested/recovery-bearing or
compound targets never enter the module namespace. Duplicate definitions are
deterministically retained and ambiguous; no first/last-wins rule exists.

The lowering path consumes one exact-operator-table association result per body
and uses one ordered CST-derived structural-recovery projection. Syntax markers
retain interpreter preorder and attach to module/item/value owners without
duplicating syntax diagnostics. Unsupported recovery-bearing/indented bodies
retain causal syntax IDs followed by one outer lowering marker, with no nested
name lookup. The phase is total for ordinary source errors and reserves its
`Result` error for validated availability/invariant failures.

M2 review initially exposed recovery-body ownership, global marker order,
quadratic recovery routing, availability propagation, and an overlap between
recovery and unsupported bodies. One batched repair plus one narrow overlap
repair closed them. Final spec and compiler delta reviews found no remaining
findings.

Verification: `cargo test -p yu-hir` (26 tests including docs), `cargo test -p
yu-syntax structural_diagnostic` (8 tests), `cargo fmt --check`, and `cargo
check --workspace` pass with `RUSTC_WRAPPER=` because the configured `sccache`
wrapper lacks permission in this environment. No timing experiment ran: review
verified one structural projection, one recovery partition, one association tree
per body, and linear counters. The next coherent migration is parser-ledger/API
retirement; type attachment remains out of scope.
