## Objective, method and result

Test the composition from the selected original Call constructors to authentic
native source records and the typed profile/event/lifetime consumer. Method:
static constructor/consumer audit, with the mathematical rules and native
producer code inspected separately. No H1-G producer output or defense was
read. H1-F was consulted only for its bounded background and already identified
discriminators; this packet introduces no replacement alpha/beta toy model.

**Result:** the first unsupported composition is already the claim that the
native `ApplySourceInput`/`NativeInterface` is an authentic, complete emitted
Gen-Call-0 record to which `OC-CallEff` applies. The native carrier authenticates
source syntax, recipe identity and Function4 endpoints; it explicitly leaves
original Gen-Call-0 formation and complete semantic interfaces pending. The
selected definitions supply original source-semantic constructors, so this is
an implementation-correspondence premise, not an absent language rule.

No source-qualified operational counterexample was established. In particular,
no relay example is asserted admitted, source-typed or executed. This result
does not establish impossibility, incorrect compiler execution, or closure of
the all-admitted shallow Catch theorem.

The source formation approval applies to actual emitted Gen-Call-0 records.
It expressly does not assert that every source Call has one. An ordinary Call
without one keeps its old derivation; no acceptance restriction follows.
The selected source meaning preserves typed value paths, historical origins,
current resumed state and expiry. Borrowed/owned enter/leave is a Draft
realization, not an additionally selected semantic transition convention.

The necessary composition premises, left explicit here, are:

1. `e` is an authentic emitted complete Gen-Call-0 record at its original
   `(B,X,xi,Delta_e; declaration, demand, lexical uses, Call, upper occurrence,
   beta, p0, p_out, ElimOrigin)` indices, rather than an Apply-shaped stub.
2. `Q_e` references the actual complete original predecessor Call operation,
   and independent C0 types that unchanged interface, including actual role/
   dispatch, all arms, open carriers and output-dependent future interfaces.
3. One original assignment `sigma` interprets the entire tuple and its ordered
   continuation/evidence. Native endpoints and typed evidence refer to its
   restrictions, rather than separately inhabited interfaces joined afterward.
4. Each typed query input is produced at its source owner: view/position path,
   immutable historical receiver, actual Receive/Observe, current active
   owner/handler roots, and expiry/current-state correspondence.

The native code inspected below does not establish these four premises. This
is a bounded owner characterization, not a theorem that no implementation can.

## Constructor-to-consumer derivation

### 1. What the native producer actually supplies

`yu-hir/src/module/local_source.rs:115` retains occurrence, syntax position,
range, lexical scope and form. Its Apply at line 143 contains callee and
argument indices plus source syntax kind. The formation at line 667 constructs
those indices from real syntax. Lambda/formal and Catch binder identities are
also retained. None of these fields claims complete original Call typing.

`candidate_source.rs:604` constructs an Apply recipe and `ApplySourceInput`
from those exact local expression indices and component endpoints. It retains
checking occurrence/cause and an optional resolved formal-name route.
`shadow_apply.rs:1432` checks that the input and recipe agree before admission.
At line 1522, the same recipe stores callee/argument/result terms, callee and
argument evaluation rows, one negative Function demand, invocation row and
application row in `NativeInterface`.

This is genuine joint construction evidence. It should not be misreported as
arbitrarily choosing each native port independently. `candidate_call::observe`
at line 341 validates source ownership, callee/argument indices, Function4
field equality, polarities, invocation-row identity and the optional original
formal/name/omission route. Those checks supply their stated structural joins.

They do not validate original `Idx(e)` or authentic complete `Q_e`. The decisive
owner is `candidate_call.rs:139–176`, whose `OriginalGenCall0Input` inventory
still requires **every original coordinate**. `PendingCallConstruction` at
line 270 returns that inventory and, unconditionally, the suppliers
`OriginalGenCall0`, `ArgumentReifyAndWholeCarrier`, and
`ReceiverDispatchAndCompleteResultFutureInterfaces`. Its optional formal inputs
remain requests for original complete interfaces as well.

Consequently the attempted inference

```text
authentic LocalSource Apply + validated NativeInterface
    therefore authentic complete e for OC-CallEff
```

has no implementing introduction in this inspected path. This is the first
missing premise, before invoking the mathematically selected contribution
wrappers or interpreting their witnesses. Filling its input enum with a native
row/type/scope label alone would assume the desired semantic correspondence.

### 2. Receiving the provider and calling the callback remain separate

For H1-F's conditional relay syntax, `C_in = relay provider` and `C_cb = cb()`
produce distinct source Apply occurrences, recipes, checking origins and native
demands. `C_in`'s argument endpoint is the supplied provider; `C_cb`'s callee
endpoint is the resolved formal and its argument is Unit. The omitted-formal
`DirectionalIntroduction` is stored at the exact `C_cb` demand's ResultEffect,
as `shadow_apply.rs:1499–1514` and `candidate_call.rs:491–523` require.

Thus a proposed field map that identifies those two complete records is
incompatible with their constructors. This static distinction is preserved;
it is not evidence that the source provider was dynamically received, or that
the C_in Argument comparison alone supplies typed Receive/Flow into C_cb's
protected upper occurrence. The remaining edge must originate in authentic
complete Call/receipt construction, under the same original tuple.

No new relay execution or alpha/beta source witness is claimed here.

### 3. One recipe is weaker than one interpreted original assignment

The native demand's four fields are constructed simultaneously from one Apply
recipe. `candidate_catch_operation` at `candidate_effect.rs:806` also deliberately
shares one values/effects/views environment for declaration argument/response
construction. These are positive partial coherence facts.

Neither fact supplies `sigma`'s interpretation of actual callee-produced
provider/current world, original ordered pending suffix, original arm witness,
or provider-dependent future use. `NativeInterface::result` is a Value term;
it is not the authentic `ReturnFutureRef_e` interface. Its scalar effect rows
are not ordered raw continuation witnesses. `shadow_apply.rs:1570–1585` joins
callee-evaluation and invocation effects into application effect by constraints;
that does not construct the distinct callee-pending and already-entered
receiver-pending suffixes specified by `C-Call`.

The crosswalk source explicitly preserves this boundary. In
`shadow_candidate_call_formation_crosswalk.rs:579–606`, even a joined captured
record leaves `OriginalBX`, `OriginalXi`, original types/scopes, emitted
Gen-Call-0 membership, complete clause/joint witness, invocation interpretation
and legal whole-tuple substitution unresolved. Ordinary source stubs at
line 106 leave the corresponding complete-emission premises unresolved too.
The test source is corroborating contract evidence, not a test run in this job.

### 4. Typed evidence/lifetime consumers consume assumed source facts

`shadow_typed_evidence.rs:1–5` declares its caller-owned status. Its constructor
checks wiring and exact context identity. `query_conditionally` at line 100
joins Observe(event,port), Receive(owner,port), typed reachability and currently
active roots. It does not construct any of those source judgments.

The `AssumedBoundary` retains an immutable `original_receiver`, while
`AssumedConfiguration` separately supplies current active owners/handlers.
The query checks membership of the candidate handler, candidate owner and that
historical receiver in the supplied current roots. A shared context pointer
prevents mixing differently supplied contexts; it does not prove that the
underlying witnesses interpret one lawful source assignment. The context
itself (`shadow_directional_protection.rs:12`) has caller-supplied beta, scope,
xi and shared-variable witnesses.

A literal-symbol search over the seven assigned HIR/solver owner files found
no `AssumedTypedEvidence`, `AssumedConfiguration`, `AssumedReceive`,
`AssumedObserve` or `shadow_typed_evidence` references. Together with the
inspected producer/consumer APIs, this locates the absent direct bridge; it is
not an exhaustive proof about all repository code or indirect aliases.

The solver's `candidate_context` retains structural relations, origins,
inferred-entry facts and replay/drain state. `lib.rs:11956–12010` sends the Apply
value constraint through the ordinary drain with no inferred-entry or formal
handle. No claim equates that solver continuation or its `ReturnReady` stage
with a source callable's invocation return or receiver expiry.

For raw Catch continuation construction, `candidate_effect.rs:830–864` creates
Function4 response/original-result ports and conservatively includes original
scrutinee effects. It expressly leaves exact suffix precision/hygiene open.
It supplies no historical receiver/current-root/Observe/Receive/expiry tuple.
The existing operation-Catch fixture checks raw-result versus arm-result and
response effects, while its generic and some callback interfaces are explicitly
unsupported. These finite candidate fixtures cannot qualify the original
all-admitted domain, including generic arms, returned providers, residual
lineages and saved shallow resumptions.

## Falsification limits and recommended next action

The exact falsifier for a completed bridge would be an authentic original
admitted complete Call/evidence tuple whose proposed native image loses or
changes one original coordinate, provider-dependent future interface, ordered
suffix, typed receipt/observation, or lifetime test. Constructing such a witness
requires the authentic original-to-native map and its source admission
premises. This packet found the map's first missing constructor, so it supplies
no justified runtime counterexample and no impossibility conclusion.

The mathematical definitions and native field readers are different evidence
sources, but they share the selected source contract. A finite checker supplied
with `Q_e`, sigma, transitions or roots would validate their consequences only;
it would not independently establish their native production. No oracle,
enumeration seed/range, mutation or executable experiment was used.

**One next action:** assign the owner of native Apply admission a bounded
source-correspondence obligation for authentic original `Idx(e)`/complete `Q_e`
under one original sigma, explicitly listing which existing retained fields
implement each original coordinate and which still have no producer. Use that
handoff to decide the smallest separately authorized compiler slice. Do not
repeat the alpha/beta model, infer fresh runtime roots from static identities,
invent a new carrier here, or promote H1/H2/U. H3/P remain disabled.
