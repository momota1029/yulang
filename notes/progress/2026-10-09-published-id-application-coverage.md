## Objective, method and result

Determine whether the selected `Application_N` supplies an authentic source
derivation for a direct published top-level `id` Name applied to an Int literal.
The method is exact source-owner inversion and comparison of retained provenance,
including the imported Old/Keep module. No executable model is used.

The **new `LiteralApply` constructor** requires actual resolution to an immutable
ordinary Value formal. A direct Name of a previously published `id` instead has
its actual publication/instantiation provenance. Under the hypotheses below it
cannot enter that new branch. This is a conditional constructor exclusion,
not a source-language exclusion. The complete `Application_N` also imports
every old emission through `KeepEmission`; the inspected sources neither
provide a concrete old emission for this call nor prove that none exists.
Therefore full-family nonderivability and rejection of `id 0` are unestablished.

Source Generalize supplies real instance formation and preserves its source
frame. Generic source Call and interface constructors retain actual callee,
argument, receipt, entry, result and suffix evidence, but require the actual
Application origin at this seam. They do not identify an Instance owner with
the new branch's formal owner. No extra formal root may be inferred from the
decoded Function type, raw provider identity or the identifier `id`.

## Derivation and exact stopping points

### New branch

Suppose `NewEmission(build,...)` for c is formed by the selected `LiteralApply`
constructor. By §§3–4 and §7 inversion, build retains:

```text
Resolve/Capture(u) -> immutable ordinary Value formal d_f
actual ValueBind(d_f,r_bind) and Reg_N(d_f,R_f)
Name-N route to the same b_f/r_bind
```

Its `D_lit` premise is an actual source route, not a condition saying only
that the callee returns a Value or has Function type. Under hypothesis 2,
the recovered route reaches the published binding/instance, with no formal
there. It therefore cannot supply the required formal provenance. The new
constructor is unavailable for this exact direct Name occurrence. This
conclusion relies on the actual graph/provenance hypothesis; it is not an
universal assertion that a spelling `id` can never name a formal.

Source Generalize §3.3 supplies `Published` and then `Instance`; §3.4 new
derives the definition's description for the same actual binding, and Name
restricts that existing joint certificate. It does not insert a Parameter
rule at the client. The id definition's own `Desc(C,x,...)` describes its
argument and remains under the definition's original scope. Instantiation
of that description does not make the client Name resolve to x. Thus neither
that Desc nor the public root r_i supplies `(d_f,R_f,r_bind)` at c.

### Keep branch

Full `E_N` inversion has two cases:

```text
NewEmission(build,...)   -- ruled out under the exact hypotheses above
KeepEmission(e_old)      -- requires an actual old emission e_old at c
```

Decision-object §3 imports the entire old family, including any old case;
§7 explicitly retains any old literal case. The inclusion/retraction equations
preserve an existing witness but do not create one. To conclude full-family
exclusion requires a separate premise:

```text
H_old_absent(c): no authentic old Application emission at this exact
published-instance callee / Int-literal source occurrence and scope.
```

No inspected clause proves `H_old_absent(c)`. Conversely, to establish coverage
by Keep requires a concrete `e_old`, its installation/member derivation and
complete dependent source origins. No such witness was found in the inspected
clauses. This is a bounded unresolved old-owner supplier, not evidence that
the entire repository or source language lacks this call.

### Generic source/call clauses

The selected source Name rule retains the same binding/provider and complete
joint certificate. The Data-Name and Code-Result rules can form a Value callee
constituent when its actual binding/interface and Result port are supplied.
The literal can likewise have its actual ground Value/Return constituent.
These facts leave the Application owner unresolved:

- Call-input §3.4 `Code-Call` explicitly consumes the actual Application/
  Gen-Call-0 origin, argument ReifyOrigin, complete result port and emitted
  operand-check origins. It constructs Check from these inputs; it does not
  infer their source emission from two well-typed operands.
- Source-interface proof §5 inserts child frames and retains the original
  Application origins; §6 assumes the actual emitted inventory and authentic
  complete operation. IF-Use at an imported Name is contextual incidence,
  not an Application-emission membership constructor.
- Source Generalize's Call schema and `run` preserve the complete real local
  Call law and event fields under L2/L4/L5. Its adequacy theorem cannot supply
  an unprovided particular local owner law, nor identify it with `LiteralApply`.
- Decision-object §9 proposes a typed-operand composition seam but explicitly
  does not adopt its additional cases. Using it for an Instance callee needs
  its authentic returned-provider/root and source exposure incidence. The
  selected formal registration must not be reused by inventing a formal.

The smallest unresolved **positive** premise is therefore an actual emitted
Application owner at c whose callee origin is `Instance(p,i,r_i)`, with the
same complete callee/argument/result/check/operation incidences and scopes.
Either a concrete imported Old witness can supply it, or a separately
authorized owner constructor and its typed realization must do so. A premise
that merely declares a successful call, an endpoint equality or a satisfied
VIncl is larger/circular and does not solve this cut.

## Analytic falsifiers and evidence independence

These are discriminating substitutions of premises, not executed mutants:

| Change | Consequence |
| --- | --- |
| Shadow the spelling `id` with an actual Value formal | The new branch may form under its full contracts; hypothesis 2 fails. This is a different resolved source occurrence. |
| Call `apply id`, then inspect its body `f 0` | Its body Name resolves to formal f, so it may use the new branch. The received runtime provider can be id; the direct published-id Call remains a different owner. |
| Alias the same monomorphic instance to h, then use `h 0` | Source Generalize preserves that instance frame; Alias supplies no Parameter owner. The missing formal route remains missing. |
| Supply a genuine old emission for the direct `id 0` | Keep immediately establishes N coverage; a full-family exclusion claim would be falsified. |
| Substitute the decoded Function root for `R_f` based on type shape | Nominal owners, ValueBind and source route have not been supplied; the derivation is invalid at Formal-N/Name-N. |

No independent semantic oracle or checker was run. This audit trusts the
selected source rules, complete contract interfaces and actual provenance
classification shared with the cited proofs. Constructor inversion tests
applicability of those rules; it does not prove their semantic laws or compiler
conformance. No random seeds/ranges, model enumeration or runtime mutation
counts exist. Coverage is the named selected clauses and their old/new seam,
with the schematic client above; no exhaustive historical-family search was
completed. Some broad initial captures truncated; decisive owner, instance,
Call and interface clauses were reread in bounded slices.

The result fails to establish New exclusion if the actual Resolve graph has

It establishes no full-family exclusion without `H_old_absent`, no positive
Keep coverage without `e_old`, and no semantic whole-call result without the
independent complete local laws and consumer evidence.
