# Powerset carrier candidate for pure intrusion semantics

Branch: `research/simple-sub-intrusion`

Classification: unselected semantic candidate; no implementation authority

## Candidate

An architecture analysis proposed interpreting graph variables in
`D = P(N)`, ordered by subset. Set union/intersection interpret type union and
intersection; `Bottom = ∅` and `Top = N`. `N` is a countable tagged encoding
universe with a distinct constructor tag and disjoint coordinate channels for
each constructor argument and variance direction.

- A nullary atom denotes its unique tag.
- A covariant argument channel contains the encoded argument set.
- A contravariant channel contains its complement in `N`.
- An invariant argument uses both the covariant and complement channels.
- A Function uses a complement channel for its argument and a covariant
  channel for its result.

With disjoint channels, inclusion between same-head Function encodings is
equivalent to contravariant argument inclusion and covariant result inclusion.
For an invariant nominal argument it is equivalent to equality of the encoded
argument sets. Distinct head tags make irreducible constructor mismatches
non-inclusions. This gives a concrete candidate for the pure saturation
axioms; the explicit construction and conditional proof follow, with the
independent review disposition recorded below.

### Explicit tagged-universe construction

Here is a precise candidate construction for that shorthand. Let `C` be the
countable set of admitted constructor symbols, let `A` be a countably infinite
set of atom codes, and choose an injective head-code map `h : C ↪ A`. Let `L` be a countable set
of distinct labels `arg(C,j,+)` and `arg(C,j,-)` for every constructor
argument position `j`. Define `N` as the set of all finite trees generated by

```text
n ::= atom(a) | pair(label, n)       where a ∈ A and label ∈ L
```

The constructors are injective and disjoint: atom codes differ only when
their `a` differs; pair codes differ only when their label or child differs;
no atom code is a pair code. `N` is countable, and for each label `l`,
`channel_l(X) = { pair(l,n) | n ∈ X }` is an injective image of `X`.

Interpret every graph variable as an arbitrary subset of `N`, ordered by
inclusion. Set `Bottom=∅`, `Top=N`, union to set union, and intersection to set
intersection. A nullary constructor `C` denotes `{atom(h(C))}`. For an
`k`-ary constructor `C` with argument variances `v_j`, define

```text
Enc_C(A₁,…,Aₖ) = {atom(h(C))} ∪ ⋃ⱼ ArgChannel(C,j,vⱼ,Aⱼ)
```

where the argument contribution is:

```text
vⱼ = covariant:     channel_arg(C,j,+)(Aⱼ)
vⱼ = contravariant: channel_arg(C,j,-)(N \ Aⱼ)
vⱼ = invariant:    channel_arg(C,j,+)(Aⱼ) ∪ channel_arg(C,j,-)(N \ Aⱼ)
```

`ArgChannel(C,j,v,A)` denotes the corresponding right-hand side above.

By injectivity of `h`, disjointness of the `atom` and `pair` constructors, and
distinct argument-channel labels, for same-head endpoints `Enc_C(A) ⊆ Enc_C(B)`
holds exactly when every covariant `Aⱼ ⊆ Bⱼ`, every
contravariant `Bⱼ ⊆ Aⱼ`, and every invariant `Aⱼ = Bⱼ`. For an invariant
argument, the positive channel proves `Aⱼ ⊆ Bⱼ`; the negative channel proves
`N \ Aⱼ ⊆ N \ Bⱼ`, equivalently `Bⱼ ⊆ Aⱼ`. If heads differ, the left head
code is absent from the right encoding, so inclusion fails. In particular,
these facts establish the pure Function decomposition, invariant nominal
comparison, and distinct-atom mismatch assumptions for this carrier. Set
union/intersection and the empty/full extrema satisfy the remaining lattice
axioms directly. This construction does not define product/record/effect
encodings, a source-to-carrier map, or scheme principal projection. Its use
here remains an unselected semantic candidate, not an Oracle adequacy result.

## Assignment-fiber counterexample

Under the candidate encoding, the finite pure obligation
`Fun(x, Bottom) ≤ y` does not have a pointwise least satisfying assignment to
the full variable tuple `(x,y)`. Let `t` be any universe element. Both
assignments satisfy the obligation:

```text
A: x = N,       y = {fun-tag}
B: x = N \ {t}, y = {fun-tag, arg-channel(t)}
```

The Function result channel is empty because the result is `Bottom`; its
argument channel contains the complement of `x`. A pointwise lower bound of A
and B would have `x ⊆ N \ {t}` and `y ⊆ {fun-tag}`. Since the Function tag is
required in every Function value, `y` must equal `{fun-tag}`. The obligation
then requires `N \ x = ∅`, hence `x=N`, contradicting the lower-bound
condition. Thus the fiber is nonempty but has no least tuple under pointwise
subset order.

This graph belongs to the abstract pure Function/variable fragment as a
Function lower endpoint on a variable. It rules out claiming a pointwise least
assignment for every graph in that fragment. It does **not** refute the draft's
scheme-principality criterion: that criterion projects satisfying local
assignments to a chosen root and compares the full root instance/subsumption
relation. With root `y`, for example, A realizes the least feasible root
value `{fun-tag}`. The witness has not selected a source member root, free
anchors, or fresh identities, and the draft's pure fragment does not yet cover
latent Function effects. The next proof must use the exact `Root_d`/`Pred_d`
criterion from the abstract-semantics draft; assignment-fiber minimality is too
strong as a stand-in for principal scheme behavior.

For the exact graph `G = { Fun(x, Bottom) ≤ y }`, with no anchors or other
obligations, let both `x` and root variable `y` be member-local identities
ranging over `P(N)`. Its projected relation is directly calculable. Let
`F(X,∅) = {fun-tag} ∪ Arg(N ∖ X)`. Every realized root value `Y` contains
`fun-tag`; conversely, for every `Y` containing `fun-tag`, choose `X=N`, giving
`F(X,∅)={fun-tag}⊆Y`. Therefore
`Root_y = Pred_y = {Y | fun-tag ∈ Y}`. The ground scheme root
`F(Top,Bottom)` denotes `{fun-tag}`, and its instance/subsumption closure is
exactly this relation, assuming the candidate's ordinary upward subsumption.
So this graph has no least full assignment but does have a finite principal
root scheme for this particular local root. This is a graph-level calculation
in the candidate carrier, not evidence that Oracle generalization actually
selects this view or erases `x`, or that the public Oracle typing relation uses
the assumed subsumption relation. Fixed anchors or additional obligations can
change the projection.

Adding a fixed outer anchor makes that dependence explicit. For each incoming
use `u`, take local identities `x_u,y_u`, shared anchor `z` with
`η(z)=Z`, selected obligations
`Fun(x_u,Bottom)≤y_u` and `y_u≤z`, and root `y_u`. Then
`Root_y(η) = {Y | fun-tag∈Y ∧ Y⊆Z}`: necessity follows from the two
obligations, and sufficiency uses `x_u=N`. This root fiber is empty exactly
when `fun-tag∉Z`. Its upward closure is empty in that case; otherwise it is
`{T | fun-tag∈T}`, witnessed by `Y={fun-tag}`. A finite candidate scheme with
root `Fun(Top,Bottom)` and selected edge `Fun(Top,Bottom)≤z` has exactly this
`Pred_y(η)` relation under the candidate's instance/subsumption definition,
including the empty-fiber case. Its exact root set is only `{fun-tag}` when
feasible; the original graph can realize any `Y` with
`fun-tag∈Y⊆Z`.

For two or more uses at a fixed `η(z)`, give each use disjoint fresh
`x_u,y_u` identities. With no other cross-use constraints, the exact joint
local-root fiber is the product of the per-use `Root_y(η)` fibers; the
scheme's joint instance/subsumption relation is the product of the per-use
`Pred_y(η)` relations. If the anchor omits `fun-tag`, every required use fiber
is empty. If the anchor is existentially chosen, preserve one shared `Z` for
the family and each use's own fresh range; the result is a union over shared
`Z` of those products, not a product of separately projected marginals.
Receiving-use constraints can also interact through `Z`. This verifies the
identity/fiber calculation for this finite isolated graph only. It does not
show that Oracle root preparation selects these obligations, that its source
scheme erases `x_u`, or that actual incoming uses leave the anchor invariant.

The carrier distinguishes an interval from an equation. The one-sided
`Bottom ≤ q ≤ Fun(Int, q)` has the assignment `q = ∅`; it does not force a
recursive equation. The two-sided matching interval
`Fun(Int, q) ≤ q ≤ Fun(Int, q)` asks for a fixed point of the result-positive
map `q ↦ Fun(Int, q)`. That map is monotone on the complete lattice `P(N)`, so
Tarski gives a fixed point for this specific interval. This does not prove
existence for every recursive or polarity-reversing graph.

For one polarity-reversing guarded self-cycle, `Fun(q, Bottom) ≤ q`, let
`s(n)=pair(arg(Fun,0,-),n)` be the injective argument-channel map and let
`f=atom(h(Fun))∈N` be the Function head element. Its exact assignment
condition is

```text
f ∈ Q  and  for every n ∈ N, n ∉ Q implies s(n) ∈ Q.
```

Equivalently, `Q` contains the Function head element and meets every pair
`{n,s(n)}`. This relation is upward closed: if `Q⊆T` and `Q` meets every such
pair, so does `T`. Therefore this graph's local-root `Root_q` equals its
upward closure `Pred_q`; the same finite regular graph, with its recursive
variable as the root, represents that relation under the candidate
instantiation definition.

There is no pointwise least satisfying assignment. Since every element of
`N` is a finite tree, each `n` has a unique representation `s^k(b)` where `b`
is not in the range of `s`. Let `Q_even` contain every even-depth element
`s^(2m)(b)`, plus `f`; let `Q_odd` contain every odd-depth element
`s^(2m+1)(b)`, plus `f`. Both meet every pair `{n,s(n)}` and contain `f`.
Their intersection is `{f}` because `f` is a root of its own `s`-chain
and all other chains are disjoint. There are atom roots `b≠f`; neither `b`
nor `s(b)` belongs to the intersection, so the intersection is not a
satisfying assignment. A least assignment would have to be contained in both
solutions and hence in their nonsatisfying intersection, a contradiction.
Thus absence of a least full assignment does not by itself defeat this
finite-graph scheme representation. This is one pure carrier calculation;
it does not establish that an Oracle source SCC induces this selected bound,
or that latent Function effects preserve the relation.

### Rejected projection explanation for this trace

An earlier candidate calculation treated the selected upper endpoint as a
positive union `q ∪ K`, and concluded that `Bottom ≤ q ≤ q ∪ K` is assignment
vacuous. That interpretation was wrong. `CompactBounds::Interval.upper` is
collected through `compact_neg_id`; `CompactType` is finalized on that side by
`finalize_neg_type`, which combines its components with negative intersection.
The observed upper is therefore `q ∩ K`, not `q ∪ K`. Its upper inequality is
`q ≤ q ∩ K`, equivalent to `q ≤ K`; it is not tautological. The previous
fiberwise `Pred` explanation based on `q ∪ K` is withdrawn and must not be used
as evidence for Oracle equivalence.

The captured compact root body still places `q` only in the outer Function
argument, with its other occurrences in the recursive interval. The Oracle
polarity trace and pruning path remain valid operational observations. What
remains unproved is whether eliminating this negative-only variable while
discarding its nontrivial upper constraint preserves the scheme's full
instance relation. The earlier independent review checked the proposed
set-theoretic calculation under its stated join premise, but did not audit the
compact endpoint's polarity; it therefore does not review or validate the
withdrawn explanation.

The Oracle's representation path is also now localized. A temporary focused
Rust trace reported `TypeVar2` at level/birth level `TypeLevel(1)`, equal to
the simplification boundary. During both polarity-elimination visits it
reported positive occurrence `false`, negative occurrence `true`, and
`is_simplification_candidate=true`. In
`compact/analysis/mod.rs::eliminate_polar_variables_with_roles_and_non_generic`,

`generalize/mod.rs::prepare_stack_cleaned_compact_root` calls
`prune_unreachable_recursive_bounds`, which keeps only recursive variables

## Conditional review of the negative recursive interval

A compiler-referee review confirmed a counterexample **if** the captured
pre-projection recursive interval is carried into the assignment fiber as an
enforced selected obligation. Its upper is `q ∩ K(q)`, so it requires
`q ≤ K(q)`. In the tagged powerset carrier, every Function encoding omits its
distinct head atom, so `Top` is not feasible; `Bottom` is feasible. The exposed
root has `q` only in its negative outer Function argument. If that argument is
erased to `Top` while the interval is still enforced, the projected upward
closure gains `Fun(Top, R_saved)`: any pre-erasure root below it would, by
Function contravariance, require a feasible `q` with `Top ≤ q`, which is
impossible. The same reasoning applies if the exposed argument is `q ∩ K(q)`,
since the interval makes it equal to `q`.

This does **not** refute the draft's `Root_d`/`Pred_d` definition as currently
staged. There, `H_d` is already projected and simplified; `Erase_d` identities
do not occur in `H_d`. The Oracle trace reports precisely that q is rewritten
out of the root and its now-unreachable recursive row is pruned before the
saved scheme is finalized. Thus the counterexample rejects a tempting but
unjustified modeling step—treating the pre-projection interval as an additional
obligation in the post-projection member relation. It does not prove that
Oracle's projection is sound. Simple-sub §4.3.1 proves polar removal inside its
type-expression semantics is mutually subsuming; it does not by itself prove
the Oracle's pre/post root preparation preserves source typing observations.

The source trace and scheme output establish representation facts, not a
source-to-carrier semantic bridge. The exact Function/effect identity and
public use relation still need characterization before claiming that the
projection preserves Oracle behavior. No public Oracle bug is established.

### Oracle stage boundary confirmed by source audit

Read-only tracing of the frozen Oracle confirms the stage distinction above.
`eliminate_polar_variables_with_roles_and_non_generic` rewrites eligible
one-sided variables to `None`; `rewrite_type_vars` removes their occurrences.
The recursive record can remain in `rec_vars` immediately after that rewrite,
but `prepare_stack_cleaned_compact_root` calls
`prune_unreachable_recursive_bounds`, which computes reachability from the
projected root and roles and drops the now-unreachable q row. Finalization copies
only the surviving recursive rows into `Scheme.recursive_bounds`, and the
scheme instantiator freshens/reinstalls only those rows. For this source, the
captured and previously recorded output has zero finalized recursive bounds.

The collector creates `rec_vars` on a same `(TypeVar, polarity)` recursion
hit (`compact/collect/mod.rs:746–782`, `compact/collect/type_nodes.rs:657–675`).
That representation fact does not establish that a transient row is an
independent public subtype obligation. Only a row that survives into
`Scheme.recursive_bounds` is reinstalled as two subtype edges by the ordinary
scheme instantiator.

Therefore q's interval is operational input to Oracle projection, not an
enforced obligation of the *resulting* scheme instance. Source inspection
establishes this lifecycle, but not that the pre-projection interval denotes an
independent constraint on all source typings, nor that deleting it preserves
all contextual results. The next proof must define the pre-projection meaning
of the compact recursive side table (possibly as projection metadata), then
compare the source/use relation before and after rewrite+prune. Separately,
the already-projected `H_d` relation must match the actual finalized scheme
instantiation path; q's removed edge must not be silently reintroduced there.
Source anchors in the frozen checkout: `compact/analysis/mod.rs:41–56,
214–243`; `compact/analysis/occurrence/substitution.rs:69–85,110–125`;
`generalize/mod.rs:811–829`; `generalize/core/prune.rs:90–121`;
`compact/finalize.rs:119–135`; `generalize/finalize.rs:3–25`;
`instantiate.rs:620–658,1013–1043`. This was source inspection only; no
Oracle files or tests changed.
