## Constructive workspace rollback and allocation argument

`RoutePurpose` and `WorkspaceUndo` are actual source types (`lib.rs:8112–8125`). `RetainedResume` enables inverse workspace events; Fresh rollback clears its empty-entry workspace instead. All non-test queue/frontier mutation sites found by the bounded search go through the helpers below or their rollback inverses. Manual test fixture mutations are outside this constructor claim.

For Q, `enqueue_item` reserves worklist and workspace undo before replay transfer and queue insertion (`lib.rs:12653–12668,12776–12802`). After a successful replay transfer only infallible event/push operations follow. PushFront/PushBack events remove their corresponding newly pushed end on reversal. PopFront owns the exact item and restores it to the front. Reverse chronological composition therefore restores the original ordered Q, including repeated equal items; it never substitutes queue length or a set for the sequence.

For D's frontier, `reserve_diagnostic_admission` reserves vector/index capacity and undo first. `admit_diagnostic` records an event before inserting a previously absent key and appending its position (`lib.rs:12672–12721`). Duplicate admission changes neither vector nor index. Reversal removes the latest exact key. Clear does not destroy the old frontier: retained clear reserves two undo slots, separately allocates replacement lanes, moves the old vector/index into `DeltaClear`/`IndexClear`, records their charge, and samples before continuing (`lib.rs:13452–13476`). A failure after vector replacement but before index replacement already has vector undo; the index has not changed. A failure after either resource sample likewise has its corresponding undo. Each clear reverses to the original allocation and exact values in its original vector order.

When a retained Q/D lane is full, growth allocates a replacement before replacing the old lane, transfers existing contents without changing their order/positions, and retains the old now-empty allocation in a growth event. The replacement's reserved capacity is at least the transferred length. There is no fallible call between replacement/transfer and its event insertion. Later reversal first undoes subsequent additions/pops/clears; at the growth event the earlier length fits the retained old allocation, so transfer back needs no new reservation. This covers failures of the post-event accounting sample as well as later semantic failures. Old queue/vector/index allocations are restored, not merely capacities re-created.

`rollback_workspace` reverses these events (`lib.rs:12733–12768`). It then clears/rebuilds the index from the restored vector in its same allocation. The constructor invariant is a unique-key vector with a position-bijection index; the restored index capacity is sufficient for that vector. Rebuild removes tombstones left by inverse admissions so the capacity-based accounting matches the retained buckets again. The exact mathematical map and allocation capacity are restored. No byte-identical HashMap bucket layout, allocator address theorem, or identity of freshly copied replacement lanes is claimed.

F's old acknowledgement allocation is retained separately by context undo. Context rollback can reinsert a removed old top frame using the stack's retained capacity before truncating new frames. Replay/restoration snapshots are reversed before new operations are removed, so referenced old operations remain available during undo. Both P components come from actual checkpoints: `candidate_context::Checkpoint.processing` and `candidate_effect::Checkpoint.processing`; intrusion rollback invokes their rollback owners (`candidate_intrusion.rs:85–137`, `candidate_effect.rs:159–210`). ReturnReady's temporary scope restoration is therefore reversible even if the route closure reports a later failure.

The named outer parent checkpoint also exists: route begin saves `candidate_source` and the top Local cursor (`lib.rs:9131–9136`); rollback reinstalls them (`lib.rs:9365–9382`). Local atomic steps temporarily pop their Local frame, then push it back before propagating error or committing a test pause (`candidate_scheme.rs:1390–1401`). Its captured G and constructed U remain in that same frame. These are real cursor/ownership facts, but they do not create the missing suspended typed-child return destination.

## Reservation, accounting and fallible boundaries

The owning boundary inventory is:

- Route begin rejects journal-generation exhaustion before changing store state. Its seen-vector reservations and resource samples precede installing the active journal; on those setup errors it rolls back the store (`lib.rs:8981–9130`). Q/D/P/F have not been mutated by setup. This does not assert that spare-journal capacities or physical peaks shrink.
- Start can fail at F reservation, diagnostic clear, resource sample, source seed or enqueue. The synchronous adapter removes its newly created F if present and restores P. The surrounding route owner still supplies semantic rollback; start alone is not a self-contained semantic transaction.
- Full-prefix entry can fail at F undo reservation/copy, any occurrence's replay undo, or accounting. The saved stage has not executed; partial preparation is covered by frame/replay undo. The direct Function path uses this same boundary. Terminal entry retains its one-ack rule.
- Pop reserves both ack storage/preparation when needed and queue inverse before changing ownership. Transport/Context/Dispatch errors propagate before their next-stage assignment; the original checkpoint F/current and semantic journals remain owned. Function admission errors do not install pending; successful admission installs pending before a possible committed pause. Enqueue errors retain pending and do not increment next.
- Diagnostics may fail after earlier helper effects; the whole Diagnostics stage is atomic with respect to commits. Memo mutations use `journal_candidate_memo` before writes (`candidate_intrusion.rs:257–304`), and new error keys/errors have route undo before publication (`lib.rs:14009–14055`). Delta clears have allocation undo. Stage changes to Acknowledgements only after every diagnostic call/clear succeeds.
- Terminal acknowledgement errors occur before d advances; ReturnReady removal has frame undo prepared first. A completion receipt observed inside an eventual failing route is reversed with the same F/P journal; it is not a committed parent handoff.
- `finish_route_transaction` routes errors through one rollback owner and success through commit (`lib.rs:9199–9239`). Context rollback restores F/replay/restoration/P; outer rollback restores source/Local/memos/bounds/errors; retained workspace reversal then restores Q/D. Fresh rollback instead clears Q/D because its admission domain begins empty.

The new accounting is constructional, not supplied by the prefix lemma. `RouteMutationJournal::checked_retained_bytes` charges workspace event capacity plus `workspace_payload_bytes`; growth/clear compute old-allocation charges with checked arithmetic before mutation and update the payload when retaining the old allocation (`lib.rs:8168–8181,12635–12701,13452–13469`). Current Q/D allocations are separately in the resource sampler. `candidate_context::replay_operation_bytes` charges live and undo frames, both A allocations, replay children and restoration/replay undo (`candidate_context.rs:1748–1764`). Candidate intrusion/context and Local cursor/publication undo are included in the sampler (`lib.rs:10594–10637`). Growth samples occur while the new and rollback allocations are both retained; commit/rollback clears payload only when those events are dropped/restored. This verifies the representation and sample wiring for the inspected lanes, not arbitrary allocator overhead or a globally measured peak.

**Rollback-success qualification:** the outer rollback still has fallible `last_mut` validation, `state.refresh_bytes()?`, and accounting reconciliation (`lib.rs:9372–9386,9520–9698`). In particular, refresh failure would return before workspace reversal. On valid constructor states whose retained-byte arithmetic fits, refresh performs checked sums of retained allocations without allocating (`candidate_scheme.rs:238–260`), and the cursor owner exists; workspace reversal itself uses retained capacity. A universal proof that every admitted failure keeps all rollback arithmetic successful is not established here. Physical peaks, spare journal/undo capacities and some existing semantic lane capacities may remain high after rollback; exact restoration of the Q/D/F allocations does not prove equality of all historical resource counters. This qualification is already explicit in W and must remain visible.

## Completion-distinct parent handoff: actual evidence and remaining seam

`ReplayDriveOutcome::{Complete,Queued}` is an actual distinction (`candidate_context.rs:19,2952–2992`). With provenance, a replay child calls synchronous `constrain_live_item`; that call returns only after Diagnostics, ordered acknowledgements and ReturnReady removal. A provenance entry with queued-but-unconsumed work fails rather than treating transfer as completion. With no provenance, the replay drive may enqueue all children and return Queued; the outer drain owns their semantic completion. `candidate_replay_bound` intentionally ignores that queued outcome while still inside dispatch (`candidate_extrusion.rs:748–785`); its `Ok(())` is not a restoration completion receipt.

The actual restoration consumer checks `ReplayDriveOutcome::Complete` before `advance_restoration` (`candidate_extrusion.rs:705–716`). Its saved emission/count remain retained; creation reserves restoration storage before bound insertion, and later steps re-read canonical owner/bound/opposite at the original index (`candidate_extrusion.rs:661–734`). Local advances `next_bound` only after restoration returns Some, with its restoration pointer cleared then (`candidate_scheme.rs:1466–1482`). Thus H5's completion discipline has source evidence for the **synchronous** parent chain, including zero-product retirement. No new bound insertion or fresh use is done by the retained typed stage itself.

The private retained route has no matching operational parent handoff. `candidate_context_consume_replay_child` still drives provenance children synchronously; it neither starts a child that can return More to restoration nor retains a waiting typed-drain handle there. `TypedDrainFrame` contains no replay/restoration/Local return destination. `resume_typed_drain_route` returns a generic closure value to a test caller; none of the inspected callers receives that value as the blocked restoration's completion. Stored restoration/replay pointers and exact rollback cannot supply this absent control edge.

**Smallest exact remaining source premise and owner:** establish a callable retained provenance-child owner that (i) stores the child's F/return destination above its blocked replay/restoration/Local, (ii) returns an unfinished outcome without advancing `next_opposite` or `next_bound`, and (iii) delivers that same child's committed Complete receipt to the retained parent before either cursor advances. The owners are `candidate_context_consume_replay_child`, `candidate_step_bound_restoration` and `step_candidate_local_use`; primary owns any authorized implementation packet. The synchronous Complete check supplies only the synchronous instance of this premise. Do not replace it with Queued, More, stored generated progress, or successful transaction commit.
