1. A successfully retained optional sidecar can reduce availability of a

2. Borrowed batch queries may mutate shared atomic counters; cloning is not

3. `solve`, `run` and `finish` consume the attempt. Late metadata failure does
   not restore a resumable F5 session. Existing error variants do not encode
   all new missing-supplier or invariant causes faithfully.
4. Terminal materialization is a candidate only if authentic inputs survive
   there, no counted query follows the snapshot, no later baseline allocation
   is displaced, and failed optional construction drops all added storage and
   returns the completed baseline result. Equal process-level availability
   remains unproved.


Combining all four premises preserves their exclusions. The conclusion
“the id metadata gate, its caller API and required-metadata failure are
approved for production” requires propositions absent from every antecedent:
reviewed concrete implementation scope and explicit API/resource/failure
approval. It cannot follow from A and J and N and D. This is an authority-scope
derivation, not a proof of source semantics.

The smallest documentary discriminator needs only J: a proposed caller
parameter `valid: bool` with no authentic evidence/dependencies violates the
approved caller-context requirement even if it is set to true. Replacing it
with actual complete evidence removes that particular violation, but still
does not select borrowing/ownership, invalidation or failure policy. This is
a rejected packet shape, not a source counterexample or an executed test.
Adding an otherwise F5-solvable input that fails required metadata separately
exposes the unapproved failure-boundary extension under owner draft §5.

No third guessed-supplier toy model is useful here. The blocker is the actual
producer output and its complete ownership/dependency contract. A transition
checker that assumes those records cannot prove their source production.

## 6. Smallest future reviewable decision packet

Prepare one narrow **caller-context input contract for the identity producer**
first, without publishing it now. It must hold caller ownership fixed and
contain these concrete reviewable objects:

1. Exact entrypoint and admitted one-binding source envelope; concrete input
   type/signature and complete evidence/owner inventory. Identify every field's
   source constructor, dependencies, scope, generation and lifetime. An
   opaque H-source/valid field or a list of type names is insufficient.
2. Explicit ownership alternatives at this seam: borrow complete immutable
   caller evidence through the operation, or retain a typed owning reference
   for the produced package's lifetime. State retention cost and caller
   lifetime consequences. This map selects neither.
3. Concrete validation and stale/foreign/incomplete-context outcomes; exact
   caller-visible error/fallback and certificate-publication behavior. Explain
   whether reuse is absent in this gate or include one bounded versioning and
   invalidation contract. Incremental-compilation rationale alone supplies
   neither policy.
4. Allocation/work/lifetime/teardown account and one deterministic admitted
   envelope. State the memory-pressure claim and process-OOM boundary.
5. Frozen hash, independent focused review, exact choices for the user,
   affected API/implementation paths, and explicit scope excluding general
   annotations/Call, successor solving/consumption and Gate E.

This is a packet outline, not an authoritative draft or choice among its
options. It is not ready for approval until item 1 has authentic suppliers
and items 3–4 are concrete. The follow-up private id SourceBuild producer
packet can then select representation, placement and optional/required/defer
policy against that fixed caller contract. The existing broader owner draft
cannot stand in for this missing API contract. A general annotation+Call
producer and the Direct implementation need separate bounded packets after
their own evidence gates; do not bundle those open families into an id-only
approval question.
