## 3. Operationally relevant typed fields: the real possible seam

Raw U/carrier equality does not suffice. Ordinary source visibility reads the
actual executing typed views, their observation ports, corresponding profile
paths, receiver receipts, source boundary contracts and exact current activity.
Two aliases of the same raw value may have different typed evidence packets.
Changing those fields can therefore matter without any invented type
reflection. This is the first relevant class of potential executable reads.

The responsible source constructors provide two useful exclusions:

* Typed-boundary §4's `View(v,p,c)` enters only its marked **current**
  computation position. Latent construction enters no delimiter for future
  execution. A later latent view requires its own entry/Observe witness.
* Typed-boundary §6 distinguishes `call.effect` from
  `result.latent.effect` by tagged paths even when endpoint variables are
  equal. Result transport acts on matching result paths; it does not copy a
  root call annotation to every descendant. Receive belongs to actual typed
  bindings; merely calling f does not paste f's public view onto all of its
  private bindings.

Consequently changing only dormant result-path checking metadata cannot,
by those constructors, activate a new pre-result observation or grant.
An attack must identify a changed **currently executing** view/port or a
changed matching receipt/profile path, not an unexecuted A_i descendant.
No such original-source change was constructed in this audit.

However, these exclusions are not an exhaustive source elaboration theorem
that every independently regenerated C_i has the same complete executing
view/receipt projection. The typed-boundary package itself retains the raw
source-to-executable-view decoration bridge as an input obligation. Its
projection theorem proves correctness of supplied decorations. Typed-core
§7's erasure theorem also fixes common typed transport/receipt derivations;
it cannot be used to assume precisely their equality under regeneration.

The exact remaining source-owner premise is therefore:

```text
For these independently valid regenerated source contexts, at every prefix
before the first g installation, the current invocation's source-generated
executing view/port, matching boundary/profile/receipt and retained actual
dependency projection are unchanged by the owned result description A_i.
```

The construction owner is Application/Invoke view generation, together with
the source-derived View/Receive/Flow actions at the same tagged ports. It
must account for any A_i dependency of a genuinely retained actual contract;
such a dependency cannot simply be relabeled EventProof. A hypothetical
result binder's free type occurrence alone does not exhibit an executable
read of that occurrence.
