## Alias and separate-new obligations

The selected client handle grammar fixes whether a rule is `new` or alias;
spelling a Name does not decide this after solving. For `new(p,i,r)`, open
one whole description frame at original scopes. For `alias(i,j)`, j uses
literally that same u_i, A_i, ViewLogic tuple and complete certificate frame;
the alias has no new template, anchor allocation or initializer replay.
A separate `new(p,k,r)` allocates another u_k and eligible declaration/image
and ViewLogic region. Both frames retain the same fixed actual provider and
original Shared tuple. A later publication of an alias is a separate source
publication rule, never silently inserted by Alias.

Actual event keys preserve original origin/parent path/occurrence. Two
references to the same event share actual EventField operands. EventProof
may differ by description frame under that same actual event. Distinct
actual invocations have distinct event operands. The same global strategy
and worlds must satisfy a join/Bind, including W; separately satisfiable
views do not establish this joint obligation. These are selected allocation
requirements, not new claims inferred from current F5 fresh rows.

## Bridge readiness falsifiers and broad residual gates

Any one of the following falsifies a claim that this bounded bridge is ready:

1. A required field has only HIR identity/F5 shape/Q success as its supplier,
   or has no authentic owner/local law; a schema tag replaces actual p,
   U_g/IF0, J_z or a dependent operand.
2. A telescope/guard/production alternative is omitted, a type image is
   chosen after its challenge, an actual executed/shared field is freshened,
   or alias/separate-new/event sharing violates the selected keys.
3. Retain/fix is computed from F5 levels/incidence instead of the authenticated
   source records, or an installed monomorphic J_z is replaced by its scheme.
4. Extraction selects an interior root, retains a source-body resolver, loses
   proof choices/intermediates, or erases more than forced raw aliases.
5. Decode installs scalar metadata beside a hidden source root, consults the
   source body, or fails the z=0/z=1 and alias/separate-new discriminators.
6. Direct treats Any as a Function, omits complete domain/observation arms,
   validates a proof against a different root, or assumes an ungrounded law.
7. Publication transfers partial/dangling/cyclic-owning records, claims
   counter neutrality without an uncounted path, or lacks the selected
   failure/discard/drop and bounded resource account.

These are explicit inspection obligations, not executed tests or a theorem
that passing a checklist establishes whole-language conformance. The next
exact owner is the source-formation/publication architect: supply a frozen
authentic producer-and-layout packet for the minimum package, with each
missing local-law/publication/anchor supplier assigned. The id-only draft

Extraction/decode/Direct implementers require subsequent explicit scope.

Effective joint solving/inference, proof search, ordinary diagnostics and
