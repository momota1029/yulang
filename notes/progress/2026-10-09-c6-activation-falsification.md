## Objective and result

realized annotation slot, and local release additionally requiring a live
eligible handling opportunity. The assigned contracts establish neither
equivalence nor a forced selection. They explicitly leave lawful realization
open. A difference between candidate guards is derivable, but no actual
source-observable distinguishing execution follows from those guards alone.

The remaining alternative is genuine at the proposal level, not an established
pair of complete language semantics. In particular, the evidence does not
justify asking the user to choose between two already validated observable

rule at an authentic annotated contribution, including its activation
condition and its connection to an observer.

This lane does not repeat the incidence-composition derivation. It grants

## Explicit hypotheses for the local comparison

Use the following proof symbols only to expose the missing premises; they
are not proposed compiler atoms or runtime state.

H1. `B(s,a,k)` is an authentic local package for state/cut `s`: actual
annotation `a`, corresponding contribution `k`, original scope and one joint
`xi`, genuine direct endpoint/complete target comparison, and retained prior
evidence. If release changes protection, its changeable protection origin is
authentic; it is not fabricated from the annotation-absence lineage of this
annotated formal or taken from unrelated provider-owned evidence.

H2. `R(s,a,k)` is a supplied set of local release outcomes with independent
lawful-action and frame certificates, all changing only the governed
contribution. Its existence and source adequacy are **not established**.
Fix this same set for both candidates so that the comparison changes only
the activation guard. The guard alone cannot construct `R`.

H3. `H(s,a,k)` means an independently eligible live handling opportunity for
this contribution at this same cut. It is not merely an ambient handler,
a static slot, successful comparison, or a Handler spelling. Its provider,
receipt, typed incidence and scope obligations must be genuine. The exact
producer is also unsupplied.

H4. Both candidates permit a common unchanged local outcome `N(s)` when
otherwise appropriate; release permission is not an obligation. The same
role/entry, endpoints, contribution and evidence checks govern both.

Under these hypotheses their release-outcome sets are:

```text
Slot(s) = R(s,a,k)  if B(s,a,k), otherwise empty
Live(s) = R(s,a,k)  if B(s,a,k) and H(s,a,k), otherwise empty
```

The unchanged outcome is outside these *release* sets and common to both.
Calling `B` a realized annotation cut does not assume that release has already
occurred. Otherwise the proposed comparison would be circular.

## Conditional characterization and minimized pair

**Local guard lemma.** Under H1–H4, Live release outcomes are included in
Slot release outcomes. Their local release sets are equal throughout an
explicit envelope `E` iff every `s` in `E` with `B(s,a,k)` and not
`H(s,a,k)` has `R(s,a,k)` empty. Proof: the conjunction restricts the same
set `R`; its only lost branch is `B and not H`. That branch has no difference
exactly when it has no release outcome. This is a rule-relative conditional
characterization, not a theorem that source typing supplies H1–H3. QED.

| Authentic package B | Eligible live H | Slot release outcomes | Live release outcomes |
| --- | --- | --- | --- |
| absent | either | empty | empty |
| present | present | R | R |
| present | absent | R | empty |

The last row is the sole local separating case. Its smallest hypothetical
pair uses one annotation, one corresponding `io` contribution, one actual
boundary, one lawful release certificate and a common unchanged option:

```text
s0: B(a,k), R(a,k) nonempty, no eligible live opportunity H(a,k)
s1: B(a,k), same kind of release certificate, eligible live H(a,k)
```

At `s1` the candidate guards agree. At `s0` only Slot licenses that release.
This is minimal in the number of incident contributions and annotations for
the stated local question: without either, the guard has no governed action;
without a nonempty lawful outcome, there is no difference. It is not a
minimized accepted source program. Altering a Boolean H while claiming the
remaining typed certificates survive is precisely an unproved construction.
No such typed pair was established or executed.

A genuine contract-relative counterexample must supply that `s0` from an
owning source derivation, not posit it as a legal state. Conversely,
equivalence would require a source theorem excluding such nonempty `s0`
states, for example `B and R nonempty implies H`, over a stated envelope.
None of the assigned governing sections supplies either result.

## Why the obvious request witness does not discriminate

The smallest source-shaped starting point is the approved
`apply(f: _ -> [io] _, x) = f x`, a known existing callable with one `io`
contribution and ordinary value `x`. Keep the actual callable role and entry;
retain its lower occurrence separately from the annotated formal's upper
view. Merely placing this use outside an ambient handler does not construct
`s0`: a live eligible opportunity might arise from a separately justified
invocation boundary, and incidence/protection must still be supplied.

Even if absence of every eligible opportunity were genuinely proved, a
request at that same point is not automatically an observable separator.
Neither candidate thereby supplies an actual eligible handler, so choosing
different local evidence does not alone prove different handling traces.
A statement that one run handles the request and the other does not would
invent exactly the visibility/handling bridge still missing here.

Likewise, recording a different internal realization certificate is a local
proof-output distinction, not by itself an acceptance, principal-solution,
adapter, residual-profile or runtime distinction. Printed `[io]` endpoints
can coincide despite different internal origins. The selected contracts do
not permit deriving source observability by inspecting this spelling.

A later continuation could discriminate only with additional premises:
authentic transport of the changed contribution evidence, a then-live typed
event and receiver, a specified visibility/handling dependence on that local
change, and proof that Live cannot realize the same behavior at a later
eligible cut. Static persistence cannot restore an exited maker's authority.
The callback §8 escaping case explicitly supplies no substitute for this
future live-view derivation. Thus the simple “remove now, handle later” story
does not establish a separator either.

This argument does not prove observational equivalence. It establishes why
the two shortest proposed observations fail to follow from current premises:
an immediate unhandled request and a later request after transported release.
Both leave the same lawful-source/visibility premise untouched. No third
transition-table probe or larger case enumeration is warranted.

## Exact blocker and falsification obligations

For a distinguishing accepted-source result, the missing producer package is:

1. A genuine source-derived `B and not H` cut for the annotated `k`, including
   authentic removable protection if the action changes protection.
2. Independent lawful release at that cut, with its scoped frame; this must
   justify nonempty `R` without assuming Slot as the source rule.
3. An independently typed observation/continuation whose allowed outcome
   changes, with the same original identities/dependencies and all later
   activation opportunities accounted for.

For equivalence, replace that package with a scoped exclusion theorem or a
continuation simulation proving that every extra Slot release is unobservable
and does not change the approved inference/evidence outcomes. A no-request
example, an empty R, or proof of agreement only while H holds is insufficient.

If “eligible live opportunity” is defined using visibility *after* the
proposed release, eligibility would depend on its own conclusion. The owning
rule must avoid that circularity or explicitly supply a justified joint
derivation. This note selects neither an ordering nor a new handler rule.

Failure conditions: invented incidence or protection origin; provider-owned
marks changed; comparison success used as authority; no ambient handler
mistaken for no eligible receiver; inferred role mistaken for actual role;
permission made mandatory; prior endpoint/evidence dropped; later reactivation
silently allowed in only one candidate; or local certificate difference
reported as observed behavior without an independent observation judgment.
