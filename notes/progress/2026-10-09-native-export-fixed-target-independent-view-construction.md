## Objective and result

Construct the Fixed target at its own authentic source interface first, then
ask for an actual lawful map to bare id's original telescope/root at the same
scope. This differs from C1's attempt to install a capture directly into
id's unchanged IF.

The selected rules construct a complete `VP+Fixed(J_0)` source/public record
for `my pick ignored=z`, with `my z=0`, at `IF_pick`. They do not supply the
next root-relative source certificate that turns this into an independently
valid view of the original `my id x=x` component. The first missing bridge
is an owner-preserving map for the resolved read/capture operands, or a
separately justified complete comparison law at the two actual roots. An
own-head-valid target and a shared lexical scope do not constitute that map.

This is a constructive success for independent **pick** target formation and
a localized gap for **id** same-source validity. It is neither a counterexample
to arbitrary sound Function views nor a proof that every cross-root comparison
is impossible.

## Single source instance and construction

Use one enclosing lexical block with the following immutable declarations:

```text
my z=0

```

This is a schematic instance of the selected native constructors, not a
parser/compiler run. Put both instantiated input types at Int. Let `Gamma`
be the enclosing installed scope, `p_0` the once-created literal provider,
and `Omega_id`, `Omega_pick` the original registered telescopes. The two IF
maps remain distinct throughout.

Explicit hypotheses are authentic ground literal/publication, immutable
Parameter/Lambda/Name formation in the native envelope, and the complete
generic inlet/phase rules with their original world/guard/evidence operands.
The following construction is licensed under those hypotheses:

1. Literal/publication at Gamma constructs
   `J_0=(0,p_0,Int,ground hereditary certificate,original world/slot dependencies)`.
   Its initializer runs once; all future events must remain compatible with
   those dependencies. The public contract contains no private source body.
2. Bare id formation registers its formal x and the resolved read of that
   formal. Its phase record is `VP(I_id[Int;Delta],Int,Int,IF_id)` with the
   source-owned same-value result dependency. Its capture set is empty.
3. Pick formation registers formal ignored and captures the installed z
   binding. This supplies an authentic `IF_pick` capture incidence and J_0's
   full restriction evidence there. Pick's capture is monomorphic.
4. Pick entry still Forces and rebinds its input at ignored, including pending
   or divergent entry. At completed entry, restrict J_0 along the compatible
   current-world history. This supplies `V(Int,0,p_0)` at the captured z slot.
5. The actual resolved Name z and pure Return produce `(0,p_0)` at pick's body
   result; the raw aliases are `read=body=outward=z`. They do not identify z
   with the ignored formal or with an arbitrary argument provider.
6. PICK-J constructs
   `V_pick=VP(I_pick[Int;Delta],Int,Int,IF_pick)+Fixed(0,J_0)`.
   Completed BodyValue/Done select `(0,p_0)`; Start/Received/pending Force
   assert no such result equality. Hereditary J_0 covers independent future

7. PE-PICK retains J_0's complete fixed free dependencies and generalizes only
   the eligible ignored-input binder. Its result tag is `PublicValue(J_0)`.
   Decode and public use operate on this actual pick record and its own scopes.

Thus the target's ground certificate, capture producer, current-world

## First missing map

The relevant original source operands are:

```text
id:   formal x;       ReadCert(slot x); body Name x; captures {}
pick: formal ignored; ReadCert(slot z); body Name z; captures {z -> J_0}
```

Both records may be available in Gamma. That gives legal access to the
literal's installed public contract; it supplies no incidence in Omega_id
owning a capture of z. Whole renaming moves all existing incidents together.
It cannot change a Name resolved to the formal into a Name resolved to the
external capture. Renaming or grafting an endpoint is insufficient when the
ordered source operands, original typed paths and provider witnesses remain
active.

The missing certificate is a map `mu` from the independently registered
Fixed target to the actual original id root that justifies all of the
following together:

```text
original pick z/read/capture scope and provider witness
    -> lawful use at original id formal/read/result incidences;
J_0 restriction at each compatible current world and future event;
all original ordered constructor operands and source occurrence constraints;
one shared input/output/intermediate proof tuple at the actual root check.
```

No selected constructor instance here supplies `mu`. In particular, logical
own-head validation in PE §6.1 is a prerequisite to a comparison, not its
proof. A fresh definition of an auxiliary coordinate does not supply an
authentic source capture/read witness. Identical displayed `Int -> Int`
arrows or equal runtime return integers supply neither provider identity nor
this scoped map.

Under the **Draft §6.3 hypotheses**, the pick derivation alone already fails
to provide condition 1's derivation for the same id source component. Trying
to transplant its source occurrence witnesses next reaches condition 2's
original kernel/path alignment: id's resolved formal read is replaced by a
different capture read. Calling the containing block the common component
does not select pick's witness as id's root witness; the corresponding original
source occurrences and root must still be preserved. This is a conditional
classification of the supplied derivation, not an adopted production view policy.

One candidate route is to restrict the initial id carrier to a separately
constructed t that returns exactly J_0's decorated value/provider, then prove
a complete ordinary inclusion between the actual id and Fixed target records.
Merely writing `H: c=t` does not construct t's Force/result/future law, its
current-world dependencies or the comparison's scope pairing. Even a completed
semantic inclusion would require separate justification before being claimed
as §6.3 same-source validity. Those missing certificates are not assumed here.
