## Conditional direct-append obstruction

Exact premise: let S remain its canonical owner at level m. Ordinary
`candidate_apply_effect(X,S)` can insert a **direct positive lower** X on S
only when X is a distinct EffectRow and L(X) < m. When L(X) >= m, the first
row/row branch instead installs a negative upper S on X. The equality branch
does nothing. This follows directly from `candidate_extrusion.rs:727–750`,
without assuming an abstract replay checker.

Thus, under the candidate assumption that every row available during the
callback has level >=1 and S remains level1, an ordinary comparison cannot
append any direct lower on S. Negative extrusion cannot create its copy link
at S when its target is >=1 either: `Work::Visit` returns S unchanged when
L(S) <= target (`candidate_extrusion.rs:74–88`). An extrusion `Work::Bound`
owns a fresh copy; identifying that copy with S requires a separate qualifying
merge. This statement deliberately excludes direct initialization/restoration
and merge insertion owners; their physical insertion is not level-oriented.

The reviewed exact source supplies bounded evidence for the floor. The last
full state preceding the target restore is action56 at log1543: all 103
allocated Effect rows have minimum level1; S53 and R47 both have level1.
The restoration is at log1712. Source traversal starts at1, preserves lambda
levels, and raises block initializer levels (`candidate_source.rs:229–280`);
freshening allocates local rows at the actual use level
(`candidate_scheme.rs:841–853`). This is evidence for this local route, not an
all-source/all-import/all-auxiliary-constructor level-floor proof. No level0
restriction is proposed.

## Why lifting the owner does not supply the callback

The primary proposed this shape: an outer annotated f parameter at level1,
then an inner local left binding containing the old bridge/defer body at
level2. The actual source traversal supports these relative levels: outer f
stays1, inner left's initializer and g parameter start2, and its bridge/defer
initializers start3. Conditional on the same extrusion construction, the g
demand can make S level2 while the old f-derived anchor stays1. Its defer
capture boundary/use level are2. The strict-level obstruction is consequently
not a universal blocker for that wrapper.

But the local Function-loop mutation schedule remains unavailable directly
inside this **Effect** restoration. The first task is R <: Allowance, not a
Function comparison. `lib.rs:11576–11583` dispatches the candidate Effect task
to `candidate_apply_effect`; that owner does not extrude Functions or enqueue
a Value comparison. Function ports establish prior state but are not invoked
by the restored Effect comparison itself. Global intrusion settlement is a
separate possible bridge and has not been ruled out.

One discriminating conditional invariant follows from the real task cases.
Assume an idle entry, a negative Allowance restore, and no callback-time SCC
merge/reconstruction. Row-origin callback tasks have Allowance uppers.
Installing one replays lower rows/exact operands against that same Allowance.
Support expansion emits members and its tail against the same upper.
A mismatching Contribution/AnnotationMember flows to the Allowance tail;
its resulting row insertion is an **exact scalar lower**, and subsequent
replays still carry that scalar lower. Contextual filter execution registers
additional Allowance uppers on the same lower. Bottom does nothing. These
cases preserve “row-origin tasks have non-row uppers”; none creates X <: S
with row X and row S, hence none supplies a direct lower displacement or a
Function comparison. Sources: `candidate_effect.rs:781–833`,
`candidate_context.rs:1869–1923`, `candidate_extrusion.rs:645–691,727–750`.
This conditional case analysis leaves SCC-induced comparisons open. Merely
raising S from1 to2 changes the necessary inequality and leaves its missing
task-construction premise untouched. No compile/run was justified by it.

## Exact surviving equality-transport route

The prior action56 parent records do identify a real third-owner candidate:

```text
Parent { copy: Effect(47), parent: Effect(45), polarity: Negative, target: 1 }
R45: level3, direct lowers [47], direct uppers [11], exact sides empty
R47: level1, direct lowers [], direct uppers [53,51,6],
     exact uppers [Allowance1,Allowance3,Allowance8]
q96: level2, direct sides empty, exact uppers [Allowance8]
```

The R47/Allowance9 callback can supply the graph path
`R47 -> Allowance9 -> q113`. For the recorded pair R47/R45 to become one SCC
at that callback, the missing return is **q113 ->* R45**. R45 -> R47 already
exists through the parent's direct lower. This is an exact graph constructor
target, not a claim that it occurs. The reviewed q96 has no direct return;
the viewed prior run observes generation8 throughout every callback boundary
and no such merge. Simply spelling the old tail in another annotation scope
does not create q113/R45 identity or this return. The wrapper described above
does not add it either.

If this pair did merge, `candidate_context_canonicalize_bounds`
(`candidate_context.rs:2064–2082`) would scan third-owner keys and transport
S53's old key `(S53,+,R47)` to its current `(S53,+,R45)` without a full S53
owner replay. This is the actual promising writer for post-frontier fiber
growth/key change. `merge_candidate_rows` replays the **merged parent R45**;
that replay does not by itself prove incoming-use coverage for S53's old
ordered obligation. Conversely the physical lower positions stay present,
and the target's repeated R47 slots can select the current fiber later, so a
merge is not by itself a missing-omega witness. A concrete source must show
the return appearing at the required time and the required ordered relation
remaining absent after all later restores, links, diagnostics and retries.

Capture incidence cannot substitute for this constructor. Its registration
links a tail to `(source,view)` metadata only
(`candidate_effect.rs:372–435`). Capture enumerates that metadata into a
negative Allowance bound (`candidate_scheme.rs:490–502`). The resulting
fresh transport attaches before the associated restore begins
(`candidate_scheme.rs:1000–1030`); the restoration loop itself does not
re-enter scheme capture/freshening. Incidence registration alone appends no
positive lower and calls no relation-fiber attach. Three actual fiber attach
entrypoints in `candidate_context.rs` are bound origin at1978, fresh transport
at2092, and transport witness at2140. Ordinary insertion/filter registration
has its own replay; equality/extrusion transport still needs separate coverage.
