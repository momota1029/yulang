## Additional direct source rules and their limits

### Known Name synthesis

[Source result synthesis §4](../design/2026-10-02-source-result-synthesis-choice.md#4-selected-a-and-rejected-implicit-alternatives)
is Authoritative and states:

```text
Gamma(x) = I
-----------------
Synth(name x) = I

Result(Value(A))         = Comp(empty,A)
Result(Computation(E,A)) = Comp(E,A)
```

Its §1 makes lookup, transport and synthesis inert; an additional pure result
layer requires explicit introduction. Its §3 requires consistent transport of
selected ports, original profiles and corresponding symbolic `K,D`, while
explicitly leaving the generalization/intrusion theorem open. This is a direct
source lookup/interface rule, not an endpoint-allocation or existential-opening
judgment.

[Typed computation core §6, “Structural rules producing the core derivation”](../design/2026-10-02-typed-computation-core-elaboration.md#structural-rules-producing-the-core-derivation)
copies `Gamma(x)` for Name and binds an ordinary local result as
`x:Value(A_r)`. The following coherence/transport subsection proves skeleton
substitution only when source tags and typing premises are preserved. The
document is Draft, and explicitly excludes a completed recursive-binding
inference theorem. Its table's “explicit introduction” introduces computation
data; it is not a rule introducing a §22 existential.

### Existing Name occurrence and routing

[F4 §1](../design/2026-09-21-oracle-aligned-f4-int-scheme-scc-draft.md#1-oracle-から引き継ぐ意味論)
adopts live inference roots, internal `target.root <: use.value`, and closed
positive-predicate freshening followed by `predicate <: use.value`. F4 §2
owns resolved Name value/effect components; §5 specifies the separate use
occurrence and route. F4 §3's final scheme has zero binders and only
`Bottom | Int`. These are direct adopted rules within F4's stated slice.
They do not cover recursive Function schemes or classify a Name row under
§22.

[F5 §5](../design/2026-09-21-f5-general-function-scheme-foundation-draft.md#5-live-inference-ownership)
translates source endpoint recipes into session-local live variables with
level and origin/non-generic metadata. F5 §21 retains module-Name occurrence
recipes and internal/incoming routing; §30 says an Integer or module-Name body
keeps its own live value/effect row, unlike a parameter Name, whose value
reuses its parameter directly. These rules establish a real distinction
between the known source interface and its live representation. The origin
metadata is specified for generalization eligibility; no section identifies
it with §22 existential introduction.

The earlier [SCC foundation, “Oracle invariant”](../design/2026-09-20-constraint-collection-scc-foundation-draft.md#oracle-invariant)
and [static session §4](../design/2026-09-21-oracle-aligned-static-scc-inference-session-draft.md#4-fixed-ordering-obligations-for-the-future-f4)

supplies an existential typing rule. F4/F5 later supersede their narrower
Name/scheme exclusions within the stated scopes.

### Recursive binder and external substitution

[F5 §7](../design/2026-09-21-f5-general-function-scheme-foundation-draft.md#7-arenas-and-closed-scheme-representation)
directly separates ordinary `Q` and recursive `R` namespaces. Every `R` has a
neutral lower/upper entry. §§8,23 create `R` from productive Function-guarded
active re-entry; §33 classifies retained `R` before one-sided elimination and
excludes it from `Q`. This is an adopted representation rule for recursion,
not a source package existential-introduction rule. A recursive bound record
is not identified with `Req_p` or the equality kernel's `X` anywhere here.

F5 §§9,23 directly require a fresh live variable for each `Q/R` at the
consuming definition's use-site level, restore both `R` sides, and route the
positive predicate below the exact occurrence row. Repeated references share
one fresh row within a use; separate uses have disjoint substitutions.
“Fresh live variable” establishes allocation and sharing; it does not itself
establish either sign of the §22 introduction predicate. The charter's later
retirement boundary prevents promoting these F5-specific rules into mandatory
successor generalization semantics.

F5 §12 is a further direct provenance rule: scheme drafting/finalization must
not fabricate a source cause, while recursive-bound restoration carries
derived instantiation provenance keyed by route, binder and bound side. This
provides a useful trace key for a future source-to-row bridge. Absence of a
fabricated HIR cause is not proof that the corresponding source typing step
introduces no existential, so the provenance key cannot replace that bridge.

## Limited constructive derivation

Let `d_name` be a source synthesis step using the Authoritative §4 Name rule.
The exact hypotheses are:

1. The occurrence resolves to `x` with already supplied interface `Gamma(x)=I`.
2. `I` carries its existing binder identities and source interface positions;
   equality of an erased type shape does not replace those positions.
3. The step is this Name synthesis judgment, without an additional package
   elimination or other typing judgment being silently attached to it.

Then the interface of `d_name` is exactly `I`. The displayed rule has no fresh
binder premise, substitution premise, or package-opening conclusion. It copies
the interface supplied by hypothesis 1. Therefore this step contributes no
new source binder identity. An alias/return of a value with a previously
packaged witness can transport that witness without making an independently
solvable witness; charter §20 directly requires that correspondence for
request aliases.

This conclusion is about the Name rule's contribution. It does not establish
that `I` contains no existing existential package, that generalization never
instantiates the binding, or that a fresh live occurrence row carries no
guarded dependency. Hypothesis 3 also does not prove every production Name
occurrence is elaborated using only this step.

To infer a property of an allocated row `v`, one additionally needs an
interpretation/transport statement associating `v` with the relevant source
endpoint and preserving the source introduction/opening history. F4/F5's
directed relation to `use.value` is not identity of endpoints or such a
transport theorem. Merely substituting a fresh `R` row into a legacy predicate
does not construct that missing source interpretation either.

## Proof obligation versus new policy

The current authority expressly leaves complete source generation,
generalization/lifecycle correspondence and variable/extrusion coverage as
proof/representation gates. Constructing a source-to-row correspondence for
the selected Name rule and preserving already selected existential openings
is work under those gates. It does not require reopening the accepted guard,
variable-only levels, or witness retention.

However, this inventory cannot turn an unspecified introduction judgment into
a theorem. No selected source generalization/use judgment here classifies the
successor analogue of `R`. A candidate bridge must label its allocation and
opening clauses as assumptions until derived from an adopted source contract
or selected as part of the successor design. This is a precise missing
definition/premise, not evidence that the user already chose either a blanket
exemption or blanket guarding of ordinary fresh inference rows.

A new policy would arise if a proposed bridge added existential opening to
ordinary lookup/instantiation, guarded all fresh inference allocations merely
because they are fresh, or introduced new source rejection/generalization
restrictions. Those additions need authority resolution and, when they change
language meaning, approval. The present documents do not force such a change.
Absence of an operation request in the source group alone is insufficient:
§20 distinguishes inference existentials rather than eliminating them.

Recommended next action: construct one comparison-independent source-to-row
origin transport judgment for the exact bare-alias envelope, using the selected
Name-copy rule as a premise and exposing the generalized-interface/use rule
needed for the fresh recursive row. Return any clause that changes source
meaning to the primary; do not add another origin-free graph completion probe.
