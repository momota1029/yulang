## 3. Smallest candidate construction, and why it is not a witness

Consider two distinct actual immutable Lambda occurrences `g_L,g_R`, each
with a Unit formal and inert Unit result, and two actual Lambda occurrences
`f_L,f_R` whose Unit-entry bodies return respectively `Name(g_L)` and
`Name(g_R)`. These are construction trees using the selected Lambda, Name and
Result cases, not invented alternate packet profiles or an opaque primitive.
They can be placed in one immutable registered source environment; this
description is not an assertion that a native run of a particular surface
program has been performed.

Constructor inversion gives different actual returned providers at the two
branches. Source-interface construction §5 retains each original provider
and its latent/future slot; Bind and the following Name retain the chosen
branch's same actual result. Their ordinary scalar skeletons can both be
`Unit -> (Unit -> Unit)` with empty outward support. Thus the provider
coordinate is a plausible collision target after erasure.

Three additional facts would be needed to turn this into the requested
counterexample, and none follows from that erasure:

1. Complete independently valid descriptor instances and checked challenges
   for both providers in the original common source fiber, including all
   original scopes, admission and observation contracts.
2. A source-required discriminatory observation or incidence predicate on
   the same transported result path. Distinct roots must be retained, but two
   pure extensionally matching providers need not cause opposite comparison
   answers. The source rules prohibit replacing the actual provider; they do
   not require rejection merely because two provider identities differ.
3. An actual native accepting route demonstrating that this predicate is
   violated or identified incorrectly. Equality of printed/erased types is
   neither equality of native row handles nor equality of `RelationKey`.

The first item is already the stopping input. Contextual membership §2 and
its semantic construction §§2,3.1 require independently interpreted `D_F`
and `P_F`; the displayed Function skeleton does not instantiate them. No
admitted challenge or observation with a different required answer was
supplied by this candidate. Inventing a provider-sensitive guard or choosing
protected/unprotected profiles freely would add precisely the missing input.
Giving two opaque W/Z arms different guards has the same defect unless their
actual independently typed declarations and domain certificates are supplied.

Consequently this is only a minimized *candidate attack*, not two complete
source-qualified contrast cases, an established same-scalar native collision,
or a compiler counterexample. No exhaustive source search was performed.
