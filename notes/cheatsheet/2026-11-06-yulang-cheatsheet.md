## 束縛と順序 (章2・4.7)

値制限を受けない束縛は順不同、受ける束縛は上から順に評価される。

- 関数は自分自身を呼べる。引数のない値の束縛は、自分を指せない。(確定, 章2.1)

  ```yulang
  my fact n = if n == 0: 1 else: n * fact (n - 1)   // 自己再帰
  my a = 1
  my a = a + 1                                       // 右辺の a は 1 行目の a。結果は 2
  ```

- 関数・lambda・literal・constructor は、順不同で互いを参照できる(相互再帰も可)。関数適用を含む束縛は、上から順に評価される。原則は「副作用の順番が変わったらエラー」。規則の主語は、computed な束縛どうしの順序。(確定, 章2.1)
- 判定は保守的。評価される位置に関数が現れたら、呼んでも渡しても「呼ばれた」とみなす。lambda で包むと外れる。(確定, 2026-11-05)

  ```yulang
  my h x = x + late
  my k = map h [1, 2]        // エラー: h が呼ばれたとみなし、h が読む late は k より下
  my late = compute 3

  my k2 = \ys -> map h ys    // OK: lambda の中は呼ばれるまで評価されない
  ```

  名前で決まらない呼び出し(`fs[0]` の結果を呼ぶなど)は、モジュール内の関数本体が参照する computed な束縛を、すべて読みうるとみなす。
- 値の cycle は、この規則の特別な場合として拒否される。(確定, 章4.7)

  ```yulang
  my a = make b
  my b = make a              // エラー
  ```

## 型と注釈 (章4・5.5)

注釈は「許す型」。値の型は公開型になり、effect の行は検査だけ。

- `never` は最小の型、`any` は最大の型。どちらも注釈に書ける。(確定, 章4.1, 2026-11-06)
  `any` は TypeScript の `unknown` と同じで、受けた値は何にも使えない。TypeScript の `any`(型検査を抜ける穴)とは別物。junction の `all` / `any` は値の名前で、型とは名前空間が別。推論で負の位置に残った未知の型は `any` になる。
- 値の型の注釈は、公開される型を決める。推論結果 ≤ 注釈を検査し、公開型は注釈の型。(確定, 章4.2, 2026-11-06)

  ```yulang
  my f(): {x: int} = {x: 1, y: 2}   // 本体は {x: int, y: int}。公開型は () -> {x: int}
  my g(n: int) = n + 1              // 公開型は int -> int
  ```

- effect の行は例外。注釈は検査するだけで、行変数を束縛しない。検査する時点は、その binding(相互再帰なら SCC 全体)の推論が終わった、一般化の直前。ソース順にも本体内の順序にも依らない。呼び出し側で後から入る effect は見ない(型の具体化は代入)。入れ子の `my` は自分の終わりで検査する。(確定, 章5.5・5.5b)

  ```yulang
  my f(g): [io] _ =
      undet::choice [1, 2]        // 推論の終わりで undet が見える → [io] に収まらずエラー
  ```

- 一般化されるのは構文上の値だけ。計算された束縛は単相のまま。(確定, 章4.7)

  ```yulang
  my id = \x -> x                // 多相
  my id2 = (\f -> f) (\x -> x)   // 右辺が計算 → 単相
  ```

- SCC の中は単相で連立して解く。全引数と戻り値の型がすべて書かれた binding だけ、多相再帰を使える。effect 行は数えない。再帰の最中、その関数の行は共有される。(確定, 章4.7, 2026-11-05)

  ```yulang
  my depth(x: 'a, n: int): int =
      if n == 0: 1
      else: depth((x, x), n - 1) + 1   // 注釈があるので 'a を変えて呼べる
  ```

- union / intersection は推論結果にだけ現れる。注釈には書けない。(確定, 章4.8)

## variant (章4.5・3b.4)

- tag は一意で、payload は tag ごとに union へ合流する。(確定, 2026-11-05)

  ```yulang
  if b then :id 1 else :id "a"      // :id (int | str)。:id int | :id str にはならない
  ```

  payload の一部だけを処理することはできない。`case` が `:id x` を拾えば、`x: int | str` の全体が取れる。
- 拾った tag を除いた残りは推論される(`'r`)。網羅性は「tag の集合が閉じているか」で決まる。guard 付きの arm は網羅に数えない。残りが空になる ⇔ 全 tag を処理した。(確定)

## effect と handler (章5)

高階の callback の effect は、境界ごとの符号付き重みで守られ、解除で呼び出し側に戻る。

- operation 固有の型変数 `'b`: 呼び出す側は好きな型、handler の側は抽象型。(確定, 章5.1, 2026-11-05)

  ```yulang
  act apply:
      our twice: ('b -> 'b) -> ()

  apply::twice (\x -> x + 1)         // 呼び出し側は 'b を int にしてよい
  ```

  handler の中で `'b` の値は、`k` に渡して再開するか、別の `'b -> 'b` と合成するだけ。handler の結果の型や外側の環境に現れたらエラー(存在型は導入しない)。
- 保護と解除は、境界ごとの整数の重みで表す。handler が捕まえられるのは、全部の重みが 0 のときだけ。(意味は確定、記法は暫定, 章7.3)
  `'e`: 保護(許可なし)。`'e[io]`: `io` だけ引ける。`'e?`: その位置で解除。入れ子の解除は `'e??`(暫定)。重みの数字は表示に出さない。

  ```text
  ('a -> ['b[io]] 'c) -> ('c ['b] -> ['b?, 'd] 'e)
  // f の戻り行で保護(+1)、g の戻り側で解除(−1)。往復して 0 に戻る
  ```

- 再帰のたびに保護が積み増される型も許す。意味は有限制約の最小解。(確定, 章10.3.2・7.3b)

  ```text
  [k, 'e] as 'e                      // 'e は { k } と、'e 自身を保護したものを含む
  ```

- operation の署名に role 制約を付けるなら、署名の下に `where`。handler でもその role の method が使える。(確定, 章5.1・6.3)

  ```yulang
  act logger:
      our log: 'b -> ()
          where 'b: Display
  ```

## role・impl・where (章6.1–6.3)

- `where` を書かなくても、未解決の role 制約は型に自動で付く。使う側で型が決まるたびに、その制約の解決が走る。(確定, 2026-11-05)

  ```yulang
  my twice(x) = x.add x              // 'a -> 'a where 'a: Add
  ```

- 一般化できない束縛に残った制約は、同じファイルの終わりまで待つ。決まらなければエラー。見える `impl` が一つしかなくても、その型には決めない(`impl` を足して既存のコードが壊れないようにする)。注釈で決めさせる。(確定, 2026-11-05)

  ```yulang
  my z = default ()                  // 値でないので単相。ファイルの終わりまでに決まらなければエラー
  ```

- `impl` の候補は、**具体化した場所**(呼び出し側)で見えるものから選ぶ。入れ子の `where` も根の呼び出し側の可視範囲で解く。coherence も孤児規則もない。別ファイルの同じ `impl` は共存でき、一箇所に両方見えたときだけ曖昧エラー。終端の検査は、そのファイルで見える `impl` の集合を使う。(確定, 章6.2, 2026-11-05)
- `impl` の `where` は、head より構造的に小さくなければならない(違反は宣言時に拒否)。条件の型サイズの合計 < head のサイズ、かつ各変数の出現回数が head 以下。深さの上限は置かず、解決は必ず止まる。(確定, 2026-11-05)

  ```yulang
  impl Display (list 'a): where 'a: Display   // OK
  impl Foo 'a: where (list 'a): Foo            // 拒否: 条件のほうが大きい
  ```

- 関連型は、新しい型変数と制約の等式で表す。`impl` の右辺で、他の role の関連型は参照できない。`'v` は普通の型変数で、`impl` が選ばれた時に等式が足され、先に積まれた制約と合わなければその時点でエラー。(確定。記法は暫定)

  ```text
  first : 'c -> 'v where 'c: Index(int, value = 'v)
  ```

- `impl` の head の `_` は、名前を付けない型変数。出現のたびに別の変数で、`where` から参照できない。(確定, 2026-11-05)

  ```yulang
  impl Add (ref _ int): ...          // impl Add (ref 'e int) と同じ
  ```

## `x.method` の解決 (章6.4)

- 探す順(型が分かっているとき): field・`with:` の method → role の method → effect 行の method。先に見つかったものが勝つ。(確定)
- receiver の型が SCC の終わりまで分からないときは、**role を先**にする。なければ field。その名前の method を持つ role が複数あれば曖昧エラー(注釈で解く)。解釈は SCC の解決時点で固定され、呼び出し側で後から型が決まっても変わらない。(確定, 2026-11-05)

  ```yulang
  role Size 'a: our a.size: () -> int
  struct box { size: int }

  my f(x) = x.size                   // 'a -> int where 'a: Size
  f (box { size: 3 })                // Size box の impl が無ければエラー。field には切り替わらない
  ```

- receiver が union のとき、その method を持つ型が**一つだけ**なら、その型に決まる。二つ以上なら曖昧エラー。決まったら、receiver はその型への普通の cast 境界になり、他のメンバーはその型へ cast される。(確定, 2026-11-05)

  ```yulang
  my x = if c: 1 else: user_id_value  // int | user_id
  x.add 2                              // Add を持つのは int だけ → user_id 側は int へ cast
  x.show                               // どちらにも show がある → 曖昧エラー
  (x: int).show                        // 注釈で解く
  ```

- `ref` の receiver は `ref` だけを探す。中身には降りない。(確定, 2026-11-05)

  ```yulang
  my $n = 0
  &n.get          // ref の method
  $n.add 1        // 中身の int の method
  &n.add 1        // エラー(ref _ int に特化した add を定義すれば別)
  ```

## cast (章6.5)

暗黙の変換。型が合わないときに、期待型が分かっている境界でだけ入る。

- 型が既に合っていれば、cast の規則があっても適用しない。明示された規則がなければ変換しない。(確定, 2026-11-05)
- `cast` の本体は純粋でなければならない。effect を起こす cast は宣言時にエラー。失敗しうる変換や入出力を伴う変換は、普通の関数にして呼び出しを明示する。(確定, 2026-11-05)
- 型引数を持つ型にも cast を書ける。ただし target が source より大きくならない。型のサイズが source 以下、かつ各変数の出現回数が target ≤ source。連鎖の深さに制限はなく、探索は必ず止まる。(確定, 2026-11-05)

  ```yulang
  cast(x: box 'a): 'a = x.value             // OK
  cast(x: 'a): box 'a = box { value: x }    // エラー: 行き先が元より大きい
  cast(x: pair2 'a 'b): pair 'a 'a = ...    // エラー: 'a の出現が source より多い
  ```

- cast は方向を持つ位置に沿って通る。関数の引数(反変)・戻り値(共変)、tuple の成分・record のフィールド・variant の payload(共変)。nominal な型の型引数(`list`・`ref`・`box`)は不変で、cast も通らない。(確定, 2026-11-05)

  ```yulang
  apply_to_id inc            // inc: int -> int が、user_id -> int として渡る(引数側に cast)
  my q: (int, str) = p       // p: (user_id, str)。成分ごとに cast
  ```

- union の値は各メンバーを別々に cast する。一つでも cast が無ければ型エラー(実行時に失敗させない)。(確定, 2026-11-05)

  ```yulang
  my y = if c: 1 else: "text"   // int | str
  use_int y                      // エラー: str から int への cast が無い
  ```

- 不変の型引数を持つ nominal 型の構築(list・struct の literal・enum の constructor)は、型引数に当たる値に「保留された cast 境界」を持つ。ファイルの終わりまでに決まらなければ、cast なしで要素の型の合流に決まる。すでに型が決まった `list user_id` の値は `list int` の場所に渡せない。(確定, 2026-11-05)

  ```yulang
  my xs = [1]                    // list (int | '_a)。'_a は弱多相
  my ys: list user_id = xs       // '_a := user_id。要素 1 に int → user_id の cast が入る
  ```

## 型の表示 (章7)

- 変数の見え方: `'a` 多相 · `'_a` 弱多相(値制限で一般化されない) · `'e?` 保護の解除 · `'e[io]` マスク付き保護 · `[…] as 'e` 再帰する行。(意味は確定、記法は暫定, 章7.2b・7.3・7.3b)
- 意味が等しい型は、同じ文字列で表示される(標準形)。型変数は左から読んだ出現順に `'a`, `'b`, …。union・intersection・effect の行は、型変数を先に、具体的な型を名前の辞書順。簡約は意味を保つものだけ。(仮採用, 章7.4b)

  ```text
  'a -> 'b -> 'a | 'b       // if c: x else: y と if c: y else: x のどちらも
  ```

- 見せられない内部の実体は `…` に置き換える。偽のきれいな型は作文しない。`…` が公開面に出たら、表示の問題ではなく上流の不具合。再帰する行は正当な型なので `as` で見せ、`…` にしない。(仮採用, 章7.4)
