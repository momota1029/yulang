# dots の常設の指示 (standing orders) (2026-11-08)

このファイルは、dots が**起きるたび（毎時の定期実行）**に最初に読む、変わらない手順。
今回の具体的な指示は `notes/plan/dots-inbox.md`（監督役が書く）にある。会話の履歴は毎回は渡らないので、
状態はすべてリポジトリに置く。落ちても、起きたときにここと inbox から再開できる。

## 1 サイクルの手順（1 回の実行は 50 分以内）

1. `integration/m1-final` を取得し、`notes/plan/dots-inbox.md` を読む。`STOP` と書かれていたら、何もせず、サイクルの報告に「STOP を確認」とだけ書いて終わる。
2. 前回のサイクルの報告（`work/dots-main` の `notes/handoff/dots-cycle-<N>.md` の最新）があれば読む。前回の作業中の Lean ツリーがクラウド PC に残っていれば、それを続ける。無ければ `integration/m1-final` の先頭から始める。
3. 自分のクローンに `integration/m1-final` の先頭を取り込む（監督役が前回の公開分を統合している）。衝突したら、監督役の統合版を優先し、自分の追加分だけを重ねる。
4. inbox の「現在の指示」を実行する。小さな単位（補題一つ・定理一つ）ごとにローカルで commit し、ビルド `cd lean && lake build --wfail` を通す。
5. 公開: push はできないので、GitHub アプリ経由で `work/dots-main` ブランチに、`integration/m1-final` の先頭から変更・追加した**全ファイル**を公開する。サイクルの途中でも、30 分ごとに公開する。
6. サイクルの最後に、全体の検証 `bash tools/verify-lean.sh . origin/integration/m1-final` を実行し、その出力全文と終了コードを含めて、サイクル報告 `notes/handoff/dots-cycle-<N>.md`（N は 1 から連番）を `work/dots-main` に公開する。公開後、公開した tree を取得して照合する。
7. 次のサイクルまで何もしない（待機の間に勝手に作業を広げない）。inbox が変わっていなければ、前回の続きをする。

## サイクル報告に書くこと

実行したコマンドと結果（verify-lean.sh の出力全文）／追加・変更した Lean ファイルと、追加した定理の名前と日本語で読める主張（量化子と前提を省かない）／inbox の受け入れ条件のどれが達成されたか／確かめていないこと／残りの補題（次の指示の候補を 1〜3 個、名指しで）／質問ノートを積んだか／公開したファイル数／起きた中断や制限／このサイクルの所要時間。できなかったことを、できたと書かない。

## 守ること（変わらない）

- 意味論はユーザーの設計判断。決めない。spec が黙っている点や選択肢がある点は、Yulang の例つきで質問ノートを `notes/questions/` に 1 本書く（遅延する案を先頭に）。決めずに進められる部分は続ける。回答は inbox や spec に書かれるので、次のサイクルで読む。
- `sorry`、新しい公理、`native_decide` を使わない。既存の定理を弱めない。既存の Lean ファイルは変更せず、`lean/Yulang.lean`・`lean/Audit.lean`・`lean/README.md` に追記する。新しいコードは `lean/Yulang/` の新しいモジュール。新しい主要定理は Audit に登録する。`spec/`、`notes/plan/`、lakefile は変更しない（必要なら質問ノート）。
- 書き込みは `work/dots-main` ブランチだけ。`integration/m1-final`、`yulang3`、`main` などには書き込まない。
- 設計を先に: 大きな Lean を書く前に、データ、独立な宣言的判断、実行版、証明する定理の型（量化子つき）を `notes/design/` に短く書く。上から作る。外側の定理が仮定を持つなら、その仮定を名前つきで明示する。狭くて本物の断片を決めて、その上で仮定なしの定理にする。
- E2（反例）が出ても終わりにしない。定義を設計し直して証明まで進める。
- 「証明できた」と「正しいものを証明した」を分ける。未証明の仮定を持つ定理を、完成した定理として報告しない。
- 使用量の枠が分かるなら、サイクル報告に書く。不明なら「不明」と書く。
