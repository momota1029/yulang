# I-56: 既存の論理名から where と関連型を読む

C321 の新しい純論理名は保守的だが、元の普通状態に既にある名前を
同定したことにはならない。C322 は普通等式の alias / 構成子合同から
既存の順序つき三端と出力 target を検証する。元の名前を置換せず、
新しい事実が全モデルで既に成り立つ場合だけ使う。出力側の通常の等式と
候補検査の展開根拠を分けたままにする。

独立な source 規則側は actual の構成子・共有中心の根拠を供給し、
compiler はその根拠を読んで source の構文に従い普通の等式列を出す。
一般の選定や候補の完全性を新しい制限で置き換えず、既存の意味は変更しない。

## 既存の source emitter に合わせる

`GeneralDeclarationDemands.childDemand` は、正規化した where 入力が
単なる変数なら捕捉の区間そのものを、名前付き出力が出力専用変数なら
その binder の論理名そのものを使う。この規則を保持して actual 中心を
付ける。合成型だけに既存名の読み出しを求め、変数の要求にまで別の
候補名を選び直さない。前者の位置付き emitter と、同じ型を指す別名の
忠実性実験を区別する。

## 次の一般補題の境界

`OrdinaryProducer322.ordinary_produces` は、実中心側の普通式を認識し、
重複 binder が実際に同じだという普通の導出と既存の実名があれば、一つの
捕捉写像を作る。通常の構文のメタデータ被覆なら、pattern 正規化の後に
constructor 解釈・arity・既存の role default を再仮定する必要がない。
新しい名前を作らない source emitter による where の区間三端／出力を導き、
候補自身の出力 RHS も実際の要求名で検証する。正規化で変数になった入力は
元の捕捉、出力専用変数はその binder が元から持つ一つの actual を使う。

残る source exactness では、承認済みの一般選定がこの観測と普通の導出を
どのように供給するかを示す。宣言的な側だけの論点は、(a) supported input
の provenance を保持した正規形と K2 の正則同値・実調査位置、(b) 何を
生存／未解決とするかの一般の区間伝播、(c) 得られた実位置と共有 binder
の境界、および既存の合成 operand・関連型結果が安定普通状態で成立すること。
`Residual` はこのうち残った普通式の条件を明示する。任意に普通等式を
付け足すことで通すことはできない（固定 target の反例）。投影と停止成功
診断の一致は別の (2)。未決の「未完了出力しかない根の K2 優先」は
変更せず、その問いと独立の部分で進めた。
