## Allocation is a separate obstacle, not notation

`GeneralNominalAllocation.capture` uses a singleton's literal bounds when one
binding remains, but uses invocation-local allocated merge bounds when zero or
multiple occurrences remain. Therefore multiplicity collapse can change the
chosen capture source identities even if all actual observed values agree.
The invocation/declaration seed-based allocation remains stable, but the
singleton-vs-merge selection does not. Before transporting materialization,
prove the necessary semantic relation between these selected inputs from the
actual merged/private constraints. Mere overlap with one actual value is not
endpoint equality and must not be substituted for it.
