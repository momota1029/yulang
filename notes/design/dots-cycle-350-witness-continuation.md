# C350 witness checker: soundness envelope and next interfaces

## Trusted problem vs witness

The fixed problem determines the declarative state, the original normalized
source tables, demanded outputs, and (for the current positive branch) the
allocation layout per generated ordinal. The witness may supply indexes, paths,
ranks, current projection triples, ordinary derivations and reported output, but
cannot choose another state or ordinary model. Candidate choice is rederived
from the real singleton-role source registry and actual supported lower/upper
observations; old Local, raw solver history, journal and stopping are absent.

The positive portal is explicitly finite and partial. It accepts an arbitrary
finite ordered certificate tree in which each visited candidate fits the current
I-61 direct binder-record pattern (including named tails, nonpoint ends,
standalone residual and repetitions) and the registered descent checks. The
checked two-child example reads a compound root payload as the actual next source
demand, but does not establish arbitrary nested *patterns*. The original C334
point path remains a different validated fragment. The new declarative
projection/recursive soundness theorem uses C340's exact sidecar dictionary.

A compiler receipt is semantic ordinary data with literal symbolic outputs
and children: each source node computes its actual where requests and the
ordered requested fixed rows. Descriptor positions are verified exactly, not
reconstructed by model equivalence. A missing checker certificate is a certificate
miss. It is not a new rejection or delay rule.

The ordinary root K2 proof is indexed to the demanded argument and requires
a true nonempty structural path closing at that root. The explicit I-59
unfinished producer reason further requires exact ordinary pending producer
ownership, absence of a supported constructor under the finite recorded view,
and the exact reported rejection. That is the existing narrow reason, not a
universal classifier. The retained positive subtree proof is unchanged when
this specific root K2 rule coexists.

## Next interfaces worth implementing

1. Bind the caller's allocation layout and origin table to independent normalized
   input/producer data. Use finite entries at exact generated ordinal paths, merge
   repeated read plans without changing fixed targets, and reject absent/mismatched
   anchors as certificate errors. Do not allow the witness to declare its own
   creator or release. C350 already reflects the author/owner/release table and
   locally feeds actual released endpoints to the record allocator. Integrating
   this producer view into a whole positive witness variant is still open.
2. Add a named tagged-join/nominal input decoder from actual authorized source
   spine and compound syntax, not from endpoint model equality or a failed legacy
   observer. The highest-leverage next route reuses C340 merged-tag observation:
   certify the two independent supported bounds and every joined arm, then feed
   the real `TaggedInputs340.Input.whole` and the exact ordered compiler receipt.
   It does not choose a tag or a priority for unresolved shapes. Arbitrary nested
   record *pattern* input needs an explicit nested read/receipt constructor, since
   the current `Input.prior (.record …)` expects direct binder fields.
3. Keep a proof-producing negative layer per approved reason. C350 establishes the
   narrow I-59 unfinished ordinary root even if the exact same ordinary state
   cannot supply a positive rank. General ambiguity, pending, and conflicting
   ties are different obligations; do not derive them merely from missing
   witnesses or rank. Completeness (C) remains parked until soundness (S2) is
   covered for the approved input family.
