# Canonical source roots under append-only allocation

Status: Draft. Scope: the finite source-identity boundary of B4, not its complete resolver.

The source table is an ordered list of source names. Existing `retain` embeds old
occurrences by their unchanged numeric index. New occurrences append to the table.
The executable representative is the first occurrence of each name, not a reader
value and not a choice of a source model.

For all finite tables `table`, `extra`, and every old occurrence `i`, prove:
`canonical (table ++ extra) (retain table extra i) = retain table extra (canonical table i)`.
Prove that every newly allocated occurrence with an old name points to precisely
that retained canonical root. Distinct names must stay distinct. Extend this from
roots to every retained capture/cycle reference by commuting observation transport
with canonical routing; apply it to the real variable/shared inspector.

The incremental `newRoot` first queries the old table, then the new suffix.
Prove it equals rebuilding the complete canonical map for every new occurrence.

Independently, use the existing arbitrary-constraint source model extension to
connect identity allocation with model preservation and the actual ordinary solver.
No new constraints or requests are generated by allocation itself. Constraints
introduced by a child still require a separate semantics and saturation argument.

This closes stability of the finite canonical allocation interface. It does not
claim recursive graph reconstruction, declaration-driven allocation, stable scalar
observations after new constraints, final classification, or general B4. The source
semantics are unchanged. Existing Yulang2 X13-X17 and C3-PARENT evidence in the
audit branch supplies context, not a proof about internal numeric root allocation.
