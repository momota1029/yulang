## 公開 checker の proof-free wire と元の要求

新しい枝は `Wire436` として、producer の元の request locator（occurrence・role・point input・出力名・固定 target、入力が一つ／出力が一つの最初の scope）、producer の authored declaration ordinal、source Origin ordinal、出力の raw row ordinal、consumer の authored declaration ordinal、独立した upper/actual-center の Origin ordinals、双方の raw-root escape wire を持つ。producer の候補 key・payload・dictionary・tree・B6 RHS・選択済みフラグは与えない。一般の I72 `State` (`FixedGoal402` + `State365`) に demands の独立した索引は**ない**。従って「`s.requests[i]?` を読む」処理は書かない。最初の wire は producer の小さな元要求をデータから組み立て、その occurrence を point に置かれた元の Origin.issuer と照合し、現在の独立した role row, declaration, checked input, 原文 body lookup、`s.b6.read producer declarationOrdinal i body` を照合する。atlas は元の `Request`（role、引数、outputs を含む）をキーとして受け、出力番号だけではない（`GeneralDeclarativeI65B6MixedOutput401` 冒頭の `B6OccurrenceAtlas401.read`）。B4 が B6 の出所に関するこれ以上の忠実性を主張しない。現在の declarative State でその正確な元要求の完成を実際に導出する。値だけの root identifier、異なる issuer/occurrence、同じ declaration の別出力、または aliases だけの一致では進まない。
