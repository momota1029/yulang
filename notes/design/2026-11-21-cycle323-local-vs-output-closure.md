# C323 設計: 局所候補選定と固定 target の通常等式を分ける

I-56 と I-57。状態は通常制約・区間・通常式のみ。solver、停止、局所選定の変更は扱わない。spec 6.3（関連型の等式は先に束縛しない）は、impl 選定に続いて同じ出力変数への通常等式を足す。ここで「選定前の全モデルで既に等式が成り立つ」は述べられていない。where の最終化は兄弟の更新が安定してから。

- 固定 demand、宣言、共通捕捉で実 `rootFact` が単一式を返したとき、どの割当でも、その式と `OutputMeaning` は同値。`Supplies` 一意性と構文翻訳の健全性から直接示す。通常式追加前の entailment と、追加後条件付きの含意を別にする。
- 既存 C322 の実 source where emitter の名と順序を保つ Wrap→Container の小例で、唯一の候補と下界・K2 の条件を維持したまま、子の固定 target の一式を外す。別のモデルが親の既存式まで満たすかを検査。局所 fragment の出力を無条件の安定済み source 選定とは呼ばない。式を足した後だけで同一診断・同一 target の証明を比較する。
- 用いる純粋な判定は既存の `Local` の前提と source emitter から取り、`Compiles` や Evidence を生成に仮定しない。任意の引数の shared 中心については、実出現と承認済みの普通等式/区間交差の違いを検査。言語上の追加拒否も推論規則も導入しない。
- この周の一度限りの I-57 復旧は integration の二つの既存 Git blob ID を指し直しただけ。本周の Lean 差分・公開経路は凍結ファイルを含まない。
