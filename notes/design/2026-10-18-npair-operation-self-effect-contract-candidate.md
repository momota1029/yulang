## 2. Proposed complete field interface

Let `s0` be the actual root signature Function's ResultEffect path. Its
argument effect, result value and every callback/returned Function path are
different paths. A path includes original occurrence and phase, not just a
sequence of type constructors. Let `Fields(Sigma)` be the original finite
signature/interface graph, retaining recursive edges and dependent families;
future indices need not be finitely enumerated.

**Candidate addition C1:** expose, together with the existing whole telescope,
a field-indexed contribution presentation `E_s(w)` for each effect field s,
and an emission-schema field `req(w)`. Each contribution record contains

```text
c = (original contribution identity, declaration p, actual v, theta,
     owner field s, phase, provider/observation, nu,K,D,
     continuation/current-state/future dependencies, original license,
     alternative and witness lineage)
```

The schema `req(w)` names the declaration consumer's possible request emission
at this Operation use; it is not a fresh dynamic event and does not assert that
invocation occurs. Its family operand is exactly `F(theta(rho))`, payload A_theta,
response B_theta and complete Lambda_theta. Dynamic emissions instantiate this
schema under the original current-state/request contract, retaining their own
identities and raw suffix J_q. Carrier creation emits no dynamic request.

**Candidate addition C2:** root field construction is the following tagged
presentation, before support forgetting or public normalization:

```text
E_s0(w) = Self(req(w))
          + ConsumerDirect_s0(w)
          + Written_s0(w)
          + Tail_s0(w)
          + Extra_s0(w).
```

`+` retains contributions, constraints, origin tags and sharing; it is not
an assertion that dependent worlds can be chosen independently. Every summand
is evaluated within the same original whole judgment. Distinct records remain
distinct even when family points coincide. Repeated derivations of the same
original record may share representation only with actual identity evidence.
No equality `w = req(w)`, `w = E_s0(w)` or `whole IF = member0` is introduced.

C2 specifies **descriptor contributions**, not an exact execution trace:
Self supplies the intrinsic request-schema family operand to this latent
field. ConsumerDirect contains only contributions of the declaration-derived
consumer's own computation at s0, under its actual original result/effect
judgment. It excludes the carrier's construction effect, request payload's
latent effects and raw suffix's unrelated effects. Any actual original rule
that sequences another computation must carry that computation's authentic
field-to-result action; that action is not inferred from containment in IF.

Written_s0 retains each written root-row operand at its own position with its
original constraints and licenses. A written F and Self(F) are separate
origins. A written row describes the declared field/allowance according to its
original rule; it does not prove a dynamic request or new permission. Tail_s0
is the original shared symbolic row with all existing and future lowers/checks;
an unknown tail is never empty. An omitted row has no written summand and
keeps its ordinary fresh/open field dependencies; an explicit empty row has
an empty written summand. Neither erases intrinsic Self or authorizes solving
an open tail. Whether a written guarantee conflicts with the intrinsic request
is checked by the original whole constraints, not repaired by dropping either.

For every s != s0, retain its original field presentation, including its own
written operands, tails and contributions. C2 adds no Self at those paths.
`Extra_s(w)` is the field component of the original licensed whole-tuple
alternative, as specified below; it can be nonempty and need not have a source
execution. This preserves Option 2 rather than defining the bound by requests.
