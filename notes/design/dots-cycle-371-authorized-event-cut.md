# C371: literal body production needs the actual source allocation

This is a source-level cut for the unchanged I-65 step 1. It does not equate generalized typed coverage to the older ordinary compiler, and does not prescribe a new name allocation or eligibility rule.

## Produce the literal ordinary body

For the existing ordinary lane, `prepared_exists` (C327) derives a real ordered preparation from verified source coverage, declaration membership, and the actual capture and placement inputs. `compiled_frames` then supplies the successful where batch and fixed-output batch for the declared demand and same role. Substituting those three results into C350's `execute` gives the actual body, with the source's ordered children. This is production from compiler/source premises, not from a supplied finished receipt or a fitting model. The initializer is the real repeated-center/aggregate compiler state, not a fabricated replacement.

The scope is the older ordinary syntax that this compiler covers. No conversion from the generalized declared-mode/typed carrier is asserted. For the frozen arbitrary-state theorem, one must additionally derive that the *actual current declarative state* retains those particular rows. The existence of a successful run alone does not show their presence in the state or in every state with the same head facts.

## Two precise allocation cases

C322's `children` maps the written `requirements` in source order. At actual clause ordinal (i), its request role and capture list belong to that clause. At output ordinal (j), it uses the written equation's name and exactly `outputTarget`:

- For a direct variable whose name is a declared output binder, locate its unique **producing** source clause and equation. The target is that producer's address, not the current consumer's fallback address.
- Otherwise the literal target is the placement's allocation for the actual current clause and its written equation ID.

Consequently equal literal child lists imply equality of the chosen target at every represented non-direct clause/output ordinal. This follows by reading the same two list indices and projecting the output target. Semantic equivalence of names, including C327's theorem about equivalent **input** spans under equal target functions, cannot supply this literal equality.

In the covered ordinary lane, the same declaration, captures, demand and pre-body named data can be submitted with two different target functions. Each succeeds by the actual production argument above. If the functions differ at one genuine non-direct where output, the emitted child lists differ at that index and their serialized literal demands differ. Yet the **root** fixed target list is still the same, read from the original main demand, in both runs. This is a parametric observation about what the compiler consumes, not evidence that both written states coexist in an arbitrary fixed declarative state or that any target is authorized in the real source. It proves why the source-selected body interface needs independent actual occurrence/producer placement, not just the head verdict and root targets.
