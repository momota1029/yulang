# Cycle 2: conservative ordinary-state scalar materialization (Draft)

A source receiver is not chosen from singleton role visibility. Instead, a
finite executable scan searches the recorded ordinary atoms for both
`slot <= base` and `base <= slot`. The independent syntactic witness retains
both memberships. For every assignment satisfying the original state, the
slot is Common.Equivalent to the detected scalar. Existence of a model makes
such scalar evidence unique, but consistency is not assumed by the scan.

The scanner is complete only for these explicit paired atoms, not arbitrary
ordinary entailment. It does not select an arbitrary solver witness. A partial
materializer translates only int/str evidence into the existing Roles example
constructor codes, with a proof of the original slot's meaning. It does not
claim full Common/source interpretation or final source resolver exactness.

The concrete `produceIndex` adapter recovers a receiver payload from this scan,
then uses the real checked `Index (box 'a) int` declaration and actual assocOf.
A str receiver equation yields its associated str output equation; the empty
state remains pending. The initial receiver equation's source is not generated
here. Even inconsistent states can contain scalar evidence: Option.some is NOT
solver success. `index_preserves` ensures every output model is an original
model, so contradictions cannot be overwritten; final consistency is separate.

`checkedProduceIndex` now runs the real ordinary consistency test on the
produced state. `checked_exact` identifies accepted outputs exactly with
produced outputs having a model. `checked_models`, `checked_preserves`, and
`inconsistent_not_accepted` prevent contradictory scalar evidence from being
reported as a successful local update. None deliberately does not distinguish
pending, unsupported, and inconsistent; this is not language finalization.
