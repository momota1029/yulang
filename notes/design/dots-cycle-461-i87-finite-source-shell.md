# C461 / I-87: 元 source の有限欄と安定性の分離

`StartShell` は、同じ解決済み Problem の実 `OriginalAnchor` を読んで、元の可視候補、唯一の実 head/入力/where、point、空の named outputs、role table、現 scope/mode coverage、静的な `Smaller` を検査する。構文や照合が通っただけで `DeclarationReady` を作らない。同じ source に対する普遍的 `StableSmaller` が最後の別条件であること、またそれを与えたとき元 source を変更せずに Ready と同一 anchor を復元することを示した。

`StableSourceProtocol` は、独立に正しい有限証拠の供給源が既にある場合だけ、その証拠と shell と単一経路を組み合わせる。安定性の全域アルゴリズムを主張しない。実 §6.3 の after-capture 合流を単一入力の pair に包んだ対照では、実 catalogue/role/head/where を読む有限欄と静的な縮小は通るが、`'a := int` で head/where が同じ大きさになり、元宣言は Ready ではない。

旧 raw tickets と元 header key は配置中立な注釈を消すだけで元の同じデータに戻る。結合 reader は、全ての wire で「同じ旧 raw run、その後の指定構文位置」と一致する。旧 C459 の inline/use stamp はこのとき元の値のまま。実 fitting state の named-only 経路では receipt は読めても stamp が false で、旧 C459 の field 分岐にそっと送って受理させない。一般の言語受理・拒否ではなく、既存の入口条件の切り分けである。
