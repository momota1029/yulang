# C337: exact standalone record subtraction, design checkpoint

The build host was disconnected while checking this approach. The C336 proof pin remains intact. This checkpoint is a mathematical design and a finite JavaScript differential check, not a new Lean proof or a change to the language.

## Why deletion and forgetting differ

For a closed source `record x int exact-empty`, consuming `x` should leave a standalone exact-empty record. The test `optional x int` holds there because `x` is absent. The existing producer mask instead forgets that optional probe and does not pass this test. Leaving a synthetic fresh label masked in the output would have the same bug at that label.

## Proposed carrier operation and proof path

- Operate on the outer record/default/mask/union/intersection spine only. Remove each consumed record/default node and strip removed labels from existing outer mask lists. The payload references and their recursive state graphs do not change. Width and exact-empty terminals are separate and preserved.
- A removed record wrapper has to retain its non-field record observations and make the trivial optional probe hold, without strengthening any required or nontrivial optional probe in its tail. The proposed shell is identity on record/default/width/exact, maps lattice nodes and masks structurally, maps an unrelated leaf to width, and maps bottom to `record 0 bottom bottom`, which retains all tail field probes with no observable unique chosen field. The shell is used on a removed wrapper, not indiscriminately as a preprocessing operation on a retained default source.
- For an unconsumed field, keep the very same query. For a consumed field, use a genuinely fresh query label absent from the original outer syntax and masks, with incoming mask membership corresponding. Prove both required and optional identities simultaneously; a default combines source optional, source required-trivial, and the unchanged fallback probe. In non-field probes the operation is observationally unchanged. This proof idea compares two inputs at the same absent fresh label to obtain monotonicity without inspecting payloads.
- Lift the finite probe proof through `CommonNominalSyntax.Layer.evalAt`: at depth zero a default becomes an ordinary record with a bottom payload; at successor depth it is a default. Both should commute with deleting or retaining the label. Then literal subtraction on a rigid authored spine is the syntactic filter, with first-field-wins normalized via the existing denotational congruence. At the two trusted endpoints this yields unmasked literal residuals; the actual residual is computed on the actual model value, while the origin of the center's row is still never used for selection.
- For nested capture, materialize only the authored projected endpoint expressions and preserve their evidence. Recurse on a projected interval when the normalized payload is a compound pattern. Compute the occurrence list in the same ordered walk that prepares the sidecar. Feed that list to the existing body compiler and keep the original fixed target/child names. I-58 actual projected center ties belong only to the elected append, not to the endpoint probe.

The following statement is a useful next check: if both supported endpoint subtractions are exact-empty, monotonicity sandwiches the actual standalone subtraction between two exact-empty types, so its consumed optional probe is genuinely absent even without a center source row. If the endpoints differ, use the actual deletion rather than the nonunique C336 lift from masked observations.

## Independent bounded test (not Lean)

The JavaScript check ran against 1,336 finite type terms and 141 probes. The test vocabulary covers width/exact, bottom/top, regular field/default nodes, outer masks, union/intersection, primitive and nonrecord representative shapes. Outer labels in inputs are 0–2; label 5 is actually absent. Eight deletion sets and eight incoming mask contexts are all subsets of labels 0–2. Shell identities: 188,376; query-routing identities: 12,056,064; ordered pairs preserving sampled probe inclusion: 5,245,304. No difference found. The specific consumed optional probe was true for exact deletion and false under forgetting. Empty identity, shell commutation and sequence-vs-batched deletion passed respectively 1,336, 10,688 and 85,504 exact structural checks.

Emit union/intersection for each ordered pair. Mask the eight with [], [0], [1], [2], [0,2], [1,2]. Append 768 terms using unsigned LCG seed 0x337, multiplier 1664525, increment 1013904223; sample operands by modulo current list length and labels by modulo 3; cycle record/default/mask/union/intersection. The nine outer probes were trivial, impossible, records, int, float, pair, variant, and two role tests. For labels 0–5, required and optional payload probes included all nine plus required-label-0 trivial and optional-label-1 int. Test required/optional routing for each input mask context, using label 5 with transferred membership for consumed labels. Test monotonicity on all ordered type pairs whose original bit-vector inclusion holds. This is finite evidence, not a substitute for arbitrary depth, negative-argument semantics, or Lean verification.
