# 次の停止性の橋: 保存の同型と、意味の変わらない install の除去を混同しない

今回閉じた二つの同型は raw Step を変えない。圧縮・復元がうまくいった分だけ、旧239/240の循環も、全モデルが私有値だけ違う場合も残る。これを次に除くなら、別の operational rule が必要。

1. 各固定ポートに live の読み先と immutable な過去の読み戻し表を分けて置く。同じ fixed owner の live 表を置き換えるとき、過去の effect はその snapshot の表で検査する。公開射影を保つ型付き同時コピーは `GeneralRebasePortProjection280.projected_replace`。その前提である公開値・保護された意味の支持・コピー元との分離を、予約だけの名前と実際に読む名前を分けて source compiler から導く。支持の有限性だけで、値の有限性は言えない。
2. 別の source 観測では、有限な owner と fixed port の上に、型名・構成子と現れる有限の引数の観測を記録する。ここでの次の補題の型は「任意の checked source、到達状態、及び rewritten install に対して、公開意味が真に狭まるなら、source から先に作った有限の意味事実のうち一つ以上が初めて成立する」。有限の事実表が全将来の制約を表現することを先に証明する必要がある。旧239/240に固定テスト列を当てるだけではない。
3. 観測の識別力と scheduler 側の許可を分ける。固定辺も意味事実も増えない一歩を単純に禁止すると、後続の knownness や cache certificate が生まれる一歩を失う危険がある。同じ観測内容の下で newly ready な phase を有限個数えられること、または source の十分条件からすでに再生できることを示す。Display X1型の「全モデルは同じだが子が生まれる」一歩は許し、旧239/240の fresh private 名が繰り返し差分を作る場合は新しい名前を増やさない。

この順のうち、今回確かめたのは固定子・復号・実 Step の保存と、保護条件つきの port copy まで。有限意味事実の完全性と compile される live-table rule はまだない。spec のアプリケーション意味の変更は提案しない。
