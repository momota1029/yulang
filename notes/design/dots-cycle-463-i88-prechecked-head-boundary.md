# C463 / I-88: 検査済み head の位置と whole-read の限界

旧 result/report の入口は不変。証明支援の head 受領だけは、元の全可視 declaration の実 ordinal と実 head argument ordinal の組を使い、単一候補や where の存在を仮定しない。点であることと exact な実 authored registry 上の検査済み表 membership は維持する。実例は where なしの二可視候補・二引数で (1,1) の既存 field route を確認するが、受領自体は候補の head matching、全候補の検討、K2 と曖昧性の優先順位を決めない。

旧 source match の ordinary `Head` は `Center.direct` の `EquationRead.whole` を使える。閉じた literal `{30:{40:'a}}` が実 Ready で、表 lookup も成功し、point4 の実 ordinary `SourceHead` と fitting model があり、slot5 は raw 循環中でも、4 の actual row が inline のままで raw shape に名前付きの子がなければ最初の訪問を作れない。この状態では新 head 支援 reader の全有限 wire が none。モデルの値が一致しても、5 を inline 部分の実 raw 位置とは言えない。言語の拒否や K2 表示を選ばない。

宣言表の使い回しには exact な `authoredRegistry` 等式が必要。ordinary/request だけが変わっても、この等式があるなら同じ元宣言 rows と順序・lookup のまま居場所を移し、GD の verifier を再実行しない。現在の raw state を書き換える証明や action はない。残りは、実際に調べる source から named raw/source 証跡を生む上流（既存 331/351 のサポートとの接続）、複数候補の matching と K2 優先、残余 join の現行訪問境界。GD の完全性は別行として残す。
