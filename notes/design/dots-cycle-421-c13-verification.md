# C421 C13: 二つの非点区間、選択後の実中心の等式

- 仕様: [`spec/06-roles.md` §6.3「型変数を共有する impl を選んだら、実際の引数が等しいという等式を足す」](https://github.com/momota1029/yulang/blob/2c584f7f1555e9f4e9ab057f9028b6591c2deb01/spec/06-roles.md#L410-L419)。C13 の実要求は `R` 自身。原例の外側の `P/Foo → where` の生成・解決までは扱わない。
- 検証した技術ピン: `2ca91ca23c76b3ee4d52522c78643bcd3a12a670`、Lean tree `0683c008ffbb1a4527f24f602efc6b3aa3503e3c`。後の文書コミットではこの tree を変更しない。
- 二つの元の区間は `(0,1,2)` と `(3,4,2)`。実中心は 1 と 4。共通上端 2 の同一性や両側の tag からは、中心同士の型の等しさを推論しない。型の選択をモデルに求めず、元の下端の由来、区間制約、元の可視一候補と宣言番号、両引数の元グラフ K2 だけを pre-choice で読む。中心識別子は元の区間の一部で、中心の型行は post-choice まで読まない。
- 実中心が保持済みの正確な等式 `4 = 1` で結ばれ、同タグの実 payload の型も整合するなら、第一出現の**元の区間全体**を共有捕捉として選択する。名前付き出力も where もないため、空であるべき報告の台帳・子列を空にする。等式がまだ保持されていなくても、整合した実中心の型証拠がある任意の適合モデルは、正確な等式を追加したあとにもそのまま適合する。ただし未保持の等式を検査器が成功として扱うことはない。
- 逆に、同タグの二つの実中心が int と bool の異なる payload を持つなら、どの同じ状態の割当ても追加後を満たさない。例の追加前には実際に適合モデルがあり、共通上端には両 variant の和を与える。等式の欠落だけでは型エラーにせず、その証人では `false`。これは保留の仕様追加でもない。
- 不整合の証拠がある同じ要求で旧 `R12` から選択へ逃げられず、新 `R13` にも選択導出はない。旧の非根診断に必要な別の候補形はこの範囲にはなく、実際の post-outcome が示された場合の `R13` の報告は同じ verdict・同じ台帳に一意。`RootCycle` は新しい拒否証拠として読み替えない。第二引数の実自己環を加えた別の制御例は、新分岐を拒み、旧の根 K2 の証人だけが通る。
- 証人の監査: 元の根・宣言・出現・行番号の照合があり、望む verdict の証明を実行データには入れていない。3 条件は (a) `R13` と `dictionary_sound_R13`、(b) 数値アドレスで読む `RepeatedCenters421.check` と旧分岐の完全な委譲、(c) 既定の固定目標の `RepeatedCenters421.check_sound` と同じ実報告の同じモデルでの辞書・意味の証拠。新しい `DictionaryEvidence` を定義していない。

## 追加の対照: 実行 locator と意味の区別

公開 audit `lean/Audit/Cycle421I74RepeatedCentersSpec.lean` の `build`・`probe` だけを使い、展開した補助 harness でも `lake env lean --trust=0 -DwarningAsError=true` で exit 0。Lean tree には補助 harness を追加していない。

- `build mismatch tie cycle` の 8 通りで「新・選択／新・不整合拒否／旧・根 K2」の 24 照合。順序 `mismatch`→`tie`→`cycle`、各 `false,true` として三組の期待値は `000,001,100,001,010,001,000,001`（0/1 は checker の false/true）。旧 K2 証人の閉じる alias 行は `tie = false` では 6、`true` では 7。二番目の引数の構造行 1 と子 6 は不変。古い locator 6 を等式追加後にも流用した 2 対照はいずれも false。K2 の意味は保存し、古いアドレスを勝手に読み替えない。
