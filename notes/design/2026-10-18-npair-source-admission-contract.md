## Decision and exact change

The adopted slice is one nonempty concrete-only negative formal-port row. The
source gate already admits the relevant HIR shape except for the negative-row
predicate in `crates/yu-solver/src/candidate_source.rs::preflight_formal`.
Extend that branch from

```text
row.concrete.is_empty() && row.variables.len() == 1
```

to

```text
(row.concrete.is_empty() && row.variables.len() == 1)
|| (!row.concrete.is_empty() && row.variables.is_empty())
```

The positive branch remains `row.variables.len() <= 1`. The extension is only
for negative formal rows reached through recursive Function-port variance.
It does not admit an explicit empty row, a mixed concrete/symbolic row, or a
row with multiple symbolic variables. The existing singleton symbolic-only
case remains accepted. Root computation rows and ordinary/local annotation
preflights retain their existing rules.

No change is proposed to `candidate_call.rs`, the HIR parser, the producer in
`candidate_effect.rs`, ordinary constraint generation, or expected output.
The producer already accepts the exact concrete-only negative row and retains
one inert Permission with the annotation owner, parameter, lambda occurrence,
solver scope, source row key, typed path, and all concrete effect IDs. It keeps
the full positive/negative Function trees and emits existing links 43/44 before
publication. A distinct `FormalEntry` handles a root computation row; concrete
root atoms do not gain links 45/46. No Permission is an emptiness, provider,
lower/upper-bound, closed-row, or subtraction fact.

## Source-to-action correspondence evidence

The read-lease amendment pins the direct HIR owners and the graph-plan owner.
`lower_module_with_local_source` forms the `LocalSource`; `form_ordinary`
retains each parameter's HIR ID, syntax source key, lexical scope and parsed
annotation. `parse_row` stores a row-position key, resolves each concrete name
to its `SourceEffectId`, retains symbolic variables and permits zero or one
symbolic variable. `SourceAnnotation`, its recursive type/value/row records,
and their derived `Clone` retain the owner, nested tree, row keys and operands.
These are source-construction facts, not a claim that every input has a usable
carrier; the normal-entry regression below is the falsifier for the target.

`CandidateInference::solve` obtains the HIR-owned carrier and runs preflight
before candidate collection. For a successful carrier, collection records the
actual parameter recipe and emits `Action::FormalAnnotation` with the cloned
source annotation, parameter position, lambda occurrence and computed source
scope. The collector checks carrier pointer identity and owner/occurrence
ownership. The source schedule dispatches that action directly to
`candidate_formal_annotation`; the producer derives typed Argument/Result
paths from the retained annotation tree rather than reconstructing them from
names.

`execute_candidate_graph_plan` runs each member's source schedule before graph
capture and publication. A failed `run_candidate(self)` returns an error and
does not yield a public `CandidateInference`; this is the source-attempt
visibility boundary. The source action does not carry an independent path field.
No stronger route-local rollback claim is needed for this source-entry slice.
The constructor's internal all-or-nothing details remain governed by its
separately reviewed producer evidence and its existing caller boundary.

The ordinary source constraints and links remain generated by the existing
collector and action schedule. The predicate change cannot suppress or replace
them. The proof does not claim consumer discharge, `At`, N-Transport,
N-Subtract-Elim, soundness, principality, termination, or production closure.

## Regression and verification contract

Add a focused unit regression under the existing `shadow-apply-candidate`
test configuration, in `candidate_source.rs`, using normal `parse_file`,
`lower_module_with_local_source`, and `CandidateInference::solve`. Use a declared
effect and a nested result/result negative port, for example:

```yu
act ctrl:
    our choose: () -> (() -> [ctrl] int)

my receive (f: () -> (() -> [ctrl] int)) = ()
```

The test must first establish that the parsed source has no structural recovery
and the lowered HIR retains the target parameter annotation with a nonempty
concrete row, no symbolic variable, and its concrete `ctrl` identity. Then the
normal `CandidateInference::solve` entry must succeed. This proves source
admission and normal candidate completion for this input; it does not prove the
parent theorem or downstream effect consumption.

In the same regression, preserve accepted behavior for an omitted negative
formal row and a singleton symbolic-only negative row. Require refusal for the
target port when separately changed to explicit empty, mixed concrete/symbolic,
and multiple-symbolic forms. If HIR itself rejects multiple symbolic operands,
record that normal-source rejection as the observed first gate; do not attribute
it to solver preflight. Include a positive concrete port as a variance control.
Keep all existing expected outputs unchanged.

Run only the focused test command for this source-entry regression (one Cargo
test process, one verification owner), then obtain independent review of the
frozen code delta. Report any repository-known formatting CI failure separately
from the targeted result. No broad suite is required in this gate.
