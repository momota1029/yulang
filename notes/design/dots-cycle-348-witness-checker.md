# Cycle 348 — I-63: 証人検査器の設計

根拠: `integration/m1-final` の `c65291c929b0fd2754fd34af93c9e617bbb06e63` における
`notes/plan/dots-inbox.md` の I-63、`spec/06-roles.md` の 6.3・6.5、B4 草稿の補遺 5–10。
これは設計であり、新しい検査器・証明の実装ではない。既存 C316 の実行器から作者を推測する作業は止める。
検査が不成立になることと、言語の `pending`・`rejected` は別である。旧 `Local` との対応・完全性・停止性を前提にしない。

## 1. 境界と型

- **固定入力 `Problem`**: 同じ元プログラムから独立に与えられた宣言表・解釈・根の需要、元の構文／制約の位置と値、および検査の対象となる宣言的状態 `Σ`。状態は通常の制約・区間・等式・必要な論理上の正確な射影だけを持ち、solver の slot、物理番地、journal を持たない。根の出力は名前・ターゲットの順序付き列として入力側で固定する。solver はこれらを書き換えられない。
- **返値 `Result`**: 診断木（各ノードの局所タグと子のタグを保持）、選定辞書があるときの順序付き辞書、根・子の出力レシート（正準節番号、節内の出力番号、要求された名前と元のターゲット、再生した右辺の正規形）。辞書が無い結果を空辞書と同一視しない。診断失敗を親の根拒否に畳まない。
- **有限データ `Witness`**: 以下の表・有限の構文木・検査可能な推論のトレースと索引の有限直列化。`Prop`、`Assignment`、関数値、完成済みという自己申告、`Classify`／`Evidence` の証明、任意の決定手続きを payload に入れない。内部の計算可能な等価判定は式の構文等値、順序・長さ、表の参照と、定めた証明命令の再生に限る。全モデルを探索しない。

概形（まだ Lean ではない）:

```text
replayWitness (P : Problem) (Σ : State) (w : Witness) : Option Result
checkWitness P Σ w := (replayWitness P Σ w).isSome
checkResult P Σ (out, w) := (replayWitness P Σ w == some out)
```

`P` は検査対象を固定する引数。API を `checkWitness Σ w` と見せるなら、`P` を呼出側で閉じる。
普通の等式列が同じでも「ソースで書かれた」と「未解決の出力だけが与えた」は異なるので、
`Σ` と witness の自己申告だけから source origin を復元することはできない。
独立な入力は、元 AST の指定箇所からの再生成か、別に検査済みの入力表への完全な照合で認証する。
ハッシュが一致するだけで出力レシートや作者の内容を真にしない。

### 有限化するもの

`Registry.roles : Nat → RoleDecl`、`RoleDecl.assoc : Nat → Option (Option Term)`、
解釈の関数、`Supported.derivesFrom`、完成／待機の述語はそのまま有限データではない。
変換はチェッカー側で行う。明示されたコンストラクタ・role・関連型（必須、既定値、未宣言を区別）の表を、
表の外が空の正準検索関数に持ち上げる。空の role に許す arity などは既存の入力形式に合わせる。
外部の関数型 registry を受ける版では、表が元の registry と同じことを trusted bridge で別途示す。
既知の有限の名前に問い合わせただけでは、任意の role/name の `DefaultsCovered` は言えない。
`Coverage r i` は見えている候補だけでなく、正準入力表全体の既定値まで確認する。

## 2. Witness のデータと検査の階層

| 階層 | Witness に入れるデータ | 検査器で再生すること |
| --- | --- | --- |
| 宣言・解釈 | 表の索引、各宣言の正規化・サイズ／保守的下降の有限な根拠、正準節順 | 可視の宣言 ID の一意性、role の arity、スコープ、入出力名、constructor の種類・引数数、関連型本体と role 側の既定値、既存の宣言正規化と下降の条件。`Checked r` と `Coverage r i` を構成。子が小さい事実はここでは宣言検査であり、solver 停止の証明ではない。 |
| 状態・作者 | 普通の行／区間の索引、元 AST 位置または検証した出力作者の参照、使用時の owner・版・節／引数位置・mode、release の参照 | 同じ宣言的行と同じ作者を照合。出力作者を根拠にする場合は、要求先の名前／固定ターゲットと完成した子までを検査した owner にだけ release。履歴参照は古い slot と現在の読みに同じ作者／版がある証拠ではない。元の solver が release を出さないときは新しい返値の側で記録する。 |
| 通常グラフと支持付き読み | 行証拠、方向付き別名／境界の足取り、使用する支持行、入れ子の読み木、K2 の有限経路／閉包の理由 | 通常の行は K2・まとめ・通常制約に残す一方、候補の頭には許された由来だけを使う。要求位置で下端・上端を別々に読む。真正な遅延と失敗した証人を区別する。独立な出典にない関連型行を、等式が真だというだけで入力の根拠へ昇格させない。 |
| 候補と診断 | 可視かつ role 一致の候補ごとの正規化された照合／不成立／未解決の証拠、判断で実際に調べた位置、局所タグ | 選ばれたものだけでなく競合候補を表から全て列挙し、抜け／重複を検出。唯一性と未解決なしを証明するには、不在を有限閉包・反射定理で再構成し、単なる `false` の主張を信用しない。I-59 の根 K2 は未完成出力由来の通常行を含めて検査し、そこで新たな照合・子生成をしない。I-59 以外の優先順は承認済みのもののみ。 |
| I-61 の読みと捕捉 | 下端／上端の支持行、選んだ候補のパターン位置、端点の field／payload／tail ごとの具体式、open/closed、中心の名前、元からある名前と新設する名前 | 入れ子の record/pair/variant と認可済み nominal・同タグ join を正規形で再生。非点で下端と上端を別の式として保つ。中心行の支持の有無は端点からの選択の条件にしない。field と tail の独立の役割、見えない／未知 field と lower-clash を分ける。残部は独立の実削除と不在を検査し、単なる mask を同一視しない。plain でない合流後 payload を枝に分解しない。非点端点の一つを実中心と取り違えない。 |
| I-58 と compiler | 実際の取り出し順の binder／mode／中心、保護名、有限の fallback と節・出力ターゲット表、出力ごとの制約導出、順序付き子需要 | 選定した後で反復変数の実中心の tie 行を再生成して普通の状態のレシートを検査。端点が合うだけでは tie を認めない。未支持の中心行を使用せず、中心の名前は使う。固定出力、同じ名前の重複要求、子を順序付きで照合。新しい捕捉用座標が既存の保護名を上書きしない。 |
| 木と返値 | 選択 ID、子 witness の列、各子から用いるレシート、根・子で要求された出力 | 再生した需要と子リストの同じ位置で witness を再帰検査。`Resolves` の後に `Summarizes` を独立に再構成。solver の診断木、辞書、固定出力の全てを再生結果と構造的に比較し、順序・重複・ターゲットを含めて一致した場合だけ通す。 |

由来の注意: where の入力を作る節の式と、impl の関連型の**出力**は別のレシートにする。
節入力の構成を認める場合も、親の許された入力と実際の compiler の対応から示す。
親が物理 commit 済み、または `Ready` というだけで、関連型出力を completion として自己開示しない。
完成 owner の参照は検査済みの有限な依存 DAG と別にチェックし、出力の輪だけで相互に「完成」を付けない。
独立なソース根をもち旧出力と同じ式になる行は、独立な根拠で使える。順番や DAG 証書が見つからないことは
証書の不合格であり、言語の新しい拒否・保留ではない。

## 3. 健全性の分割 (S2)

1. **索引と有限関数の反射**:
   `checkWitness P Σ w = true → Checked r ∧ Coverage r i ∧ Declared r d`（同じ `P, Σ, d`）。
   `Declared` は要求列の各位置を元の role 表に照合して作る。節の子の `Declared` は同じ source/compiler から運ぶ。
2. **局所の読みと receipt**: それぞれの専用検査から、承認済みの読み・捕捉・実中心／順序・現在の `Receipt` を構成。
   `GeneralDeclarativeWitnessHead334`／`WitnessNode334` と、I-61 の
   `GeneralDeclarativeEndpointRecord336`、`GeneralDeclarativeExactDeleteAuth337`、
   `GeneralDeclarativeTaggedInputs340`・`TaggedSelected340` を利用する。
   334 の元の証人へ具体的に帰着する枝は `GeneralDeclarativeWitnessClassify334.dictionary_sound` に渡す。
   I-61 の端点経由で 334 の従来の読みに変換できない枝は、334 の木の fold と局所インターフェースを使い、
   `GeneralDeclarativeTaggedDictionary340.dictionary_sound` との接続を別に示す。旧 `Local` 対応で置き換えない。
3. **同じモデルの補題を明示**: `Models Σ m` を任意の一つの `m` で固定して子まで再利用する。
   340 側が要求する `ModelsExact` の sidecar を witness が勝手に追加して真と仮定してはいけない。
   既存の論理座標を使う版では、受理した各 exact read/write が**同じ** `Σ` の全モデルで成り立つことを
   receipt 検査から示す。新しい論理座標を明示する版では、exact 射影を意味づけた宣言的状態を返値の外部の
   検査対象として固定し、同じモデルで証明する。元状態へ戻す保守拡大や射影は別の補題とし、
   選定後の I-58 等式が元モデル全てで自動的に成立するとはしない。ここは 334 と 340 の接続で未証明。
4. **返値一致**: `checkResult P Σ (out,w) = true →` 同じ `Σ` から再生した診断木と返された木が一致し、
   選定された辞書と全ての固定出力位置が一致する。選定の場合は、任意の `m` について
   `Models Σ m → Evidence r i m d dict`。選定でない場合に辞書健全性を空にして「主要結果」としない。
   負のタグは対応する承認済みの診断の証明に接続できたものだけを最初に認証する。失敗理由が証明できない
   タグは未対応とし、accepted な selected の意味を変更しない。全タグへの対応は S2 の残項目として追跡する。

注意: 340 の `Ranked` は選定の有用な正の証明書だが、状態全体の rank を全候補に必須とするのは仕様ではない。
狭い最初の検査では rank を補助証書として許せるが、一般化では選定で実際に調べる位置の
K2 判定の有限な閉包と否定側の反射が必要。rank 証書の欠如を K2 や言語の拒否にしない。

## 4. 最初の実装の切り口・試験

- 次周の最初の薄い縦切りは「有限な宣言表・既定値・需要の出力列 → `Checked/Coverage/Declared` の反射」。
  その後 `Witness334` から正の point の一ノード（根＋既定値）の ordinary receipt を再生する。
  全状態に対する `Decidable` や包括的な非構成仮定は使わない。
- 次は C348 で既に公開した元の反復 binder の一子 fixture の**宣言側**データを、実際の子順と固定 target 4 の
  独立検査の回帰に利用する。C317 の物理修正版は実装出力の設計の参考に留め、
  旧 C316 から同じ作者が出ると主張しない。同じ名前を繰り返す別の節、別の版の行、target 4 を 5 に変えた入力、
  二子以上の別 fixture で子の順を逆にした入力は拒否する検査例にする。これは言語の拒否ではなく証書／返値の不合格。
- I-61 の縦切りは、distinct lower/upper、中心の行が未支持、入れ子の open tail と closed tail、standalone 削除。
  lower が未知／clash、同じ tag の join、古い版・別 mode の行、未完成の関連型出力を支持にする偽造を別々に試す。
  併せて I-59 の根 K2 と、根 K2 が無い単なる待機を取り違えないことを試す。
- **残り**: S1（有限データと検査器の実装）1 群、S2（反射・同一モデル・診断／返値の照合と 334 接続）1 群、
  C（通る証書を実行器が必ず作る完全性）1 群、後回し。このノートで設計を選んだだけで群は閉じない。

## 5. 実装順を固定するための小さい境界

- 構文・宣言表の反射を、`Problem` の再構成時に一度だけ実行する。検査器が同じ `Decl.id` を持つ別本体を
  選べないよう、witness の候補参照は検索した宣言本体への索引にする。各 `RoleDecl.defaultsScoped` は
  非空の既定値行の scope の検査から構成し、table の外の既定値が無いことは正準検索の定義から示す。
- 論理式の証拠命令には、明示された ordinary 原子・区間・行を参照する命令、構造に沿った等式導出、
  前の命令を参照する合成命令を用意する。検査するのは行の membership の自由宣言ではなく、
  具体的な索引から戻る型の式（向き・引数・mode を含む）。証明を受け取る命令やモデル探索は置かない。
  `Alias` の有限化は、ordinary の変数間制約と interval の到達可能性、および行の変数間の等式を反映する。
  K2 の閉包と候補の不在に必要な否定側の反射は、同じ有限の節点・辺集合に対して別補題にする。
- witness 内の修正済み extent を検査対象 `Σ` に加えない。「等式を出力した」と「現在の `Σ` がその等式を
  満たす」を別に反射する。返値に型式を持つなら、固定出力は名前・位置・ターゲットだけでなく、
  compiler が再計算した**記号的な右辺**まで比較する。全モデルで同じ具体型値になるとは仮定しない。
- 子列の照合では「長さ + 各位置」を使う。ハッシュ・集合同値・並べ替え後の比較で済ませない。
  仕様／既存の compiler が正準化するものはその境界で一度だけ正準化し、実際の出力列の順序と区別する。
