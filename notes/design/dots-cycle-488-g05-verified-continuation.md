# C488: 照合済み全候補と後続処理の境界

新タグの受理は prior / 局所意味の前提を置かずに、元要求座標の数・順序・guard、および report・tape・local token 枠の三つがすべて実可視候補と同じ個数であることを保証する。各 report row は正しい表示順と元 registry ordinal に対応する。未検査のものを言語の拒否にしない。

続きの処理は抽象 callback として受け取る。真の scoped K2 を含む正確 report が検査を通るなら、任意の callback に対して同じ元 ordinal の非空リストを返す。K2 が無く検証済みのときだけ、二つの rigid match や unresolved も含め、実際に読まれた全候補印を元順に渡す。一般の候補探索、曖昧性の決定、辞書選択を実装したとは言わない。

独立な試験で実可視候補を四つ作り、K2・rigid match 二つ・未確定一つを同時に保持した。原 registry の入替後も、本当に訪れた field の K2 に対する優先を維持し、数値の ordinal は元の新しい位置に合わせる。正式な局所判定は名前つきの型と前提の側に残り、試験は明示 token に限る。
