## Required implementation-ready audit, not just proof-parent status

At every substantive dispatcher consultation with an idle implementation lane, inspect **at least two relevant, distinct code ownership areas** in the approved active goal before asserting that no implementation work is ready; use the smallest bounded code/test/history reads needed. Include the explicitly user-approved Simple-sub/F5 retirement and existing playground/runtime contracts, not only the currently stuck N1 primitive-image theorem. Reuse prior code, tests, implementation receipts and proof results by exact path; do not restart withdrawn mechanisms. A broad source audit is not needed on every tool call. Produce one of:

1. **Code-ready patch:** a source-owner-local change required by already approved semantics, with concrete file/symbol, preserved invariant, old/new dependency and focused test. This is an actual `implementer` Luna/high packet, not another proof note.
2. **Executable validation:** run one *bounded, existing* focused compiler test/check for a selected supported source behavior; if coverage is missing, add a small independent regression encoding an already established/approved expectation. In ordinary authorized implementation work, adding such a focused test and running its narrow checks does not need an additional user decision. If it exposes an implementation defect, the next packet repairs the actual source owner; never change existing expected output merely to pass. Test-only exploration is evidence, not implementation closure.
3. **Provisional source evidence:** when a genuinely necessary A/B theorem cannot be discharged without an actual source construction, build only the minimal reversible, explicitly nonproduction code/instrumentation slice authorized by the existing proof-first policy. Its own code/test gate may close; dependent production stays OPEN.

For a selected implementation packet record **source path/symbol, selected authority, exact edit or observed command, bounded resource/time limit, expected result/falsifier, test command, original proof dependence and lease**. Give primary Luna the executable packet before another standalone speculative architecture/conditional-theorem packet. The dispatcher proposes; Luna validates and grants authority and leases.

## Breaking the research-only cycle

After **two consecutive proof/research-only checkpoints without code execution or an assigned implementation packet**, a third speculative/conditional research packet is **not the default next action**. Luna first invokes the ready audit above, launches an authorized executable slice if available, or provides an explicit `NO_SAFE_CODE_SLICE` decision listing the distinct code owners/approved gates inspected and the exact blockers for each. In the latter case, move only affected tasks to WAITING/BLOCKED, ask for the genuine missing choice when needed, and allow only a bounded new proof method that actually supplies a concrete dependency for the next code slice. Do **not** generate more equivalent abstract reformulations just to keep the proof lane busy. Existing running disjoint work need not be interrupted.

A global open soundness/principality, full-Call or primitive-image theorem cannot by itself block unrelated, already approved code, focused tests or a permissible provisional source-evidence slice. Conversely, neither a test success nor a provisional patch proves that theorem or authorizes production/cutover. If all inspected work really depends on unselected semantics, do not invent code or relax soundness: report that precise blocker to the user and stop the unproductive research loop.

A successful correction is demonstrated by one actual bounded code/test/implementation artifact with a source-path and test result, or a defensible `NO_SAFE_CODE_SLICE` with concrete evidence and the stopped research churn. A new design note, TODO count, conditional proof or static role parse is not success. No compiler code was changed by this policy patch, and live worker/test behavior remains unverified until Luna executes an actual packet.
