## 用語（既存の Lean 名との対応は作業者が埋める）

- **registry** `R`: 有限個の `impl` 宣言の集合。各宣言は `(role, head, where 節の列, 関連型の等式)`。宣言検査（6.3: where の子は、隠れた同名 field を除き同じ tag を併合した後で head より小さい。型変数の捕捉の後に初めて併合が起きる impl は拒否）を**通ったものだけ**を含む。
- **状態** `Σ`: 通常の型・行の制約と、共有された graph（型変数の下界・上界の区間を含む）。モデル（`Common` の割当）の集合 `Models(Σ)` を持つ。
- **需要** `d = (r, a₁…aₙ)`: role `r` と、各引数が区間 `aᵢ = (loᵢ, upᵢ)` であるもの（中心なし。同じ頭の constructor は区間の中で単純化済み）。

## 宣言的な分類 `Classify_R(Σ, d) ∈ { pending, selected(k, ds), ambiguous, rejected }`

実行版を参照せずに定義する（作業者が Lean の帰納的な判断として書く）。

- `pending`: `d` の下界の頭が `Σ` で未解決（上界だけでは解決を始めない）。
- `rejected`: (i) `d` の根が名前のない構造的な再帰型、または (ii) 生き残る候補のうち、名前のない再帰型の constructor を調べる必要があるものが一つでもある（K2。曖昧より先）、または (iii) 区間の制約の伝播ですべての候補が消える。
- `ambiguous`: K2 の拒否がなく、未解決の検査もなく、候補が 2 つ以上生き残る。
- `selected(k, ds)`: K2 の拒否がなく、未解決の検査もなく、候補 `k` だけが生き残る。`ds` は、`k` の **すべての** where 節に、捕捉した束縛（同じ変数の繰り返しは区間を併合して）を代入してできる子の需要それぞれに対する `Classify` が `selected(·, ·)` になったときの辞書の列。子の一つが `pending`/`ambiguous`/`rejected` なら、全体は辞書を持たない。
- 候補が生き残るかは、区間の伝播（自己の `lo ≤ up`、同一の実引数の交差条件 `loA ≤ upB`、`loB ≤ upA`、通常制約）で決める。`∃` 代入の探索は使わない。
- 注意（未決。作業者は決めない）: 「最終的な `pending`」は、**安定した状態**（ファイルの終わり）でなお未解決のものに限る。途中の `pending`/`ambiguous` は言語のエラーではない（spec 6.3）。

## 主定理（B4）

**任意の** registry `R`（宣言検査を通る）、**任意の** 状態 `Σ`、**任意の** 需要 `d` について、次が成り立つ。

1. **飽和の存在と停止**: 飽和 `Sat(R, Σ, d)`（兄弟の更新が安定するまで、兄弟と親を再生成して再計算する）は停止し、安定した状態 `Σ*`（`Models(Σ*) ⊆ Models(Σ)`）と、各生成された需要の安定した状態を返す。停止の尺度は、宣言検査（Paterson 的な下降）と K2 から導く。
2. **正確性**: `Sat` が返す分類は `Classify_R(Σ*, d)` に等しい。
3. **順序独立**: where 節の列を並べ替えても、visible な impl の列を並べ替えても、`Classify_R` の結果（`selected` の識別、`ds` の内容を含む）は変わらない。
4. **辞書の健全性**: `Classify_R(Σ*, d) = selected(k, ds)` なら、`Models(Σ*)` の**任意の**モデルで、`d` の role の実装として、`ds` が構成する証拠が成り立つ（`k` の head への代入と、すべての where の子の証拠が整合する）。
5. **拒否の正しさ**: `rejected` は、上の (i)(ii)(iii) のいずれかが実際に成り立つ場合に限る（偽の拒否がない）。

注意: 完全性（「仕様が受理すると宣言した範囲の `d` は拒否されない」）は、(5) と、宣言検査・K2 が仕様の決定として書かれていること（拒否の理由が仕様にある）から出る。拒否の範囲は spec 6.3 の決定に限る。

## 補遺（2026-11-11、サイクル 112 の忠実性レビューを受けて）

1. **保留が拒否より先（ユーザー決定 2026-11-11「1 だね」）**: `pending`（下界の頭が未解決）のとき、(iii)「区間の伝播ですべての候補が消える」による拒否はしない。(iii) は、検査が始まった需要（下界の頭が解決済み）に限る。例: `x` の型が未定の時点の `show x` は、可視の `Show` impl が 0 個でも保留。安定した状態（ファイルの終わり）でなお未解決なら、最終の保留として扱う。spec 6.3（型の決まった需要だけを可視 impl で検査する）の読みと一致する。
2. **結果は診断ツリー（既決の境界 1 の反映、監督役）**: 主定理 (2) の「`Sat` が返す分類」は、4 分類ではなく、子の結果を保持する診断ツリー（`Resolves Local d tree`）で述べる。4 分類への写像は、子がすべて辞書を持つ完成ツリーについてだけ定める（`Completed`）。子が失敗した親を、根の拒否へ畳み込まない。
