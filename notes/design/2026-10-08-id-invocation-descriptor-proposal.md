# Ordinary invocation descriptor for the transformed `id` root

Status: Draft; not user-approved
Scope: candidate ordinary public contract for import-free `id x = x`
Implementation authority: none
Supersedes: none

## 1. Purpose and boundary

The approved root-policy decision requires an actual transformed public root
whose ordinary clauses are active at use time. The current D0 research supplies
a conditional source-free graph for `id`, but does not identify the independent
meaning of its invocation interface or prove local image typing. The current
ordinary F5 arrow exposes only polarized endpoint structure and does not carry
that contract.

This draft proposes a decision surface for the missing `id` invocation
descriptor. It does not select a representation, claim an `id` decoder is
sufficient, authorize implementation, or close any inference gate. Its clauses
must be interpreted independently of the source relation and activated at the
actual transformed root `u_id`.

## 2. Existing commitments this draft preserves

The approved root-policy answer and receipt require the displayed transformed
scheme and any necessary use information to work at the actual public root.
Public use cannot consult the original definition or retain a renamed full
source relation as its oracle. They leave the concrete descriptor, decoder,
query rule, and implementation unapproved.

The selected source and membership rules already fix these constraints for the
`id x = x` source case:

- The callable is Pure and is entered through Value entry with the actual whole
  carrier and receiver incidence.
- Receipt is followed by the designated Force. A returned value is rebound at
  the original formal incidence in the current world; the body returns that
  same value, and the invocation returns it outward.
- Force progress without an exposed operation `Request` retains the receipt
  and designated Force incidence but does not invent an operation instance or
  raw continuation. When an actual `Request` suspends, retain its operation
  instance and raw continuation; resumption continues at the current
  configuration without replaying receipt. Divergence produces no synthetic
  Return or rebound value.
- Every genuine decomposition of the same actual callable must accept every
  independently admitted complete challenge, including pending challenges.
  Every actual observation and compatible future demand must satisfy its
  independent contract. Admission cannot depend on query success, provider
  acceptance, or output safety.
- Immutable returned values retain their hereditary contracts. Static capture
  provenance does not itself grant dynamic activity.
- Original whole scopes, shared coordinates, event fields, rigid imports and
  incidence correlations remain joint. The import-free `id` case has no fixed
  public imports.
- Independently licensed non-source production observations remain possible.
  Their admission and complete obligations cannot be made dependent on source
  execution.

These commitments are inputs to the proposal; this draft does not redefine
them.

## 3. Proposed public descriptor fields

At `u_id`, the public descriptor would expose one jointly scoped contract:

```text
E_id = (head, ports, D_id, Guard_id, Complete_id, scope/incidence certificate)
```

The fields have the following intended jobs:

- `head` and `ports` identify the callable and its actual Value-entry,
  receiver, body-result and outward-return incidences.
- `D_id` is the independent, comparison-free admission relation over complete
  input challenges and their compatible continuations.
- `Guard_id` is the independent ordinary observation predicate over the whole
  `(h,O,w;xi)` tuple. Its leaves are active jointly at `u_id`.
- `Complete_id` is the exhaustive public observation relation. Every member
  satisfies `Guard_id`; non-source members need separate licenses.
- `scope/incidence certificate` preserves the original binders and exact
  shared, frame-local and event-local dependencies. It is not an executable
  source-root pointer.

`D_id`, `Guard_id`, and every production license must have independent
interpretations. Defining any of them as “the observations produced by the
original source” would violate the approved source-free use boundary.

## 4. Required invocation-phase meaning

The candidate `Interface_id` leaf classifies observations by the actual
invocation prefix, with the same original whole scope and incidences throughout.
The phase distinctions below constrain that leaf without requiring a runtime
phase machine:

| Actual observation | Required interface facts |
|---|---|
| Initial invocation, including zero steps before receipt | Actual callable/receiver and whole carrier are well-typed; receipt preconditions hold. Receipt need not already be established, and no rebound payload or result is required. |
| Receipt completed; Force has not exposed Request or Return | The receipt evidence and designated Force incidence remain current. Administrative prefixes and pure divergence need no operation instance or `Request` witness. No rebound payload or result is fabricated. |
| Force exposes a Request and suspends | Preserve that actual request, operation instance, handle/port and raw continuation. Do not invent a rebound payload or result. |
| Force returns at current configuration `C1` | The returned actual value `v` is installed at the original formal incidence in `C1`; its hereditary value contract remains active. |
| Body result and outward return | **Source-image obligation:** source `id` uses the same `v` and current-world incidence. The independent public guard's requirement for other licensed observations is determined by `ResultPolicy_id`; this row does not select S over T. The body does not force latent descendants of `v`. |
| Response, raw resumption or future demand | Original request/handle/port, operation instance, current configuration, history, lifetime and authority remain visible to the independent admission and observation clauses. |

The source-image clauses in this table describe obligations on `R_id`; they do
not by themselves define the independent public guard for every production
observation. In particular, source identity behavior must not silently become
a universal public result restriction: the S/T alternatives in §8 remain open.
The pending-request row applies only when an actual `Request` is exposed; a
designated Force is not itself an operation request.

This table rules out requiring a completed receipt for the pre-receipt
observation, because the selected source contract includes the actual
zero-step invocation prefix. It also rules out treating receipt-precondition
checking as if receipt had already happened.

## 5. Independent admission and observation equations

The descriptor must define admission before comparison. For a complete
challenge `h`, the candidate relation has this shape:

```text
D_id(h;xi) = Initial_id(h;xi)
             or a valid same-history Response_id extension
             or a valid same-history RawResume_id extension
             or a valid hereditary Future_id demand
```

`Initial_id` ranges over every independently typed compatible context with the
actual callable and whole carrier filled. Response and raw-resumption
extensions retain their actual request/handle and witnesses. Future demands
come from an actually returned value at its original port. None of these rules
requires a successful query, a completed invocation, a selected provider
acceptance proof, or a source execution.

`Guard_id(h,O,w;xi)` is a conjunction of independently interpreted leaves:

```text
Interface_id(h,O,w;xi)
and Endpoints_id(h,O,w;xi)
and EventTypingAndLicenses_id(h,O,w;xi)
and PhaseBounds_id(h,O,w;xi)
and SharedScopeAndAuthority_id(h,O,w;xi)
and ResultPolicy_id(h,O,w;xi)
```

Their required content is:

- `Interface_id` enforces the phase table in §4 and the actual role, entry,
  receiver, receipt/rebind and consumer incidences.
- `Endpoints_id` checks the complete carrier at entry, the body and invocation
  result at their actual ports, and every latent result provider under its
  original future contract.
- `EventTypingAndLicenses_id` checks each actual operation instance, argument,
  response, raw resumption and live authority. A family name alone is not a
  typed operation or a handler witness.
- `PhaseBounds_id` enforces the selected Pure body behavior while leaving
  entry and future latent demands governed by their complete independent
  contracts.
- `SharedScopeAndAuthority_id` checks original scopes, sharing, lifetime,
  dependencies and authority on the same whole tuple.
- `ResultPolicy_id` is one of the unresolved choices in §8; it is not inferred
  from the printed arrow.

At the actual root, ordinary descriptor membership must activate this
conjunction rather than store it as inactive metadata. The independent source
image obligation is then:

```text
R_id(h,O,w;xi) implies Guard_id(h,O,w;xi)
```

The implication is a theorem to prove from local constructor/accessor laws and
current-world Bind composition. It is not supplied by conjoining the guard to
`Complete_id`.

## 6. Exhaustive public observations

Two production presentations remain available; neither is selected by this
draft.

**Finite rule inventory.** List each independently licensed ordinary
production rule with its operands, guards, admitted domains, provider
contracts and future obligations. This makes completeness depend on an
exhaustive source of rule constructors.

**Guarded positive closure.** Use the candidate schema

```text
Complete_id = least X.
  Guard_id(y) and (R_id(y) or Z_id(y)
                   or exists x,z. X(x) and W_id(x,y,z)).
```

This makes recursive license derivations explicit and supports shared
transport proofs. It requires concrete meanings and lawful action for every
`W_id` and `Z_id` alternative. Empty `W_id/Z_id` describes only a source-only
subcase; it cannot stand for an unspecified production inventory. An unanchored
`Z_id` alternative remains admissible when independently licensed, even though
it has no source execution witness.

For either presentation, every member must satisfy the independent guard, and
every actual production arm must be accounted for. If an arm changes provider
or history coordinates, it needs either a proof that the existing full
admission/future domain is preserved or an explicit changed-domain rule with
the required containment proof. Positivity does not establish this.

## 7. Public observation and actual-root query

For an admitted challenge `h`, expose

```text
Obs_id(h) = Pi_xi { (O,w) | Complete_id(h,O,w;xi) }
```

as active ordinary clauses at `u_id`, together with the displayed head,
ports, admission and scope/incidence evidence. At an actual invocation of
provider `v`, same-provider membership checks `v`'s real acceptance and actual
complete invocation against this independent contract for every challenge in
`D_id`.

The query must target the transformed root:

```text
Direct(u_id,F)
```

One candidate finite certificate uses matching actual interfaces and original
scope/incidence, `Eq(D_id,D_F)`, and `Le(Complete_id,Complete_F)`. If adopted,
the ordinary Function rule must be explicitly approved and shown sound at the
same root. A hidden source query, semantic equality alone, or a chain of
separate successful concrete queries does not establish this rule. The
alternative is to defer query-rule adoption; that leaves effective ordinary
inference and D0 incomplete.

## 8. Decisions required before this can become authoritative

### 8.1 Completed-result policy

Both alternatives retain exact source behavior for `id`:

- **S — selected-provider hard guard:** every completed descriptor result is
  the same actual value/provider rebound at the formal incidence. This excludes
  independently produced replacement providers from completed observations.
  Every production rule must prove that equality.
- **T — independently licensed replacement:** source-derived observations
  retain that exact value/provider, while a separate production arm may expose
  another provider only with the same complete result/import contract and a
  full future-domain certificate. This allows a wider abstract observation
  set and adds license, containment and admission obligations.

The approved direction does not choose S or T. This draft supplies no lawful T
license or required natural use that separates them.

### 8.2 Production presentation and licenses

Choose the finite inventory or guarded positive closure from §6, then provide
every independently licensed arm with its full guards and future-domain proof.
Leaving the inventory unspecified or setting `W_id/Z_id` to empty without an
approved source-only policy does not close the contract.

### 8.3 Ordinary query rule

Choose whether to approve the bounded actual-root `Eq/Le` Function certificate
from §7, or defer it. Approval requires a source-free checker, complete
operand/alternative validation, and a proof that a successful certificate
establishes the whole Function relation. Deferral leaves the public contract
without an effective use rule.

## 9. Required proof and implementation gates

Before this contract could authorize production:

1. Define independent clause meanings and their activation at `u_id`.
2. Prove exact source access/evaluation and local image typing for every
   selected phase, including zero-step, pending, response, raw resumption,
   current-world rebind and outward return.
3. Prove `R_id subset Guard_id` without defining the guard from `R_id`.
4. Enumerate all licensed production arms and prove their active guards,
   complete admission and future-domain obligations.
5. Prove public observation/accessor equations preserve original scopes,
   shared coordinates, events and dependent imports jointly.
6. Prove generalization and instantiation preservation at the transformed
   public root, including fixed/template dependencies, shared internal
   incidence, independent-use freshness, and alias behavior. Prove the
   necessity and sufficiency of any additional public use information; a
   scope certificate or representation sketch alone does not discharge this.
7. If the Eq/Le query is adopted, prove actual-root recognition and effective
   checking. Prove that its admitted envelope preserves the required natural
   inference behavior and any required principality result.
8. Instantiate the transformed descriptor through two aliases, check distinct
   incoming call frames with preserved internal sharing, and make a later call
   through a returned value. This is a concrete regression probe, not a
   substitute for the general preservation proofs above.
9. Set and measure deterministic resource limits before choosing the public
   representation or checker.
10. Pass Gate D representation/resource review and Gate E semantic/specification
   review; obtain explicit user approval and record the approved scope.

This draft authorizes none of those implementation steps.

## 10. Falsifiers and rollback conditions

Reject or revise this candidate before adoption if any of these is established:

- A lawful zero-step or pending source observation fails the independent
  ordinary guard.
- Receipt, Force, Rebind, ValueResult or outward Return loses its actual
  provider, original incidence, current configuration, witness or suffix.
- A production arm or unanchored independently licensed alternative is
  omitted, or an introduced provider creates an uncovered compatible future
  demand.
- Two incoming instances or a returned recursive peer lose the shared/fresh
  frame distinctions required by source Generalize.
- `Direct` accepts a transformed root only by consulting hidden source data or
  by using an invalid equality/containment certificate.
- A resource limit truncates the relation, makes output partially visible, or
  rejects ordinary input inside the approved practical envelope.

## 11. Review and decision status

This is a candidate contract for review. It does not resolve the result policy,
production grammar, licenses or query-rule adoption. Independent semantic and
specification review must test the whole clause set, source-image derivation,
admission/future coverage, actual-root query and natural inference behavior.
After review, the questioning primary can present the complete choices and
consequences for approval. Until then, no representation is adopted and F5
remains the production implementation.
