# C462 / I-87: 元 head / where の有限な安定性証拠

(1) 有限の負側: 実元の head と where に書かれた変数 support に任意の capture を制限しても、元 AST の二つの代入結果は正確に同じ。実 StartShell の下で、Ready が成立しない iff 有限 table の一例で代入後の Smaller が偽。個々の代入型のサイズの一様上界や正側の判定は主張しない。

(2) 有限の正側: 元の全 pattern grammar に対し一つの再帰で証明用 AST を計算。既存 hide が覆う同名 field と、証明用の二つの arms が文字通り同一の既存 merge の冪等性だけを使う。独立の Projection/ProjectionArgs と計算結果は iff。どの capture でも両側の normalize が一致する。既存 WrittenArgs 閉プロフィールと元の Smaller を検査した場合、旧 Paterson 証明を元の全 capture に運ぶ。

(3) 同じ実元: 真正な空 record の constructor key と (2) を、実元の有限 StartShell に結合。同じ元 head、実 where、role、point、同一 state、選んだ実 field の K2、実 stamp を保つ。任意の反映済み source protocol で、独立な scope と有限の同じ report/stamp は iff。既設三 provider も有限欄と全捕捉安定性へ分解して、前と同一の report/stamp を返す。証明支援であって既設入口に足さない。raw 読取は shadowed field の下を読まない。

正例は同じ true-stamp の K2 field fixture で、元 where 内の隠れる同名 field のみ追加。同じモデルは FitsFull、元宣言は現物のまま。全旧 provider が任意の key で元 WrittenArgs を供給できないが、この限定的な証明支援は実元の安定性と正確な同じ report を構成する。負例は元 shell と静的縮小を通る既存の late-capture 例で、現物の `'a := int` table が strict descent を消す。どちらも新しい言語の判断ではない。
