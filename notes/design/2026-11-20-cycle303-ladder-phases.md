# C303: Counted raw paths and observable terminal agreement

The I-54 work separates true raw states from journal compiler results. Cycle 302
classifies every pre-promotion raw edge, every legal late promotion, and suffix
edges for its specific model-preserving equation-padding refreshes.

Use actual `Counted` raw paths, not a newly defined transition or reader fuel:
after any supported early refresh, every suffix has the exact number of installed
edges reported by its phase. A halted suffix has the unique terminal of that
chosen refresh. Pre-promotion paths cannot halt; arbitrary late promotions may
have distinct raw terminal state but must return the same independent dictionary
as the supported early schedules, in exactly the same total number of raw steps.

The remaining boundary is an arbitrary *early* refresh: its variable numbering
and context may not fit the concrete ledger phase. The result must expose that
scope rather than identify raw journals just because their selected keys agree.

## Early certified refresh

outer-kind probe even when a refreshed catalogue contains unused shapes;
nominal children strictly descend the finite tower depth. The first
post-refresh candidate uses the existing refinement certificate's support
condition and old ownership ledger to discharge the exact allocator
freshness hypothesis. A separate actual-step classification must keep the

For iteration, do not assert that the arbitrary refreshed context equals a
concrete append-only ledger context. The required next lemma would show that
the *extended* retargeted context still refines the next equation-only
reference snapshot: same seed, source-support coverage and owned-key mappings,
and a model-preserving constraints/cache certificate for all normalized
observations. The old certificate alone cannot be reused verbatim after an
install, since the actual append changes both sides of these obligations.

The packet → append subproblem is now witnessed by `InstallData303`,
`Replay303` and `InstalledCert303`: equality of erased report data supplies
literal equality for allocated keys, reserved identifiers and ordinary atoms.
The `Refresh` constructor after a reference install uses its inherited trusted
cache, not an assumption that target cache validity follows only from
projection agreement. A subsequent operational bisimulation must still account
for historical plan/effect snapshots in the two true raw states.

A proof relation for the remaining whole early suffix can retain an
equation-only reference phase and an actual retargeted source state, with:
