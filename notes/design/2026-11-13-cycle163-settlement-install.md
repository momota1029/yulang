# Settlement through an actual child installation

This module does not fabricate the missing concrete output-only consumer prefix.
It proves a dynamic sufficient bridge for any genuine guarded child installation:
if a producer packet is already recorded, its children other than the installed
terminal child are discharged, then the child installation settles the producer.
Trusted input facts and the producer's existing output fact survive the transition,
so its output is admitted to the trusted ledger. A separately checked readback
certificate gives the consumer decision guard; actual generatedness, ordinary
installability, novelty, and the old value guard remain explicit before making
an actual consumer Step. No generic eventual progress or terminal installation
existence is asserted: a semantically trivial leaf can already be Committed.

A companion concrete reservation timeline distinguishes these stages: an actual
terminal producer installation settles the packet and justifies its output 2
semantically; neither installation nor the subsequent recorded equality provides
a current head at source 2. Only the actual refresh supplies the current slot,
after which ReadyAt holds. This avoids silently treating a trusted output as a
currently inspectable output. The existing final consumer remains a query, not
a generated/installed consumer, and this terminal fixture does not instantiate
the nonterminal producer contract above.
