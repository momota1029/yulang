## What the checked run decided

The same-role sketch is not a valid way to add a terminal candidate:
the inspector can *block*, rather than report a mismatch, when it
tries the structural head on the nominal root. Separate roles 0
(parent) and 1 (leaf). Their output arities are equal, so the numeric
child identity, two endpoint IDs, and actual center do not move.
The added terminal declaration has variant tag 0, payload binder 0,
a closed associated equation, and no where clauses. Its generated
demand actually requests no associated output.

The five actual transitions are: old parent installation, nominal
reobservation, first trusted structural refresh, second trusted
structural refresh, ordinary leaf installation. Both occurrences
are then stable. Leaf installation adds only already-known raw
inequalities, but really adds its packet and fixes the leaf binder.
New unused reservations stay freely assignable; the stability proof
uses two values at an arbitrary unused coordinate to rule out
spurious equate steps, and a headless witness for each possible
newly refreshed coordinate. This is stability of one explicit
state, not an argument about termination of any class of runs.

The real Classify tree is selected at both levels. In one explicit
live model the leaf has its actual recursive certificate, yet the
parent has no certificate in *any* live model. The parent uses the
same lower endpoint address after its effective lower operand
changes; the upper endpoint remains justified. The counterexample
eliminates both the former C315 residual producer and the existing
EvidenceNode claim for this boundary. It does not imply a different
source-level type rule is needed.

## Next representation checkpoint

Use a separate address for each compound endpoint version, keyed by
the ordered actual read IDs (C315's independent footprint encoding).
The first implementation checkpoint is not just checking a patched
assignment: make the **compiled current row** name the fresh address,
bind it to the reading of the current expression, and produce the
real emitted child descriptor from that row. Preserve the historical
model constraints and the stable actual center.

A child occurrence is not its numeric owner alone. Its interval
endpoint pair is part of its demand record. If an address changes,
the old and new records need a relation preserving the actual
center, exact arity and ordered children, and all requested output
identities. On the terminal fixture this reduces to the same variant
tag/current payload readback and an empty actual output request list.
Do not identify old and new occurrences by their numeric ID alone,
and do not delete an old inequality or dictionary obligation. Then
prove genuine checked replay/transport or a new install in the
successor boundary, including stability in this concrete fixture
and all actual source witnesses.

Alternative for comparison: make the dictionary certificate read
materialized *actual* child semantic witnesses independently of
versioned interval endpoints. This is a change to the proof/record
interface only if a theorem shows it still realizes exactly the
existing declaration and child semantics. Merely dropping the
endpoint row from `Holds`, changing candidate selection, indefinitely
deferring the illustrated program, or adding a new rejection would
not establish the requested result. No representation choice
is enacted here.
