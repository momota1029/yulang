Do not recover these by a global family scan. 3. **Apply/Catch consumers.** At `admit_candidate_fact`, bind the exact authenticated `k response` source Apply, exact argument Name/definition and its actual FreshUse `S`, actual result port, and the matching continuation owner. At Catch finishing, carry that specific result association through the actual arm body value-flow derivation to `R_catch`, then through the actual `Install(g)` root, only if the source derivation proves that the arm result is that Apply result. ## Option A — retain the successful annotation derivation

**Producer.** The local annotation owner retains a derivation object from the exact response initializer check and paired annotation construction: the actual `L <: A-` comparison, `A+ <: R_response`, exact response definition/annotation, and source field realization linking the `h_arg`-selected callback-body member `m0` to that derivation. The annotation-origin positive Support/AnnotationMember remains a different native operand from `m0`; the rule must provide their source-justified relation, not relabel one as the other. The derivation must carry q/declaration/license and `c_outer` provenance. Its introduction rule must explain why this exact successful derivation exposes the q-bearing callback member at `R_response`; the constructor may not place the desired incidence in its input premises.

**Payload.** Store a rooted, typed `FieldRootA` payload next to the source-owned local root/Graph capture metadata. It includes source owner/occurrences, the exact annotation derivation identity, q and h_arg lineage, `L`, `A-`, `A+`, `R_response`, lower member and upper allowance node coordinates, and the actual Apply/Catch extension identities when they are constructed. Annotation endpoints remain distinct; the derivation is evidence relating them, not endpoint rewriting.

**Consumers.** The exact Apply admission consumes the payload's retained source derivation and appends the selected rule's justified argument/resumption incidence to the actual Apply result. Catch finishing may connect that result to the arm/Catch root only when the actual arm body's value-flow derivation returns that value; it must not infer forwarding from syntactic order. If the Apply is ignored and the arm returns `other_response`, Catch and Install(g) retain the latter root, and the old A payload cannot flow into it. Graph capture then includes only q-bearing endpoints justified as reachable from the installed root and the corresponding A payload. FreshUse maps all payload node coordinates; the specialized field child is drained and acknowledged as described above.

**Potential advantage / cost.** A retains the proof object at the constructor where both annotation comparisons and the exposed root already exist. It avoids treating the callback annotation as unrelated syntax. It adds derivation storage, provenance validation and transactional publication across annotation, Apply and Catch owners. If the adopted A rule needs a post-solve successful derivation, the current immediate local scheme installation cannot publish the field early; stage it privately until the conflict-free gate.

**Required falsifiers.** Change the initializer while keeping an equal annotation; change the resolved callback member/ordinal; substitute another same-family member; make `k` receive another definition; discard the response or return a different provider; use a sibling FreshUse; mutate a shared anchor or scope. Each must reject the stale A payload or produce an independently justified new derivation. Equal annotation syntax alone must not transfer the old `m0`.

## Option B — independently exposed response presentation

**Producer.** Construct and retain a response presentation rooted at `R_response` independently of initializer/field realization. Separately retain the exact source realization `m0` under q/h_arg. The adopted B rule must specify the source-owned operation that combines these distinct objects through the actual `k response` argument FreshUse, continuation interface, and complete result map. The combination rule must be strong enough to derive the field incidence and no stronger: it cannot assume `S=R_ping`, fabricate a returned value after discard, or borrow an unrelated result provider.

**Payload.** Store two typed lineages: (i) the independent presentation's root and annotation-origin typed graph coordinates, including its Support/AnnotationMember and Allowance provenance, and (ii) source realization/q/h_arg plus the separate actual callback-body `m0` provenance and exact Apply/continuation/result/Catch lineage. A bridge token must name the exact join constructor and both input identities. Do not relabel the annotation member as `m0` or union the graphs merely because their annotations or effect families compare equal.

**Consumers.** At `admit_candidate_fact`, consume the exact argument's own FreshUse and source-authenticated continuation interface; at Catch finish, consume the complete return/result map for that same continuation and link only the actual returned root to the arm and `R_catch`. Install(g) keeps that root. A unique Apply nested in the arm is insufficient: if its result is ignored and the arm returns `other_response`, the complete result map must report no edge from that Apply result to the arm/Catch/installed root, and B must emit no bridge there. This distinction follows source/value-flow edges, never a syntactically-last-expression rule, and must not be hidden by rejecting the source. Capture follows both lineages only through the adopted typed bridge, then maps every graph coordinate in one FreshUse and routes the field child through the exact drain/ack. If the source use is not the response definition named by h_arg, or if the continuation drops/replaces its value, the constructor emits no bridge.

**Potential advantage / cost.** B can model response presentation independently from how its initializer realizes a source field, which may fit a more general source interface. It requires a new join object and a complete argument-to-resumption-to-Catch result map with stronger identity and completeness checks across more owners. A presentation by itself contributes no field realization; a source callback by itself contributes no exposed-root incidence. B cannot be implemented as post-hoc copying into a captured Graph.

**Required falsifiers.** Independently vary the presentation and initializer, return the response, discard it, and return a different provider; vary exact Apply argument resolution and use count; retain shared anchors and scope changes. A must not be imported into B by annotation equality. A field receipt for one argument/use/result must fail for a sibling use or another Catch result.
