## Purpose and current result

This document refines the reviewed-gate input for any later implementation
that would connect a retained concrete-only `FormalPermission` descriptor to
an authentic native seed and processing derivation. It grants no source,
compiler, consumer, test, or semantic-change lease.

The applied producer constructs a bounded internal pair: both polar terms use
one fresh row, the separate Permission record retains the exact typed child
path and source-owned operands, and ordinary formal links 43/44 succeed before
publication. In the unchanged successful construction snapshot,
`formal_domains[parameter]` plus the typed path reconstructs the exact
Function effect child and raw row ordinal. This is a candidate constructor
lemma pending fresh independent review. It does not make the source form
reachable: `candidate_source::preflight` rejects the negative concrete row
before emitting its FormalAnnotation action.

The prior authentic seed path can supply native evidence: an Operation-owned
physical `Support(view)` emission with its exact admission and member, followed
by checked actual FunctionPort and ordered Replay derivations and a lower at
the recovered port. This supplies a bounded structural certificate when all
records are live and the finite derivation checks. It does not alone identify
the original dependent semantic witness `w` or validate adopted
`At(D,w,delta)`. No existing reader consumes `formal_permissions` to do this.

## Certificate required for an implementation gate

A later consumer may report an authenticated native incidence only if it
validates all of the following from one live construction snapshot:

1. **Exact Permission incidence:** validate the source owner, formal
   occurrence, parameter, scope, source row, concrete operands, typed path,
   successful formal root, links 43/44, Function tags and composed polarity.
   Recover the raw constructed row from the exact negative effect child. If an
   endpoint is canonicalized, retain the raw occurrence and separately prove
   its current representative belongs to the same snapshot. Never substitute
   family equality, a row number, or a parent Function path for this check.
2. **Authentic source seed:** validate a live physical lower emission against
   its exact bound admission, physical owner, lane, slot and operand. For the
   current Operation case, validate the retained OperationOrigin, declaration,
   owner, occurrence, signature position and member. Check that the source
   view and slot remain live; a fabricated view, stale slot, out-of-range
   member or bare Contribution ID fails closed.
3. **Processing derivation:** validate a finite tree of retained FunctionPort
   edges against exact parent/child endpoints, field, variance operation and
   actual bound keys. Validate ordered Replay inputs and endpoints where used.
   Validate both admission relation and optional processing relation for
   bounds. Reachability alone is insufficient. Preserve alternative Origins,
   relation premises and provider lineages; use cycle guards and never select
   the first Origin.
4. **Reached Permission port:** validate a live lower emission and admission
   at the recovered port, with OwnerEmission.processing linked to the checked
   derivation. Permission is published only after synchronous formal drains,
   so inspect qualifying lowers already present at publication and every later
   lower while the ingress remains live.
5. **Original semantic witness:** prove which existing native identity and
   derivation fields realize each original provider, observation, assignment,
   world, typed-position and `delta` coordinate of `w`. A native interface
   member is not silently promoted to the complete `w`. If current retained
   evidence cannot justify an existential derivation over all alternatives,
   return the precise missing source event/field to Luna; do not invent an ID
   or accept an arbitrary selector.

The certificate is for the selected unchanged-construction snapshot only.
Owners must specify rejection of route rollback, truncated/reused slots,
stale canonical representatives and generalized/copied presentations.
Permission checkpoint/rollback owns its record lifetime today; owners of
physical emissions, bounds, FunctionPort/Replay relations and canonicalization
must state their respective invalidation behavior. Do not infer freshness from
an ID or slot contents alone.

## Exact unresolved gates and owners

**Source admission.** The concrete negative formal row currently fails
`candidate_source::preflight_formal_value` / `preflight_formal`. The ordinary
route therefore creates no admitted negative FormalAnnotation event. A
separate source-owner contract must decide admission of this exact row while
preserving ordinary constraint construction and refusal of explicit empty,
mixed, and multiple-symbolic forms until their original premises are resolved.
Deleting a refusal or citing internal constructor availability does not meet
this gate.

**N-Ingress semantics and consumer.** No owner currently emits or validates
the adopted `At(D,w,delta)` association for this descriptor. The Function,
physical-emission and context/evidence consumer owners must establish the
native realization of every original `w` coordinate, connect the certificate
above to the reached port, and state success and failure disposition. The
current evidence does not prove a new stored selector/event ID necessary, and
it does not prove that existential native alternatives suffice for the
provider-indexed delta. That choice remains open pending evidence and semantic
authority.

**Bounded traversal and accounting.** Any eventual validator needs a finite
work/storage bound, cycle protection, checked accounting, and atomic
publication/rollback behavior. It must preserve independent Origins and
existing/future lower events without turning relation reachability into a
proof. Runtime resource behavior requires a separately authorized execution
gate; this Draft contains static evidence only.

## Falsifiers and next authority boundary

Falsify the certificate if it accepts a wrong Function path, stale or reused
physical slot, unsupported FunctionPort/Replay step, missing bound admission,
an arbitrary first Origin, a family-only match, an Operation member as the
whole semantic witness, or an ingress without an admitted source event. Keep
the original receive route `f () -> R1 / Install(g) / whole FreshUse -> g ()`,
J1 and J2 distinct, and all provider/observation/assignment/future quantifiers.

The exact next decision is split: source admission requires the source-signature
owner and Luna; N-Ingress identity/consumption requires formal construction,
Function propagation, emission and context consumer owners. Neither is
authorized by this readiness Draft. N-Transport, `rho_u`, local receive
consumer, subtraction, `C_sym`, F1/FK1, source-Generalize, soundness,
principality and production remain OPEN.
