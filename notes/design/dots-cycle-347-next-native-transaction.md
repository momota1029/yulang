# C347 の正確な境界と再開点

## Native の (2)

C316 の原始状態では、ルートは実際に観測された `nominal(0,[2,2])` で読み取れる。独立の出所は初期ラベルと width の入力原子。元の宣言は `impl ... (nominal 't 't)` に相当し、反復する 0 を distinct にしない。通常の選定は状態の端点を使い、選定側の I-58 の実中心は、二つとも 2 として取得できる。選定が書く等式・通常捕捉の合成・where の入力を、元の同じ宣言と生の出力要求列 `[(0,4)]` から実際の `compileBody` で生成した。

- 実生 solver の停止時の子: 登録された旧物理子の下側は variant(4)、上側は variant(2)。同じ raw model において意味も一致しない。
- 宣言的な側の子: 独立の支持付き入力から生成した一つの子。下端・中心・上端はいずれも variant(2) と同値。
- 全 native assignment は journal footprint を固定したまま両方を満たす assignment に延ばせる。その共通モデルで一般の mode-by-mode 配置は不可能。これは番地のつづりだけの反例ではない。I-62 が外した旧 `Local` との照合を復活させていない。Native に選定辞書を返す関係と、独立に生成した現在の選定入力・出力の具体比較であり、特定の executable scheduler の返却は主張しない。

C319 の隔離版では、現物理スロットを読んで release を導き、同じモデルの再帰辞書と固定された出力 4 を確かめられる。過去の upper の配置と現在から読む証拠は別。C319 が意図して異なる distinct-binder 例を実験に使うことは、上の C316 の反復宣言と混同しない。逆に、実際に観測される C319 予約目的 10/11 の座標は、非改変 native 到達関係では決して導入されない。

## 次

(2) の第一群には native transaction が実際に現在の where 入力版を生成し、current/archived の対応と受理後の release を保つことが必要。新旧の観測者を同じ意味として扱わず、別の検証可能な variant を先に作るなら原始 solver の変種であることを明記する。第二群は、その本物の停止時スナップショットから I-58/I-59/I-61 の診断・順序・辞書を全階層で得ること。C347 の (4) の一般部品は独立に使えるが、任意の混在した入力 graph から全必要源を得る一般生産群は残る。停止性は別。
