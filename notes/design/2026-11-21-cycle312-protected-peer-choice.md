# C312: Selective reuse of existing aggregates in historical-choice transport

Target (I-55 (4a)): for an actual source-reachable selected occurrence and any
aliased historical packet, reduce current `Prepared` of that declaration to
actual current inspection and finite reuse of aggregate equations, even when
some candidate aggregate names are already constrained. Do not assume old and
current chosen keys are equal.

- The executable data are the actual historical ledger, its exact equation
  entries, the current report, and the candidate's versioned aggregate-entry
  list. Candidate used names, candidate identity and observation version are
  distinct. Allocation is across the registry; an allocated reservation by
  itself does not imply an installed equation for that declaration.
- Separate current raw head feasibility (`Models raw`, cross compatibility,
  report self-checks and projections) from aggregate equations and from the
  full journal. For the pure choice bridge the target is an existential
  private model. The semantic raw support excludes bare reservations.
- For each candidate aggregate entry in that support, actual historical
  target coverage with the same version identity is enough. Equal entry IDs
  recover the exact equation even across distinct installed packets using
  the recorded seed. Preserve protected values, patch only unprotected
  aggregate targets, and prove the patched assignment realizes all candidate
  equations. Non-aggregate feasibility must be preserved by this patch.
- The new theorem should quantify over any actual path, historical aliased
  packet, current bounds, and common starting model. Assume current report
  is finished, real candidate allocation Fresh, explicit non-aggregate
  feasibility (or a proof transporting it) and protected entry coverage.
  Transport to old-key compatibility by current diagnostic uniqueness.
  Equal bounds/ordinary extensions may be useful derived cases, not the only
  statement. Do not assert that arbitrary refresh preserves old applicability.
- For (4b), separately reduce the real selected output diagnostic to its
  actual feasibility witness. Existing aggregate completion can preserve a
  witness on a semantic support; current materialized output and child
  equations are not part of the selected head diagnostic. Do not pass off
  the private (4a) assignment as the common full model. If possible, expose
  which exact current targets need values versus are already protected.

Only the declarative `Sat`-return partial correctness is a secondary
direction. No termination guarantees, Rust integration, or language change.
