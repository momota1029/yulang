# Cycle 287: nominal row parameter at a real where child

Design before proof. The existing declaration syntax has a catalogue row
position, but a named associated result carries a **type**, not an ambient
row. Keep the distinction between a row hidden inside the type of an opaque
nominal argument and an independent ambient row coordinate.

Independent negative judgment: a checked child declaring R(r) where the
constructor R has a row position translates that head to deferred under
the current inspector, even if the source has a point descriptor for R.
Prove the concrete model/lookup and absence of Prepared, rather than
misreporting this as a K2 rejection, a missing dictionary, or a parser claim.
Also characterize recursive descriptor extraction with an explicit row
position and separate it from a whole-type capture.

Independent constructive path: reuse the same layout in a parent whose
head is F(a), where the child input is the whole a and the parent template
is F(F(a)). A child accepting the whole value can avoid deconstructing its
row, and a row nested inside the nominal type can be carried in the output.
Try the actual parent packet and mixed-kernel install, then the child's
evidence, not just a source-expression mapping. True dependence on an
ambient row with every type coordinate held fixed is a separate obligation.
Use the audit's actual constructor/associated-type/where program solely as
surface context, not verification of this new Lean fixture.
