# Bounded next-prefix search (read-only review)

Do not try to force the recursive scalar-leaf fixture to resume: every installable
packet there is already committed. Cycle163 now states this as an actual fixture
theorem. The reserved-output fixture also has a `generated_only` theorem; its
consumer query cannot simply be called a generated child.

The apparent sibling consumer which reads a produced output binder as a where
input is rejected by `GeneralDeclarations.output_input_rejected`, concretely
`GeneralDeclarationExamples.output_used_as_input_rejected`. Preserve OutputOnly.
A generated consumer needs legal checked syntax plus a genuine emitted edge or
alias, before readback and installation can be claimed.

A promising positive prefix already exists below the old Value boundary:
`GeneralNominalSupportSiblings` parent P emits a terminal container child;
`GeneralNominalBudgetContainer` proves actual installability and novelty using
an independent finite countermodel. Unlike the scalar empty-output leaf, this
candidate has a real named output obligation. Promoting its source-justified
parent/child steps to I26 is a separate bounded task. Its parent has other siblings,
so a terminal child certificate alone does not prove the parent is settled.

An alternate future fixture is a wrap parent with reserved root output and
containerChild output: positive model child=Int/root=List Int, countermodel
child=Bool/root=List Bool after parent installation. Observing the parent output
as List Int before the child may accidentally force commitment again. Prove
novelty at the actual intermediate state, not only initially.

Only after a verified novel-child prefix should one attempt full producer
settlement and generated consumer resumption. No change to guard, Step,
OutputOnly or language semantics is proposed here.
