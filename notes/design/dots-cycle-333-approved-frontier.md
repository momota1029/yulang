# C333: 安定 source からの最後の一群の切り分け

「正の Read を列挙できない」はもはや、この断片での穴ではない。元の `InlineTrace331.Read`、旧 `Trace321.Trace`、閉じた `Spine` の各証明から、実際に使用した RHS と alias を有限表に落とせる。where 子の順序と固定論理名は compiler の結果として維持される。I-58 の実中心等式を足す位置と I-59 の例外は変えない。

## まだ示していない二つの入力

同じ I-56 (4) の未完の一群の、二つの入力を分ける。

- **中心の供給:** 実仕様の安定した選定は候補に端点を使うが、端点が positive というだけで元の支持側に実中心 `Read` があるとは限らない。C330 の `ObserverSource330.Input.projected` は、より狭い `Shape` のとき ordinary 状態に実中心の `One` を作る。これを正当な旧区間観測として再利用する。導出した行を元から使えた source 根拠に昇格しない。証拠が自然に二種の read になる場合は、今回の `AlternativeMixed333.capture_plan` に入る。
- **現在の同名 receipt:** `AlternativeMixedReplay333.consume_current` は選定が使った同じ論理名の Frame、実 constructor/name trace、where と根の固定出力に通常 receipt を要求する。これは観測のモデル保存と同じ条件ではない。次は `NFComplete324.ReadBack` の各項と `StableUnder` を切り分け、既に通常伝播で得られるもの（既存行・区間）と、実コンパイルによって安定状態で保証される必要があるもの（選定後の等式・固定ターゲット）を別々に示す。モデルの同値を根拠に支持や別 target へ付け替えない。

候補を作る `Local` が任意の生成関係を受け取るというだけでは、実 compiler の正しさや receipt は出ない。逆に receipt を承認済み source 選定の定義に足して自己証明とするのも避ける。今回の具体的な二引数宣言は、旧 named の未知の残余と inline の actual を同一の checked 宣言に使える肯定例であり、任意の安定状態を覆った証拠ではない。
