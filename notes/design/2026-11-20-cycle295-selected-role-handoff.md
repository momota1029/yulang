# Cycle 295: source-bound selected role to the existing consumer

C294's `BoundReceipt` compares the retained wire but intentionally permits
the same diagnostic list to be checked at multiple disjoint clean selections.
A downstream declaration-specific handoff has a different purpose: require
the explicitly approved selection (exact mixed child address), not merely
an independently recoverable second role in the same snapshot. Bind policy,
brand, and path before using the existing wire and diagnostic gates. Do not
use Rust diagnostic identity, raw path, or the role's spelling as a numeric
semantic ID.

Data: an explicit selected address and fixed scope policy with the prior
wire-bound receipt. Execution: compare address and policy, then call
`useBound`; use only its singleton `Tracked` in existing `runTracked`.
Independently state that a successful handoff has the same chosen address
and old projected payload, then that every readback of the resulting table
has an attached source child under that exact selected declaration and a
separately supplied environment mapping. Inspect separately the C293 archived
real role CST (method-only in the supported extractor) and a synthetic wrapped
role with an associated output whose value is read by the existing solver.
Do not claim a Rust parse, an authenticated diagnostic receipt, or a production
name-resolution environment from either.

Progress: at the archived role `[0]` the actual CST's binding comes from
`[0,4,2,0]`, not an associated-type declaration. An explicit caller map
`a → 7` produces a single arity-1 table row with no outputs; an empty name
map refuses the same clean selected role. The closed synthetic pair uses
one common role spelling and environment but different associated defaults,
`'key` versus `char`. Both raw occurrences pass C294 independently. C295
admits only the designated occurrence and the existing association reader
observes `int` versus `char` when their receipts are separately issued.
These are deliberately labeled different kinds of evidence.

One post-selection limit matters for a production caller: a scope tag does
not prove two independently supplied naming environments agree. Reuse the
already proved local naming-law only for the selected symbolic role.
An executable optional narrower witness records role lookup, output ID
lookup, and nullary constructor lookup when the corresponding output
exists. The theorem will characterize agreement only on those requested
names, not authenticate the source of either map or claim language validity.
