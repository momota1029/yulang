This document records a missing A/B source-construction premise and the
smallest decision object needed to resolve it. It selects no new source
behavior, declaration equation, compiler representation or implementation.

## 1. Frozen objective and boundary

For the accepted unannotated Value formal in `my invoke f = f 1`, connect the
actual Parameter/Lambda source derivation to the selected
[source-owned registry API](2026-10-10-original-registry-constructor-adoption-proposal.md).
The missing original application is:

```text
Gamma_form^src(P) |- mu : Delta_in^orig
intro_orig[mu]
```

`Delta_in^orig` denotes the complete original formal-origin/entry-port input
telescope. It is not a supplied signature. `Entry-Value` consumes the
resulting `ParameterOrigin`, received-carrier and designated-view ports,
receipt, Force and typed rebind declarations. It does not introduce those
declarations.

The parent obligation remains sound, natural inference for the original
supported source domain. This draft does not narrow that domain, require an
annotation, infer source rejection, or establish an impossibility result. It
does not close complete Call, source correspondence, soundness, principality,
or F5 replacement.

## 2. Decisions already fixed by authority

The 2026-10-11 top-level inference principles require the Simple-sub
generation, accumulation, propagation, levels, extrusion, intrusion and
generalization algorithm; proof convenience cannot make ordinary inference
less natural.

The approved registry adoption fixes six representation/API choices only for
the resolved nonrecursive formal/Name/Int pre-Call fragment. In particular:

- raw source recipes are sealed before typed decoding;
- `Header-Parameter`, `Declare-Owned-Port`, `FormalOwner-Ports`,
  `Assemble-Value-Entry` and `Register-Parameter` are candidate APIs;
- each local `Fam_delta` application carries its complete ordered arguments
  and actual scope map;
- a static owner-port permission returns its exact owner, port, whole
  declaration and scope map; it does not provide original contribution
  permission, C0 or live authority;
- the adopted API is not identified with an independently fixed original
  judgment merely because the candidate construction succeeds.

The operational Value-entry order is fixed: Receive, Receipt, one designated
Force, same-result typed rebind, body/continuation, then invocation return.
Request/resumption retains its original response and unfinished suffix.
Static formation creates dependent schemas; it does not assume later event,
receipt, guard, body or future witnesses.

## 4. Required declaration contract

A completed contract must replace the metavariable `Delta_in^orig` with the
actual ordered fields and their declared types. For every binder position
`i`, it must establish the original dependent formation and substitution:

```text
Delta_in^orig = (z_1 : U_1; ...; z_n : U_n)
Gamma_form^src(P), z_1 : U_1, ..., z_(i-1) : U_(i-1)
  |- U_i type
Gamma_form^src(P) |- mu_i : U_i[mu_<i / z_<i]
```

The `z_i` are declaration binders; the `mu_i` are the actual substitution
terms and may be compound values. Each `mu_i` is checked in the original
predecessor context after substituting only the preceding declaration binders.

The full list must account for the actual ParameterOrigin and every complete
carrier, designated view, receipt, Force, rebind and source-scope/license
argument consumed by the original formal-entry rules. For each field it must
record:

- its owner and exact original rule that introduces it;
- its complete dependent type at the preceding binders;
- whether it is a static schema, a proof of a static formation law, or a later
  event witness;
- its scope map and all nominal owner/provider/occurrence identities;
- the lawful action on the entire dependent package;
- the exact consumer and the field preserved there.

Introduction must produce the original `ParameterOrigin` and the whole
entry-port package. Elimination must return that same package, its full
application arguments, formation trees, licenses and scope maps. `Entry-Value`
must then produce the source-owned `ValueBind` with the original rebind
incidence. No output may depend on a later typed decoder, registration, Call
result or challenge-specific witness.

## 5. Unresolved definition inputs

The current authority and inspected owner cone do not settle these items:

1. The exact ordered `Delta_in^orig`, including each `U_i` and its predecessor
   context.
2. Whether the original declaration is independent of raw registry `P`, or
   consumes a well-typed raw-`P` argument. If it consumes `P`, every such
   argument must be available before typed decoding and pass binder-by-binder
   formation.
3. Which complete local declarations supply the carrier, designated view,
   receipt, Force and typed rebind domains, guards, provider/world/future
   fields, and any static licenses. Existing candidate `Fam_delta` names do
   not answer which independently fixed original declarations are imported.
4. The exact introduction/elimination and whole-package action equations that
   preserve dependent scope, original providers, incidence and alternatives.
5. The typed map from that original package to the adopted candidate
   `Declare-Owned-Port` / `FormalOwner-Ports` outputs. Candidate owner-port
   permission must not be upgraded into a contribution license, C0 or runtime
   authority.

These are constructor-definition and source-correspondence obligations, not
observed alternative program outputs. No user-visible A/B semantic
alternative has been established by the current evidence. If existing source
authority supplies the missing fields, the task is to locate and prove their
application. If it does not, a proposed local declaration rule is a new
durable contract and requires independent review and explicit user approval
before implementation.

## 6. Acceptance and falsification

This declaration gate is ready only when an artifact supplies:

- the complete ordered original telescope, not an opaque `Fam_delta`,
  `LocalLaw` or other complete-input placeholder;
- a well-typed substitution for every binder from genuinely preceding source
  inputs;
- an authentic `intro_orig[mu]` derivation and the exact `Entry-Value`
  application;
- preservation of the same source owner, provider, carrier, scope, receipt,
  designated Force, typed rebind and original lawful alternatives;
- a typed correspondence to the adopted candidate owner/port declarations,
  without assuming candidate predicates equal original judgments.

Falsifiers include any field whose type requires a later decoder or
registration, a license not supplied by its owner, a scope/action equation
that changes provider/domain or shares unrelated owners, or an operational
shortcut that changes Return, Request/resumption, prefix, pending suffix or
future behavior. A missing application is not a source rejection.

## 7. Review and approval path

Class: M3 design/source-construction gate, because new local equations could
affect natural inference and complete-call soundness.

Before any new declaration is adopted:

1. Fill §5 with a concrete complete telescope and equations, or identify the
   exact existing source rule that already supplies them.
2. Obtain independent `compiler_referee` review of dependent formation,
   licenses, scope/action preservation and whole operational behavior.
3. Obtain independent `spec_auditor` review of conformance with the scoped
   registry adoption and existing source contracts.
4. Present any genuinely new declaration/API equations and their consequences
   for explicit user approval; record an authoritative successor/addendum.
5. Prove the original substitution and source-to-native correspondence before
   authorizing the dependent implementation or F5 cutover.

Approval selects only any genuinely new declaration equations. The
formal-entry input cut closes only after the complete substitution,
`intro_orig[mu]`, and source-to-candidate correspondence are proved and
independently reviewed. The complete Call, actual checker/domain/observation
laws, ordinary natural inference, soundness, principality, termination,
production publication and F5 replacement each retain their independent
gates.
