# C456 / G04: 宣言モード付き単項 point を含む混在経路

最初の C456 は実 record / variant / pair の経路を通す。独立した native nominal 証拠は存在しても、旧候補変換の nominal は snapshot の invariant flag を要求し、同じ名前の authored declared mode はその flag を false とする。これは同じ FullProblem での入口能力の差で、言語の拒否ではない。

新しい query は同じ元の正規化済み候補木を読み、旧変換の成功を保存し、旧変換で出なかった実の declared unary covariant value application のみ源泉 Use と exact mode table から Visit 用形状を得る。値の意味に旧 Expr を再利用しない。新しい開口は同じ元 native 観測の point（両端が同じ名前）に限る。継承 mode のどちらでも同じ元引数の actual ordinal 0 を特定し、同じ Fits の中で 1 または 4 個の reflexive 比較原子を正確に出す。区間で両端が異なる場合、unused/行・多引数の一般的な visit、nominal body、open record tail は扱わない。

最終入口 `RoutedNominalMixed456.check_full_nominal456` は actual nominal hop がある field K2 の分岐を足し、ほかは以前の C456 variant/pair 入口に正確に委譲する。五箇所の複合経路は同じ実 FullProblem・同じ Fit・独立導出・有限データで確認した。元 where/header の審査と全旧 witness Bool は変更しない。G04 全域は未完。
