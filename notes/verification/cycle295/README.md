# Selected role handoff, cycle 295

The [archived source replay](archived-selected.txt) and the
[synthetic association controls](selected-consumer.txt) are deliberately
different evidence:

- The checked-in Rust/Rowan golden contains a single selected role `a`, a
  method child, and no associated type. The map `a → 7` is supplied by the
  verification driver, not produced by the Rust parser.
- The synthetic wrapped `Index` roles have different defaults at two
  different mixed ordinal addresses while their lookup spelling is the same.
  These are hand-built input wires. The association reader is the original Lean
  resolver, executed here against those controlled rows, not a Rust lookup.
- A local trace contains only read queries and replies. Its equality checks
  stop accidental reuse with changed naming data; no reference environment
  or diagnostic receipt authenticates itself.

## Reproduce

From an ordinary checkout at the result with Lean 4.35.0 and its pre-cycle
dependencies built:

```sh
bash notes/verification/cycle295/verify-focused.sh
```

The optional first argument selects the exact equivalent C294 base commit.
The optional second selects the prior `.olean` directory. Only earlier
dependencies are reused: this script removes every C295 module from the
shadow cache and rebuilds it. It runs all C295 standalone audits and the
C293/C294 boundary regressions, reconstructs the Rust golden from the
archived test text, and byte-compares the four program outputs. It does
not build the complete Lake target and does not invoke Rust.

The [complete declaration signatures](theorem-index.md) are regenerated by
`python3 notes/verification/cycle295/theorem-index.py`.

## A future Rust verification

When an authorized Rust toolchain is available, the existing golden can be
rerun without altering syntax or the parser:

```sh
cargo test -p yu-syntax role_method_signature_where_keeps_its_pre_wp17_recovery_cst
cargo run -p yu-syntax --example syntax_guide_check -- \
  notes/verification/cycle293/proposed-rust-role-cases.md --tree
```

Then capture the exact source and tree for each positive nonduplicate
associated-role case, including its actual mixed member paths. The current
Cargo workspace has syntax/recovery tools, not an observed production name
resolver for these role IDs. An end-to-end Rust producer must collect
`green()` and fallible `syntax_diagnostics()` from one retained `ParsedFile`,
keep diagnostic identities separate from verified source attachment, and
obtain role/output/constructor decisions from an independently established
semantic provider. Only then could it create a production receipt. Neither a
clean raw CST nor repeating the same dictionary constitutes that evidence.
