# Incident records

`notes/incidents/` preserves dated operational failures, observed resource use, root causes, fixes, and lessons.

Incident records are evidence, not automatically active policy. Before applying an old command, skip list, test count, environment workaround, or model-specific procedure, verify that the current branch, workspace, tools, and failure mode still match.

Current durable safety rules live under `rules/`. A new incident may justify a rule change only after its scope and current applicability are reviewed.
