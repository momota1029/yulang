# T19: 未完の sigil の文脈

状態: CST や受理構文の変更は保留。2026-11-09。

第一案は構文変更を先送りし、現状の Error と入力文字列を維持すること。カーソル API は既存の Error token と祖先ノードから sigil と可能な文脈を導出する。次の途中入力のうち、前二つは binder と型右辺、後二つは文脈不明として返す。

```yu
my '
type T = '
$
&
```

別案は、必要になった時点で不正な途中入力に専用の未完ノードを持たせること。その場合はノードの意図、行末や EOF 以外の境界、既存の受理と診断への影響を検討する。現在の補完 API にこの判断は不要であり、受理構文を変更したり、その変更が必要だと主張したりしていない。

## 状態（監督役, 2026-11-09）

CST・受理構文の変更はしない方針のまま、カーソル文脈 API（`cursor_context`）が既存の Error token と祖先ノードから部分 sigil の文脈を導出する形で、T19 の目標（2）を満たした（`my '`・`type T = '` は binder と型右辺の文脈、単独の `$`・`&` は「不明」を返す）。専用の未完ノードを CST に足すかは、LS 側で不足が出たときに再検討する（遅延案のまま）。ユーザーの追加判断は不要。
