# T19: EOF の `---` と演算子

状態: 未決定。2026-11-09。

第一案は判断を先送りし、現状の recovery を維持すること。空の syntax environment では、EOF の `---` は 3 個の Error token（診断上は `0..3` の ErrorGroup）であり、`1 +` の `+` は未宣言の Error（`2..3`）である。宣言済み二項演算子の `1 +` は右辺に Missing を持つ。この差はテストで固定した。

別案として、EOF の `---` を未完の block doc の開始として扱う、あるいは未宣言演算子に未完の演算子文脈を保持する方法がある。これらが受理や診断に与える影響を含め、言語上の扱いを決める必要がある。例えば次をどう扱うか。

```yu
---
```

```yu
1 +
```

## 回答（ユーザー, 2026-11-09）

- 改行の無い EOF の `---`: **選択肢 1（現状維持）**。3 つの Error token のまま。改行が入れば、既存の「閉じていない block doc」（EOF にゼロ幅の Missing 1 つ）として扱われる。
- 未宣言の演算子（`1 +` で `+` が未宣言）: 質問としては出さず、同じ遅延案（現状維持）で据え置く。実際のファイルでは prelude で演算子が宣言されており、宣言済みの `1 +` は右辺に Missing を持つ（テストで固定済み）。差が出るのは空の syntax environment だけ。
