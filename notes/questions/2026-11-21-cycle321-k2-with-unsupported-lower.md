# 下界の展開根拠が未完了の出力だけだが、その等式が K2 の自己環も作るとき

**第一案（遅延）:** 展開しない。独立の根拠を待ち、入った時点では保留中も
保持していた等式を使って K2 を判定する。根拠が最後まで来なければ、
既存の一般化／非一般化の保留規則に任せる。宣言時の拒否は追加しない。

**比較案:** 展開（候補照合・子生成）はしないが、普通の等式から根が既に
K2 と分かるなら、展開せずその需要を拒否と報告する。候補の深部を新規に
調べることとは別。前者とは診断、場合によっては一般化の可否が違う。

章6.3の「片付いていない出力だけなら保留」は展開を指し、同時にその等式を
K2 に使うと指定している。草稿の「保留が拒否より先」は候補全滅のケースを
明示する。11/14の trigger は別で、b の頭の独立の根拠がある。
ここで聞きたいのは **独立の頭の根拠が一つもない、かつ普通の等式に
構造的自己環がある** 場合だけ。

    // 関連型・method の role 宣言は省略した配置例。
    impl Make (list 'a) (list 'u):
        where 'u: Hold
        type out = list 'a

    impl Inspect (list 'x):
        // method の実装は省略
        // where なし

    impl Use (list (list 'a)) (list 'u):
        where (list 'a): Make(list 'u, out = 'a)
        where 'a: Inspect

通常の名前 A, U で Use(list (list A), list U) を考える。
A と U 自体の頭は利用箇所からまだ分からないとする。
Make(list A, list U, out=A) は外側の二つの list が既知なので
照合可能、Hold U は保留。未完了の Make の普通の出力等式は A = list A。
これ以外に A の頭の根拠がない Inspect A について、K2 の根の報告も
遅延するか。実行系の構文検査はしていないので、例は優先順位を説明する
ための source 配置であり、再現済み実装挙動ではない。

Lean の宣言的等式断片では、普通の構造グラフに自己環があることと、
展開用の射影からその出力の根拠が除かれることを両立できる。本周の
局所優先境界はこの重なりを未分類のままにしている。入力が独立に
既知のときの K2 優先・新たな拒否条件を足さない原則は変更していない。
