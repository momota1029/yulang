# 閉じられていない区切りの再同期の方針 (T18) (2026-11-08)

状態: **解消(2026-11-08, ユーザー: 「それでいいと思います」): 選択肢 1 を採用する。**出典: `notes/audit/ls-recovery-audit.md`（Sol の監査）の E2。意味論ではなく、エラー回復の方針（受理する構文は変えない）。ユーザーの承認が要る（文法が複数行の項目を許すため）。

## 例

```yulang
my a = (1
say: 2
my c = 3
```

`(` が閉じられていない。今のパーサは `say: 2` を括弧の中の式として飲み込み、`my c = 3` まで影響が出る。LS では、入力の途中でこの状態が普通に起きる（`(` を打った直後）ので、後ろの文が壊れる。

一方、文法は複数行の項目を許す。次は有効で、行頭の `1,` は文の桁と同じ桁にある。

```yulang
my xs = [
1,
2,
]
```

つまり、「文と同じ桁の行は継続になれない」という桁だけの規則では、有効な入力を壊す。

## 選択肢

1. **（推奨・遅延案）閉じが見つからないときだけ、後ろの文の先頭で再同期する**。まず、字句の列に対して、区切りの対応づけ（`(` に対応する `)` があるか）を事前に一度だけ行う（線形）。対応する閉じが**存在する**区切りは、今までどおり複数行を許す（有効な入力は一切変えない）。対応する閉じが**存在しない**区切りだけ、その後で最初に現れる「文の先頭の行」（宣言のキーワード `my`・`our`・`use`・`type`・`enum`・`struct`・`role`・`act` など、または文と同じ桁で始まる制御構文の頭）で閉じたものとして扱い、診断は「区切りが閉じていない」1 つにする。判断を遅らせる（最後まで分からないときだけ回復する）という、これまでの方針に合う。
2. **桁だけで再同期する**: 文と同じ桁の行が来たら、区切りを閉じる。実装は簡単だが、上の有効な複数行の例（`1,` が文と同じ桁）を壊す。受理の範囲が変わるので、承認が要る。
3. **何もしない（今のまま）**: 文法の自由は保てるが、LS で後ろの文が壊れる。回復は別の層（LS 側のヒューリスティック）に任せる。

## 影響

1 は、受理する構文を変えない（閉じのある入力は同一）。閉じのない入力の木だけが変わる。テストは、監査の E2 の例（`say`、`for` の行）、閉じが後ろにある有効な複数行（上の `xs`）、入れ子、閉じ括弧が別の種類の場合（`(` と `]`）。
