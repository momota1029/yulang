# M1 B4r3 結果（2026-11-07）— normalized core registry の tail 捕捉による E2

状態: **列挙された任意 core-registry 前提への E2**。
主定理は `CommonRoleFiniteTailObstruction.normalized_registry_undecidable`、非存在部分は
`CommonRoleFiniteTailObstruction.no_total_normalized_resolver`。
normalized Paterson、HDA、既存の実 verified-declaration API、両 K2 規則を満たしても、
任意 core registry に対する全域 exact resolver は存在しない。
旧 E2 と旧結果は保存した。E1 を前提付き同名 theorem へ置き換えていない。

**source-generated な閉 spine の定理は反証していない。**
surface の record 型注釈には `..tail` が書けない一方、列挙された core checker と既存 `VerifiedDeclaration` は
未知の record tail を許す。実 source-to-registry 到達可能性は未証明。
この境界と、量化範囲を変える未承認案を [一問](../questions/2026-11-07-b4r3-core-tail-capture.md) に明記した。

## 1. 最小 core 反例と強い E2

次は Yulang code block ではなく、有限 core 型の数学的表示である。

```text
head  R {x:int, ..a}
where R a
associated value = int
```

role 一つ、impl 一つ、変数一つ、recursive graph なし。
宣言には x が一度しか現れず、N は head/where を変えない。
normalized head/child サイズは 3/1 で新 checker が受理する。
既存 `CommonRoleHeadDetermination.verify` も受理することを `old_verified_api_accepts` で証明した。

有限 C={x:int} に a:=C と捕まえると、head は `{x:int,x:int}` と解釈されて C と要求同値、child は C になる。
重複は宣言の構文ではなく、捕捉後に初めて現れる。
`normalization_does_not_commute_with_capture` と `post_capture_sizes` は、
捕捉後 raw head のサイズ5、N後サイズ3、childサイズ3を示す。
a:=emptyRecord でも head は同値だが、child は C と同値でない。
`requirements_not_determined` が where の意味の非一意性を示す。関連型 RHS は定数 int なので HDA は満たす。

同一 goal のループだけでは全算法不可能とはしない。
強い E2 では、有限 C を独立した pair slot に並べ、各 head slot を `{x:int,..fresh}`、child slot を fresh とする。
slot 一つで head/child サイズ差2が生じる。有限 program の全 rule の right.size より大きい有限 slot 数を選び、
旧有限線形 interpreter の任意 data rule を実 impl へ翻訳する。
全実 head/where は N 固定で、全実 goal は有限木。
任意 program の有限停止評価 iff 実 guarded 有限辞書の存在を証明し、全域 finite tape 成功判定を否定する。

## 2. N と amended semantics

[設計 note](../design/2026-11-07-b4r3-normalization-and-tail-capture.md) に全定義・理由・代案を記録した。

新規 `CommonRoleNormalizedDeclarations` は、既存固定 grammar
（変数、int、pair、variant、empty record、field 名0の record）について N を定義する。
`Pattern.visible false` により、record tail で先の field に隠れる明示的な同名 field を除き、
payload 内も含めて再帰する。未知の tail は変数として残す。
実 `normalizeTerm` / `normalizeGoal` / `normalizeImpl` は実 fields を固定 decoder で読み、正規化して同じ grammar へ戻す。
checker は decode 可能性、N 後の既存サイズ/出現回数 checker、実 associated RHS の int 十分検査を行う。

全 Common grammar の N の実装を完成したとは主張しない。
この E2 の全入力は上の grammar にあり、一般の duplicate removal がこの入力部分集合に作用しても
各宣言は既に N 固定である。

独立 Dictionary と両 K2 gate は既存 `CommonRoleInspectedSemantics` をそのまま使う。
変数捕捉を許し、非変数 pattern が構造的再帰型を検査すると拒否する。
拒否対曖昧性は既存の推奨案、拒否先行を作業上の選択とする。未決事項を確定として記録しない。
全反例 goal は有限木で Ready なので、その優先順位への E2 の依存はない。

全 child が同じ visible を使い、Dictionary の Unique は任意 Common 代入の候補を量化する。
消去は実 impl ID と全 where child を持つ既存 `RoleDictionaries.Plan`。
旧 raw syntactic `Roles.resolve` をこの goal で実行したとは主張しない。
対象は Common 同値を保存する head matching と独立 evidence / dictionary の exactness である。

## 3. 主定理の完全な日本語 statement

以下 P は任意有限 `CommonRoleComputation.Code`、x は任意有限 `Tree`。
n(P) は有限 rule 列の right.size の合計に1を加えた有限 slot 数。
C={x:int}、clock(P) は C を n(P) 個、pair で並べた有限型。
D(P)=`CommonRoleFiniteTailRegistry.environment P`、V(P)=その実 cores と等しい visible。
g(P,x) は role 1 の単一引数 pair(clock(P),pair(code(P),pair(data(x),halt))) の有限 description。
queryWire(P,x) は実 head/where/key/associated RHS、一引数の五つの有限 signature、有限 clock/data goal を保持する有限 Tree。

### `CommonRoleFiniteTailObstruction.no_total_normalized_resolver`

**追加前提なし**で、次を満たす有限 binary-tape transition-table machine M は存在しない。

> 任意有限 P,x に対し、ある最終 configuration f が存在し、M は終端付き queryWire(P,x) を初期 tape として
> 有限に実行して f に停止し、`f.current=true` iff
> `Nonempty (CommonRoleInspectedSemantics.Dictionary V(P) g(P,x))`。

任意 semantic Common 値を受ける非計算的 Bool 関数の非存在ではない。
この具体的な有限入力を受け、全域で selection/rejection/ambiguity と実辞書を正確に返す実算法は、
特にこの成功 bit を判定できるため、その必須成分を否定した E2 である。

### `CommonRoleFiniteTailObstruction.normalized_registry_undecidable`

**追加前提なし**で次の連言を示す。

1. 任意有限 P について、実 `CommonRoleNormalizedDeclarations.checkEnvironment D(P)=true`、
   `CommonRoleNormalizedDeclarations.NormalizedWellFormed D(P).cores`、
   実 stored head/RHS に対する `CommonRoleFiniteShadowRegistry.HeadDeterminesAssociated D(P)`、
   `Roles.AssocWellFormed D(P) CommonRoleFiniteTailRegistry.roles`、および
   任意実 i∈V(P) に対し `normalizeImpl i=i`。
2. 任意有限 P,x について、g(P,x).argument.finite=true かつ Ready V(P) g(P,x)。
3. 直前の全域 finite tape machine は存在しない。

NormalizedWellFormed は、N を実 head/where fields に適用した cores の既存 `Roles.WellFormed`。
HDA は任意実所属 impl、任意二つの `Nat→Common.Ty` 代入について、実 head の pointwise 要求同値から
全実 associated RHS の要求同値を得る条件であり、finite Description へ制限しない。
全 head は固定 int/pair/variant/record grammar で解釈でき、HDA を空虚に満たしていない。
全 where の宣言済み arity は `constraints_declared` が別に供給する。
実 family は raw WellFormed も満たすが、主契約では承認済み normalized checker を使用する。
成功、停止、fuel、support、residual、RoleRank、安全性を最終定理の外部前提にしていない。

### `CommonRoleFiniteTailHalting.dictionary_exact`

任意有限 P,x について、**追加前提なし**で、

```text
Nonempty (CommonRoleInspectedSemantics.Dictionary V(P) g(P,x))
↔ ∃ output, CommonRoleComputation.Eval P x output
```

構成方向は実 finite run から有限 Description 代入を作る。
fresh を有限 C に写し、data 変数は fresh より小さい bound にあるため data の代入は保たれる。
全子の有限性、Ready、同じ visible、任意 Common 候補一意性を証明する。
反映方向は実 fields と任意 Common data 一致から有限 data capture と実 rule.Step を回収する。

### `CommonRoleFiniteTailHalting.actual_plan_exact`

任意有限 P,x について、**追加前提なし**で、g(P,x) の独立 Dictionary d で、
任意実 impl i について `i∈d.erase.declarations → i∈V(P)` を満たすものが存在 iff
`∃ output, Eval P x output`。
全 where child を持つ一つの有効な実 Plan の存在を要求し、別の強い plan uniqueness を前提にしない。

### `CommonRoleFiniteTailSemantic.arbitrary_common_exact`

任意有限 P,x について、**追加前提なし**で、両 K2 gate と候補一意性を取り除き、
任意 Common 型・行を代入像とする既存の実-field-reading unary Derives が g(P,x) の Common 意味に成り立つ iff
`∃ output, Eval P x output`。
`guarded_iff_arbitrary_common` は、任意の同じ P,x について、有限 Description の guarded 辞書の存在 iff この上位 Derives。
Description で表現できない代入を捨てたための障害ではない。

### `CommonRoleNormalizedDeclarations.normalize_meaning` / `normalized_head_match_exact`

`normalize_meaning` は、任意固定 grammar Pattern p、任意 Common 代入 σ について、
N(p) の解釈が p の解釈と要求同値であり、隠れた文脈での正規化は label0 を隠した双方向 RecordTailLe を保つことを示す。

`normalized_head_match_exact` は、任意実 Term t、任意 Common 代入 σ、任意 Common goal T について、
decodePattern(t).isSome=true なら、
N(t) の実解釈で T と要求同値なものが存在 iff t の実解釈で T と要求同値なものが存在する。

### `CommonRoleNormalizedDeclarations.checkEnvironment_sound`

任意実有限 associated 環境 D について、checkEnvironment(D)=true なら、
N(D.cores) の実 WellFormed と、元の実 stored fields に対する任意二 Common 代入の HDA。
checker は有限構文上の計算可能な Bool 関数。int RHS を使う十分検査であり、全 HDA 宣言の checker 完全性ではない。

### 最小例の追加 theorem

- `old_verified_api_accepts`: 固定最小 Declaration の toImpl は上記実反例 impl と等しく、既存 verify.isSome=true。
- `normalized_checked` / `declaration_fixed` / `declaration_sizes`: 同じ固定実 impl は新 checker=true、N固定、N前後head size3、child size1。
- `goal_ready` / `head_matches` / `child_returns`: 固定有限 goal C は Ready、有限 C 捕捉で実 head が一致し、実 child は同じ goal。
- `normalization_does_not_commute_with_capture`: 固定 head を N してから有限 C を構文捕捉した値は、捕捉してから N した構文値と等しくない。
- `post_capture_sizes`: 同じ捕捉後 raw head size5、N後head size3、child size3。
- `finite_children_differ`: 有限 C と emptyRecord は要求同値でない。
- `requirements_not_determined`: 固定最小 impl に対し、任意二 Common 代入で head が同値なら全 where 引数も同値、という条件は成り立たない。

そのほか、任意有限 P の全実 declaration の N 固定性、raw/normalized checker、関連型 scope/completeness、
全 where role<5 / arity1、任意 finite configuration の Ready、queryCode の有限計算とその output iff を証明した。
全72 theorem の名前・量化子・premises は [progress の B4r3 checkpoints 1–6](2026-11-07-m1-b4r-progress.md) に記録した。

## 4. 他の型同値を調べた結果

duplicate-field removal だけが Common のサイズを消す同値ではない。
`another_size_erasure` は union(int,int)≈int と構文サイズ差を示す。
`union_padding_scope` は任意 Common 代入について既存の別 union grammar の実 interpreter を用い、
union(unit,unit) の padding が同じ unit に解釈され、record 用 N では消えず raw size が大きいことを示す。
**同時に、その encoding は今回の checker に拒否されることも示す。**
一般 union 注釈は surface で禁止され、これを accepted declaration の E2 へすり替えない。

既存 pair/variant/required union grouping も確認したが、variant row の区切りを producer union と混同しない。
名付き recursive body は承認済み規則で展開せず、nominal unfolding を padding に使わない。
row/variant/alias の full declaration lowering を完成したという主張もない。
今回の強い E2 の機構は、受理される未知 tail の代入後に作用する、同じ first-field-wins である。
