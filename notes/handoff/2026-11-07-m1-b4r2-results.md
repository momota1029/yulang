# M1 B4r2 結果（2026-11-07）— constructor 検査拒否の承認後も有限木で E2

状態: **E2**。承認済みの root 再帰型拒否と head constructor 検査時の再帰型拒否を入れても、
既存の raw な宣言検査だけでは全域の Common role resolver は存在しない。
新主定理は `CommonRoleFiniteShadowObstruction.finite_tree_registry_undecidable`。
非存在部分は `CommonRoleFiniteShadowObstruction.no_total_finite_shadow_resolver`。
旧 `reached_root_registry_undecidable` と旧結果はそのまま保存した。

## 1. 障害は再帰型ではなく、型の意味で消えるサイズ

最小構成の目視例は、一 role、一 impl、型変数なし、recursive graph なしである。
全構文の文字数最小性や constructor 数最小性の定理ではなく、必要な構成要素数についての最小例である。

```yulang
role R 't:
    type value

impl R ({x: int, x: int}):
    where {x: int}: R
    type value = int
```

実 head/child の raw サイズは 5/3。既存 checker は受理する。
しかし同名 field の型同値により両方とも `{x:int}` であり、独立 Common matching は同じ goal に戻る。
対象は有限木なので K2 の両拒否は起きない。
`CommonRoleFiniteShadowExamples.loop_sizes` / `loop_accepted` / `loop_ready` /
`loop_matches` / `loop_child` が実 fields についてこれを示す。

これは同じ goal の cache で扱える可能性があり、この例だけから全算法不可能とはしない。
同 module の一変数例 `{x:'a,x:int}` requires `{x::tick 'a}` は、raw サイズ 5/4 で受理され、
互いに Common 同値でない有限木 `{x:G^n int}` の無限列を作る。
`growing_step` / `chain_equivalent_iff` / `no_natural_descent_measure` がその性質を示す。
この growing chain だけも全算法不可能とは扱わない。

強い E2 では、任意有限 program の有限線形 interpreter の data rule left→right を、実 impl の
head `{x:left,x:G^k int}`、where `{x:right}` に翻訳する。k=rawSize(right)+1。
第二 field は閉じた有限 ground 木なので変数を持たず、HDA や where の変数の決まり方を損なわない。
型の意味では消えるが、既存 checker はそのサイズを数えるため、任意の線形 rule が受理される。
実 guarded 有限辞書の存在 iff program の停止となり、全域 finite tape 成功判定を否定できる。

**これは Common 型同値を読む head matching に対する障害である。**
既存 `Roles.resolve` の raw syntactic matcher を正規化済み goal で実行したり、その結果を保存したりしたとは主張しない。
raw matcher なら余分な field のある head は一致しない。B4 が要求する Common の意味と独立 evidence を保つ拡張に対し、
既存 raw サイズ検査だけでは停止を保証できないことを示した。

## 2. amended semantics と未決の優先順位

定義の理由は [設計 note](../design/2026-11-07-b4r2-constructor-inspection-and-shadow-size.md)。
新規 `CommonRoleInspectedSemantics` は、int/pair/variant、field 名0の record、有限 Ground/Tree data、
一 node の構造的再帰 graph μ=variant 7 μ を持つ固定 countergrammar を扱う。
意味的型や row predicate を有限入力の葉に置かない。

root 拒否は μ とその同形な tag 7 unrolling に作用する。
head の非変数 pattern は、その比較対象の root が構造的再帰型なら禁止検査になる。
そうでなければ constructor 外形が一致する子について、pattern が必要とする分だけ降りる。
変数による捕捉は許す。隠れた同名 field の payload は検査対象から除く。
`Ready V g` は root 非再帰かつ全 visible same-role head に禁止検査がないこと。

`HeadOutcome` は作業上、**拒否を曖昧性より先にする**。
rejected は ¬Ready、selected / ambiguous / absent は Ready を必要とする。
この順序は spec が黙っているので [一問](../questions/2026-11-07-b4r2-rejection-priority.md) に記録した。
仕様へ確定事項として追加していない。
今回の反例では全比較対象が有限木であるため、どちらの優先順位を採っても E2 は変わらない。

独立 `Dictionary` は Ready、実 visible 所属、実 head fields の Common 照合、
任意 Common 代入での候補一意性、実 where fields を同じ有限 Description 代入で解釈した全 child を要求する。
全 child は同じ visible を使う。辞書は有限な帰納 Type。
消去は既存 `RoleDictionaries.Plan` で、実 impl ID と全 where child を保持する。

これは full Common grammar の全 graph classifier や全失敗結果の算法を完成したという意味ではない。
普遍的な全域 exactness を否定するのに必要な入力部分集合で、独立した amended semantics を定義した。
部分言語の E1 を目標全体の完了と扱っていない。

## 3. 主定理の完全な日本語 statement

以下 P は任意有限 `CommonRoleComputation.Code`、x は任意有限 `Tree`。
D(P)=`CommonRoleFiniteShadowRegistry.environment P`、V(P)=その実 cores と等しい visible。
g(P,x) は role 1 の単一引数 `{x:pair(code(P),pair(data(x),halt))}` の有限 description。
queryWire(P,x) は実 head/where/key/associated RHS、一引数の五つの有限 signature、g(P,x) を
具体的な有限 Tree に保持する。

### `CommonRoleFiniteShadowObstruction.no_total_finite_shadow_resolver`

**追加前提なし**で、次の性質を満たす有限 binary-tape transition-table machine M は存在しない。

> 任意有限 P,x に対し、ある最終 configuration f が存在し、M は終端付き queryWire(P,x) を初期 tape として
> 有限に実行して f に停止し、`f.current=true` iff
> `Nonempty (CommonRoleInspectedSemantics.Dictionary V(P) g(P,x))`。

任意 semantic Common 値を入力とする非計算的 Bool 関数の非存在ではない。
実有限入力で必ず停止して selection/rejection/ambiguity と実辞書を正確に返す算法なら、この成功 bit を
特に判定できるため、その必須成分に対する E2 である。

### `CommonRoleFiniteShadowObstruction.finite_tree_registry_undecidable`

**追加前提なし**で、次の連言を示す。

1. 任意有限 P について、既存実 `CommonRoleRegularResolutionObstruction.checkEnvironment D(P)=true`、
   `Roles.WellFormed D(P).cores`、`CommonRoleFiniteShadowRegistry.HeadDeterminesAssociated D(P)`、
   `Roles.AssocWellFormed D(P) CommonRoleFiniteShadowRegistry.roles`。
2. 任意有限 P,x について、g(P,x) の引数は finite=true かつ `Ready V(P) g(P,x)`。
   つまり root 拒否も head の再帰 constructor 検査拒否も起きない。
3. 直前の全域 finite tape machine は存在しない。

HDA は、任意実所属 impl、任意二つの `Nat→Common.Ty` 代入について、実 head の全引数が
pointwise 要求同値なら全実 associated RHS も要求同値になる性質。
今回は固定 int/pair/variant/record grammar で実 head と RHS を解釈する。
全 head は実際に解釈でき、record が読めないため HDA の前件が常に偽になるという空虚な定義を使わない。
RHS は定数 int。HDA を有限 Description 代入に制限しない。

成功、停止、安全性、fuel、support、residual、RoleRank を最終 theorem の外部前提にしていない。
全実 where の宣言済み arity は、さらに `constraints_declared` で確認する。

### `CommonRoleFiniteShadowHalting.dictionary_exact`

任意有限 P,x について、**追加前提なし**で、

```text
Nonempty (CommonRoleInspectedSemantics.Dictionary V(P) g(P,x))
↔ ∃ output, CommonRoleComputation.Eval P x output
```

構成方向は finite machine run から有限 ground Description 代入と全辞書 child を作り、
各子で finite=true と Ready を証明する。反映方向は実 fields を読み、任意 Common head 一致から
有限 data capture と実 rule.Step を回収し、有限 MachineHalts を得る。

### `CommonRoleFiniteShadowHalting.actual_plan_exact`

任意有限 P,x について、**追加前提なし**で、g(P,x) の独立 amended Dictionary d で、
任意実 impl i に対し `i∈d.erase.declarations → i∈V(P)` を満たすものが存在する iff
`∃ output, Eval P x output`。

実 ID と全 child を持つ一つの有効な辞書を要求する。Common 同値な goal の全 Plan が等しいという
別の強い plan uniqueness 契約を E2 の前提にしていない。

### `CommonRoleFiniteShadowSemantic.arbitrary_common_exact`

任意有限 P,x について、**追加前提なし**で、実 head/where fields を読む上位の独立
`CommonRoleFiniteShadowSemantic.Derives V(P) (goalOf (CommonRoleRegularHalting.start P x))`
iff `∃ output, Eval P x output`。

この上位判断は、代入像を任意 Common 型・行に広げ、両拒否と候補一意性も取り除く。
それでも成功集合は停止 program に正確に一致する。
`guarded_iff_arbitrary_common` は任意の同じ P,x に対し、有限 Description の guarded 辞書の存在 iff
この上位判断を示す。Description で表現できない代入を捨てたことが障害の原因ではない。

### `CommonRoleFiniteShadowHalting.matched_step` と候補一意性

`matched_step` は任意有限線形 rule、任意有限 Configuration c、任意 Common 代入 σ に対し、
rule.source=c.role かつ left.eval(σ) が c.value.eval と要求同値なら、有限 target が存在し、
実 rule.Step c target と right.eval(σ)≈target.value.eval が成り立つ。

`unique_compile` は任意 P,c,target、任意 registry 所属 entry とその実 rule.Step c target、
任意 role,value Description に対し、role=c.role と value.eval≈c.value.eval なら、compiled entry は
同じ V(P) の任意 Common 代入での head 一致候補の中で一意。
`unique_terminal` は同じ role/value の対応と role=0 の下で、terminal の任意 Common 候補一意性を示す。
独立 no-overlap は既存 finite compiler から導き、最終 boundary の追加前提ではない。

### `CommonRoleInspectedSemantics.finite_ready` と `configuration_ready`

`finite_ready` は、任意有限 visible V、任意 goal g について、g.argument.finite=true なら Ready V g。
visible head の全 Pattern を量化するので、特定の選ばれた候補だけに禁止検査がないという主張ではない。
`CommonRoleFiniteShadowObstruction.configuration_ready` は任意 P、任意有限 machine configuration c に対し、
canonical goal の finite=true と Ready V(P) を前提なしで示す。

### 実宣言・有限入力の橋

- `compile_wellFormed` / `compile_accepted`: 任意 key と任意有限線形 rule について実 impl の WellFormed と checker=true。
- `declarations_wellFormed` / `declarations_accepted` / `environment_checked` / `associated_wellFormed`:
  任意有限 P に対し、実有限宣言表の対応する検査が成り立つ。追加前提なし。
- `visible_declared`: 任意 P、V(P) 所属 impl i について i.role<5 かつ i.head.length=1。
- `constraints_declared`: 任意 P、V(P) 所属 impl i、任意 c∈i.constraints について、c.role<5 かつ
  c.args.length=(roles c.role).arity=1。
- `eval_queryCode`: 任意有限 P,x について固定有限 Code queryCode は node(descriptor P,x) から
  実 queryWire(P,x) を有限に計算する。
- `queryCode_exact`: 任意 P,x,output についてその評価 iff output=queryWire(P,x)。
- `signature_actual`: 任意 r<5 について serialized arity は実 roles の arity=1 と一致し、associated 宣言は [(0,none)]。

queryCode と既存の終端付き finite binary tape classifier の Code simulation を合成し、
`no_halting_classifier` により主非存在 theorem を得る。EOF や input 長の oracle は追加しない。
全65 theorem の名前・量化子・前提は [progress の B4r2 checkpoints 1–6](2026-11-07-m1-b4r-progress.md) に記録した。
