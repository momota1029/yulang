## 証明済み

1. **反復の実値を等置する通常制約。** StableTies329.model_batch は任意の通常状態・実出現列・選定代表について、バッチ適用後の各モデルが「元のモデルであり、各実出現の中心が代表の中心と同値」と同値であることを証明する。StableCanonical329.exact / permutation は各代表がその binder の実出現の一つなら、これは同じ binder の全実位置対の一致と厳密に同値であり、代表や出現列の置換に依存しないことを示す。StableScope329.source_scope は、普通の新等式が実在する異なる二中心と、実際の同じ input binder に由来し、output-only binder を入力に使わないことを確認。非反復ならこの方式では等式行が一つも出ない（no_rows_if_linear）。論理名が出力先と独立に一致し得ることは否定していない。
2. **同じ状態で head・where・関連出力を読める。** StableReads329.head は実際の順序付き head walk と literal または普通に帰結する選定等式から、任意の個数の引数の head バッチを同じ現在状態で導く。端点だけから反復の一致を要求しない。StableMerge329.compile_after / StableAssemble329.witness_projection は書込み後の実値を保ったまま、各反復群の下限 join・上限 meet を構成する。この後段の命名だけはモデル保全であり、先に足す選定等式はモデルを絞れる。StableAssemble329.frame_after は checked/covered な宣言について実 where コンパイラの順で入力名を用意し、実際の where/root 出力バッチを生成して、その行を同じ状態に置く。新規出力を足す前にその等式が成立するとはしない。
3. **実際の支持付きソースから作って、現在の子提案を照合する。** StableInputs329.for_head / StableHybrid329.ordered は、任意の有限の引数列で、任意の Trace 対応形に対する既存の実 trace と、pair・同タグ variant・単項不変 nominal に対する C328 の支持された opaque 端点観測を混ぜ、元の引数名と固定出力先を守って実名列を作る。既存の実 trace 側は各名前の実捕捉区間が必要。StableReplay329.from_sources はその列から実バッチ・局所意味を作る。replay はそこで得た行が現在の状態に実在し、**現在も**独立な支持・候補選定が成り立つときだけ、実コンパイラが出した順序・役割・捕捉三名・出力先を提出リストと照合する。StableSelect329.sound は、その宣言的な局所規則で別々に検証された親と順序付き子の木全体を、任意の**同じ一つの現在モデル**の再帰 Evidence に畳む。未検証の選定や支援根拠を過去の判断から推論しない。
4. **初めて足す実等式で、非点の選定木が成立する。** StableFixture/Result/Models329 は普通の実中心が 7 と 8、実行する選定バッチが 7 = 8、実コンパイラが出す単項不変 nominal の複合子が (9,10,11)→5、親・子の固定出力が 6 = 5、5 = 10 の例。実際に支持された端点から親と子が選定され、全最終モデルで Evidence が成り立つ。旧状態で成立した (int, int ∪ bool) の異なる成分のモデルは等式で除かれ、両成分 int ∪ bool の実例モデルが残る。その外側の実中心は両端点のどちらとも同値でない。出力先を 6 にすり替えた子はリスト検査が拒否する。
5. **別々の引数をまたぐ反復と、出所を捏造しない集約。** StableCrossSource/Compile/Resolve329 は二引数に一つの binder が現れる checked な宣言。第一の実中心はソースから観測し、第二（11）は元の状態に直接行がないので不変 nominal の実観測から回復。別々の実葉 3 と 7 を選定後に等置すると、第二を bool としていた旧モデルが落ち、実際の子は (13,3,14)。StableCrossCut329.exact_cut は、通常モデルで合流下端 13 が旧 int 3 に同値でも、記号的な union/meet だけでは既存の単純な source alias 読みで子が保留することを確認。すでに支持された int 3 を読むため、同値な端点の有向 bound 四つを論理的帰結として記録すると、**全モデルを不変に保ち、既存の行の出所だけで**子が実際に選定される。親子の辞書証拠を全モデルで示し、モデルの存在も確認。StableAnchor329.anchored / StableBackedAnchor329.expose は、各区間が実在の点（または端点が中心に支持付き alias）であり、実代表に元から支持された constructor がある場合の一般補題。本物の非点区間は勝手に畳まない。StablePendingAnchor329.exactly は、全普通モデルで同じ端点でも、唯一の alias 行が未完了出力から来る例ではこの証明が使えず、完了と与えた場合だけ使えることを確認した。
6. **矛盾は選定後の型エラー。** StableAttempt329.reject_exact は支持・非 K2・唯一候補を独立に確認した試行について、元はモデルがあるが実中心を等置するモデルが一つもないときの矛盾を正確に述べる。StableRejected/WriteVerdict329 の checked な例では、端点照合から候補を実際に選べるが、実位置 7 は int、8 は int ∪ bool の独立な普通行により固定されていて、新しい 7 = 8 が矛盾する。その試行の独立な診断は rejected leaf になり、保留ではない。全候補・全診断の優先順の変更ではない。StableOrigin/Graph329 は、既存の出所を引き継ぐだけなら追加等式で支持行や直接 constructor は増えず、通常の K2 グラフは既存 alias と正確に追加された実中心同一視の閉包だけで変わると示した。K2 と支持なしの重なりに新しい優先は付けていない。
7. **表現上の名前と、同じモデルの証拠を区別。** StableMergeEquiv329.aggregates / forest は、同じ実位置群を別順序・別代表で実合流しても、共通モデルでは三値が同値であり、同じ固定 target への where 子は順序を崩さず意味同値になることを証明。実リストのアドレス一致や候補権限までは輸送しない。StableActual329.evidence は同一実中心と適正な新しい区間、対応する出力を満たせば、端点同値が不要な同一モデルの辞書証拠の輸送。StablePoint329.distinct は、独立の未併合 raw 需要ではその証拠があるのに新しい点名に出所が無く保留し得る例。これは同じ入力を仕様どおり併合した後の挙動を否定しない。

## 残り

- **(4) 宣言的辞書健全性: 1本。** I-58 の反復実中心一致は、選定が実際に足す通常バッチから読む形で閉じた。今回実際の支持・opaque 端点を組み合わせて入力を生成し、同じ現在状態の普通行・順序付き子を検算する範囲は広がった。任意の承認済み安定 Local.selected が、このルートの実際の支持付き head 観測（すべての形・モード、保留/権限）と同一の現在 write/子リストを生成するという一般橋はまだ必要。名前付き出力が偶然同じ型を持つことを、入力 binder の等置や未完了出力の支持に読み替えない。
