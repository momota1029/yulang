# M1 B4 redo 結果（2026-11-07）— reached-root 拒否後にも残る E2

状態: **E2**。K2 の「再帰型を引数とする role goal に到達したときに拒否する」規則だけでは、
任意の型・行が確定した有限 regular description に対する全域 exact resolver は存在しない。
主定理は `CommonRoleReachedRootObstruction.reached_root_registry_undecidable`、非存在部分は
`CommonRoleReachedRootObstruction.no_total_reached_root_resolver`。
元の `common_role_registry_exact` を前提付きの同名定理で置き換えていない。

## 1. 最小の目視例と、強い E2 の違い

role、impl、型変数、正則 graph node がそれぞれ一つの例を使える。
これは構成要素数の最小構成であり、全 Yulang 構文の文字数や node 数の最小性の定理ではない。

```yulang
role R 't:
    type value

impl R (:{box :{tick 'a}}):
    where (:{box 'a}): R
    type value = int
```

μ を名前の無い再帰型 `μ ≈ :tick μ` とすると、goal `R (:box μ)` の head が一致し、
where は同じ `R (:box μ)` に戻る。head/child の構文サイズは 3/2、変数出現回数は 1/1。
box の root は循環成分に属さず、`R μ` には一度も降りない。
`CommonRoleReachedRootExamples` が実 checker の受理、独立 head 一致、実 where 解釈による同じ child、
root 非再帰性、一意候補、任意有限拒否 path の非存在を証明する。

この例だけなら同じ goal の cache が使えるので、全算法不可能の根拠にはしない。
強い E2 では、旧 B4 の任意有限 program の二引数 goal を一引数 `pair(clock,data)` に包む。
全 head と全 where を同時に包むと、両サイズに 1 を加え、全変数出現回数を保存するため、
実 Paterson checker は受理したままである。全 child の root は pair なので、新しい再帰型拒否は
どの有限 path でも起きない。それでも有限辞書の存在 iff program の停止となる。

μ の等式と goal 表記は数学的表示であり、再帰型注釈の source 構文を新設したものではない。
上の宣言 block は現行 parser が recovery なしで読むことを別に確認した。
source semantic elaborator がこの全反例 family を生成するという橋は今回の主張ではない。
依頼の対象は任意の確定した有限 regular goal description であり、その量化を source 到達可能なものへ
狭める追加前提は使っていない。

## 2. 定義と量化領域

定義の全記録は [設計 note](../design/2026-11-07-b4r-reached-root-semantics.md)。

- `Description` は有限 Ground 木、有限 Tree data、有限 pair/variant context、一 node の正則 clock を持つ。
  任意意味的 Common 型や任意 row predicate の葉を入力に入れていない。
- `StructuralRecursive p` は、この grammar では p が clock または tag 7 によるその有限 unrolling であること。
  pair や異なる tag の根は、その下に clock があっても自己へ戻らない。
- 「到達」は root または実 where child で resolution judgment を呼ぶこと。
  head 照合で内部の constructor を読むことを別の role goal の呼び出しにはしない。
- `Dictionary` は root 非再帰性、実 visible 所属、実 head 一致、head 候補一意性、
  同じ visible と代入による全実 where child を要求する帰納的な有限 Type。
  消去は実 `RoleDictionaries.Plan` で、実 impl ID と全 child を保持する。
- `Rejects` は別の判断で、再帰型 root で終了するか、選んだ実 impl と where index を path に記録して降りる。
  rejection を ambiguity や success と同一視しない。

E2 にはこの有限入力部分集合で十分である。全 Common grammar の再帰検査器を完成したとも、
部分言語の E1 を B4 全体の完了としたとも主張しない。

以下、P は任意の有限 `CommonRoleComputation.Code`、x は任意の有限 `Tree`、
D(P) は実 `CommonRolePackedRegistry.environment P`、V(P) はその実 `cores` と等しい packed visible。
g(P,x) は role 1 の単一引数 `pair(clock,pair(code(P),pair(data(x),halt)))` の有限記述。
`queryWire P x` は実 D(P) の全 head/where/key、associated RHS、一引数の五つの有限 signature、
および g(P,x) を具体的な有限 Tree に保持する。

## 3. 主定理の完全な日本語 statement

### 3.1 `CommonRoleReachedRootObstruction.no_total_reached_root_resolver`

**追加前提なし**で、次の性質を持つ有限 binary-tape transition-table machine M は存在しない。

> 任意の有限 P と有限 x に対し、ある最終 configuration f が存在し、
> M は終端付き queryWire(P,x) を初期 tape として有限に実行して f に停止し、
> `f.current = true` iff `Nonempty (CommonRoleReachedRoot.Dictionary V(P) g(P,x))`。

任意の semantic Common 値を受ける非計算的 Bool 関数の非存在ではない。
有限入力に対する実算法の必要な成功 bit だけを否定する。
selection/rejection/ambiguity と実辞書を必ず停止して正確に返す算法は特にこの bit を判定できるので、
依頼された全域 registry exactness の必要成分に対する E2 である。

### 3.2 `CommonRoleReachedRootObstruction.reached_root_registry_undecidable`

**追加前提なし**で次の三つの連言を示す。

1. 任意の有限 P について、
   `CommonRoleRegularResolutionObstruction.checkEnvironment D(P) = true`、
   `Roles.WellFormed D(P).cores`、
   `CommonRoleRegularResolutionObstruction.HeadDeterminesAssociated D(P)`、
   `Roles.AssocWellFormed D(P) CommonRolePackedRegistry.roles`。
   HDA は任意の実所属 impl と任意二つの `Nat → Common.Ty` 代入について、
   実 head 引数が pointwise 要求同値なら全実 associated RHS も要求同値になる条件である。
2. 任意の有限 P,x と任意の有限実 impl/index path について、
   `CommonRoleReachedRoot.Rejects V(P) g(P,x) path` は成り立たない。
3. 3.1 の全域 finite tape machine は存在しない。

WellFormed、HDA、安全性、成功、fuel、停止を外部前提として渡していない。
一引数の全 where が宣言済み role/arity を持つことは、さらに `constraints_declared` で証明する。
RoleRank を導入していない。

### 3.3 `CommonRolePackedHalting.dictionary_exact`

任意の有限 P,x について、**追加前提なし**で、

```text
Nonempty (CommonRoleReachedRoot.Dictionary V(P) g(P,x))
↔ ∃ output, CommonRoleComputation.Eval P x output
```

辞書 constructor は実 packed head/where fields を読む。子はすべて同じ V(P) を使う。
構成方向は有限 machine run から具体的な有限 Description 代入と全辞書 child を作る。
反映方向は任意の独立 guarded derivation から元の独立 Common derivation を回収し、有限実行を得る。

### 3.4 `CommonRolePackedHalting.actual_plan_exact`

任意の有限 P,x について、**追加前提なし**で、g(P,x) の guarded 有限 dictionary d で、
任意実 impl i に対し `i ∈ d.erase.declarations → i ∈ V(P)` を満たすものが存在する iff
`∃ output, Eval P x output`。

消去 plan は packed 後の実 impl を含む。旧 unpacked Plan と同じ値だとは主張しない。
impl key と全 where child を保つ実 packed Plan が存在することを示す。

### 3.5 `CommonRolePackedHalting.no_rejection`

任意の有限 P、任意 role ID r、任意 first,last : Description、任意有限実 impl/index path に対し、
V(P) では `pairGoal r first last` から再帰型拒否 `Rejects` へ至る path は存在しない。
**追加前提なし**であり、初期 goal と halting run の有限 prefix だけに限定しない。
理由は全 packed 実 where child の root が pair であること。

### 3.6 `CommonRolePackedSemanticReflection.arbitrary_common_exact`

任意の有限 P,x について、**追加前提なし**で、実 packed fields を読む unary
`CommonRolePackedSemanticReflection.Derives V(P) (pairGoal (CommonRoleRegularHalting.goal P x))`
iff `∃ output, Eval P x output`。

この大きい独立 Derives は、代入像に任意 Common 型・行を許し、root 拒否と候補一意性も要求しない。
それでも非停止 program に成功 evidence は生じない。
`guarded_iff_arbitrary_common` は任意の同じ P,x に対し、3.3 の guarded 有限 description 辞書の存在 iff
この任意 Common 代入の大きい Derives を示す。Description で表現できない照合代入を
捨てたことを E2 の根拠にしていない。

### 3.7 `CommonRolePackedSemanticReflection.unique_at_configuration`

任意の有限 P、任意有限 Configuration c、任意実 impl i について、
`i ∈ V(P)` かつ、ある任意 Common 代入 σ が存在して i の実 unary head が
`pairGoal (goalOf c)` に一致するなら、任意の他実 impl j と任意 Common 代入 τ に対し、
`j ∈ V(P)` かつ同じ goal の head に一致すれば `j=i`。
照合代入の領域を Description に限定しない。

`arbitrary_unique` は、任意 P,i,元 SemanticGoal について、旧二引数の任意 Common 照合での一意性から、
実 packed unary head の任意 Common 照合での一意性を導く。構成中の全 where child には、
`machine_to_dictionary` 内の同じ独立 no-overlap 議論を用いる。

### 3.8 `CommonRolePackedRegistry.constraints_declared`

任意の有限 P、任意実 impl i、任意実 where goal c について、
`i ∈ V(P)` かつ `c ∈ i.constraints` なら `c.role < 5` かつ
`c.args.length = (CommonRolePackedRegistry.roles c.role).arity = 1`。
head の signature と associated scope/completeness は別の `associated_wellFormed` が供給する。

### 3.9 実有限入力の橋

`CommonRoleReachedRootObstruction.eval_queryCode` は、任意有限 P,x について、
固定有限 Code `queryCode` が `node(descriptor P,x)` から実 `queryWire P x` を有限に計算することを示す。
`queryCode_exact` は任意 P,x,output について、その評価 iff output=queryWire(P,x)。
`signature_actual` は任意 r<5 について serialized signature の arity が実 role の arity=1 と一致し、
associated 宣言リストが [(0,none)] であることを示す。
既存の終端付き binary tape classifier の Code simulation と `no_halting_classifier` を合成して 3.1 を得る。
EOF、input 長、無限 tape suffix の oracle は導入しない。

補助 theorem を含む全56本の名前、全量化子と前提の記録は
[progress checkpoints 1–7](2026-11-07-m1-b4r-progress.md) にある。すべて Audit に登録した。
