## Checkpoint 4 と safety 判定の新しい経路

signed seed の checkpoint build は成功 (601 jobs)。

`CommonSignedSafetyPreimage.preimage_exact`:
任意 finite fiber `fiber = (key, width)`、任意 identity/shift/residual action、任意有限候補列
`allowed : List Common.Occurrence`、任意 `source` について、
`source.key = fiber.key ∧ source.weights.length = fiber.width` を前提に、
`source ∈ preimage fiber action allowed ↔
 ∀ target, action.run source = some target → target ∈ allowed`。
shift の逆像は逆 shift の map、residual は handled key の場合だけ唯一のゼロ点を足す。
`Fiber.capturable_iff` は同じ任意 fiber 内で capture と「key が handled かつ source=zero」の iff。
`run_preserves` は任意 action の成功が key と座標数を保持すること。

新経路: fiber ごとの候補を各 slot に `Any | Only finiteList` として持つ。
pure sink は Only []。Any から Only へ向く edge の安全逆像を取って source を Only にする
（各 slot 高々一回）。その後 Only の候補から、ある成功 edge の先が候補外になる点を削る
（候補総数が真に減少）。固定点は独立 Models を満たし、全 Safe を保存するので Safe と一致するはず。
これは任意 occurrence が pure sink に届くかの問題であり、特定 occurrence への path 所属決定とは異なる。
別 agent の反例探索はこの経路に反例を見つけず、必要な fiber 不変条件も確認した。
未完の正確な補題: 上の停止する候補算法の固定点について
`fiber.Contains occurrence → (allowed final slot occurrence = true ↔ Safe graph slot occurrence)`。
その後 `checkHeads S = true ↔ HeadsSafe S` へ進む。

## 追加で特定した scoped universal 求解の欠けた補題

一般 handler では、forallTypes より前の Γ/input/returned/out と、その内側の computation witnesses の依存範囲を区別する必要がある。
