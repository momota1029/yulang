## 証明したこと

1. **実際に発火する3相のすべてを追跡。** 239 の混合 Step と240の Point Step について、各周の enter → install 後 → refresh 後 → 次の enter を定義し、全辺の実 Step を証明（240 は混合 Step への消去も確認）。各微視状態と 259 の再ベース結果とのあいだで、元の公開型値と行を保った有効モデルの拡張存在性が双方向に一致する。最初の微視辺だけが再ベース側の既存レポート駆動 write に対応し、その後は再ベース側が文字どおり同一状態で追加 write なし。元の raw 無限列は消していない。
2. **install は全モデルを真に制限する。** install 直後のモデルは「直前の全モデルであり、かつ実 plan の Holds」を満たす割当と正確に一致。refresh と reobserve は全モデル述語を保存する。任意の周 i で、元の公開割当・行と一致して上側名だけを bottom に置いた具体的全割当は、対応 install まで有効で、そこから先は無効。したがって全モデル集合の逆向き包含は「実 install の累積回数が以下」と同値で、全モデル集合の等しさはその回数の等しさと同値。全状態のモデル判定は、初期モデルの条件と、それまでに実 install された packet の Holds をすべて満たすことにまで分解できる。raw モデル集合の列はどの時点からも安定しない。下側名への Known 観測が成立する時点は、対応する refresh の直後。こちらの集合の包含は実 refresh の累積回数で正確に判定できる。
3. **残す binder を値そのままで戻し、実 V8 証拠を得る。** 両例で任意の有効な再ベース済み全割当から、文字どおりの retained binder の値（行を含む）と公開端点・行を保って、一つの共通旧モデルを構成。これは全周・全微視状態を同時に満たし、各状態で実 V8 `.node 0 []` を持つ。enter の証拠 payload と packet の充足条件を逆方向からも確認。source の現 Frame と正確な空の子列を使い、install 後と refresh 後の任意の有効モデルからも実 V8 leaf を構成。一般の V8 Local の値や非葉・分岐 producer まで求めた主張ではない。
4. **当該 install 分岐の吸収と、その限界。** 生成された focus 上の実 install は各 enter では到着先が唯一。install 後と refresh 後は候補が committed なので install 不可能だが、reobserve 後の次 enter で新しい install が再び可能になる。二つの回数で作る観測キーは全モデル・指定された Known の比較には完全ながら、refresh 後と次 enter で衝突する。両例とも、この同じキーだけから raw install の可否を判定する関数は存在しないことも証明した。一方で install 可否の 1 ビットを加えれば、この二列の tick は一意に復元できる。不整合キーを拒否するデコーダーを実装し、キーの各更新が実 239 混合 Step と 240 Point Step の両方に対応することを確認した。
5. **旧割当名の実行可能な逆算。** 平方帯域ペアリングを整数平方根で戻し、再符号化で照合した厳密に小さい先行名だけへ降りる方式で、この二例の下側・上側の名と順位を正確に復元。従来の「数値 ID まで走査」は使わない。240 の埋め戻しは従来の走査版と全入力割当で点ごとに一致し、元の全モデルと証拠を保つ。239 については実行可能な名前順位と観測プローブまで（埋め戻し置換は240のみ）。閉じた例で名前復号、無関係な名前の拒否、Known/上側パッチの状態変化、キー衝突、不整合キー拒否、1ビット追加後の3相更新を実行した。一般の割当モデル判定や計算量上界ではない。
