# M1 B4 結果（2026-11-07）— 承認修正後も K2 の E2

## 継続の最終結果

**E2 に到達した。** ユーザーが承認した `HeadDeterminesAssociated` を追加しても、
全有限正則 goal に対する、停止する正確な role resolver は存在しない。
主定理は `CommonRoleRegularResolutionObstruction.amended_registry_undecidable`。
元の `common_role_registry_exact` を弱い同名定理で置き換えていない。
qualified generator 単体の不可能性や、E1 の全 parameter family 完了は主張しない。

以下の theorem はすべて Lean 4、全体 build、trust=0 Audit を通過した。
二つの独立レビューが、有限正則 goal 上の全域実算法に対する K2 の E2 と判定した。
旧 finite-tree resolver に循環入力を直接渡して実行したという主張ではない。

## 主定理の正確な日本語 statement

以下で P は任意の有限 `Code`、x は任意の有限 `Tree`。
`environment P` は実 `Roles.AssocEnv`、その `cores` は実有限 `Roles.Impl` の visible 集合。
`startGoal P x` は型・行が確定した有限 description で、一 node / 一 back edge の正則 clock と
有限 pair/int/variant data を含む。`queryWire P x` は実 declaration fields、associated RHS、
五つの有限 role signature、この goal を具体的な有限 Tree に符号化する。

1. **`CommonRoleRegularResolutionObstruction.amended_registry_undecidable`**

   追加の前提なしで、次の連言を示す。

   - 任意の有限 P について、実 `checkEnvironment (environment P) = true`、
     `Roles.WellFormed (environment P).cores`、
     `HeadDeterminesAssociated (environment P)`、
     `Roles.AssocWellFormed (environment P) roles` が成り立つ。
   - 任意 P,x に対し、`queryWire P x` の具体的な終端付き binary tape 入力から有限に実行し、
     終了位置の bit が true である iff
     `CommonRoleActualEvidence.Dictionary (environment P).cores (startGoal P x).eval`
     の値が存在する、という条件を満たす有限 transition-table machine は存在しない。

   非存在部分を単独で述べる theorem は **`no_total_actual_regular_resolver`**。
   成功／拒否／曖昧性と実辞書を必ず停止して正確に返す実算法なら、特にこの成功 bit を判定できる。
   その必要成分を否定したので、修正後 B4 の registry exactness に対する E2 である。

2. **`CommonRoleRegularResolutionObstruction.actual_dictionary_exact`**

   任意 P,x について、追加前提なしで、実 Impl の head / where fields を直接解釈する上の
   独立 Common Dictionary の存在 iff `∃ output, CommonRoleComputation.Eval P x output`。
   Dictionary の constructor は実候補の一意性を要求し、全 child に同じ visible 集合を使う。
   消去は既存の `RoleDictionaries.Plan` であり、実 Impl ID と全 where child を保持する。
   安全性・成功・fuel・停止・型の有限展開深さを前提にしていない。

   **`actual_derives_exact`** は同じ任意 P,x、追加前提なしで、
   実 head / where を読む独立した有限 Derives の存在 iff 同じ停止評価の存在を示す。

3. **`CommonRoleRegularResolutionObstruction.checkEnvironment_sound`**

   任意の実 `declarations : Roles.AssocEnv` について、実 decidable
   `checkEnvironment declarations = true` なら、`Roles.WellFormed declarations.cores` と
   実 stored head / associated RHS に対する `HeadDeterminesAssociated declarations` が成り立つ。
   後者は、任意の所属 impl、任意の二つの `Nat → Common.Ty` 代入 σ,τ に対し、
   全 head 引数の解釈が要求同値なら全 associated RHS の解釈も要求同値、という条件。
   Common 代入を有限木だけに限定しない。

   この checker は actual RHS が `int` である十分条件を使う。
   `environment_checked` は任意 P についてその実 checker の受理を前提なしで示す。
   意味的 HDA を solver の成功前提へ移していない。
   全宣言言語に対する checker の完全性は主張しない。

4. **`CommonRoleRegularResolutionObstruction.associated_equations`**

   任意 P、任意 `implementation ∈ (environment P).impls`、任意の stored pair
   `(name,rhs) ∈ implementation.assoc`、任意 Common 代入 σ について、
   `name = 0` かつ固定実解釈 `interpretTerm rhs σ = some (.base .int)`。
   実 Dictionary の `all_visible` により、すべての再帰 child の宣言にも同じ equation がある。

## 還元の要点と補助 theorem

- `CommonRoleLinearClock.compile_accepted` は任意の有限 linear rule と key に対し、
  実 Paterson checker の受理を示す。head の clock に十分な有限個の variant を付ける。
  child の clock は元の変数なので構文サイズは減るが、正則型 `A ≈ variant 7 A` では同じ clock へ戻る。
- `matched_child_finite` は任意の linear rule、有限 source、任意 Common 代入について、
  実 head の一致から実有限 rewrite target を回収し、child の要求同値を示す。
  任意 decoder / arbitrary Theory は使わない。
- `CommonRoleLinearExecution.halts_exact` は任意 P,x、追加前提なしで、
  生成した有限 linear rewrite による terminal-role 到達 iff 独立 Eval の停止。
  データのコピーも明示的な有限の線形 rewrite として実行する。
- `CommonRoleRegularRegistry.registry_safe` は任意 P と任意有限 start に対し、
  全到達 configuration の候補が一意で、terminal と transition が重ならないことを前提なしで示す。
  重複 rule は除去し、`idxOf` により同じ宣言には同じ key を与える。
  `compile_entry_eq_iff` が実 Impl identity と entry identity を一致させる。
- `CommonRoleActualEvidence.dictionary_iff_special` / `derives_iff_special` は、
  任意 registry / terminal / Common goal について、実 Impl fields を読む一般の独立判断と
  compiled rule に特殊化した独立判断を双方向につなぐ。
  `ofSpecial_erase` は全子を含む既存 Plan を等号で保存する。
- `CommonRoleRegularWire.eval_queryCode` / `queryCode_exact` は任意 P,x/output について、
  固定の有限 `queryCode` の出力が、実レジストリ・署名・正則 goal の wire になることを示す。
  `implWire_injective` / `assocImplWire_injective` は全実宣言 fields の保存を保証する。
- `CommonRoleTuringDelimited.reads_frameBits` は任意有限 bits と任意無限 suffix に対し、
  EOF を観測しない実 tape 読出しが `2*length+1` cells で同じ bits を読むことを示す。
  最初の raw list 符号化は blank と終端の区別が不足すると review で判明し、この終端付き表現に修正した。
- `CommonRoleComputation.no_halting_classifier` と実 finite tape machine の Code simulation により、
  上の固定 query constructor と合成した停止 classifier を対角化で否定する。
  非計算的な特性関数の非存在や、任意 semantic Common 型を入力とする Bool checker は仮定しない。

## 初回 E2 の記録: 関連型計算を Common 同値へ保存できない

以下はユーザー承認前の初回結果であり、その後 `HeadDeterminesAssociated` の追加が承認された。
現在の継続結果は上記の K2 E2 である。

状態: **E2**。元 B4 が要求する既存の関連型証拠・実計算の保存と、Common の型同値、
head 引数から関連型が一つに決まるという契約の連言に反例を構成した。

## 反例と元契約への接続

一宣言・一関連型・一型変数・空 where の次の例を使う。

```text
role R 't: type value
impl R ({x:int,x:'a}): type value = 'a
```

Lean の `roleDeclarations` は一要素の有限宣言表で、`environment : Roles.AssocEnv` は実 `CheckedRoles.checkDatabase`、
実 `Roles.WellFormed`、実 `Roles.AssocWellFormed` を満たす。
任意 decoder で Common 型を既存木へ押し込むことはせず、有限の record 型構文 `Pattern` の
constructor identity と Common 解釈を固定した。行、一般 union annotation、正則再帰は使わない。

実 first-order resolver に二つの確定 goal を渡すと、同じ一つの impl が選ばれる。

| 実 goal の引数 | 実 `Roles.assocOf ... 0` | Common における引数の意味 |
| --- | --- | --- |
| `{x:int,x:int}` | `int` | `{x:int}` と要求同値 |
| `{x:int,x:bool}` | `bool` | `{x:int}` と要求同値 |

これは実計算だけの例ではない。両方について既存の独立 `Roles.AssocDerives` と実 dictionary を構成した。
辞書の消去は両方とも `.node implementation []` であり、別 impl や別 scope の選択ではない。
`int` と `bool` は Common で要求同値でない。

元契約との接続は二つの独立した要求による。

1. B4 §7.6 の「既存の evidence と実 dictionary の対応」、spec 10.7 に記録された
   `assoc_explicit_eq` / `assoc_derivations_unique` に従い、既に成功する有限 ground の実関連型計算を保存する。
2. spec 4.3 の隠れた同名 field の型同値と、spec 6.3 の「associated type は head の型引数から決まる一つの型」
   に従い、同じ impl の Common 同値な型引数から得る関連型は要求同値である。

この二つは同時に成立しない。どの探索算法・正規化・cache・計算時間を選んでも解消しない。
canonical な代入を一つ選んで既存の一方の結果を捨てるなら 1 を変える。
同値な型の書き方に応じて関連型を変えるなら 2 を変える。
head を先に正規化し `'a` のない宣言として拒否するなら、現在の宣言検査の前提を変える。
いずれも未承認の変更として黙って適用しない。

**ordinary equation を既存 store に連言で追加する法則を反証したのではない。**
追加された等式が既存 bounds と矛盾するときは拒否してよい。その規則は変更しない。

## 主定理：量化子と前提

以下の省略名を用いる。

- `H(p) = {x:int,x:p}`、`rigidGoal p = R H(p)` の実 `Roles.Goal` 符号化。
- `interpret p = p.eval (fun _ => (.bottom : Common.Ty))`。`Ground p` は変数がないこと。
- `environment` / `roles` / `declaration_wellFormed` は上の固定 registry / signature / 検証済み証拠。
- `≈` は既存の `Common.Equivalent`。

### `CommonRoleAssociatedExactness.no_common_associated_registry_extension`

**入力前提なし**で、次を満たす関数 `select : Pattern → Option Common.Ty` は存在しない。

```text
(∀ hidden value : Pattern,
  Ground hidden →
  Roles.assocOf environment roles declaration_wellFormed (rigidGoal hidden) 0
    = some value.encode →
  ∃ selected : Common.Ty,
    select (H hidden) = some selected ∧ selected ≈ interpret value)
∧
(∀ first last : Pattern,
  Ground first → Ground last → interpret first ≈ interpret last →
  ∀ a b : Common.Ty,
    select first = some a → select last = some b → a ≈ b)
```

実行入力は有限構文。任意の semantic row predicate を受ける Bool resolver を仮定していない。
`select` の計算可能性さえ要求せず非存在を示すため、実行可能な有限 resolver にも適用される。
有限の二入力が反例なので、全 regular goal を含む普遍的な元契約もそのままでは満たせない。
これは部分言語に限定した E1 ではなく、普遍的な保存契約への反例である。

### `CommonRoleAssociatedExactness.checked_registry_counterexample`

**入力前提なし**で、上の固定 registry に対する次の連言を示す。

```text
CheckedRoles.checkDatabase environment.cores = true
∧ Roles.WellFormed environment.cores
∧ Roles.AssocWellFormed environment roles
∧ Ground (H int) ∧ Ground (H bool)
∧ ¬∃ select, PreservesComputedAssociated select ∧ CommonExtensional select
```

二つの最後の述語は直前の主定理で展開した条件そのもの。宣言の受理・適格性・goal の確定性を
未証明の外部前提にしていない。

## 証拠を供給する補題

以下はすべて `CommonRoleAssociatedObstructions` 名前空間。

- `declaration_accepted` / `declaration_wellFormed` / `associated_wellFormed`:
  前提なしで、上の実 checker の受理と二種類の実 well-formedness。
- `every_head_instance`: 任意 `assignment : Nat → Common.Ty` に対し、前提なしで
  `headPattern.eval assignment ≈ closedGoal`。`closedGoal` は `{x:int}`。
- `no_associated_value_agrees`: 前提なしで
  `¬∃ selected : Common.Ty, ∀ assignment : Nat → Common.Ty,
  headPattern.eval assignment ≈ closedGoal → selected ≈ rhsPattern.eval assignment`。
- `first_order_selected`: 任意 `hidden : Pattern` に対し、前提なしで
  `Roles.candidates environment.cores (rigidGoal hidden) = [implementation]`。
- `first_order_resolved`: 任意同じ hidden に対し、前提なしで
  `Roles.resolve environment.cores declaration_wellFormed (rigidGoal hidden) = resolved`。
- `first_order_associated`: 任意同じ hidden に対し、前提なしで
  `Roles.assocOf environment roles declaration_wellFormed (rigidGoal hidden) 0 = some hidden.encode`。
- `first_order_derivation`: 任意同じ hidden に対し、前提なしで
  `Roles.AssocDerives environment roles (rigidGoal hidden) 0 hidden.encode`。
- `first_order_dictionary_plan`: 任意同じ hidden に対し、前提なしで
  `(firstOrderDictionary hidden).erase = RoleDictionaries.Plan.node implementation []`。
- `ground_head_equivalent`: 任意 `hidden : Pattern` と任意 `assignment : Nat → Common.Ty` に対し、
  前提なしで `(H hidden).eval assignment ≈ closedGoal`。
- `finite_ground_associated_conflict`: 前提なしで、上表の int / bool の二つの実 `AssocDerives`、
  両 head と closedGoal の要求同値、両 associated value の非同値の連言。
