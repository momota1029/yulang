# M1 B4 redo 第四回 結果（2026-11-07）

終了: **E2**。主定理は `Yulang.CommonRoleMergedObstruction.canonical_merged_registry_undecidable`。
canonical residual の承認を守っても、実 variant tag merge が残す payload union の冪等性により、
現在の record 用 N と Paterson 条件だけでは全域 exact resolver を保証できない。
旧 tail-clock E2 は現在の意味へ適用していない。

## 1. 主定理の全量化と前提

`Code` は既存の有限 program 構文、`Tree` は有限入力、`Ground` は有限 int/pair/variant 木。
`environment code` / `visible code` は新 module の実 `Roles.AssocEnv` / `List Roles.Impl`。
`Dictionary` は canonical structural capture と全実 where child を保持する有限帰納的辞書。
`N` は承認済み hidden record field 除去、`roles` は実 unary signature 5個と必須 associated type 0。

`canonical_merged_registry_undecidable` は追加前提なしに、次の三つを同時に示す。

1. **任意の有限 `code : Code`** について、実 `checkEnvironment (environment code) = true`、
   `NormalizedWellFormed (environment code).cores`、`Roles.WellFormed (environment code).cores`、
   任意二 Common 代入についての実 `HeadDeterminesAssociated (environment code)`、
   実 `Roles.AssocWellFormed (environment code) roles` が成立する。
   **任意の実 `implementation ∈ visible code`** について `N implementation = implementation` であり、
   **ある有限コピー数 n と data Pattern P が存在**して、実 `Variants.Merged.normalize` の結果
   `mergedRow n P` から実 `implementation.head` を取り出せる。
2. **任意の有限 `code : Code` と任意の `goal : CanonicalMergedEvidence.Goal`** について、
   `goal.description.argument.finite = true` かつ `Ready (visible code) goal.description`。
   したがって、この family では root 再帰型拒否も constructor 検査拒否も発生しない。
3. **次を満たす有限 tape machine M は存在しない**。
   **任意の有限 code,input** について **ある有限最終状態 final が存在**し、
   `Runs M (initial (queryWire code input)) final` かつ
   `final.current = true ↔ Nonempty (Dictionary (visible code) (startGoal code input))`。

3だけを独立に示す定理名は `no_total_canonical_merged_resolver`。
query は実 head/where/key/associated RHS、実 signature、有限 goal description の wire を含む。
固定有限 queryCode が descriptor と入力からこれを作ることを証明しており、停止答や意味 oracle は入力に含まれない。
selection / rejection / ambiguity と実辞書を正確に返す全域 resolver があれば、この必要成功bitを返せるので矛盾する。
返却辞書がある場合だけの部分正当性や、fuel付き探索の停止を E1 と呼んだものではない。

追加の強い定理は `CommonRoleMergedSemantic.head_determines_requirements`。
**任意の有限 code、任意 i∈visible code、任意二代入 σ,τ : Nat→Common.Ty** について、
**全実head termの両解釈が定義され同値なら**、**任意の実child∈i.constraints**について、
**両child解釈が存在**し、そのroleは等しく、型引数も Common 要求同値になる。
この定理には finite target 前提がない。`HeadDeterminesRequirements` の追加だけでも今回の family は除外できない。

## 2. 反例と修正提案

実 merge は同じ tick tag の payload を右結合 union で合流する。
tag は一意になるが、payload `union(P,P)` は構文に残る。
Common では任意P代入でPと同値、しかし record 用Nはそれを減らさない。

小さい構成は、head `tick(union(int,int))`、where `R tick(int)` の一宣言。
実 size4/2、変数なしで実 checker を通り、唯一のchildは同じgoalに戻る。有限辞書はない。
この recipe の最小構成（一tag、二コピー、一child）であり、全文法での絶対最小性は証明していない。
より強い主定理は任意linear ruleをpaddingして全Codeを符号化するため、self-loop cacheだけでは解決できない。

source の比較例は次。一般 producer union 型注釈を仮定していない。

```yulang
role R 't:
    type value

impl R (:{tick 'a, tick 'a}):
    where :{tick :{box 'a}}: R
    type value = int
```

parser probeはok1/recovery0。実mergeから実core headまでのLean bridgeも証明した。
ただし、全source elaboratorやconstructor ID allocatorの正確性まで証明したものではない。
対象は原契約の任意verified **core registry**。source-generated集合に狭めた別定理は未証明。

修正案は、hidden record fieldの除去に加えて合流payloadの同一union branchも縮約し、
**縮約後にsizeと変数出現回数を数える**こと。
任意全registry / 全finite regular goalの量化は維持し、checkerの正規化を変更する提案とした。
[承認用の一問](../questions/2026-11-07-b4r4-merged-payload-size.md) に推奨を先に書いた。
提案後のfull E1は未証明であり、specへ採用していない。
拒否先行は依然 [未決の作業上の選択](../questions/2026-11-07-b4r2-rejection-priority.md)。確定扱いしない。

## 5. 正確な残り

- **E1は成立していない**。現core契約の全域成功判定がE2で否定される。
  新payload縮約の提案を承認済み規則へすり替えず、その後のfull E1も主張しない。
- 全Common grammarのN意味保存と完全なchecker、全regular graphのclassifier/head matcher、
  全selection/rejection/ambiguity resolver、一般finite-tree agreement、一般nominal agreementは未証明。
  今回は全goalが有限木なので両K2/priority/nominal unfoldingの内部選択に依存しない。
- canonical residualの一般source/複数tail/open variant row bridge、全type-equivalence-invisible sizeの完全分類は未証明。
  duplicate record fieldだけが問題という主張は実payload idempotenceで否定した。
  associated RHSは定数であり、他roleのprojectionやnominal unfoldingによる新障害を証明したとは言わない。
- `generate_common_qualified_finite_exact` の全Common代入に対する実有限生成 iff 独立typing、
  method ID / ordinary・associated等式 / pending goal / weak-captured-generalizedの保存、
  全自由parameter familyは未証明。正確な全称lemmaは [設計note §7](../design/2026-11-07-b4r4-canonical-residual-and-merged-payload.md#7-qualified-の正確な未証明-lemma)。
  単独qualified generatorの非存在は証明していない。未解決tailは具体化までpendingのままにする。
- full source elaborator / constructor allocator / public Core.infer / Rustへの統合は未証明。B6へ残す。

これらを追加仮定にして同名E1を閉じたとは扱わない。
今回の終了理由は元全称core-registry契約へのE2である。
