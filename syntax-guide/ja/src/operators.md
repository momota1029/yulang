# 演算子は宣言で決まる

演算子は、パーサに固定されていない。`nullfix`・`prefix`・`infix`・`suffix` の**宣言**で作る。
**その宣言を import したファイルだけ**が、その演算子を読める。

```yulang
pub prefix(not) 8.0.0 = std::bool::not
pub infix (+) 5.0.0 5.0.1 = \x -> \y -> x.add y
pub suffix (..) 8.0.0 = std::data::range::from_included
```

## 結合力

結合力は `5.0.0` のような、dot 区切りの数列で書く。**大きいほど強く結合する**。
桁数は 3 つに固定されない。`70` は `70.0.0.0...` を表すので、短く書いても誤りではない。

```yulang
pub infix (+) 5.0.0 5.0.1 = ...    // 左右で値が違う → 結合方向が決まる(左結合)
```

`infix` は左右の結合力の組を持ち、**左右を非対称にする**と結合方向が決まる。`5.0.0 5.0.1` は左結合。

## 短絡評価: `lazy infix`

`lazy infix` の本体は、両辺を thunk(`() -> value`)として受け取る。`and` / `or` の短絡評価はこれで実現する。

## 標準の演算子

`+`、`==`、`and` などの標準の演算子表は、標準ライブラリの prelude が定義する。
**言語そのものではなく、標準ライブラリの章で扱う**。

## なぜファイルの依存が減るか

演算子が「宣言を import したファイルだけ」で読めるので、ファイルをパースするのに必要なのは、
**そのファイルが import した宣言だけ**になる。プログラム全体の演算子表は要らない。
パースの依存が、import の依存と一致する。

## パイプライン `|`

```yulang
"data" | parse | render     // render (parse "data")
xs | map f                  // map f xs
```

`x | f` は、左辺の値を右辺に渡す。左辺は右辺の**最後の引数**になる。
`|` の結合力は、全演算子の中で一番弱い。左辺は `and` / `or` を含む式全体になる。

```yulang
xs | map f == ys           // xs | (map f == ys)
1 + 2 | f                  // f (1 + 2)
a and b | f                // f (a and b)
```

## application との強さ

`.` / `::` / `(...)` / `[...]` の後置と、ML の並置は、prelude のどの infix 演算子よりも強く結合する。

```yulang
1 + f x          // 1 + (f x)
not x.field      // not (x.field)
```
